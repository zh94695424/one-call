## 5. Exact data flow, signatures and response

Verifier signature:

```java
VerifiedCustomerSession verify(OpaqueCustomerBearer bearer, String expectedAudience)
        throws CustomerSessionVerificationException;
```

The authenticator always supplies the fixed constant `onecall:customer-session:v1`; no caller-selected audience/configuration override. The adapter must verify opaque server session existence, validity, customer domain, revocation/expiry/disabled state and server-stored account/channel facts. Only an accepted server session returns VerifiedCustomerSession. A null/malformed result is adapter unavailability (503); wrong audience is 401. Neither adapter nor boundary decodes JWT claims, accepts signed client account claims, infers channel from User-Agent/Origin, or maps a UUID-shaped bearer directly to an account. TTL/storage policy is adapter-owned and deferred; no clock/TTL default is invented here.

1. REQUEST filter accepts only exact servlet path `/api/v1/customer/me`, method GET, normal initial dispatch; also require raw request URI to equal the context path plus that literal path, so percent-encoded aliases cannot pass merely because a container decoded servletPath. Reject other paths/methods with sanitized 404/NOT_FOUND without verifier or DB access. This intentionally prevents MVC's automatic HEAD/OPTIONS, trailing-slash/encoded aliases, other canonical API paths and `/error` being usable as extra endpoints. Error dispatcher remains available internally. No proxy-header trust or URL-based identity fallback.
2. Enumerate Authorization headers: require exactly one nonempty value. Accept case-insensitive `Bearer`, one or more ASCII spaces, then RFC 6750 b64token grammar `[A-Za-z0-9._~+/-]+={0,}` with no trailing text/whitespace, control characters, comma folding or extra credentials. Leading whitespace, tabs, empty token, multiple headers, Basic, embedded spaces, query-only/cookie-only bearer are 401. Do not invent a session-token length policy; container header-size limits remain transport limits, not approved token/TTL policy. A JWT-shaped string is merely opaque bytes and must be accepted/rejected by the server verifier, never decoded.
3. Call verifier once; validate UUID/channel/audience result, then construct a CustomerRequestPrincipal and HttpServletRequestWrapper overriding `getUserPrincipal()`/`getRemoteUser()` with this principal. Never reuse an incoming/container principal, forwarded identity header or request attribute. The wrapper contains no bearer field, but the underlying servlet Authorization header remains readable; this slice does not physically strip headers. Bearer material exists only transiently for parsing/verifier invocation, never in PA11 logs, serialization, principal, attributes, caches, fields surviving the call or diagnostic objects.
