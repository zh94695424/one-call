## 3. Source-verified facts and corrected window rule

- `DefaultShareMediaAuthorizationService` performs authoritative grant/admission checks, leaves the transaction, invokes `issueOrReplay`, then commits the existing access event. Preserve that ordering and existing public error mapping.
- `decision.grant().evidenceId()` is the evidence accessor. Do not call the nonexistent `decision.witness().evidenceId()`.
- Resolve evidence with `EvidenceMediaObjectReader.resolve(evidenceId)`. Require `Found`, nonblank object ID, valid metadata, and a strictly positive `durationSeconds`; every resolution failure follows the exact `DEPENDENCY_UNAVAILABLE`/no-event rule below, never an invented invalid-authorization outcome or guessed fact.
- No authoritative sub-window exists in P3, the admission witness, grant snapshot, request, or schema. PA20 currently authorizes the full object window. Therefore PA21 pins exactly one production window: `[Duration.ZERO, Duration.ofSeconds(durationSeconds))`.
- PA19 accepts only an opaque credential and expected purpose, not a requested window. It validates claim window shape/bounds (`0 <= start < end <= duration`) only; PA20 enforces the full-object window before physical byte open/read; PA21 issues only `[0, duration)`. This does not remove PA19's other audience, purpose, time, current-state and object checks. Sub-window issuance/product policy remains deferred.
- Resolve evidence once outside sharing transactions per authorization call, after authoritative grant/admission/lifecycle checks close and before fingerprint comparison or provider invocation; reuse that immutable fact bundle for replay/race recovery. Zero/ambiguous evidence readers (even with `@Primary`), a throwing provider/reader, null reader/result, `Missing`, `Unavailable`, or malformed facts throw existing `DEPENDENCY_UNAVAILABLE`, append **no access event of any type (including FAILURE)** and invoke **no credential provider**. Existing prior events, if any, remain unchanged and are compared only after successful resolution. A later successfully resolved call must still conflict before provider replay if recorded media facts changed. No witness/schema/public error-code change is permitted.

## 5. Exact wire and binary contract

Credential text is exactly `ocmp1.<kid>.<payload-b64url>.<mac-b64url>`, used only as the opaque Bearer value. No JWT, JSON, compression, padding, whitespace, alternate separator, URL, or query form. Total ASCII credential length is 1–2048 bytes inclusive; reject empty, non-ASCII, overlong, under-segmented, over-segmented, and trailing-byte forms before unbounded allocation.

Canonical payload field table, in this order:

| # | Field | Type/bytes | Prefix/endian/UUID order |
|---|---|---|---|
| 1 | domain | fixed ASCII `ONECALL-MEDIA-PLAYBACK\0`, 23 bytes | no length prefix |
| 2 | version | fixed unsigned byte `0x01` | no prefix |
| 3 | audience | strict UTF-8 bytes | u16 unsigned big-endian byte length |
| 4 | grant ID | UUID, 16 bytes | no prefix; RFC-4122/network order: most-significant 64 bits then least-significant 64 bits, each big-endian |
| 5 | admission ID | UUID, 16 bytes | same UUID order; no prefix |
| 6 | evidence ID | UUID, 16 bytes | same UUID order; no prefix |
| 7 | media object ID | UUID, 16 bytes | same UUID order; no prefix |
| 8 | revocation generation | signed int, 4 bytes | big-endian; value must be nonnegative |
| 9 | code generation | signed int, 4 bytes | big-endian; value must be nonnegative |
| 10 | purpose | strict UTF-8 enum name | u16 unsigned big-endian byte length |
| 11 | issuedAt | signed epoch microseconds, 8 bytes | big-endian UTC |
| 12 | notBefore | signed epoch microseconds, 8 bytes | big-endian UTC |
| 13 | expiresAt | signed epoch microseconds, 8 bytes | big-endian UTC |
| 14 | durationSeconds | signed int, 4 bytes | big-endian; strictly positive |
| 15 | window start | signed nanoseconds from zero, 8 bytes | big-endian; nonnegative |
| 16 | window end | signed nanoseconds from zero, 8 bytes | big-endian; greater than start and at most duration seconds |

Only `audience` and `purpose` use u16 lengths. Every fixed field has no length prefix. Maximum payload is 4096 bytes; reject a u16 length overflow, cumulative payload overflow, truncated field, trailing payload bytes, invalid UUID, negative generation/duration/window, invalid enum, invalid UTF-8, impossible time ordering, and noncanonical Base64URL. Base64URL decoding must re-encode without padding and byte-compare the original. MAC is exactly 32 bytes.

MAC input is ASCII `onecall-media-playback\0v1\0`, ASCII `kid`, one NUL byte, then exact payload bytes. HMAC is SHA-256 with exactly 32-byte selected key; compare with `MessageDigest.isEqual`. `kid` is 1–32 ASCII bytes matching `[A-Za-z0-9_-]+`, case-sensitive. Verification first resolves and validates key authority/snapshot, **before any token parsing**, under §6 precedence. Only with that usable snapshot do structural, Base64, UTF-8, MAC, claim, time, range, key-id and trailing-byte failures map to `Invalid`; unknown-but-well-formed kid is also `Invalid`. Unavailable authority/snapshot wins over all token faults and remains `Unavailable` (existing HTTP 503), while credential faults under usable authority remain existing denial/403; no public response distinguishes individual credential faults.

All `Instant` values are normalized deterministically to PostgreSQL-compatible epoch microseconds by truncating nanoseconds toward zero at the issuer/verifier boundary (`instant.getNano() / 1_000`), and reconstructed with `Instant.ofEpochSecond(floorDiv(micros, 1_000_000), floorMod(micros, 1_000_000) * 1_000)`. Issuer and verifier both use this canonical value; ordinary `Clock.systemUTC()` issuance never fails because of residual nanoseconds. The same normalized value is used for issuedAt/notBefore and event fingerprinting.
