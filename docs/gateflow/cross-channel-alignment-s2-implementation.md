## Implemented behavior

The admin now has exactly six primary entries: dashboard, users, catalog, orders, employees and audit. Existing activation/IVR routes are user subnavigation; trial settings are catalog subnavigation; `/roadmap` remains a legacy offline-support explanation. Unknown subject, employee, version, order and session IDs show an absent record without fallback.

Login uses a particular employee's normalized login name and six-digit DEMO code. There are two active administrators, two active operators and one disabled seed. Employee records, the private credential Map and local login session are separate from canonical business state. Role is derived from the active employee on render and mutation; the session binds employee ID, credential version, role and a fresh local nonce. The review drawer no longer changes roles. Even the local review import requires an active admin, and the general review snapshot omits employee records for non-admins.

Admin employee actions cover create, name/role editing, disable/enable and credential reset. Each confirms an exact target, before/after inputs and a reason of 4–200 characters. New/reset DEMO codes appear once in a result dialog; no code enters audit or business snapshots. The last active admin cannot be disabled/demoted. Current employee disable/reset/role changes revoke the local session, cancel pending writes and return to login. Mutation confirmation revalidates actor/session, actor revision, target/family fingerprint, page and data state. Double submission, cancellation, Escape, short reason, changed revision and low-privilege forged DOM actions cannot write.

The existing admin parallel catalog/rule/subject model has been removed. One `OnecallBusiness` state drives current offers, trial, users, IVR, orders, evidence and entitlement views. Admin changes use a candidate business snapshot and the shared atomic loader before committing. Current commercial data comes from S1; shared module/generator/unit tests were not changed.

Pre-alignment PKG-PER/PLUS/TEAM values are migrated as explicitly historical, read-only versions. ORD-601—604 retain original price, recording quota, term, IDs, source and independent payment/entitlement facts in full canonical snapshots. Existing subject/trial/IVR/evidence facts, including EVI-9901's unverified capture identity, remain historical facts. Missing fields in the old small offer objects are represented by explicit zero/default DEMO metadata, not new production rights. Old PKG history cannot be reactivated or cloned into a competing current product. Historical fact migration is validated by the shared snapshot validator at startup.

Catalog supports product-family grouping; status/channel/audience filters; display/name/version sorting; unique new code/SKU; complete name/description/type/audience/price/term/installment/interval/six-rights/channels/sort/features fields. New rows save DRAFT; editing a draft preserves its ID and increases revision. Published versions only clone to a new draft; one editable draft per SKU. Publishing retires the old ACTIVE SKU version; sale changes increase revision without rewriting published commercial content. Inputs enforce the plan's integer/price bounds, fixed term combinations, nonempty MINIAPP/WEB channels, bounded features, quote-only enterprise semantics and zero enterprise seats/fixed lines on individual offers. Every version and order details show full rights and DEMO caveats.

Trial publishing retains FIRST-TRIAL and only affects subsequent first grants. Browser assertions independently compare whole prior order/grant/evidence/entitlement arrays before and after catalog and trial publication. The basic IVR drawer now calls shared start/confirm/consume/claim helpers, retaining S2's existing new/repeat/unconfirmed/missing-caller/expired/conflict behaviors; complete S3 branch expansion is deferred. Purchase guidance never creates an order, and claiming preserves trial and capture/session links. All support text comes from the shared unconfigured OFFLINE configuration.
