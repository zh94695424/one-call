## Behavior and contract decisions

1. **Wire authority:** one public final `MediaPlaybackCredentialAuthority` implements the existing P3 issuing seam and PA19 verifier. Its package-private codec encodes the exact domain/version, u16 audience/purpose lengths, network-order UUIDs, signed fixed-width generation/time/duration/window fields, strict UTF-8 and unpadded canonical Base64URL. The HMAC input includes its separate domain, kid and NUL separator; HMAC-SHA-256 uses exactly 32-byte keys and constant-time MAC comparison. The total envelope is capped at 2048 ASCII characters before decoding, and the binary payload cap is 4096 bytes. Truncation, trailing bytes, bad lengths/UTF-8/enums/MAC/shape/time are denied under a usable authority.
2. **Authority precedence:** every P3 issuance/replay/verification resolves up to two key providers and obtains one usable snapshot before token inspection. Zero/multiple/throwing/null/invalid snapshots return Unavailable; unknown or removed kids under another usable active key return Invalid. Entries copy key bytes on construction/access; overlap lists are immutable. No production key adapter, property secret or remote client is supplied. P2 `issue` always returns Unavailable without looking up keys.
3. **Expiry/time:** epoch microseconds use checked `epochSecond * 1_000_000 + nano / 1_000` and floor-div/mod reconstruction. Fresh authority issuance uses exactly the normalized minimum witness expiry, never a policy TTL or fresh sub-bound expiry. The admission service still accepts normalized provider expiry strictly after database decision time and at most the normalized witness bound, retaining ordinary/sub-microsecond synthetic-provider compatibility.
4. **Evidence handoff:** after authoritative sharing transactions close, the service resolves one immutable positive-duration object through the named evidence reader and derives only `[0,duration)`. The authority receives facts, not an evidence/repository dependency. Missing/null/throwing/unavailable/malformed evidence fails with DEPENDENCY_UNAVAILABLE before provider invocation, access-event insertion or fingerprint fabrication; recovery of the same request is fresh if no prior success exists.
5. **Event identity:** the event ID formula and raw UTF-8 request digest are unchanged. The pre-provider sorted map has 19 fields including the normalized witness bound and eight facts, but no fresh anchor/kid. Success maps have exactly 24 fields; post-resolution provider failures have exactly 20. Success stores normalized returned provider expiry and nonsecret issued/not-before micros/kid. It never persists a token, encoded payload, MAC, key bytes, bearer/header, credential URL or raw request key. Canonical payload-hash comparisons avoid Jackson int/long node-width differences after PostgreSQL JSONB round trips.
6. **Replay/races:** a prior success is validated against its complete canonical hash, identity, expanded fingerprint, exact fields, current facts and bounds. Its committed expiry and anchor are passed to the provider. Reconstruction uses only the recorded ACTIVE/VERIFY_ONLY key and never replaces a missing key. Current-bound equality is not required. Conflicting first writers validate `EventWriteResult.first()` and reconstruct the winner outside the write transaction; they do not return the loser or insert again. Missing winning keys fail closed.
7. **Spring:** one unconditional authority bean is created in `MediaPlaybackConfiguration` with system UTC clock and `ObjectProvider` keys. The persistence root imports that configuration and removes its old credential fallback factory/type. Both admission consumers and the playback verifier receive the identical instance. Missing keys/evidence do not prevent startup. Playback requires the one verifier; there is no second verifier fallback. The evidence resolver checks exactly-one per call, including ambiguity hidden by `@Primary`.
8. **Ownership/architecture:** no public API, named interface, broad evidence query, database migration, ACL, storage locator, physical-reader authority, deployment or external secret integration is added. The three credential files are pinned; global command remainder is 22, credential files three, global internal files 76, public-admission files ten with nine top-level/13 nested exported classes, admission implementation eleven, playback eight and gateway four. Existing source prohibitions remain and the credential scan limits imports and forbids persistence/network/logging adapters.
9. **Integration fixtures:** `MediaGatewayTransportIT` retains the six historical STUB methods and adds explicit STUB/REAL composition. REAL uses the actual web authority/service beans and a non-bean fixed-clock issuer. Public-admission fixtures seed an ORIGINAL object/validated recording in the allowlisted test file and resolve it through the real named evidence reader/role; the shared unallowlisted fixture is unchanged.
