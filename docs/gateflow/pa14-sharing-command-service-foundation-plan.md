Routes are `POST /api/v1/customer/shares`, `POST /api/v1/customer/shares/{shareId}/revocations`, and `POST /api/v1/customer/shares/{shareId}/code-rotations`. Preserve GET `/api/v1/customer/shares`, GET `/api/v1/customer/me`, the context path, query service and read-only `sharing_role` transaction. Unknown methods, aliases, encodings, and other paths retain the sanitized 404 behavior.

No schema, migration, OpenAPI, or documentation contract changes; no V001–V010 edits. No admission, ticket, media/playback authorization, Redis, COS/KMS, SMS/OTP delivery, frontend, deployment provisioning, or production policy/KDF/TTL/provider values. Do not guess policy, code parameters, normalization, secret, HMAC key, TTL, or credentials. Test adapters are deterministic and test-only; missing/unconfigured production policy, token, code, or HMAC providers fail closed. Do not change production policy or enablement.

## Identity and canonical data

All canonical JSON in the digest formulas below uses RFC 8785 per frozen docs/14 §2.5; the snapshot member names are exactly `content`, `verification`, and `creation` per §2.12.

Database grant, row and aggregate IDs are UUIDs; public `shareId` is opaque and never parsed as UUID. Creation and action request keys are nonblank, 1–128 Unicode code points, hashed as exact UTF-8 bytes without trim, normalization or case folding. Digests are lowercase SHA-256 hex.

- `shareId = "share:" + lowercaseHex(SHA-256(canonicalJson({creatorAccountId, creationRequestId})))`; these are exactly the two canonical object properties. It excludes database time, evidence, fingerprint, and generated secrets.
- `creationRequestDigest` is SHA-256 of exact creation-key bytes. Define the exact persisted `content_snapshot` members `content`, `verification`, and `creation`; persist those as JSONB object nodes, never as JSON string nodes containing canonical JSON. `scopeDigest = lowercaseHex(SHA-256(canonicalJson({content,verification})))`; `content_sha256 = lowercaseHex(SHA-256(canonicalJson({content,verification,creation})))`. Content binds evidence, subject/source/identity-at-capture and immutable artifact facts; verification binds mode and approved extraction/mobile semantic binding (mobile HMAC and key version, never raw number). `creationFingerprint` hashes `creation` with only its fingerprint member removed. The IT reads the stored row back, asserts `jsonb_typeof` is `object` for all three nodes, and recomputes both digests from the read-back objects.
- `creationFingerprint` is lowercase SHA-256 of canonical creation JSON with only `creationFingerprint` removed. Its exact fields are `schemaVersion:1`, `creatorAccountId`, frozen JSON key `ownerOrganizationId` populated from Java/business `grantOwnerOrganizationId` (JSON null if absent), `evidenceId`, `verificationMode`, `downloadAllowed`, business `expiresAt` (RFC 3339 UTC), `maxAdmissions` (JSON null if absent), `scopeDigest`, and `creationRequestDigest`. Exclude generated IDs/secrets, `valid_from`, `occurredAt`, revisions, `createdAt`, `updatedAt`, and all other observed/server timestamps. Same identity and same semantic request replays; changed semantics return `SHARE_CREATION_CONFLICT` without another grant.
- Artifact canonical order is `ORIGINAL = 0`, then `DERIVED = 1`, followed by `mediaSha256`, `mediaSizeBytes`, and `mediaMimeType` ascending. Apply this order to canonical content, scope/content digests, fingerprints, stored facts, and assertions.
- For a transition, after the locked grant UUID is known, `eventId = "share-transition:" + lowercaseHex(SHA-256(canonicalJson({shareGrantId, actionType, sourceIdentity})))`; `sourceIdentity` is exactly `{kind:"REQUEST", actionRequestId:<exact raw key>}`. `actionFingerprint` hashes canonical `{shareGrantId, actionType, reasonCode, newExpiresAt, actionRequestDigest}`. Revoke uses its exact validated reason or JSON null; rotate has no reason and `reasonCode` is JSON null. `newExpiresAt` is JSON null for both. Generation witnesses do not enter the fingerprint. Same key with changed action semantics is `SHARE_TRANSITION_CONFLICT` with no append. Transition Outbox dedupe literal is `share-transition:share-transition:<64hex>`.
- Sample `clock_timestamp()` exactly once per create/transition after command-role assertion, required locks and context reads (and grant lock for transitions); reuse the sample for expiry comparison and all operation timestamps, including create `valid_from` and event/audit persistence. It is not an identity/fingerprint input. `valid_from` is the creation-time authority.
- Web `expiresAt` requires an explicit UTC/offset designator. Before parsing to `Instant`, fingerprinting or any DB access, reject malformed/non-offset input or more than six fractional-second digits as 422 `VALIDATION_FAILED` (including seven/nine digits with trailing zeroes); never round/truncate excess web precision. Accepted zero-to-six-digit input converts to an exact microsecond-aligned `Instant`. Normalize every accepted business and sampled database `Instant` to canonical RFC 3339 UTC `Z` text: whole seconds when nanos are zero, otherwise exactly six fractional digits (right-pad shorter fractions), never retained offsets or nanoseconds. Use the identical normalized Instant/text for expiry comparison, fingerprints/canonical JSON, INSERT, replay, response and typed timestamp/JSONB read-back assertions/digest recomputation, including creation `expiresAt` and Outbox `occurredAt`. Direct non-web create input must also be microsecond-aligned or fail validation before fingerprint/DB. Equivalent offsets yield identical text/fingerprints. This does not add observed/database time to fingerprints or change exact key sets; action `newExpiresAt` remains JSON null.

The exact Outbox event types are `SHARE_CREATED`, `SHARE_REVOKED`, and `SHARE_CODE_ROTATED`. The exact access-event `event_type` values for these operations are `REVOKED` and `CODE_ROTATED`; create has no access event. Attempt `actionType` values are `REVOKE` and `CODE_ROTATE`. The `SHARE_*` names are Outbox-only and must never be inserted into V009's frozen access-event type CHECK. Create Outbox dedupe key is `share-created:<grant_id>`; transition Outbox dedupe key is the literal `share-transition:share-transition:<64hex>`. Audit action codes are `SHARE_GRANT_CREATE`, `SHARE_GRANT_REVOKE`, and `SHARE_GRANT_CODE_ROTATE`. Redacted payloads are limited to share/grant IDs, result status/counters, action fingerprint/digest and timestamps. Both access-event and Outbox `payload_sha256` are lowercase SHA-256 of canonical JSON of the exact redacted payload. No raw token, extraction code, salt, code hash, raw designated mobile, or reason is included in either payload.

## Transactions, locks, ordering

Use one READ COMMITTED command transaction/connection, `SET LOCAL ROLE sharing_command_role`, and assert exact effective `current_user` before command reads. Login membership is limited to the already-authorized evidence and command roles; there is no production provisioning. Switch only around the evidence projection read to `evidence_role` on the same connection, then restore and assert `sharing_command_role` before any sharing read/decision/write. Probe login is `NOINHERIT`, named `command_probe_<uuid>`. Keep command datasource distinct from query datasource and never fall back to query access.

Transaction control is part of `SharingCommandRepository`, implemented by `JooqSharingCommandRepository`, not raw SQL in the service. All five operations below receive the identical transaction-bound `DSLContext`, create no connection/transaction/savepoint, and fail closed with rollback and declared 503 `SERVICE_UNAVAILABLE` on role/assertion/lock/clock failure. The service calls switch→reader→restore in `try/finally`; a failed restoration aborts the command and cannot permit a subsequent read/write. `switchToEvidenceRole` also asserts `current_user = 'evidence_role'`.

| Transaction method | Exact SQL/behavior and test owner |
| --- | --- |
| `void assertCommandRole(DSLContext transactionDsl)` | Execute `SET LOCAL ROLE sharing_command_role`; `SELECT current_user` must equal `sharing_command_role` before the first command read; IT 1 `commandRoleIsAssertedBeforeFirstCommandRead` and IT 2 `queryRoleCannotAssumeCommandRole` |
| `void switchToEvidenceRole(DSLContext transactionDsl)` | `SET LOCAL ROLE evidence_role`, then assert effective role; IT 7 `evidenceProjectionUsesCommandTransactionConnection` |
| `void restoreAndAssertCommandRole(DSLContext transactionDsl)` | `SET LOCAL ROLE sharing_command_role`, then assert effective role before any further command read/decision/write, including reader failure; IT 1/7 |
| `void acquireCreatorWorkspaceLocks(DSLContext transactionDsl, ShareCommandCaller caller)` | Execute `SELECT pg_catalog.pg_advisory_xact_lock(pg_catalog.hashtextextended(?, 0))` with bound frozen keys: organization rank 7 `organization_access.organization:<organization_id>`, rank 8 `organization_access.membership:<organization_id>:<account_id>`, rank 9 `customer_iam.account:<account_id>`; personal rank 9 only; every UUID is canonical lowercase 36-character text, never membership-row ID; existing IT 6 `createConcurrentSameAndDifferentIdentities` asserts personal rank 9 only and organization ranks 7→8→9 with exact keys; transition ranks IT 12/17 |
| `Instant sampleDatabaseTime(DSLContext transactionDsl)` | Exactly one `SELECT clock_timestamp()` per create/transition, non-null result reused, never `now()` or JVM time; IT 1/7, IT 3/4/11/16 |

For transitions, acquire ranks, re-read active caller context, then lock/read the grant and verify caller-account plus selected-organization ownership. A transition path `shareId` must be nonblank and 1–128 Unicode code points; invalid values return 422 `VALIDATION_FAILED` before provider/service/DB lookup. Only syntactically valid absent or non-owned grants return sanitized 404 without append. Missing/inactive account, organization, or membership context returns 403 `FORBIDDEN` without grant disclosure/facts; context SQL/decode failure returns 503 `SERVICE_UNAVAILABLE`. Create order is grant → Outbox → audit, with no access event. Revoke and rotate order is ranks → active caller context → grant lock/ownership → exact persisted replay → source/status/mode/expiry and expected-witness validation → new-rotate-only policy evaluation → rotate replacement material generation; then append access event → conditional grant update → Outbox → audit. If `transitionGrant` returns `NotUpdated`, do one bounded same-transaction reread, then throw the rollback-only stable conflict using the frozen revoke/rotate mapping; never return success/current state. Event, Outbox, audit, state, generation and revision all roll back. All writes share one transaction; any append or commit failure rolls back all facts and state.

Create order for every mode is command-role assertion→creator workspace locks→active context/evidence reference→same-connection evidence projection with evidence-role switch/restore→single database-time sample→mode semantic material→canonical object snapshot/scope/fingerprint→risk/ownership and policy→identity replay/insert. `readCommandContext` composes the active-context/reference reads after locks; missing/ineligible context/evidence stops before material. Match reference and projection evidence/subject/status/identity-at-capture, rejecting inconsistent/unreadable projection as 503. Mode semantic material is `{mode}` for `NONE`, `EXTRACTION_CODE`, and `ORGANIZATION_MEMBER`; only `DESIGNATED_MOBILE` calls `bind(clientDesignatedMobile)` here. No grant UUID or token/code generation is needed for canonicalization, risk, policy or replay. Only after initial identity lookup misses allocate a fresh grant UUID, issue token and (code mode only) extraction code, validate material, and call exact repository method `findGrantIdByTokenHash(DSLContext transactionDsl, String capabilityTokenHash)`. An existing token-hash collision aborts with sanitized `INTERNAL`/500 and no facts/secrets. Insert SQL is exactly `INSERT ... ON CONFLICT (share_id) DO NOTHING RETURNING` only. If it returns zero rows, do exactly one same-transaction reselect by `share_id`: exact identity/fingerprint returns metadata replay; changed fingerprint returns 409 creation conflict. An actual `uq_share_grant_token_hash` race/collision propagates to transaction rollback and sanitized 500; never catch/continue in the aborted transaction. Persist grant→Outbox→audit. A pre-existing replay never allocates a grant UUID, issues secrets, or writes. Risk and policy precede every replay response. For revoke/rotate, re-read active caller context after advisory ranks; a context missing/inactive returns 403 without grant facts, while SQL/decode failure returns 503. Then lock/read the grant by opaque `shareId` and caller account/selected organization ownership, return sanitized 404 without append only for valid absent/non-owned IDs, sample time and resolve an exact persisted action replay before current-state witness predicates. Revoke preserves terminal `REVOKED` 410 precedence; incompatible/expired active transitions map to the declared 409. Rotate is allowed only from `LOCKED` with `EXTRACTION_CODE`, and transitions to `ACTIVE`; any other source status or mode returns 409 `SHARE_TRANSITION_CONFLICT` before provider invocation or write. Exact persisted replay bypasses current rotation policy. After replay misses, validate source/status/mode/expiry and expected witnesses; only for a genuinely new transition call `ShareRotationPolicyProvider.evaluate(RotationPolicyRequest)` with the locked grant state and caller. `ProviderResult.Denied` or decision `DENY` returns 403 `FORBIDDEN`; `ProviderResult.Unavailable` returns 503 `SERVICE_UNAVAILABLE`, both before material generation, update or facts. Only `Allowed(ALLOW)` permits replacement material generation, then access event → conditional grant update → Outbox → audit. IT 14 asserts this call site/order, deny/unavailable no-effects, retry of the same key after policy changes to ALLOW, and exact replay bypassing a now-denied/unavailable policy. Rotate increments both generations by exactly one, subject to adapter preconditions below.
