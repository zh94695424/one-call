# 客户账号、登录身份与企业工作空间

> 当前基线：2026-10-21。本文统一小程序、客户 Web 与 IVR 认领的账号口径；覆盖旧文档中将企业当成独立登录账号、将业务号码当成登录手机号的表述。仓库目前是浏览器原型，没有已建成的生产数据库或认证服务。

## 1. 核心规则

一个自然人使用一个客户账户。微信和经验证的登录手机号是进入该账户的身份；企业是该账户加入的组织工作空间，权限来自组织成员关系。企业没有供多人共用的登录账号。

用户可以用已登记为登录身份的手机号登录，不是任意绑定的手机号都能登录。取证用的业务手机号、独立固话、企业联系方式与登录身份分开管理；绑定、开通或认领业务号码不会自动新增登录身份。一个手机号可同时承担两种用途，但必须分别建立登录身份和业务关联，不能相互推断。

运营后台使用独立员工账号，不与客户账户、企业管理员或业务号码互通。

## 2. 表职责与关联

以下为生产建表建议，不是已执行的数据库迁移。当前原型只实现共享不可变目录与查询函数，命名对应见最后一列。

| 建议表 / 对象 | 主要字段与约束 | 责任 / 当前原型 |
| --- | --- | --- |
| `customer_account` | `id`、显示名、状态、创建时间；稳定内部 ID | 自然人账户；`accounts` |
| `auth_identity` | `id`、`account_id`、身份提供方、提供方作用域与 subject、验证时间、状态；有效身份在提供方作用域内唯一 | 微信或手机号登录身份；`authIdentities`。微信 subject 不使用昵称；多应用须明确 appid/openid 与经验证的 unionid 关联 |
| `identity_profile` | `account_id` 唯一、实名状态、受保护的核验引用 | 实名事实，独立于登录成功；`identityProfiles` |
| `organization` | `id`、名称、状态；企业认证另行管理 | 企业工作空间；`organizations` |
| `organization_member` | `id`、`organization_id`、`account_id`、角色、部门、状态；同一组织与账户至多一条有效关系 | 组织权限来源；`memberships` |
| `business_subject` / 号码关联 | 稳定 `subject_id`、号码类型、号码保护索引、开通状态、认领关联；生产需明确个人 / 组织所有权 | 号码级试用、录音和开通主体；当前 `BusinessSubject.accountId` 仍是简化自然人关联，不能代替组织所有权 |
| `subject_claim` | `subject_id`、`account_id`、验证依据、时间、请求号 | 追加已核验业务关联；`SubjectClaim`，不创建登录身份 |
| `employee_account` | 员工 ID、后台登录名、状态、后台角色 | 独立运营域，当前后台原型已有员工管理 |

个人空间由客户账户派生，不需要为了个人用户再建一套账号表。企业成员离职或被停用只移除该企业的访问权，不应删除其自然人账户和个人空间。

## 3. 登录与空间切换

微信 / 手机验证码验证 → 查找启用的登录身份 → 解析唯一、启用的客户账户 → 加载个人空间及有效企业成员关系 → 选择空间 → 按当前成员角色展示功能。

未知手机号在本原型中登录失败；正式注册、增加登录手机号、换绑、合并账号及找回账号属于后续认证流程，不能用“业务号码验证成功”代替。个人空间始终存在；被停用的账户不能登录，被停用的成员或组织不出现在空间列表。角色只读，用户不能通过下拉框自行提权。

会话过期后重新验证登录身份并重新计算成员权限。重新登录成其他人时清除原账户的详情、选中项及工作空间上下文；只有新账户仍有原空间成员资格时才能恢复该空间，返回的页面还需通过新角色的路由检查。

退出、换账号或切换工作空间时清理导入、AI 纠错、号码验证、敏感操作确认等界面草稿；退出还会清空登录手机号与验证码。导出任务保留申请人和工作空间归属，只在对应账号和空间展示及操作。上述清理不会删除或改写录音证据、试用与订单事实。

## 4. IVR 与历史事实

未注册、未实名的 IVR 主叫仍可按键确认开通、领取首次试用并产生录音证据；不创建虚假的微信或手机号登录身份。用户之后在小程序 / Web 登录，再单独验证同一号码，检查冲突及号码回收风险后认领。

认领仅追加业务关联，不补写实名认证，不改变证据原始主体、录音时身份、试用授予或累计用量，也不把该号码自动升级为登录身份。支付与权益到账仍独立；工单、退款、发票继续使用统一线下客服入口。

账号目录不进入业务快照，跨端导入业务数据不得更换已登录的人或权限。`accountContext()` 仅为只读本地评审 hook，上线构建须关闭。

## 6. 后续落地责任

- 认证服务：真实微信 / 短信验证、注册与身份绑定、会话、安全退出、账号恢复和风控。
- 业务主体服务：组织号码所有权、个人 / 企业资源归属与迁移策略；保留不可变证据和试用事实。
- 授权服务：服务端依据账户、组织、成员状态及资源归属逐次鉴权；前端导航和样例过滤不作为安全边界。

上述三项属于生产工作单元，本轮没有实施数据库迁移、真实 OAuth、短信或服务端租户鉴权。
