# 跨端套餐与状态规则

> 当前状态：S1 共享规则基线，2026-10-20。本文定义本地原型的统一演示语义；运营后台接入安排在 S2，小程序、Web 与 IVR 展示接入安排在 S3。演示数据不是生产定价、真实支付或真实 IVR 能力。

## 1. 单一规则源

`shared/onecall-business.js` 是当前套餐样例、状态标签、线下客服配置和窄业务转换的唯一可执行来源。三个原型通过受控内联生成段使用同一份模块，以兼容 `file://` 和小程序预览的 `srcdoc` 沙箱。各页面仍保留自己的内存状态；刷新重置，浏览器标签之间不会自动同步。

后续跨端 QA 传递的是经过校验的本地评审快照，不是网络服务、生产接口或真实系统联调。快照仅包含业务字段，不包含员工、凭据、客户登录会话或 UI 状态。快照中的 `sequence` 只是本地 ID 分配提示，不是唯一性证明；分配器会跳过对应业务集合中已占用的下一候选 ID，成功状态提交前还会执行完整校验。

## 2. 状态独立性

| 维度 | 状态 | 规则 |
| --- | --- | --- |
| 认领 | 待认领 / 已认领 / 冲突 / 号码回收风险 | 认领追加账户关联，不改变实名、证据主体或试用资格 |
| 实名 | 未实名 / 已实名 | IVR 未实名用户可试用并产生证据；普通客户端购买仍需满足实名条件 |
| 开通 | 未开通 / 已开通 / 已停用 | 指 ONECALL 内部服务，不是运营商产品订购 |
| 试用 | 未领取 / 试用中 / 已耗尽 / 已过期 | `subjectId + FIRST-TRIAL` 永久唯一；规则换版、认领和跨端不会重发 |
| 支付 | 待支付 / 结果待确认 / 支付成功 / 已关闭 | 只有可信的模拟服务端结果可推进；IVR 不创建订单 |
| 权益 | 未发放 / 待发放 / 已到账 / 发放失败 | 支付成功不等于权益到账，发放是独立且幂等的转换 |
| 商品 | 草稿 / 在售 / 已下架 | 已发布内容和订单快照不可被当前套餐修改覆盖 |

## 3. IVR、试用与认领

IVR 会话先记录可信主叫事实和版本化提示词。只有可信主叫、明确按键 `1`、当前同意版本且主体未停用时，才确认会话、内部开通并尝试发放一次性试用。主叫缺失、超时或其他按键不新开通、不发试用。

试用默认演示规则为 300 秒、30 天。`consumeTrial` 不接受调用方传入 `subjectId`，只从状态为 `CONFIRMED` 且 `subjectId === confirmedSubjectId` 的唯一 IVR 会话派生主体。证据必须同时引用该会话和同一主体；这些冻结关联及全部已有证据引用会在读取幂等事件前校验。结构合法的旧事件即使后来额度已耗尽或已到期，仍返回首次结果且不重复扣量；篡改、缺失、替换或复制主体时，原键和新键都原子拒绝。剩余 20 秒时请求录制 60 秒，只记录和扣减 20 秒并标记额度耗尽。真实并发预占、有效录音确认和主动挂断仍属于生产服务工作。

认领要求已登录账户和与目标主体一致的可信号码验证。手机号使用微信手机号或短信演示验证，独立固话使用主叫挑战；登录本身不算号码验证。冲突和号码回收风险一律进入线下核验，不能因当前短信成功就开放历史证据。成功认领不改写任何已有 IVR 会话主体、证据元数据、采集时实名状态或试用快照。

## 4. 订单与权益

小程序和 Web 是订单的唯一允许来源。创建订单前校验账户、实名、明确购买同意、精确 `ACTIVE` 在售版本和渠道；`visibleOffers` 返回由共享规则生成的 `versionToken`，`createOrder` 强制要求该 token。token 对对象属性顺序稳定，但商品内容变化会产生不同值，因此缺失、空值、旧 token、草稿/下架版本或页面自行拼接的非契约值都不能新下单。当前可售判断只用于创建新订单；订单深拷贝的历史个人交易快照不依赖当前目录状态，之后套餐换版或下架仍可导入、确认支付和发放权益，历史金额和权益不变。

支付结果与权益发放分开：

```text
UNPAID -> UNKNOWN / PAID / CLOSED
UNKNOWN -> UNPAID / PAID / CLOSED
PAID -> PENDING -> ISSUED（或保留 FAILED 后重试）
```

`UNKNOWN` 阻止重复结账并要求查询原订单。重复回调或重复发放返回原结果，不创建第二个订单或权益。幂等事件按动作域分开保存，同一个字符串可分别用于确认、取证、认领、订单、支付等动作而不互相覆盖；同域同键若输入改变会原子拒绝，输入一致则返回首次处理时保存的不可变结果快照，不读取后来变化的订单或试用状态代替首次事实。创建事件身份与副作用对象必须在动作域内一一对应：认领 `requestId` 和订单 `idempotencyKey` 各自唯一，客户端激活与 IVR 激活分别按 `ACTIVATION`、`IVR_CONFIRM` 域校验 `eventId` 唯一；证据和权益结果对象也不能被同域多个创建记录重复声明。相同字符串跨域仍合法；`PAYMENT` 允许多个不同事件依次把同一订单从 `UNKNOWN` 推进到 `PAID`。导入和重放都按动作域检查结果结构、输入/结果稳定身份、冻结快照和引用；幽灵对象、跨主体结果、错误动作域或缺字段结果不能进入状态。历史 `UNKNOWN`、旧 `usedSeconds` 等首次可变值允许与当前 `PAID`、当前累计用量不同。事件键经过安全编码，特殊对象属性名不会污染状态。续购叠加、抵扣顺序、自动续费和退款资格尚未确认，本原型不实现。

快照导入和事件查键使用同一完整域级校验：单条命中结果合法仍不足以重放成功，所属域每条记录及创建结果唯一性也必须有效。两个证据或权益事件声明同一结果对象时，快照、导入及任一旧键重放均原子拒绝，新键也不能绕过异常域历史。有效历史中的不同事件可创建不同证据；使用新键重复发放权益仍返回既有权益，不保存第二条创建记录。`PAYMENT` 多事件例外和跨域同字符串复用均保留。

## 6. 线下人工客服

统一配置为 `mode=OFFLINE`、`configured=false`，联系方式和工作时间为空。页面接入后只展示“人工客服联系方式待配置”以及咨询、退款、发票、认领所需信息，不提供在线提交、审批、成功回执、处理进度、虚构电话/邮箱/微信或 SLA 承诺。

真实联系方式、退款规则、发票 SOP 和生产商品参数需要产品、运营与财务另行确认；未确认前必须阻断生产发布，不能用演示值代替。
