# 跨端套餐与状态规则

> 当前状态：S1/S2/S3 本地实现与规定 QA 已通过，2026-10-20；正式评审/验收由主控后续 gate 决定。本文定义三个本地原型的统一演示语义。演示数据不是生产定价、真实支付或真实 IVR 能力。2026-10-21 锁定的生产 IVR 待拨任务、独立呼入决策、30 秒失效和通话/录音上传规则见 [13](13-ivr-call-task-and-inbound-design.md)，当前原型尚未实现该生产协议。

## 1. 单一规则源

`shared/onecall-business.js` 是当前套餐样例、状态标签、线下客服配置和窄业务转换的唯一可执行来源。三个原型通过受控内联生成段使用同一份模块，以兼容 `file://` 和小程序预览的 `srcdoc` 沙箱。各页面仍保留自己的内存状态；刷新重置，浏览器标签之间不会自动同步。

跨端 QA 传递经过校验的本地评审快照，不是网络服务、生产接口或真实系统联调。`__onecallOps`、`__onecallMini`、`__onecallWeb` 的 snapshot/import/navigation hooks 仅供本地评审，上线构建须关闭。快照仅含业务字段，不含员工、凭据、客户登录会话或 UI 状态。`sequence` 只是本地 ID 分配提示，不是唯一性证明；分配器跳过已占用候选 ID，提交前完整校验。

客户账号目录也来自共享模块的不可变演示数据，但与业务状态完全分离：自然人账户、登录身份、实名档案、组织与成员关系都不允许作为业务快照字段导入。小程序 / Web 对同一演示人解析为同一账户；Web 空间与只读角色只来自有效成员关系。业务号码绑定 / 认领不会新增登录身份，导入业务快照不会替换当前登录账户或空间。账号表职责与入口见 [11](11-account-identity-and-workspaces.md)。

## 2. 状态独立性

| 维度 | 状态 | 规则 |
| --- | --- | --- |
| 认领 | 待认领 / 已认领 / 冲突 / 号码回收风险 | 认领追加账户关联，不改变实名、证据主体或试用资格 |
| 实名 | 未实名 / 已实名 | IVR 未实名用户可试用并产生证据；普通客户端购买仍需满足实名条件 |
| 开通 | 未开通 / 已开通 / 已停用 | 指 ONECALL 内部服务，不是运营商产品订购 |
| 试用 | 未领取 / 试用中 / 已耗尽 / 已过期 | `subjectId + FIRST-TRIAL` 永久唯一；规则换版、认领和跨端不会重发 |
| 支付 | 待支付 / 结果待确认 / 支付成功 / 已关闭 | 只有可信的模拟服务端结果可推进；IVR 不创建订单 |
| 权益 | 未发放 / 待发放 / 已到账 / 发放失败 | 支付成功不等于权益到账，发放是独立且幂等的转换 |
| 商品 | 草稿 / 在售 / 已下架 | 已发布内容和订单快照不可被当前套餐修改覆盖 |

## 3. IVR、试用与认领

小程序拨号时，同一规范主叫全局最多一条非终态待拨任务，默认 30 秒有效并在创建时冻结；重复请求不续期，明确更换只能替换尚未领取的任务。IVR 用可信实际主叫和 `callId` 调用独立呼入决策接口，在短事务中取得状态、可用录音时长快照并原子领取任务。领取后被叫不可更换；按键确认并成功预占权益后才外呼桥接。IVR 通话、时长与录音上传是通信事实，小程序拨号回调不是。完整生产规则与验收见 [13](13-ivr-call-task-and-inbound-design.md)。

IVR 会话先记录可信主叫事实和版本化提示词。只有可信主叫、明确按键 `1`、当前同意版本且主体未停用时，才确认会话、内部开通并尝试发放一次性试用。主叫缺失、超时或其他按键不新开通、不发试用。运营后台的耗尽场景只在首次打开时通过规范取证消费把历史 `280/300` 推进到 `300/300`；关闭再打开保持耗尽，不能回拨用量、重建证据或重写事件历史。

试用默认演示规则为 300 秒、30 天。`consumeTrial` 不接受调用方传入 `subjectId`，只从状态为 `CONFIRMED` 且 `subjectId === confirmedSubjectId` 的唯一 IVR 会话派生主体。证据必须同时引用该会话和同一主体；这些冻结关联及全部已有证据引用会在读取幂等事件前校验。结构合法的旧事件即使后来额度已耗尽或已到期，仍返回首次结果且不重复扣量；篡改、缺失、替换或复制主体时，原键和新键都原子拒绝。剩余 20 秒时请求录制 60 秒，只记录和扣减 20 秒并标记额度耗尽。真实并发预占、有效录音确认和主动挂断仍属于生产服务工作。

认领要求已登录账户和与目标主体一致的可信号码验证。手机号使用微信手机号或短信演示验证，独立固话使用主叫挑战；登录本身不算号码验证。冲突和号码回收风险检查先于事件重放和同账户重复处理，原请求号与新请求号都必须进入线下核验，不能因当前短信成功、既有关联或历史成功记录就开放历史证据。成功认领不改写任何已有 IVR 会话主体、证据元数据、采集时实名状态或试用快照。

Mini 独立固话成功页由共享状态守卫：主叫挑战创建或复用规范固话主体，关联当前账户，记录 MINIAPP 内部开通并按正常首次规则发试用；重复提交不新增开通或试用。成功只证明本次验证和 ONECALL 内部开通，不证明固话登记名义或产权。同一主体必须延续到试用和号码管理，并可通过评审快照交给运营后台和 Web。

## 4. 订单与权益

小程序和 Web 是订单的唯一允许来源。创建订单前校验账户、实名、明确购买同意、精确 `ACTIVE` 在售版本和渠道；`visibleOffers` 返回由共享规则生成的 `versionToken`，`createOrder` 强制要求该 token。token 对对象属性顺序稳定，但商品内容变化会产生不同值，因此缺失、空值、旧 token、草稿/下架版本或页面自行拼接的非契约值都不能新下单。当前可售判断只用于创建新订单；订单深拷贝的历史个人交易快照不依赖当前目录状态，之后套餐换版或下架仍可导入、确认支付和发放权益，历史金额和权益不变。

支付结果与权益发放分开：

```text
UNPAID -> UNKNOWN / PAID / CLOSED
UNKNOWN -> UNPAID / PAID / CLOSED
PAID -> PENDING -> ISSUED（或保留 FAILED 后重试）
```

`UNKNOWN` 阻止重复结账并要求查询原订单。重复回调或重复发放返回原结果，不创建第二个订单或权益。幂等事件按动作域分开保存，同一个字符串可分别用于确认、取证、认领、订单、支付等动作而不互相覆盖；开通状态迁移使用独立的 `ACTIVATION_STATUS` 域。同域同键若输入改变会原子拒绝，输入一致则返回首次处理时保存的不可变结果快照，不读取后来变化的订单或试用状态代替首次事实。创建事件身份与副作用对象必须在动作域内一一对应：认领 `requestId` 和订单 `idempotencyKey` 各自唯一，客户端激活与 IVR 激活分别按 `ACTIVATION`、`IVR_CONFIRM` 域校验 `eventId` 唯一；每条证据和每条开通状态迁移也必须分别由且仅由一条 `EVIDENCE`、`ACTIVATION_STATUS` 事件拥有。权益结果对象不能被同域多个创建记录重复声明。相同字符串跨域仍合法；`PAYMENT` 允许多个不同事件依次把同一订单从 `UNKNOWN` 推进到 `PAID`。导入和重放都按动作域检查结果结构、输入/结果稳定身份、双向覆盖、冻结快照和引用；幽灵对象、孤立证据/迁移、跨主体结果、错误动作域或缺字段结果不能进入状态。历史 `UNKNOWN`、旧 `usedSeconds` 等首次可变值允许与当前 `PAID`、当前累计用量不同。事件键经过安全编码，特殊对象属性名不会污染状态。续购叠加、抵扣顺序、自动续费和退款资格尚未确认，本原型不实现。

快照导入和事件查键使用同一完整域级校验：单条命中结果合法仍不足以重放成功，所属域每条记录、反向覆盖及创建结果唯一性也必须有效。缺少所属事件的证据/迁移、指向不存在结果的事件，以及两个证据或迁移事件声明同一结果对象时，快照、导入及任一旧键重放均原子拒绝，新键也不能绕过异常域历史。有效历史中的不同事件可创建不同证据；使用新键重复发放权益仍返回既有权益，不保存第二条创建记录。`PAYMENT` 多事件例外和跨域同字符串复用均保留。

Web 号码生命周期的权威事实同样来自共享契约。Fresh Web 手机号和固话先建立确定性规范主体；导入跨端快照后，可操作号码按脱敏号码与账户解析且只能命中一个主体，因而 Mini 创建的同号固话会被直接复用。缺失或歧义命中原子拒绝，不保留本地成功回退。初次开通创建规范激活；停用/恢复通过 `setActivationStatus` 改变主体状态和修订并追加带 `fromRevision` / `toRevision` 的迁移记录，恢复授权引用真实迁移 ID，不重新发放试用。运营后台使用同一 owner 并以 `OPERATIONS` 标记来源。详情页展示规范状态、修订和迁移 ID；这些都是 ONECALL 内部记录，不是运营商激活回执或受理状态。

所有数值带 `DEMO_NOT_APPROVED` 标识，不构成生产价格或权益审批。个人版本不得使用 `QUOTE`，也不得携带企业席位或固话权益；订单快照导入和权益发放会再次校验个人交易边界。试用不是零价商品；工具素材免费额度也不是第二份 IVR 试用。

共享目录同时强制类型、计费周期和发放计划矩阵：`SUBSCRIPTION` 仅允许 `MONTHLY / QUARTERLY / ANNUAL`，且 `installments`、`grantIntervalMonths` 都是正整数；`ONE_TIME / ADD_ON` 必须是 `ONCE / 1 / 0`；`QUOTE` 必须是 `QUOTE / 1 / 0`。自定义订阅可使用例如 `3 months / 4 installments` 的非默认正数计划。目录、订单导入及权益发放不能只依赖客户端表单检查。

## 6. 线下人工客服

统一配置为 `mode=OFFLINE`、`configured=false`，联系方式和工作时间为空。三端仅展示“人工客服联系方式待配置”以及咨询、退款、发票、认领所需信息，不提供在线提交、审批、成功回执、处理进度、虚构电话/邮箱/微信或 SLA 承诺。Web 的 invoice-apply 旧路由同样只显示线下指南。

真实联系方式、退款规则、发票 SOP 和生产商品参数需要产品、运营与财务另行确认；未确认前必须阻断生产发布，不能用演示值代替。
