### 1-未修复-[低]-§10 把 Goal 的 PostgreSQL 16 收紧为精确 16.15 运行门槛
- **状态**: accepted-candidate
- **位置**: `docs/gateflow/pa14-sharing-command-code-rotation-plan.md` §10 "Future Implementation Validation Commands And Evidence" ("record actual `SELECT version()`/server_version and require 16.15 for this evidence run") and §10 Expected evidence ("actual PostgreSQL 16.15")
- **问题类型**: 过度验收标准 / 目标漂移
- **当前写法**: “Canonical CI is Temurin `21.0.13+9`, Maven `3.9.9`, PostgreSQL 16; prior controller evidence records PostgreSQL **16.15** … record actual `SELECT version()`/server_version and require 16.15 for this evidence run; if tag has moved, Platform supplies the established 16.15 environment”; Expected evidence also says “18 command IT methods on actual PostgreSQL **16.15**”.
- **反例/失败场景**: The test fixture image is `postgres:16` and remains unpinned, exactly as §10/§11 acknowledge. If that tag resolves to 16.16/16.17, a future implementation agent can run the full 197-test suite successfully on PostgreSQL 16.x yet conclude, per §10, that the evidence gate failed because it is not 16.15. The agent must stop and wait for Platform to supply an exact patch environment, or risk silently claiming a version it did not observe.
- **为什么有问题**: The active Goal Confirmation success signal says only “PostgreSQL 16 proves role, lock/context/ownership, replay/state/witness, policy/material ordering, exact code and generation updates, one-time-secret response, exact facts, rollback and concurrency”. It does not select a patch version. Requiring 16.15 adds an acceptance criterion outside the confirmed goal and couples implementation acceptance to an unpinned upstream image tag. The plan already lists image drift as a residual risk; §10 turns it into a hard gate.
- **直接证据**:
  - Control active Goal Confirmation line 22: “PostgreSQL 16 proves …” (no 16.15).
  - Plan §10: “require 16.15 for this evidence run”; “if tag has moved, Platform supplies the established 16.15 environment”.
  - Plan §10: “Existing fixture image `postgres:16` remains test-only/unpinned”.
  - Plan §11 residual risk: “Existing postgres:16 image is unpinned; established 16.15 run can drift with tag updates”.
  - CI/README pins are `Temurin 21.0.13+9`, `Maven 3.9.9`, PostgreSQL 16 (README line 291), not a PostgreSQL patch pin.
- **影响**: Unnecessary environment-only block/return-to-plan on a behaviorally identical 16.x run; pressure to claim 16.15 without direct evidence; avoidable coupling of the implementation gate to Docker tag drift. No code correctness impact.
- **建议改法和验证点**: Change §10 to require PostgreSQL **major 16** and record the actual `SELECT version()`/`server_version`; describe 16.15 as the established/reference environment used by prior evidence, not a hard pass/fail gate. If an exact patch is genuinely required, add it to Goal Confirmation/Control first. Verification is textual plus the existing runtime evidence recording; no test or source change.

- **严重程度（低/中/高/严重）**: 低
