## 4. Line-by-line contract conformance (V001 vs `docs/14`)

V001 was read line-by-line (536 lines) and compared to `docs/14` §§2.1–2.8, 3.2–3.3, 4.3–4.5, 6.1–6.2, 7.1–7.2, 9.0–9.3, 9.23, 10.1–10.8, 11.3, 12.1–12.4. All contracts match exactly:

- **Schemas (6):** `platform`, `audit`, `customer_iam`, `organization_access`, `operations_iam`, `subject_number`.
- **Roles (15, all NOLOGIN):** six owners (`platform_reliability_owner`, `audit_owner`, `customer_iam_owner`, `organization_access_owner`, `operations_iam_owner`, `subject_number_owner`) plus runtime/grant roles exactly as in `docs/14` §10.8.
- **Tables (3):** `platform.idempotency_record` (12 columns, `ck_idempotency_state_shape`, unique `(scope, idempotency_key)`, partial `ix_idempotency_new_alert` on `(created_at) WHERE status = 'NEW'`), `platform.outbox_event` (14 columns, unique `(event_domain, dedupe_key)`, `ix_outbox_pending_available` / `ix_outbox_failed_available`), `audit.audit_fact` (append-only).
- **Declared cross-schema functions (4, all `SECURITY DEFINER`, fixed `SET search_path = <owner schema>, pg_temp`, fully-qualified `pg_catalog.gen_random_uuid()`, no transaction control):**
  - `platform.idempotency_begin(text,text,text)` owner `platform_reliability_owner` → `NEW`/`REPLAY`/`CONFLICT`
  - `platform.idempotency_complete(uuid,integer,text,uuid,jsonb,text)` → `COMPLETED`/`ALREADY_COMPLETED` / `IDEMPOTENCY_CONFLICT`
  - `platform.outbox_append(text,text,text,uuid,text,jsonb,text,text)` → id / `OUTBOX_DEDUPE_CONFLICT` / `OUTBOX_PAYLOAD_INVALID`
  - `audit.append_fact(timestamptz,text,uuid,text,text,uuid,text,jsonb,jsonb,text,text)` → audit id / `AUDIT_REASON_REQUIRED` / `AUDIT_ARGUMENT_INVALID`
- **Idempotency concurrency pattern:** `INSERT … ON CONFLICT DO NOTHING RETURNING` + `SELECT … FOR UPDATE`; incomplete-commit replay raises `IDEMPOTENCY_INCOMPLETE`; complete is revision-CAS 1→2.
- **Outbox payload denylist + envelope:** rejects missing payload, protected plaintext keys (e.g. `phone`), and non-`v1.<key_ref>.<base64url>` ciphertext.
- **Audit:** BEFORE UPDATE OR DELETE trigger raises `AUDIT_APPEND_ONLY` (`P0001`); reason required for `EMPLOYEE` actor and high-risk `SERVICE` actions; recursive JSON denylist on snapshot.
- **Grants:** exact schema `USAGE` without `CREATE`; exact function `EXECUTE` sets; dispatcher column grants only on `status`, `attempt_count`, `available_at`, `published_at`, `revision`; `PUBLIC` ACL empty on all business objects; no runtime role holds `INSERT`/`UPDATE`/`DELETE`/`TRUNCATE` on business tables.

Creation order matches `docs/14` §11.3 (roles → schemas → tables → functions → grants → audit objects → audit grants → trigger).
