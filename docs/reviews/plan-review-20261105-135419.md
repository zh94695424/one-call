## Open questions

1. **Q1 — `actionFingerprint` member `newExpiresAt` across authorities (needs-evidence, low).**
   - docs/14 §2.12 describes fingerprint members as `{shareGrantId, actionType, reasonCode (null-safe), newExpiresAt (EXTEND only, null-safe), actionRequestDigest | expiresAt | sourceRevision}`, which can be read as omitting `newExpiresAt` for REVOKE.
   - The accepted full plan (line 26) and this bounded plan §4 both require present `newExpiresAt: JSON null` for revoke/rotate.
   - The bounded plan correctly binds sharing literals to the accepted full plan (§2) and prior dual-pass reviews accepted that reading; nothing in runtime code or tests cross-checks docs/14 wording; identity is internal (not wire).
   - Resolution: design/docs owner should eventually align docs/14 §2.12 wording with the full plan ("member always present; null for non-EXTEND") in a future docs pass — **not** a this-slice plan edit (plan §10 forbids incidental doc amendment). Does not block implementation.

2. **Q2 — Controller access to filter-validated `Idempotency-Key` (needs-evidence, low).**
   - Plan §3.1 allows either a filter-owned request attribute/accessor or identical re-enumeration in the controller.
   - `CustomerApiBoundaryTests` asserts `CustomerSharesController` source does **not** contain `getAttribute(`. A naive `request.getAttribute(...)` in the controller would fail an unchanged boundary test that the plan requires to keep green (§7).
   - Correct paths are already conventional: static `CustomerBoundaryFilter.trace(request)` pattern, or controller-side `request.getHeaders("Idempotency-Key")` re-enumeration. Implementation agent must pick one of those two; no redesign required.

3. **Q3 — Existing web-test body details (needs-evidence, low).**
   - `CustomerSharesCommandWebTests.revokeAndRotateMapClosedResponseUnions` currently ends with `verifyNoInteractions(fixture.commands)` after a both-suffixes 404 loop; §8.2 expansion makes revoke reach the command bean, so that verification must be scoped to the rotate-only branch while retaining writer-row and rotation-404 assertions.
   - `CustomerSharesWebTests.exactGetAndPostRoutesPassHighestPriorityFilter` must carve POST `revocations` out of the all-methods-404 loop — §8.2 already mandates this explicitly.
   - Both are in-place body edits fully specified by §8.2; not method-count or contract changes.
