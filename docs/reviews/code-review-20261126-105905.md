### F-01 — Low — The stored-snapshot seam can expose an out-of-contract `entitlementType` or 1-character `productCode` instead of failing closed

- **Entry/function:** `GET /api/v1/customer/orders/{orderId}` → `CustomerOrderQueryService.getCustomerOrder` → `CustomerOrderSnapshotReader.read` → `CustomerOrderSemantics.storedSnapshot` → `CustomerOrderSemantics.projection`.
- **Files/lines:**
  - `backend/src/main/java/com/onecall/core/catalog_order/internal/customerorder/CustomerOrderSemantics.java:117-125` checks only that each `entitlementType` is textual and equal to the benefit value reconstructed from the same stored JSON; no allowed enum is applied.
  - `backend/src/main/java/com/onecall/core/catalog_order/internal/customerorder/CustomerOrderSemantics.java:191` checks `!text(catalog.productCode(), 64)` but `text(...)` has no minimum length, so a 1-character code passes.
  - `backend/src/main/java/com/onecall/core/catalog_order/internal/customerorder/DefaultCustomerOrderSnapshotReader.java:12-22` translates only `OrderCreationException`; the `storedSnapshot` catch-all at `CustomerOrderSemantics.java:178-194` is happy to accept these values because it derives benefits from the snapshot text itself.
  - `backend/src/main/java/com/onecall/core/customer_iam/internal/application/CustomerOrderQueryService.java:81-95` rechecks only row↔snapshot catalog version/offer/channel/amount/currency/hash; it does not recheck benefit enum or product-code length.
  - Frozen contract: `api/openapi/onecall-v1.openapi.yaml:5279-5281` constrains `CatalogBenefitLine.entitlementType` to `RECORDING_SECONDS|AI_SECONDS|EVIDENCE_COUNT|STORAGE_BYTES`; `:5434-5436` gives `OrderSnapshotProjection.productCode` `minLength: 2`.
- **Input scenario:** a stored order snapshot that is tampered (or corrupted) but whose `snapshot_sha256` is recomputed consistently, with `entitlementType: "EVIL"` or `productCode: "X"`.
- **Expected:** fail-closed detail behavior. The accepted plan §3 requires validation of all exposed persisted enum domains and lengths; §4/§10 define the exact snapshot projection and corrupt-detail behavior, and the frozen OpenAPI enum is part of the contract. A corrupt historical detail should map to the frozen `404 NOT_FOUND`.
- **Actual:** `storedSnapshot` reconstructs `benefitLines` from the same tampered JSON, so the equality checks compare the tampered value with itself; `snapshot(catalog, benefits)` then reproduces the same tampered text and canonical equality passes. The reader's canonical hash check passes when the row hash is recomputed. `CustomerOrderDtos.Detail.from` serializes the `Snapshot`/`Benefit` strings directly, so a 200 detail can emit an out-of-enum `entitlementType`, a control-character-bearing type (only `isTextual()` is enforced), an arbitrarily long type (snapshot-row size permitting), and a 1-character `productCode`.
- **Evidence:** the corrupt-input list in `backend/src/test/java/com/onecall/core/catalog_order/internal/customerorder/CustomerOrderSnapshotReaderTests.java:52-62` covers `{}`, `[]`, malformed JSON, wrong `schemaVersion`, null/extra `terms`, negative quantity and wrong currency, but not an unknown `entitlementType` or 1-character `productCode`; `:63-70` covers safe-integer boundaries only. `CustomerOrderQueryServiceTests.java:94-103` covers invalid snapshot/hash and unexpected runtime, not benefit enum/product-code domain.
- **Impact:** data-integrity contract violation on corrupt historical data; clients relying on the OpenAPI enum can break, and an oversized/control-bearing type could affect rendering. This is **not customer-reachable**: it requires the ability to write/replace the stored order snapshot and hash (owner/DB-write privilege), not a customer request. No cross-account or cross-workspace exposure.
- **Suggested change and verification:** in `CustomerOrderSemantics.storedSnapshot`, enforce the exact `entitlementType` set (the same four values used by `catalog_benefit_line`/OpenAPI) and enforce the `productCode` `^[A-Z][A-Z0-9_-]{1,63}$`/minimum-length rule already owned by the catalog DB constraint; add a reader test with a valid recomputed hash and an unknown type plus a 1-character product code, expecting `InvalidSnapshotException` and service detail `404`. No new test identity is required if added inside existing methods.
- **Severity:** Low.
