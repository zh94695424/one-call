- **位置**: Plan §2.3 (`:69-77`), §4.2 (`:119`), §6.1 (`:172-174`), §9.2 (`:293-299`), §12 (`:378-383`); Control `:45`.
- **问题类型**: 权限/运行时边界 / open question 未收敛 / 不可直接实施.
- **当前写法**: §2.3 says the existing writable Operations datasource family is owned by `OperationsLifecyclePersistenceConfiguration.java`, and "PA38 reuses these exact beans", then says "The provisioned LO/operations-read login is the existing `pa25` operations login. - **反例/失败场景**: The lifecycle write datasource is configured by `onecall.operations-lifecycle.datasource.{url,username,password}`. The only shipped lifecycle write login oracle, `OperationsSubjectLifecycleFixture`, grants that login only `activation_consent_role`, `operations_iam_role`, `operations_service_role` — not `catalog_order_role`. If the production write login is not LO, `SET LOCAL ROLE catalog_order_role` raises SQLSTATE 42501 and every publication/offsale returns 503; if it is LO, that is an unproven external configuration and not the same physical pool the Control directed.
- **为什么有问题**: Control REV-02's accepted remediation is explicit: "Reuse the already-provisioned LO/operations-read datasource family with a new writable transaction template bound to the same physical pool, never a second pool or credential family." ### PA38-REREV-A-02-未修复-[高]-The authority read is specified both as a same-connection in-transaction read and as a `REQUIRES_NEW` transaction, so the same-connection ACTIVE/ADMIN witness is not executable as written

- **位置**: Plan §3 (`:92-96`), §4.1 file 5 (`:106`), §5.2 (`:156`), §6.1 (`:174`), §9.1 (`:277`); Control `:26`.
- **问题类型**: 事务传播 / 并发恢复 / 安全边界 / 契约矛盾.
- **当前写法**: §3: "The authority read transaction is mandatory, `REQUIRES_NEW`, `READ_COMMITTED`, and bound to the same physical datasource." §6.1: "The authority read is invoked inside that transaction and uses the same connection; no nested pool or second transaction is created." `EmployeeAuthorityReadPortTests` includes `isTransactionMandatory`.

If `DefaultEmployeeAuthorityReadPort` uses that template, invoking it inside the command transaction suspends the outer transaction and checks out a second connection. The ACTIVE/ADMIN witness is then not in the same transaction/connection as the mutation; a status/role change committed between the two transactions is not seen; `SET LOCAL ROLE` state differs; and the role restoration is not atomic with the write. If the port instead uses `PROPAGATION_MANDATORY`, §3's `REQUIRES_NEW` text is wrong.

- **直接证据**: plan `:92-96,106,156,174,277`; `OperationsLifecyclePersistenceConfiguration.java:46-51`; Control `:26`; `EmployeeAuthorityReadPortTests.isTransactionMandatory`.
- **影响**: Same-connection witness not guaranteed; security/consistency defect; web/unit tests can pass while production reads authority in a different transaction.
- **建议改法和验证点**: State one propagation: the command opens the single `REQUIRES_NEW`/`READ_COMMITTED` transaction; `DefaultEmployeeAuthorityReadPort` joins it (`PROPAGATION_MANDATORY`, or direct DSL on the transaction-bound connection) and asserts the same `pg_backend_pid()`/transaction identity. ## 8. Final verdict

**Verdict: `fail`.**

The fixed plan substantially improves the first-round plan: the port ownership direction is correct, the three-way admission classifier is explicit, the authentication → parse → authority precedence matches the shipped write path, the publication/offsale matrix now defines null-active/replay/stale/conflict/one-ACTIVE behavior, audit cardinality (one candidate publish audit; two Outbox facts only when an old ACTIVE exists; one offsale audit/Outbox; zero replay facts) is pinned, the disposable fixture is defined, and the test inventory arithmetic is mostly consistent (8/86 Surefire, 2/38 Failsafe, 97/934, 38/630, 135/1,564).

However, it is not yet safe to hand to implementation:

1. **The runtime identity premise is still unproven (F-01).** The plan transfers the PA25 LO's `catalog_order_role` membership to the separate `onecall.operations-lifecycle.datasource` write family; the only shipped write-login oracle lacks that role and the Control explicitly directed the LO read family with a new writable template on the same physical pool.
2. **The authority witness is not unambiguously same-connection (F-02).** §3 says the authority read transaction is `REQUIRES_NEW`, while §6.1 says it is inside the command transaction on the same connection.
3. **The frozen 409 codes have no authorized HTTP path or HTTP test (F-03).** The unmodified `OperationsProblemWriter` cannot emit `PUBLICATION_STALE_VIEW`/`CATALOG_PUBLICATION_CONFLICT`.
4. **The guard/CI arithmetic is still wrong (F-04, F-05, F-08).** `13 -> 14`, `926` vs `934`, `1557` vs `1565`, and the manifest carrier/bytes are deterministic lockstep defects.
5. **Audit and recovery details are not exact (F-06, F-07, F-09).** `request_id`, publish snapshots vs docs17, the audit decision-time SQL, the Outbox payload hash fields, the post-rollback reread context, and the least-privilege test scope remain under-specified.
