## Reviewed Target and Scope

The controller's active PA8 goal is binding: implement only the frozen V008 evidence persistence contract — the five `evidence` tables, their structural/ACL/deferred creation-cycle backstops and executable PostgreSQL/Flyway evidence — while preserving V001-V007 bytes. V009 sharing, application services, upload APIs/workers, COS/KMS, IVR/cloud integration, runtime wiring and design edits remain out of scope (`project-execution-control.md:18-25`).

The reviewed plan stays inside that boundary in its table, constraint, trigger, grant, test and service-separation content. The plan's two-slice split, 51→54→57 method progression, staged V007 prefix capture, final-state V008-present/V009-absent fence and explicit service deferral are directionally correct. The material defects below are specification and evidence defects, not requests to change the frozen V008 dictionaries or the confirmed goal.

The plan's rollback-migration requirement is the principal scope exception: it introduces a migration-down artifact that neither the confirmed goal nor the accepted forward-only migration convention contains (PR-002).

1. **Exact inventory.** Recounted from the frozen dictionaries: 5 tables; 56 columns `(11/15/17/5/8)`; 39 named checks `(9/11/13/1/5)`; 5 primary keys; 5 ordinary unique constraints plus 2 partial unique indexes; 8 secondary indexes; 10 FKs `(8 ordinary immediate + 2 DEFERRABLE INITIALLY DEFERRED)`; 10 defaulted columns; 5 trigger functions; 7 triggers; zero SQL service functions. The plan's §3.2-§3.10 totals match the frozen contract.
2. **V001-V007 byte freeze.** The seven SHA-256 values in plan §6.1 match the current migration files byte-for-byte. The migration directory contains exactly V001-V007 and no V008/U/R rollback file.
3. **Method baseline.** `PostgresContainerIT` contains exactly 51 `@Test` methods; `.github/workflows/ci.yml` contains the same 51 exact names and the `PA7 V007 S2 test count (51)` label. The 51→54→57 arithmetic is correct.
4. **Role/DDL context.** Creating `evidence_owner`/`evidence_role`, `evidence` schema and V008 objects under `SET LOCAL ROLE evidence_owner`, then cross-module grants under each parent owner, follows the V001/V004/V007 pattern. The frozen V008 roles and exact grants are supported by §10.21 and §11.5.
5. **Deferred cycle semantics.** Deferring both FK checks and queuing the creation-cycle constraint triggers until commit is the right shape for either insertion order. The plan's trigger predicates match §10.22 row-for-row.
6. **Deferred error precedence.** The plan's required SQLSTATEs for absent/mismatched cycle rows are not guaranteed by PostgreSQL trigger ordering; see PR-001.
7. **Immutability versus service ownership.** The plan correctly keeps status/revision orchestration, lifecycle-event identity and Outbox append semantics in future application services while testing only database-visible guard/check/append-only backstops. No service scope leaks into V008.
8. **ACL evidence.** Owned-table and cross-module grants are exact in intent, but the negative-probe set omits foreign row-lock and schema/function negatives required by §9.0.2/§10.21; see PR-008.
9. **Final-state test evolution.** The plan lists only two existing assertion locations that must change; several exact global catalog and prefix assertions also change and will fail if not updated; see PR-003.
10. **Rollback convention.** The repository is forward-only (V001-V007 only; no U/R files; the design states no destructive rollback and V001-V009 forward-only). The plan's rollback-migration options are not executable as a convention and include a dangerous repeatable-migration option; see PR-002.
11. **Function wave.** "Function wave = 5" is true only for the five frozen service functions. The plan's risk-table mitigation incorrectly describes a total `pg_proc` count and SECURITY DEFINER uniqueness; see PR-006.
12. **Slice/CI sequencing.** Two slices are proportionate and justified. The stated alternative CI expected-set timing cannot keep S1 green; see PR-007.

## Material Findings

### PR-001-未修复-[高]-Deferred FK checks outrank the creation-cycle triggers for several required negative cases

- **位置 / Location**: `docs/gateflow/pa8-v008-evidence-foundation-plan.md:258-261`, `:350-355`, `:566-568`, `:584`; `docs/14-production-data-model-and-flyway-schema-spec.md:4734-4736`, `:4755`; `backend/src/test/java/com/onecall/archtests/container/PostgresContainerIT.java:3626-3651`.
- **问题类型 / Type**: 不可直接实施 / 测试缺口 / SQL error contract.
- **当前写法**: §3.7 says a missing, duplicate, wrong-type, wrong-evidence-owner or mismatched creation event "fails at commit with `EVIDENCE_CREATION_CYCLE_VIOLATION`". §4's order-sensitive table requires `EVIDENCE_CREATION_CYCLE_VIOLATION` for "Record without event" and "Event without record". §9 S2 T-S3-09/T-S3-11 repeat the expectation. The S1 FK test also uses the savepoint-based `expectSqlFailure` helper for representative RESTRICT parent deletes.
- **反例 / Failure scenario**: PostgreSQL fires deferred AFTER trigger events at commit in the order they were queued, and same-event triggers are queued in trigger-name order. The internal RI check triggers are named `RI_ConstraintTrigger_c_*`/`RI_ConstraintTrigger_a_*` (uppercase `R`), which sorts before lowercase `trg_*`. For (a) a record with no event, the deferred `fk_evidence_source_event` check fires first and raises `23503`, not the cycle function; (b) an event with no record, `fk_evidence_event_record` likewise raises `23503`; (c) a source-identity mismatch is insertion-order-dependent — event-first can raise the cycle error from the event-side trigger, while record-first raises `23503` from the record-side FK; (d) a duplicate `EVIDENCE_CREATED` is rejected immediately by the partial unique index with `23505`, not at commit; (e) a parent delete whose only child is a deferred-NO-ACTION event row succeeds at `executeUpdate` and fails at COMMIT, so the existing savepoint helper cannot observe it.
- **为什么有问题 / Why**: The plan promises exact executable witnesses for the frozen negative matrix. If the expected SQLSTATE/constraint is physically unattainable, the S2 checkpoint cannot be green as written; an implementer may instead disable/rename a constraint or weaken the assertion, both forbidden.
- **直接证据 / Direct evidence**: Plan lines 258-261 and 350-355; doc-14 T-S3-09/T-S3-11 at 4734-4736 and T-S3-30 at 4755; existing helper binds a savepoint and `executeUpdate` only (`PostgresContainerIT.java:3626-3651`). The V008 deferred FK SQL in plan §3.7/§4 omits any mechanism to make the user trigger fire before the RI check.
- **影响 / Impact**: Required negative evidence cannot pass, or passes for the wrong reason; the "no partial creation fact" proof is not trustworthy; ambiguous implementation choices remain.
- **建议改法和验证点 / Minimal fix**: Split the negative matrix by enforcement class: (1) FK-satisfied cycle contradictions — insert a decoy non-creation event with the same `(event_domain, event_id)` so the composite FK passes and the record-side trigger raises `EVIDENCE_CREATION_CYCLE_VIOLATION` (this is how T-S3-09's "no matching `EVIDENCE_CREATED`" should be constructed); (2) genuinely absent parents — assert `23503` with the exact deferred constraint name via a commit-aware helper; (3) duplicate creation event — assert immediate `23505` on `uq_evidence_created_event`; (4) mismatched identity — pin one insertion order or accept both `{23503, EVIDENCE_CREATION_CYCLE_VIOLATION}` with an explicit rationale; (5) parent deletes involving the deferred event FK — commit before asserting. Add a commit-failure helper; do not reuse `expectSqlFailure` for commit-time checks. Verify against PostgreSQL 16 at implementation. If the frozen T-S3-09/T-S3-11 wording itself cannot be satisfied, stop and report the design contradiction rather than encoding an impossible test.
- **修复风险 / Fix risk**: 中
- **严重程度 / Severity**: 高

### PR-002-未修复-[高]-Rollback-migration requirement contradicts the repository convention and the accepted forward-only design; `R__` would execute automatically

- **位置 / Location**: `docs/gateflow/pa8-v008-evidence-foundation-plan.md:32`, `:342`, `:385`, `:674`; migration directory V001-V007; `docs/14-production-data-model-and-flyway-schema-spec.md:4203`, `:4773`.
- **问题类型 / Type**: 范围蔓延 / 不可直接实施 / 破坏性操作风险.
- **当前写法**: §2.1 requires a "Rollback migration"; §4 states "Rollback migration: drop in exact reverse dependency order (triggers → functions → deferred FKs → tables → schema → roles)"; §6 offers `R__rollback_v008_evidence_media.sql`, a "project's established rollback convention", `U008`/`R008`, or "`target()` reverse + drop" and says "pick one"; §13's risk row contradicts §6 by saying to use the test helper only if no convention exists.
- **反例 / Failure scenario**: The repository has exactly V001-V007 versioned migrations and no U/R rollback files. Flyway is configured with the single location `classpath:db/migration` (`PostgresContainerIT.java:917-921`). A repeatable `R__rollback_v008_evidence_media.sql` would run after the versioned migrations on a fresh database — including at each staged `target(004/005/006/007)` migration — and would drop V008 objects/roles as part of the same `migrate()`. `target()` only moves forward; it cannot reverse V008. An implementer following §6 could make the suite destroy its own V008 state or fail before any V008 test. The reverse order also omits revoking cross-module grants on `platform`/`audit`/`subject_number`/`ivr`/`entitlement_metering` before `DROP ROLE evidence_role`, which PostgreSQL will reject.
- **为什么有问题 / Why**: The confirmed goal is V008 persistence plus executable catalog/lifecycle/ACL/deferred-commit rollback evidence. It does not authorize a down migration, and the frozen design explicitly records V001-V009 forward-only, no destructive rollback. The plan's own §12 rule says contradictions stop-and-report. This is both an unconfirmed scope expansion and a migration-execution hazard.
- **直接证据 / Direct evidence**: `ls backend/src/main/resources/db/migration` returns V001-V007 only; the design at 4203 and 4773 states forward-only/no destructive rollback; the test uses only forward `target(N)` migrations. The `R__` prefix is Flyway's repeatable-migration convention, not a down migration.
- **影响 / Impact**: A literal implementation can break every staged and full migration run, make V008 absent after a "successful" migrate, or invent an unauthorized migration convention; the S1/S2 green checkpoints cannot be trusted.
- **建议改法和验证点 / Minimal fix**: Remove every rollback-migration requirement and every `R__`/`U008`/`R008`/`target()`-reverse option from §2.1, §4, §6 and §13. Prove rollback only with transactional forced-failure tests (T-S3-12: valid record/event/artifact/Outbox transaction, forced failure before COMMIT, zero survivors) and, if needed, a test-local cleanup that never changes the migration set. If a real down path is ever required, make it a separate authorized design with an explicit tool and a complete dependency-revocation order. Update the completion format and README wording to say "transaction rollback", not "rollback migration".
- **修复风险 / Fix risk**: 低
- **严重程度 / Severity**: 高
