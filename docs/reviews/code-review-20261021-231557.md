## Findings

### A-01-已修复-中-COS 与 VPC 网络边界表述混淆
- **入口/函数**: 部署拓扑与第 4 节“网络策略”。
- **文件(行号)**: `docs/12-technology-stack-and-system-architecture.md` (原 `b91914e` 行 154、204；修复后行 154、202、204)。
- **输入场景**: 基础设施人员按“COS 部署在私有网络”的文字执行部署并假设 COS 位于业务 VPC 或已具备私网接入。
- **实际分支**: 原架构将 COS 放在腾讯云同地域数据区，同时写明“业务服务、数据库、日志、备份和 COS 部署在……私有网络”。
- **预期行为**: 区分 VPC 内业务/数据服务与独立托管的 COS；说明对象桶私有不代表网络路径已建立，并将实际接入方式留给地域和网络验证。
- **实际行为**: 原文字会把存储权限属性和网络部署位置混为一谈，使网络设计依赖一个尚未验证的私网能力。
- **直接证据**: `b91914e` 中第 4 节明确把 COS 与 VPC 内服务一起列为部署在“私有网络”；此前拓扑也将 COS 列为数据区节点。修复后第 4 节明确 COS 不属于 VPC，并把云侧接入方式列为待验证。
- **影响**: 部署可能遗漏可用 endpoint、路由、出口策略或公网 HTTPS 安全限制，造成 IVR 录音上传或云侧证据处理不可达。
- **建议改法和验证点**: 已将 COS 标为同地域私有桶而非 VPC 资源；IVR 使用受控 HTTPS 出口，云侧私网能力或批准的 HTTPS 路径待实际地域/网络验证。确认所选路径并完成上传/下载故障演练。
- **修复风险（低/中/高）**: 低。
- **严重程度（低/中/高/严重）**: 中。
