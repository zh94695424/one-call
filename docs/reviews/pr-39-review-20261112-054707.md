Evidence-backed checks that closed clean:

1. **Endpoint contract** — `CustomerSubjectsController` exposes exactly `GET /api/v1/customer/subjects/{subjectId}`; the `Detail` record is exactly `subjectId, activationStatus, evidenceCount, orderCount` (asserted by `CustomerSubjectDetailBoundaryTests.customerCompositionContainsNoForeignSqlOrInternalImports`). The frozen OpenAPI `CustomerSubjectDetail` schema already required exactly these four fields at base (`onecall-v1.openapi.yaml` `required: [subjectId, activationStatus, evidenceCount, orderCount]`, `additionalProperties: false`); optional schema properties (`numberMasked`, `trial`, `consentRequirements`) are not emitted and `claimState` is not a schema field — matching the documented freeze-scope omission contract.
2. **Auth / workspace authority** — the boundary filter authenticates the bearer before the controller runs and admits only `GET` on `/api/v1/customer/subjects/[^/;%]+` (extra segments, path parameters, `%`-encoded segments and the raw-URI equality check all fall through to 404; non-GET methods including POST/HEAD/OPTIONS → 404). The controller requires a `CustomerRequestPrincipal`, re-derives the scope via `CustomerBusinessNumberQueryService.requireScope` (personal ⇒ `organizationId == null`, organization ⇒ non-null; shape violation ⇒ 503) before UUID validation, so an invalid trusted workspace precedes path validation (covered by `invalidTrustedWorkspacePrecedesPathValidation`). 3. **Lifecycle / membership matrix** — `requireActiveContext` runs first inside the transaction: inactive `customer_account` ⇒ 403; organization path additionally requires `organization.status = ACTIVE`, `organization_membership.status = ACTIVE` and `role IN (ADMINISTRATOR, MEMBER, EVIDENCE_MANAGER, AUDITOR)` ⇒ otherwise 403, before any subject SQL (IT asserts `noneMatch business_subject` on the 403 paths).
