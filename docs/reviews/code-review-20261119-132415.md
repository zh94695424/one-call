## Residual Risk

- **Committed-then-`503` window.** `assertClean()`/pool-guard verification runs after commit, so a client can receive `503` while the facts are durable; the retry then returns `409 PUBLICATION_STALE_VIEW` because the caller still carries pre-transition expectations. Only the rollback side is covered by a test (`restorationFailureEvictsDirtyConnection`). Owner: Backend + Platform. This is the highest-consequence user-visible risk in the unit and is inherent to the accepted same-pool design.
- **Lock-free authority read window.** A demoted `ADMIN` can complete one already-started transaction (plan §6.1 forbids `FOR UPDATE` on the employee row). Bounded to ≤1 transaction per employee; accepted by design.
- **Retirement has no independent audit fact.** The previous ACTIVE's retirement is observable only through the candidate's audit fact and the retirement Outbox event, as `plan §8.1` requires; an auditor wanting a per-row fact for the retired version must project from the event. Accepted, but it interacts with AGG-B-03's audit-side identity note.
- **`RATE_LIMITED`/429 is reachable in neither route.** It exists in the closed nine-code enum, both `write` overloads and the OpenAPI blocks, but no code path produces it (no throttler is authorized in this slice). Consistent with prior gates; documentation-truth risk only.
- **Shared four-slot / 3000 ms LO pool saturation.** Publication holds the product advisory lock across two `UPDATE`s plus two appends; sustained ADMIN write load can starve the Operations read surfaces sharing the pool. Control already classifies this to Platform/Operations; AGG-B-01 adds unbounded body buffering to the same JVM's pressure profile.
- **Two `2 s` statement timeouts plus role churn can approach client deadlines.** A worst-case request (attempt + recovery) is bounded by roughly 2 × (statement + idle-in-transaction) settings; clients must use the documented `traceId` correlation rather than blind retry, and the 10 s IT client timeout shows the accepted envelope.
- **`DispatcherType.FORWARD`/`INCLUDE` are not filtered** (only `ERROR` is special-cased, `OperationsBoundaryFilter.java:26-34`), so an in-application forward could bypass the admission predicates. There are no forwards/includes in this app and the sibling filter behaves identically; latent only.
- **PA35 CRLF detector inertness in a raw checkout** (`PA38-RR2-01`/deferred) still means the line-ending drift shape can pass locally; unchanged and owned.
- **Reviewer coverage limit (mine, not the product's).** The clean `97/934` + `38/630` sweeps, the shipped CI/XML oracle over 135 reports and the `f187461a…` XML custody aggregate were **not** re-executed in this session; they remain accepted-as-claimed Control evidence. Nothing in my findings depends on them, but the aggregate verdict should be read together with that limit.
