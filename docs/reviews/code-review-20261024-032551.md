### 01-未修复-低-Request-body guard skips valid `requestBody`/media indirection, so the closed-component request contract is still unenforced

- **入口/函数**: `validateTrustedRequestFacts` and `requestSchema` in `api/openapi/contract-rules.mjs`; the independent stage checker never inspects request bodies.
- **文件(行号)**:
  - `api/openapi/contract-rules.mjs:856-885` — `validateTrustedRequestFacts` reads only `operation?.requestBody?.content` (`:860-861`), then skips any media entry without `schema` (`:862-863`).
  - `api/openapi/contract-rules.mjs:666-673` — `requestSchema` has the same inline-only assumption and does not dereference a `requestBody` `$ref`.
  - `api/openapi/check-doc-map.mjs` — no request-body/media inspection at all.
- **输入场景**: Valid OpenAPI 3.1 request-body indirection on C4 (`createCustomerSubjectClaim`): replace the inline body with `requestBody: {$ref: '#/components/requestBodies/ClaimRequestBody'}`, where the referenced request body contains an inline `type: object, additionalProperties: true` media schema declaring `accountId`. Adjacent variants: an `application/json: {}` media entry with no `schema`, and `content: {}`.
- **实际分支**: With a `requestBody` `$ref`, `operation.requestBody.content` is `undefined`, so the guard returns at `:861` without walking anything. With a media entry without `schema`, the guard continues at `:863`. Redocly `no-unresolved-refs` resolves the reference but the custom rule never follows it.
- **预期行为**: Per accepted R2-02, every actual request media schema must be a pure `#/components/schemas/...` `$ref` to a closed component, and the trusted-fact walker must reject account/owner/role/price/payment/trial/entitlement facts anywhere in the request body.
- **实际行为**: Probe `/tmp/a1-rereview2-probes/A-requestBody-ref-inline-open-accountId.yaml`: `redocly lint` exit 0 (Woohoo), `redocly bundle` exit 0, `node check-doc-map.mjs --stage s1` exit 0 with `7/7/0/0/0=14`. Probe `B-media-no-schema.yaml` (`application/json: {}`) lint exit 0. Probe `K-requestBody-empty-content.yaml` (`content: {}`) lint exit 0. By contrast, a missing `components.schemas` target (probe C) and a non-schema component (probe D) correctly fail.
- **直接证据**: The guard's only content source is `operation?.requestBody?.content` (`contract-rules.mjs:860-861`); there is no `deref(root, operation.requestBody)` anywhere. A valid `$ref` therefore bypasses both the closed-component check (`:865-868`) and the recursive walker (`:869-881`). Probe exits above are direct.
- **影响**: Latent trust-boundary/bypass in the validator, not current contract drift: all 14 current S1 request bodies are inline pure refs to closed components. A future coordinated edit can accept `accountId`/`ownerAccountId`/`role`/price/payment facts while lint, bundle and `check:s1` stay green. `requestSchema` returning `null` for a `$ref`'d body would also silently skip the `DRAFT_OPERATION_IDS` forbidden-field checks in later slices (event-body already fails closed, so it is not a bypass).
- **建议改法和验证点**: Resolve `operation.requestBody` through `deref` (and reject or explicitly resolve `$ref` bodies), then require every media entry to (a) exist, (b) declare `schema`, and (c) have a pure `#/components/schemas/...` `$ref`; reject `content: {}` when a body is declared. Apply the same resolution in `requestSchema`. Add negative probes for `requestBody` `$ref`, schema-less media, empty content, and a multi-media sibling without `schema`. Verify stock S1 stays green and the closed control (`L-requestBody-ref-closed-control`) still passes.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低

### 02-未修复-低-Closed-object walk misses valid JSON Schema forms (`type` arrays, boolean `true` schemas), leaving an open value space under a closed parent

- **入口/函数**: `walkRequestSchema` in `api/openapi/contract-rules.mjs`.
- **文件(行号)**:
  - `api/openapi/contract-rules.mjs:758-759` — non-object schemas (including boolean schemas) return before any check.
  - `api/openapi/contract-rules.mjs:771-777` — "object" detection is `node.type === 'object' || node.properties`; a `type` array containing `object` is not recognized, and a boolean schema is never visited.
  - `api/openapi/contract-rules.mjs:778-798` — traversal covers `properties/items/prefixItems/additionalProperties/allOf/anyOf/oneOf`, but not other object-producing keywords.
- **输入场景**: Add to the closed `ClaimRequest` a valid property `probeTypeArray: {type: [object, 'null']}` (no `properties`, no `additionalProperties`) or `probeBool: true`.
- **实际分支**: For the type array, `node.type === 'object'` is false and `node.properties` is absent, so the closed-object check at `:773-777` is skipped. For `true`, `typeof schema !== 'object'` returns at `:759`, so no visitor and no closure check run. Redocly accepts both forms (JSON Schema 2020-12).
- **预期行为**: Every traversed request object must be closed (`additionalProperties: false`), and request bodies must not contain an unconstrained value space that can carry server-derived trust facts.
- **实际行为**: Probes `/tmp/a1-rereview2-probes/I-type-array-open-object.yaml` and `H-boolean-schema-property.yaml` both `redocly lint` exit 0 (Woohoo). A client can then send `{"probeTypeArray": {"accountId": "..."}}` / `{"probeBool": {"accountId": "..."}}` with no rule firing.
- **直接证据**: The closure predicate at `:773` is a string type check plus property presence; it cannot see `type: [object, 'null']`. The boolean-schema short-circuit at `:759` prevents any inspection. Probe exits above are direct. A plain `{type: object}` node with no properties (probe G) is correctly rejected, and closed `allOf`/array/cyclic control probes still pass, so this is an edge-form gap, not a general walker failure.
- **影响**: Latent. A single valid schema edit can open a nested value space while all S1 checks stay green; current canonical request schemas use none of these forms, so there is no current drift.
- **建议改法和验证点**: Normalize `type` arrays and treat any schema admitting objects (for example `type` includes `object`, or object-producing keywords are present) as requiring `additionalProperties: false`; adopt an explicit boolean-schema policy inside request bodies (reject `true`; allow `false` as "closed/nothing", including in `items`/`prefixItems`/`additionalProperties` positions). Add probes for both forms. Do not reject `additionalProperties: false` itself.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低
