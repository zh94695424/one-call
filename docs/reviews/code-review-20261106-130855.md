## Residual Risk

- **Deployment-owned security**: authentication provisioning/rotation, `pg_hba`/TLS, role-name collision, post-deploy ACL drift, and the cluster/database-global `PUBLIC TEMPORARY` revoke's external consumers. The public role is a login with no migration-provisioned password; a trust/peer/cert setup or credential leakage is outside this change's protection.
- **Scope of the DB boundary**: no row-level security; a holder of the public role's DB credential can read the allowed table-wide columns (including all share snapshots/identity-at-capture) by direct SQL, not only by an unknown token. PostgreSQL catalog visibility, built-in function availability and trusted-JVM/DBA powers are not sandboxed. These are inherent to the accepted column-ACL boundary and remain deployment/security residuals.
- **Capacity/abuse**: an additional Hikari pool with default sizing; no production load/capacity/penetration/restore evidence is claimed.
- **Evidence provenance**: runtime evidence is local synthetic PostgreSQL 16.15 (Testcontainers) and the retained final XML/logs, not hosted CI or a deployed environment; this reviewer did not rerun Maven/Docker. Raw hash identities are EOL-sensitive; the manifest digest is supplied rather than reproduced.
- **Test-harness robustness (low)**: `assertBorrowReset`/`getTotalConnections()==1` depend on Hikari thread affinity, soft eviction and timing; they passed in focused, targeted and clean runs but are test-topology assumptions, not production guarantees. The six-request HTTP phase asserts status only; envelope determinism is covered sequentially.
- **Deferred test-maintenance**: explicit `pg_foreign_server.srvacl` and large-object ACL/ownership enumeration remain unexpanded; foreign-server/large-object families are covered indirectly by the V011 `pg_shdepend`/effective-privilege checks and the fresh-role posture.
- **Maintainability coupling**: the evidence module's public adapter references a sharing-owned property prefix and transaction-manager bean name; the fixed public role name is duplicated in V011, the properties record and the service identity assertion. These are fail-closed and accepted by the plan, but future renaming requires synchronized edits.
