## Findings

### F3-01-未修复-[中]-Order-side purchase-consent validation reads `consent_record.source_ref` but the declared `catalog_order_role` SELECT lacks that column

- **入口/函数**: `catalog-order` order creation T-S2-07 step 4 (`§9.17`) calls `activation-consent.append_purchase_consent` (`§10.20`) and then, in the same transaction, validates the persisted purchase consent before inserting the order.
- **文件(行号)**: `docs/14-production-data-model-and-flyway-schema-spec.md:2712` (order service must validate `source_ref`), `:3374` (append service says the order service validates `event_id = source_ref = purchaseConsentEventId`), `:3093` (the exact `catalog_order_role` cross-module `SELECT` on `activation_consent.consent_record`, omitting `source_ref`), `:272` (SELECT collaborators name only the exact §10.12 columns), `:3214` (every emitted field must be readable under the declared grants). Supporting identity evidence: `:3235`, `:3860`, `:3862`.
- **输入场景**: Any fresh valid `PURCHASE` order with an accepted 1–475-character client key whose `append_purchase_consent` succeeds and returns the immutable consent ID. This is the normal order path, not an edge case.
- **实际分支**: The owner service appends the consent with the derived 81-character `purchaseConsentEventId` as both `event_id` and `source_ref`. The order service then reads the consent row to validate `purpose`, `subject_id`, `channel`, `source_type`, `account_id`, current policy/prompt fields, `event_domain`, `event_id`, `source_ref`, `action` and `request_fingerprint`. Its declared exact read grant includes all of those columns except `source_ref`.
- **预期行为**: The order-side validation should be executable under the declared exact-grant contract: either `source_ref` is included in the `catalog_order_role` cross-module `SELECT` on `activation_consent.consent_record` (read-only, no write or row lock), or the source-reference check is performed by the owning `append_purchase_consent` service and returned as an owner-validated immutable fact. §10.17 says every field used by the contract must be readable with the declared grants; §3.2 forbids inferring a grant from a collaborator name.
- **实际行为**: The order service cannot read `consent_record.source_ref` under its declared privilege. An implementer must either skip the normative `source_ref` check (weakening the accepted F-07/purchase-identity validation) or use an undeclared table/column privilege (violating the exact-grant/F-01 regression contract). The core derived identity is still 81 characters and fits the 1–128 `event_id`/`source_ref` checks; this finding is about the read/validation path, not the derivation.
- **直接证据**: `:2712` explicitly requires the order service to validate `source_ref`; `:3374` repeats `event_id = source_ref = purchaseConsentEventId`; `:3093` lists the granted consent columns and does not include `source_ref`; `:272` says entries marked `SELECT` name only the exact §10.12 columns; `:3214` says a field that cannot be read under the declared grants makes the contract invalid. The 81-character derivation and 1–128 checks are at `:3235`, `:1849`, `:1863`, `:1868`; T-S2-53/T-S2-55 (`:3860`, `:3862`) assert the identity and replay, but not this order-side grant.
- **影响**: The purchase-consent correction is not code-generation-ready for its own order+append path. The risk is a silently omitted validation or an over-broad privilege grant that breaks the accepted exact-`SELECT` boundary. No wrong identity is persisted if the owner service is correct, but the specified order path cannot execute as written; this is a bounded contract inconsistency, not a product-policy question.
- **建议改法和验证点**: Add `source_ref` to the `catalog_order_role` cross-module `SELECT` for `activation_consent.consent_record` in §10.12 (`:3093`), keeping it read-only with no `INSERT`/`UPDATE`/`DELETE` and no row lock; assert it in T-S2-41/T-S2-51/T-S2-55. Alternatively, move the source-reference check entirely into `append_purchase_consent` and return the owner-validated identity/fact, then remove the order-side read. Re-run the unchanged structural/checker commands; no table, column, function, workflow or wire contract is added.
- **修复风险（低/中/高）**: 低 (grant/validation wording only; no schema object).
- **严重程度（低/中/高/严重）**: 中.
