  `CatalogDraftRepositoryTests.zeroRowsAndRawUniqueRacesUseBoundedReread`.

  non-cooperating delete or suppressing trigger), so `readDraft` throws `Failure(NOT_FOUND)`.
- **Actual branch:** the new matrix covers 8 arms (unchanged, equal successor, different successor, other

  return null; the mock's `fetchOne` returns the same row for both reads. The implementation-report

  404" among the arms and suggested a case for the absent row; plan §6.3 requires the reread matrix to use
  404/409/503 as applicable.
- **Direct evidence:** the outcome list at `:101-109` has no absent-row entry; production handles absence
  correctly at `:104` (typed `NOT_FOUND`, rollback, then a non-SQL restore attempt).
- **Impact:** detection strength only. A future regression that changed the vanished-row result would not
  be caught by this unit matrix; the live suite also has no isolated reread-vanished case. No data,
  security or current correctness exposure.
- **Safe fix direction:** add one test-local outcome that returns the row on the first `FOR UPDATE` read
  and null on the second (e.g., a per-statement counter in the mock), assert 404 and the same no-write
