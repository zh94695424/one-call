A direct Spring Boot 4.1.2 `SystemEnvironmentPropertyMapper` probe returned both `ONECALL_SHARINGPUBLICREAD_DATASOURCE_URL` and `ONECALL_SHARING_PUBLIC_READ_DATASOURCE_URL` (and the analogous admission/evidence/command forms), so both bind. The operator-facing README/runbook keys are the tested underscore keys, so this is a bookkeeping/precision question, not an operator defect. Destination: plan/Controller documentation owner on the next authorized reconciliation.
2. **Non-blocking portability wording — POSIX psql.** The SQL uses `\o /dev/null` and psql meta-commands (`\if`, `\gset`, `\pset`); the runbook is shell/POSIX-oriented but does not explicitly state a POSIX client requirement or test native Windows psql. Failure could add nonsecret meta-command output or break the “success is exactly the fixed marker” observation without changing database state. Destination: CI/Operations platform-precision task, not a product fix in this gate.
3. **Hosted CI headroom.** The fresh full run is 12m20s locally with a usable image; the workflow job timeout is 30 minutes. No hosted-runner timing was supplied, so hosted headroom remains an observation rather than a proven margin. Destination: CI owner on the first hosted run.
