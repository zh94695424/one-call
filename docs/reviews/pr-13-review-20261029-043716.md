## Residual Risk

- **Reciprocal link is UPDATE-path fail-closed, not INSERT-path.** Guards fire on UPDATE only. `INSERT` of `outbound_call_task` with `claimed_call_id` pre-set (FK requires the call) or `INSERT` of `call_record` with `task_id` pre-set (FK requires the task) can create a non-reciprocal pair without violating the frozen guards. Plan §5.2 deliberately scopes the DB contract to claim-transaction ordering and says it is "not proof of the full service orchestration". Owner: IVR service (claim orchestration). Destination: later IVR service wave must use the documented NULL→claim UPDATE sequence (or add a future guard if the controller reopens the contract).
- **`call_event` payload/identity owner-level immutability is service-owned.** Only column grants protect `ivr_role`; there is no owner-level UPDATE/DELETE trigger on `call_event` (unlike `ivr_decision`). Owner: IVR service / Platform. Destination: service-layer write path; do not treat DB as the only append-only backstop for events.
- **`inbound_session` / `call_leg` terminality is service-owned.** Origin identity is guard-frozen, but session status/confirmation and leg state can be rewritten by owner after terminal labels. Owner: IVR service. Destination: service state machine (plan §5.1 mutable-head class).
- **Absent explicit ENDED→ACTIVE and extra-member redacted-payload probes** (already classified in the aggregate residual list). The terminal-tuple guard and `ck_call_event_payload_redacted` whole-shape CHECK subsume these; the suite proves the covering predicates but not those two named negatives in isolation. Owner: Database test maintainer. Destination: later test maintenance, not a new acceptance criterion.
- **`ttl_seconds` and `expires_at` are independently checked, not cross-equal.** DB freezes both on the row but does not require `expires_at = created_at + ttl_seconds`. Owner: IVR service expiry housekeeping. Destination: later service wave.
- **`postgres:16` image is unpinned by digest** (existing residual). Owner: Platform. Destination: test-image pinning work.
- **Local green is not production acceptance and not a substitute for future exact-head gates.** Observed GitHub Actions at this head are green, but production acceptance, carrier/provider/load/restore/penetration and A5 records remain out of scope. Owner: production gate. Destination: later production/acceptance waves.
