## Open Questions

1. **Clock skew between the application-written customer head and the database decision time.** `DefaultCustomerSubjectActivationService` writes `service_activation.updated_at` from `Instant.now()` (`…ActivationService:109,125–127`), while the Operations owner uses `clock_timestamp()` and rejects `decisionTime.isBefore(head.updatedAt())` (`DefaultOperationsSubjectLifecycleService:67–68`). A positive app-vs-DB skew can transiently 503 the first Operations command after a customer activation. This is the plan's explicit “reject regressing DB timestamp” choice and is already a Backend/Database residual; not reclassified as a defect.
2. **Audit role-restoration diagnostic suppression.** `JooqOperationsLifecycleRepository.appendAudit` (`:79–82`) discards a concurrent primary `Failure` when the restoration itself fails, unlike the employee lock's `addSuppressed`. Both paths roll back and map to sanitized 503; the Controller already rejected this as a gate-scope issue (Control :80) and assigned later Backend diagnostic enrichment.
3. **Non-ASCII `Idempotency-Key` over real HTTP.** The binder/authenticator contract accepts UTF-8-encodable 1–128 code points and the unit test exercises a 128-code-point emoji key, but the real-HTTP IT uses ASCII and servlet header decoding is container-governed. The key's replay equality is preserved for identical bytes; exact “logical text” preservation for non-ASCII clients remains a Backend/API live-header policy residual.
4. **Production database encoding.** The PA32-owned fixture asserts `server_encoding=UTF8`; the frozen `ck_activation_transition_reason` uses PostgreSQL `length()`, so a non-UTF8 production database would count a multibyte 64-code-point reason as more than 64 and fail closed. UTF8 provisioning remains Database/Platform ownership; no application defect.
5. **`RATE_LIMITED`/429 contract without a throttler.** OpenAPI/docs retain the common code but this slice deliberately introduces no throttler; consistent with the accepted plan boundary, not a drift.
6. **Future `/api/v1/operations/*` endpoints.** The Operations filter intentionally returns 404 for every path outside the two frozen POSTs; any future Operations route must extend the same filter/pass-through allowlist in the same change or it will be unreachable. Backend owner; not a current defect.
