## Residual Risk

- **Cooperative, not preemptive deadline (owned by Backend/Platform/Database).** A single in-flight owner statement (up to `statement_timeout=2000ms`) or required `context.enter()`/`exit()` cleanup can finish past 5s before the next `checkBudget` observes it; a blocked pool checkout is only seen at `:159` after the connection is handed back, and Hikari `connectionTimeout`/`leakDetectionThreshold` were deliberately left unchanged. This narrows the previously-unbounded batch loop materially but does not deliver an exact 5s HTTP/physical-release SLA — disclosed in the fix report and consistent with prior reviewer finding-1 caveats.
- **Bounded AGG-04 scope.** `Failure`/`Code` remain defined alongside the wire DTOs in `OperationsSubjectReadService`, so the five owner adapters still compile against an IAM-owned error type; only the import surface was reduced (wildcard→explicit), not the ownership direction. Full relocation was out of the authorized scope and is not a new defect.
- **Container coverage for this overlay is partial.** Only 36 PA33 Failsafe identities (12 + 24) were re-run against PG16; the other 440 Failsafe and full hosted/contract/firewall/JAR-smoke are static/historical, not freshly executed here. Local focused green is not full-suite or production acceptance.
- **Default-clock wiring is asserted by construction, not by test.** The `System::nanoTime` default (`:48`) is a one-line method reference exercised only via the injected seam; no test binds the production supplier itself (low risk).
- **Pre-existing fail-safe precedence.** If `context.exit()` in the `finally` throws (cleanup/restoration failure) while the `try` carries a specific `Failure` (e.g. 404), the 503 supersedes it; this predates the overlay and is integrity-preserving (rollback + `rollbackOnly`), so it is noted as residual, not a new finding.
