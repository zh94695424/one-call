## 3. Open Questions

### OQ-1 — `ck_call_event_payload_redacted` source-key subset

- **Entry:** V005 `ck_call_event_payload_redacted` (`V005__ivr_task_session_call.sql:286–300`).
- **Observation:** top-level shape is exactly `source` + `receipt` (strip-to-empty). Nested `receipt` requires both `payloadSha256` and `eventFingerprint`. Nested `source` requires `payload` only; `eventType`/`legId`/`sequenceNo` are optional (strip-to-empty of the allowed set, then `? 'payload'`).
- **Tension:** docs/14 §4.27 describes `payload_redacted` as a "Redacted view" / canonical shape; wording that implies all four source keys may be present is compatible, but wording that implies all four are required is not.
- **Status:** frozen V005 after S1-fix-1 errata; tested as accepted. Not a defect against the frozen blob. Residual for the IVR event-absorption service wave to either fill all source keys or document subset-OK.
- **Owner:** IVR event-absorption / docs/14 dictionary owner.

### OQ-2 — DDL-in-savepoint isolation for preempted unique/CHECK probes

- **Entry:** `expectDecisionSourceUniqueViolationWithIsolatedConstraint` (`PostgresContainerIT.java:3797–3850`) and `expectCallLegTypeViolationWithIsolatedConstraint`.
- **Observation:** as `ivr_owner`, drop the preempting frozen constraint/unique inside a savepoint, probe exact `23505`/`23514` + name, `ROLLBACK TO SAVEPOINT`, assert restore. This is required because `ck_ivr_decision_source` + `uq_ivr_decision_call_purpose` make a solo `uq_ivr_decision_source` violation unreachable while unisolated, and `ck_call_leg_direction` subsumes `ck_call_leg_type` under PG16.
- **Tension:** if a future reviewer rejects DDL-in-savepoint isolation entirely, the only alternatives are weakening the probe (forbidden) or a frozen V005 redesign (out of scope).
- **Status:** same established in-repo pattern as `expectProfileStatusViolationWithIsolatedConstraint` / catalog / leg-type helpers. Accepted residual by S2-fix-1; not a new material finding.
- **Owner:** controller / later suite-policy owner.
