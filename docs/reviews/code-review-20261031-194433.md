- **Status-independent replay in the S3 test harness.** `v009S3Admit` resolves an existing admission key before the status/limit check, so a same-key replay would return the original fact even after `REVOKED`/`EXPIRED`; the tests only witness replay in `ACTIVE`/`LOCKED` and use new keys for the revoked/expired races. This is test-harness SQL, not a production service, and it matches the plan’s “replay before limit test” wording, but the post-revocation replay contract remains with Sharing/Backend.
