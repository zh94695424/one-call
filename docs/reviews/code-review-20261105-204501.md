## Adversarial Failure Pass

- Auth/tenant isolation: `lockGrant` filters `created_by_account_id = caller` and `owner_organization_id IS NOT DISTINCT FROM selected workspace`, so cross-account, personal-vs-org, and other-org probes conceal as 404; inactive account/org/membership returns 403 before any grant read. Replay still requires the same active context and ownership. No IDOR path found.
- Secret leakage: first response is the only place `extractionCode` exists; replay DTO has no such field; access payload/Outbox/audit carry only digests/fingerprints; problem writer echoes only code/title/trace. Raw key is transient identity input and is asserted absent from durable rows.
- Replay/state traps: replay is keyed by grant+action+raw key and fingerprint; later relock/rotate/revoke/expiry/policy denial do not change the returned persisted ACTIVE result and append nothing. Different witness/trace replays; changed fingerprint (impossible via web, synthesized in IT) is 409 with rollback.
- Race/ordering: all commands take the same account/org advisory locks before the grant row lock; identical-key rotations serialize and the loser replays; distinct-key loser sees ACTIVE and 409. No double increment path found.
- Failure injection: every append/update/commit seam rolls back grant row and all facts; unexpected faults classify 500, declared material/lifecycle faults classify 503; no raw SQL/canary in Problems.
- Boundary inputs: empty/malformed/duplicate/scalar/trailing JSON, unknown keys, explicit null, negative/fractional/overflow witness, 128/129-code-point IDs and keys, unpaired surrogate, NUL, duplicate headers/media, wildcard/subtype media, aliases/prefix encodings, context-path, matrix params — all map to the frozen 404/422 precedence.
- Parameter effectiveness: `expectedCodeGeneration` reaches both the service matrix and the SQL predicate (`AND code_generation = ?` only when present, including real value 0); `traceId` reaches only audit; no inert or silently defaulted security-relevant parameter was found.
