## 4. Open questions

1. **Dotted suffix versus route closure**: The filter segment pattern `[^/;%]+` admits a dot, so `/api/v1/customer/subjects/<uuid>.json` reaches the controller and, under the plan's full-UUID validation, would be 422. The §7.1 test name `unsupportedMethodsAndNoncanonicalRoutesRemainNotFound` says "suffix" cases remain 404. Clarify whether "suffix" means an extra path segment (which the filter rejects) or a dotted value (which the plan admits for 422). The answer must be pinned before the test is written.
2. **Any-query-parameter/body rejection**: The frozen OpenAPI operation declares no query parameters or body, but it also does not explicitly state that unknown query parameters or a nonempty GET body must be 422. The plan adopts that behavior for authority hygiene. Confirm this is intended contract behavior rather than an unconfirmed additional rule, and keep the existing problem code/status surface unchanged.
3. **404 representation**: Even after A-05 is fixed, confirm the chosen `Optional`/exception/controller-response form is the one the Controller wants as the permanent seam, since the service is described as the only application operation and its four-component `Detail` is the full success response.
4. **Bidirectional module allowlist**: `catalog_order` already declares `allowedDependencies = {"customer_iam", "subject_number"}` while `customer_iam` will now declare `catalog_order::customer-subject-count-query`. The plan correctly notes there is no actual catalog → customer implementation edge today, so Modulith should see no cycle. Confirm Architecture accepts this one-way actual/bidirectional-permission shape rather than narrowing catalog's existing permission.
5. **V016 checksum and PA25 history literal**: The plan correctly refuses to invent the final V016 Flyway checksum. Confirm the implementation will derive and independently seal it before acceptance, and that `CustomerBusinessNumberBoundaryTests` and the new boundary test use canonical-LF hashing for V001–V015 only, never a raw/CRLF mismatch.
