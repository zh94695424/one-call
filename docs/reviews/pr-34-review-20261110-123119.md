## Findings

未发现实质性问题 (material finding count: **0**).

Adversarial checks against the real changed paths produced no evidence-backed
material defect:

- **Selector semantics.** `MediaPlaybackKeySourceConfiguration.java:38-43`
  matches only exact `provider=file` and reads no Tencent field or
  `bundle-path`; `:45-52` matches only exact `provider=tencent-ssm` and
  short-circuits on `!containsProperty(bundle-path)`. Invalid, blank, unknown,
  compound, case-variant and unresolved selectors yield no built-in provider.
  `provider=file` is therefore not suppressed by stale/unselected Tencent
  metadata; `provider=tencent-ssm` plus any `bundle-path` presence yields zero
  built-ins with no file fallback. Both conditions catch `RuntimeException` and
  fail closed.
- **Sole-authority preservation.** `MediaPlaybackCredentialAuthority.java:74-89`
  retains the existing `providers.size() != 1` cardinality check before any
  `currentKeys()` call; the file provider, parser, codec, authority, playback
  service and public surfaces are not in the diff.
- **Provider data path.** `TencentSsmMediaPlaybackSigningKeyProvider.java:27-53`
  checks null/blank settings and reader, rejects non-String/oversized input,
  encodes with reporting UTF-8, enforces the 65,536-byte bound, passes exactly
  the resulting bytes to the unchanged parser, and clears owned `source`/
  `buffer` arrays in `finally`. `Settings.create` (`:73-93`) enforces region,
  name/version, control-character, surrogate and timeout bounds with 2/3-second
  defaults; invalid settings produce one permanently unavailable provider
  without client construction.
- **SDK boundary and lifecycle.** `TencentSsmSecretStringClient.java:25-58`
  performs one application `GetSecretValue` per read, sets only the configured
  name and version (encryption fields untouched), requires exact non-null
  response name/version identity, rejects null/blank SecretString and any
  non-empty SecretBinary, catches `TencentCloudSDKException | RuntimeException`,
  constructs the SDK client lazily inside a synchronized accessor, permits
  recovery after failed construction, and establishes POST/HTTPS to
  `ssm.tencentcloudapi.com`, TC3 signing, debug off, unsigned-payload off and
  connect/read/write timeouts from validated settings. No environment/profile/
  OIDC/static credential route or file fallback exists.
- **Redaction.** Provider, `Settings` and client expose constant
  `@JsonValue`/`toString` forms; response and exception details are discarded;
  tests assert synthetic secret, credential, request-id and material canaries
  are absent from results, serialization, `toString` and captured output.
- **Test quality.** New tests exercise the real parser, real provider/client
  adapter and real authority with mocked actual `SsmClient` objects; they cover
  response identity/payload rejection, transport/factory failures, recovery,
  buffer clearing, snapshot independence, source/path bounds, role/schema
  rejection, replay/overlap/removal, ambiguity-before-read and file/Tencent
  selector asymmetry. Static inventories and CI method-name dictionaries match
  the source exactly; the only open test-probe question is OQ-1 below.

## Open Questions

- **OQ-1 — `path-resolution-guard` probe semantics (non-blocking,
  verification-claim only).** `MediaPlaybackConfigurationTests.java:353-363`
  installs a `PropertySource` whose `getProperty(bundle-path)` throws
  `AssertionError` while `MediaPlaybackKeySourceConfiguration.java:49` uses
  `Environment.containsProperty(bundle-path)`. If Spring Framework 7's
  `containsProperty` delegates to `getProperty`, the `Error` escapes the
  condition's `catch (RuntimeException)` and the test fails; if it consults
  `PropertySource.containsProperty`, the test passes. This snapshot has no
  Spring jar/source and the reviewer did not run Maven, so the question is not
  independently settled. Control line 62 records Controller-executed
  `MediaPlaybackConfigurationTests 19/19` and focused `117/117` green. This
  affects only the validation claim, not the production selector, which fails
  closed for real property sources either way.

  this snapshot and were not re-inspected; a live response-identity mismatch

## Residual Risk

- **CVM-only identity.** `CvmRoleCredential` is usable only from a CVM instance
  role; non-CVM (TKE/OIDC) deployment would require a new goal confirmation.
  Owner: Platform/Security.
- **Unbounded liveness.** CVM metadata has no exposed connect/read/call timeout
  and SSM has no total `callTimeout`/DNS deadline; bounded connect/read/write
  `2/3/2` seconds do not bound an end-to-end call. OkHttp's default
  `retryOnConnectionFailure` may produce multiple connection attempts inside one
  application invocation. Owner: Platform/Security runtime validation;
  Operations for SLO.
- **Per-call capacity.** Every issuance/verification can perform one SSM read
  with no cache/TTL by design; quota, cost, latency and throttling under media
  traffic are not analyzed in this slice. Owner: Platform/Security capacity and
  Operations.
- **Memory and dependencies.** Java/SDK `String` secret material remains in
  process memory; owned-buffer clearing is not heap erasure or HSM isolation.
  The new transitive graph (okhttp/okio/kotlin/gson/commons artifacts) remains a
  future advisory/logging-drift surface. Owner: Security/Build.
- **Selector exactness.** The accepted design replaces the prior
  `@ConditionalOnProperty` matching with exact case-sensitive literals; any
  external deployment using `FILE`/case variants or relaxed-binding spellings
  would now create no built-in provider. The repository's own configuration
  surface uses lowercase `file`, and the plan explicitly requires exact
  literals. Owner: deployment configuration maintainers.
- **Test-maintenance brittleness.** Several architecture assertions are
  source-string based; the provider's individual import allowlist is not pinned
  separately (the client's SDK imports are pinned and SDK confinement is checked
  globally). Formatting changes could require test maintenance.
- **Pre-existing contract drift.** A2/A5 source-tree documentation failures are
  outside all PA23 paths and are not fixed here; they are not PA23 regressions.
  Owner: existing contract/document maintainers.
- **Live acceptance.** No live Tencent/CAM/provisioning/readiness claim is made;
  endpoint/region/CAM/version rollout and response-echo validation remain
  Platform/Security deployment obligations.
- **Execution gap.** This review did not run JVM/Maven/Docker/PostgreSQL, CI,
  jar smokes, firewall probes or contract checks; all runtime and current-head
  CI statements remain unresolved third-party claims.
