### F-PA4-PR-02-未修复-低-S2 lifecycle 证据把冻结状态机禁止的 `OFFSALE→ACTIVE` 与 `PAID→CLOSED` 当作有效转移

- **入口/函数**: `v004CatalogVersionLifecycleAndGuardBackstops` → `assertV004CatalogVersionLifecycleAndGuardBackstops()`；`v004OrderPaymentLifecycleAndAppendOnlyBackstops` → `assertV004OrderPaymentLifecycleAndAppendOnlyBackstops()`。
- **文件(行号)**: `backend/src/test/java/com/onecall/archtests/container/PostgresContainerIT.java:9174-9180`（`// Re-activate ...` 的 `OFFSALE → ACTIVE` UPDATE）、`:9491-9504`（customer_order `PAID → CLOSED`，同时 `paid_at = NULL`）、`:9535-9540`（payment_order `PAID → CLOSED`）；`backend/README.md:64`（把 `DRAFT→ACTIVE→OFFSALE→re-activate` 与 `UNPAID→PAID→CLOSED` 写成已证明 lifecycle）；`docs/gateflow/pa4-v004-catalog-order-payment-foundation-s2-implementation.md:45,53-54`（同样记录 re-activate 与 `UNPAID→PAID→CLOSED`）。绑定规则：`docs/14-production-data-model-and-flyway-schema-spec.md:2777`（catalog version `OFFSALE` terminal for sale）、`:2778`（customer order `PAID` 和 `CLOSED` terminal）、`:2779`（payment order “Same verified-evidence transitions as the order”）、`:2793`（`PAID`/`CLOSED`/`OFFSALE` immutable）。
- **输入场景**: 运行 PA4 S2 lifecycle 方法时，测试在真实 PostgreSQL 16 上执行：① `UPDATE catalog_order.catalog_version SET sale_status='ACTIVE', published_at=now(), revision=revision+1 WHERE id=<OFFSALE 行>`；② `UPDATE catalog_order.customer_order SET payment_status='CLOSED', paid_at=NULL, closed_at=now() WHERE id=<PAID 行>`；③ `UPDATE catalog_order.payment_order SET status='CLOSED' WHERE id=<PAID 行>`。README/artifact 将这些步骤描述为有效 lifecycle 证据。
- **实际分支**: DDL 允许这些 UPDATE。`catalog_order.guard_catalog_version_published()` 仅在 `OLD.published_at IS NOT NULL` 时拒绝商业内容列，但显式不检查 `sale_status`/`revision`（V004:291-317；docs 10.16 亦要求 “allow `sale_status`/`revision`”）；`guard_customer_order_snapshot()` / `guard_payment_order_identity()` 只冻结快照/身份列，显式允许 `payment_status`/`paid_at`/`closed_at`/`status`（V004:333-378）。`ck_customer_order_payment_shape` 只要求 CLOSED 时 `closed_at` 非空且 `paid_at` 为空，因此 PAID→CLOSED 在清空 `paid_at` 后通过。全部语句在本次独立 container 运行中成功，方法为绿。
- **预期行为**: docs/14 §7.3 是冻结状态机：catalog version 只允许 `DRAFT→ACTIVE`、`ACTIVE→OFFSALE`，`OFFSALE` terminal；customer order 只允许 `UNPAID→UNKNOWN/PAID/CLOSED`、`UNKNOWN→UNPAID/PAID/CLOSED`，`PAID`/`CLOSED` terminal；payment order 同序。§4.17/§9.26 只定义 publication（候选 DRAFT→ACTIVE）与 offsale（ACTIVE→OFFSALE），没有 re-activate 服务路径；§9.18/§4.20/§4.21 没有 PAID→CLOSED 服务路径。terminality 由 catalog-order 服务拥有（DB guard 故意不承担），因此 S2 数据库证据不应把禁止转移标记为“有效 lifecycle”。
- **实际行为**: 方法注释写 `// Re-activate for guard/unique probes` 和 `// Valid payment transitions ...`，实际执行并断言了 `OFFSALE→ACTIVE`、`PAID→CLOSED`（并清空 `paid_at`）；README 与 S2 artifact 将 `DRAFT→ACTIVE→OFFSALE→re-activate` 和 `UNPAID→PAID→CLOSED` 作为已证明行为记录。若 future service 按此证据实现，就会允许冻结状态机禁止的转移，而本 suite 不会发现。
- **直接证据**: 代码行如上；docs/14:2777-2779、2793 的 terminal 文本；README:64 与 S2 artifact:45/53-54 的记录。另注意 `OFFSALE→ACTIVE` 能在同一事务内通过，是因为 `now()` 在事务内恒定、`published_at` 值未变化而绕过 published-content guard；在真实跨事务 service 路径中该步骤不具备同等语义，这也说明它不是可复用的 lifecycle 事实。
- **影响**: 无直接生产/安全影响（这是 test-only 与 README/artifact 语义漂移；V004 DDL 本身与 docs/14 §4.16–4.22/§10.16 一致）。风险是证据语义被固化：suite 无法回归捕获 service 错误允许 `OFFSALE→ACTIVE`/`PAID→CLOSED`，且 PR 的证据摘要把禁止转移呈现为已批准行为，影响后续 catalog publication 与 payment 服务实现。
- **建议改法和验证点**: 用冻结状态机允许的 fixture 达到同样断言目标：测试第二个 `ACTIVE` 冲突时，不要 re-activate 已 OFFSALE 的版本，改用新 product 或发布一个新的 DRAFT 版本；构造 CLOSED 行时使用 `UNPAID→CLOSED`（`paid_at` 保持 NULL），PAID 行单独保留；把相关注释、README:64 与 S2 artifact:45/53-54 改为“synthetic shape/revision probe, not an approved service transition”，或删除 re-activate/PAID→CLOSED 证据。验证点：仍为 31 方法、`clean verify` 10/0/0/0、`-Pcontainer-smoke verify` 31/0/0/0、V004 与 V001–V003 hash 不变、51 check/11 FK/ACL 断言不减少。
- **修复风险（低/中/高）**: 低（只改测试 fixture/注释与 README/artifact 文案；不得改 V004，不得减少断言或方法集）。
