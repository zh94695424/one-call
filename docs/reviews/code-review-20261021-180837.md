## Review evidence

- Intent / source of truth：用户确认现有自研 IVR 具备完整通话、录音、通话记录/时长及上传能力；新设计只分配任务、权限、权益和证据语义，没有把媒体引擎重建设为当前目标。
- State machine：检查 `PENDING` 的创建、替换、取消、30 秒边界、领取，以及 `CLAIMED` 后确认拒绝、通话终态和 IVR 崩溃恢复；终态不回退，待拨 TTL 不会误杀已领取通话。
- Concurrency / idempotency：同一规范主叫跨账户/空间唯一；任务唯一约束和主叫数据库锁同时覆盖创建、替换、取消、领取及直接呼入；`callId/eventId/recordingId` 作用域和冲突处理明确。
- Trust / ownership：任务发起身份来自客户会话；实际主叫来自可信线路；IVR 拥有通信事实，后台拥有任务/权益/证据状态；小程序拨号回调不推进通话事实。
- Entitlement safety：resolve 只返回余额快照；用户确认后重新校验并按 `callId` 原子创建预占，避免两个呼入共享旧余额。
- Failure pass：覆盖过期扫描延迟、跨空间替换、迟到呼入、IVR 领取后崩溃、结束/上传重复乱序、后台断网和未知枚举；未知通话不因 TTL/租约自动释放。
- Protocol / performance：呼入决策排除媒体与外部供应商 I/O；PostgreSQL 索引/事务投影为真源，Redis 仅加速；录音字节与事件元数据分流，避免阻塞在线决策接口。
- Cross-doc consistency：12 的 FreeSWITCH 强制前提已收敛为复用现有自研平台；09/10/11 与 13 对未实名直接试用、业务号码/登录身份和任务状态口径一致；历史 03/04/06/07 使用顶部覆盖链接而未伪称原型已实现。
