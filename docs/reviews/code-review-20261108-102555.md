## Residual Risk

- The reader intentionally returns an opaque `Unavailable` for every technical fault and performs no logging or metric emission. This preserves exception/row secrecy but leaves operational diagnosis dependent on database/server telemetry; a future evidence/P19 observability slice may add a redacted counter/log without changing the contract.
- No statement/query timeout is set on the reader template in addition to the connection pool acquisition timeout. A server-side hang would be bounded by the driver/server configuration rather than the reader; the accepted plan does not require a timeout, but it remains an operational residual.
- The role IT's `privilegeOnlyMigrationIsAtomicAndV001ThroughV012RemainByteIdentical` byte-identity check is run-relative (it compares the source files before and after the test run); the raw-byte pin against the accepted digests is established by the Controller audit and the implementation report, while the existing canonical pins cover V001–V011. This is a regression-guard limitation, not a candidate defect.
- Dedicated `evidence_media_reader_role` credentials are external; the migration creates the role with `PASSWORD NULL` and no membership. Deployment/database operations owns provisioning; a post-provisioning manual V013 replay fails closed by design.
- The URL validator deliberately rejects embedded userinfo and query options (for example `sslmode`); deployment must provide a bare `jdbc:postgresql://host[:port]/database` URL plus the separate credential properties.
- Recording hash/subject and broader evidence-integrity cross-checks are not performed by this query (accepted plan decision 5); Evidence service/integrity owns a later slice. `Missing`/`Unavailable` mapping to PA19 playback outcomes is owned by the later PA19 implementation.
- PostgreSQL 16 container/image availability is environmental; the Controller evidence is a local container run and the CI-recipe inventory re-execution, not a GitHub Actions run. The accepted command remains `mvn -B -DskipTests=false -Pcontainer-smoke verify`.
- The `connectionAndPermissionFaultsReturnOnlyUnavailable` IT creates a throwaway `denied_*` login role in its own Testcontainers database and does not drop it; this is test-container-only hygiene and cannot affect the production schema or another test database.
