## Findings

### PA14-A-R01-未修复-高-Revoke/rotate derive the transition identity before the grant UUID exists

- **位置**: `docs/gateflow/pa14-sharing-command-service-foundation-plan.md:27`, `:49`, `:55`, `:61`, `:69`; docs/14 §2.12 and §9.29; OpenAPI revoke/rotate path parameters.
- **问题类型**: 契约缺失 / 并发恢复风险 / 不可直接实施
- **当前写法**: The transition `eventId` and `actionFingerprint` are defined from `shareGrantId` (the grant-row UUID). The revoke/rotate algorithm nevertheless says to validate the key, compute the digest, “derive the 81-character deterministic transition eventId and action fingerprint”, and only then begin the transaction and lock the grant by `shareId`.
- **反例/失败场景**: A request supplies only the 70-character opaque `shareId` (`share:<64hex>`), not the random grant UUID. The UUID is persistence-only and is not derivable from `shareId`. Any first revoke/rotate must therefore lock/read the grant before it can compute the contract-defined event identity. As written, an implementer must either invent a pre-transaction read outside the specified command transaction, substitute `shareId` for `shareGrantId` and produce non-frozen event identities, or move the actual work to a different sequence. A resend from a second client can then miss replay or mutate twice instead of returning the first outcome.
- **为什么有问题**: This is a closed durable identity whose inputs are explicitly frozen. The repository API provides `lockGrantByShareId(String)` and returns `GrantRow.id`, but the algorithm places identity derivation before that method is callable. The plan is therefore not executable as one canonical sequence.
- **直接证据**: Plan lines 27, 49, 55, 61 and 69; `docs/14-production-data-model-and-flyway-schema-spec.md:252` (`{shareGrantId, actionType, sourceIdentity}`); `api/openapi/onecall-v1.openapi.yaml:2972-2979` and `:3049-3056` (path value is a 1–128-character string).
- **影响**: Implementation drift / wrong durable event IDs / broken replay-before-state semantics / duplicate transitions or failed resends / data corruption.
- **建议改法和验证点**: Freeze the order as: validate request key; begin transaction; assert command role; acquire ranks 7/8/9; re-read active context; lock/read the grant by canonical `shareId`; conceal missing/other-owner; derive `eventId` and `actionFingerprint` from the locked `GrantRow.id`; look up transition before state/revision/generation checks; then replay or apply. Add assertions using a real 70-character `shareId`, an 81-character event ID, two clients/resends, same identity, changed fingerprint and distinct identity.
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高

### PA14-A-R02-未修复-高-Rotate replay does not freeze whether response state comes from the first event or the current grant

- **位置**: `docs/gateflow/pa14-sharing-command-service-foundation-plan.md:41`, `:51`, `:69`, `:73`; OpenAPI `ShareCodeRotation*`; docs/14 §2.12 and T-S3-16.
- **问题类型**: 状态机漏洞 / 契约缺失 / 测试缺口
- **当前写法**: `TransitionRow.payload` stores resulting `status`, `codeGeneration`, `revocationGeneration` and `revision`, and exact event/fingerprint replay “returns metadata only.” `TransitionReplay(ShareMetadata)` does not say whether its mutable state fields come from that stored payload or from the now-current `GrantRow`.
- **反例/失败场景**: Rotate with key R succeeds, recording a `CODE_ROTATED` event with `status=ACTIVE`, code generation and revocation generation at that time. A later revoke changes the grant to `REVOKED` and increments revocation generation. Client R resends. If `TransitionReplay` is built from the current grant, the controller emits `ShareCodeRotationReplayed.status=REVOKED`, but the OpenAPI `ShareCodeRotationReplayed` status enum is only `ACTIVE|LOCKED`; the response is undeclared and is not the docs/14 “first recorded outcome.” If it uses the event payload, the plan must also define which non-transition metadata fields come from the locked row.
- **为什么有问题**: Replay-before-current-state is an explicit invariant, and the response is a closed discriminated union. Leaving the metadata source implicit lets a locally plausible implementation violate both the first-result contract and the wire schema only when a later transition exists.
- **直接证据**: Plan lines 41, 51, 69 and 73; `api/openapi/onecall-v1.openapi.yaml:6508-6585`; `docs/14-production-data-model-and-flyway-schema-spec.md:252` and `:4753` (“returns the first recorded outcome before current revision/state checks”).
- **影响**: OpenAPI-invalid response / changed idempotent result / stale or raised generation returned / hidden state-machine regression.
- **建议改法和验证点**: State explicitly that `TransitionReplay` reconstructs `status`, `codeGeneration` and `revocationGeneration` from `TransitionPayload`, not current grant state, and name the source for the remaining `ShareMetadata` fields. Test rotate R, then revoke, then resend R: expect 200 `REPLAYED`, the rotation-time status/generations, no code/token, no new rows and no revision change.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### PA14-A-R03-未修复-高-`rotationPolicy` is defined but never invoked, so rotation authorization cannot be enforced

- **位置**: `docs/gateflow/pa14-sharing-command-service-foundation-plan.md:45`, `:69-71`, `:89`, `:156-162`.
- **问题类型**: 架构边界 / 契约缺失 / 安全边界
- **当前写法**: The plan exports a `ShareCommandPolicyProvider.rotationPolicy(ShareCommandCaller, GrantRow): ProviderResult<RotationPolicy>` and maps an “explicit forbidden outcome” to 403. The revoke/rotation algorithm never calls this provider, never maps `ProviderResult.UNAVAILABLE`, and the test inventory never names a rotation-policy deny/unavailable case.
- **反例/失败场景**: A production adapter exists and returns `DENY(FORBIDDEN)` or `UNAVAILABLE`. The service as sequenced never consults it, so a LOCKED `EXTRACTION_CODE` grant is rotated and a one-time code is returned where the policy required 403 or 503. Conversely, an implementer may invent a policy call before exact replay, causing a previously successful rotation retry to stop replaying when the current policy changes.
- **为什么有问题**: The Goal requires server-owned policy ports with fail-closed behavior when policy/configuration is absent. A defined port with no call site is not closed design; it leaves both authorization and replay ordering to implementation.
- **直接证据**: Plan lines 45, 69-71 and 89; Control line 22 (provider/policy boundary); docs/14 §2.12 transition replay rule; OpenAPI rotate declares 403 and 503 but the plan names no producer of its 403 policy result.
- **影响**: Authorization bypass / undeclared behavior / inconsistent resends / implementation-time design choice / security regression.
- **建议改法和验证点**: Freeze when `rotationPolicy` runs relative to exact event replay, then map `UNAVAILABLE -> SERVICE_UNAVAILABLE/503` and `DENY(FORBIDDEN) -> FORBIDDEN/403`. If following the frozen replay rule, exact event replay can return its first result before current policy is consulted; a new transition must consult policy before state mutation. Add deny, unavailable and retry-after-policy-change assertions without changing the 18-method total.
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高

### PA14-A-R04-未修复-高-The Create algorithm still specifies a pre-transaction projection/fingerprint ordering

- **位置**: `docs/gateflow/pa14-sharing-command-service-foundation-plan.md:33`, `:65`; docs/14 §2.12/§9.29.
- **问题类型**: 架构边界 / 契约缺失 / open question 未收敛
- **当前写法**: The role protocol says the projection is read on the command connection inside the transaction under a temporary `evidence_role` switch. The same Create paragraph first says, “Validate request; derive deterministic share identity, projection-backed content snapshot, designated-mobile HMAC … and creation fingerprint. Begin transaction …”, then later says to switch to `evidence_role`, read the projection and build `content_snapshot`.
- **反例/失败场景**: An implementation that follows the first sentence must obtain the projection before the transaction begins. That requires a second/unbound connection, skips the command-role assertion, and cannot satisfy `evidenceProjectionUsesCommandTransactionConnection`. An implementation that follows the later sentence silently supersedes the first; a resend can then compute/replay against different evidence facts depending on which ordering was implemented.
- **为什么有问题**: This is the exact same-connection invariant that prior A1/B1 required closing. The canonical plan now contains two incompatible sequences in one algorithm paragraph, so the accepted protocol is not one canonical definition.
- **直接证据**: Plan lines 33 and 65; `docs/14-production-data-model-and-flyway-schema-spec.md:255-257`; prior A1/B1 and Control line 35.
- **影响**: Wrong connection/role behavior / ACL failure / stale or non-reproducible fingerprint / failed evidence-projection IT / implementation rework.
- **建议改法和验证点**: Move only transport/key/share-ID/mode/HMAC validation before `Begin transaction`. Put projection read, evidence ownership/solidified check, content construction, scope/creation fingerprint computation, policy/risk and replay strictly after the role switch and locks. Add an assertion that the reader's supplied DSL/connection is the command transaction connection and that `current_user` is `evidence_role` only for the read.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### PA14-A-R05-未修复-中-Create's ineligible-evidence and structural validation outcomes have no declared mapping

- **位置**: `docs/gateflow/pa14-sharing-command-service-foundation-plan.md:31`, `:45`, `:49`, `:65`, `:87`; V009 grant checks; Create OpenAPI.
- **问题类型**: 契约缺失 / 测试缺口 / 不可直接实施
- **当前写法**: The plan says an empty projection is “handled fail-closed” but does not name its exception/HTTP code. “Validate request” does not define checks that prevent V009 constraints from becoming the validator: `expiresAt > valid_from`, `ORGANIZATION_MEMBER` requires an organization workspace, and `DESIGNATED_MOBILE` requires a mobile HMAC. Create declares no 404 response, while `ShareCommandException.Code` includes `NOT_FOUND`.
- **反例/失败场景**: (1) A create for missing, other-owner or non-`SOLIDIFIED` evidence returns an empty projection. If implemented as `NOT_FOUND`, Create emits an undeclared 404; if delayed to insert/FK handling, it becomes 500. (2) `expiresAt` equal to or before the sampled DB time passes ordinary JSON/schema validation, then violates `ck_share_grant_validity` (`23514`) and falls to default 500 instead of 422. (3) `ORGANIZATION_MEMBER` in a personal workspace violates `ck_share_grant_org_member`; `DESIGNATED_MOBILE` without an HMAC violates `ck_share_grant_mobile_binding`.
- **为什么有问题**: The operation-specific OpenAPI set must remain closed, and DB constraints are backstops, not the planned validation contract. No named test covers missing/shared/non-solidified evidence or these structural mode/time failures, so all 18 tests can pass while normal client errors become 500s.
- **直接证据**: Plan lines 31, 45, 49, 65 and 87; `backend/src/main/resources/db/migration/V009__sharing.sql:47-60`; `api/openapi/onecall-v1.openapi.yaml:2843-2877` (Create has 403/409/422/503/default but no 404); `docs/14-production-data-model-and-flyway-schema-spec.md:4752`.
- **影响**: Undeclared 404/500 / existence leakage or wrong disclosure / failed client recovery / production incident path for routine invalid requests.
- **建议改法和验证点**: Freeze a validation table: empty/non-solidified/other-owner projection -> the chosen declared Create code (recommended `FORBIDDEN/403` to avoid existence disclosure); `expiresAt` not strictly after the sampled DB `validFrom`, `ORGANIZATION_MEMBER` without an organization workspace/membership, and `DESIGNATED_MOBILE` without the required mobile -> `VALIDATION_FAILED/422` or the contract-approved code. Exercise each within the existing 12/18 method counts and assert the exact Problem code/status.
