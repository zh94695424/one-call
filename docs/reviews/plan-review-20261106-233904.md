## 3. Blocked implementation finding and fix-10 resolution

The blocked report demonstrates an information gap: the frozen `ADMISSION_GRANTED` witness (six fields, eight for member) and the seven-column admission row carry persisted session/admission/grant windows but no original ticket TTL or policy reference. Two approved policies with the same session duration and different ticket durations can therefore produce byte-identical durable projections while requiring different reconstructed ticket expiries. The blocker's two proposed alternatives were (a) post-transaction current-policy lookup, or (b) a durable original-policy witness. The Controller selected (a); fix-10 implements (a) and adds no durable TTL.

The plan now resolves the gap coherently: persisted windows identify the maximum lifetime, and a fresh current approved Q22 ticket TTL supplies only the ephemeral ticket expiry under the docs/14 minimum formula. The durable projection no longer has to choose the ticket TTL.

## 6. Assumptions tested and failure scenarios

1. **Current replay policy is obtainable through the same seam.** If the provider is unavailable/malformed, the plan returns 503 `SHARE_SESSION_POLICY_UNAVAILABLE`, preserves state and lets a later same-key retry look up afresh. Failure scenario (persistent provider outage) is a deliberate fail-closed residual, not a contract gap.
2. **The lookup is outside every transaction/lock.** The four existing methods use policy doubles that assert no active PostgreSQL transaction, row lock or advisory lock at invocation (L312–L315). A misplaced in-transaction lookup fails the tests.
3. **A later approved TTL cannot lengthen persisted windows.** The formula's minimum plus the no-write replay path guarantees `ticketExpiresAt ≤ sessionExpiresAt, admissionExpiresAt, current grant expires_at`; the witness/windows must stay byte-identical (L313). An implementation that persists the new TTL fails the assertions.
4. **Preliminary-miss race.** If a concurrent same-key admission wins during fresh proof, the plan discards the precomputed proof and policy and performs exactly one post-transaction lookup (L46, L313). Using the precomputed TTL would fail `lostResponseRetryReconstructsWithoutSecondAdmission` and the duplicate-key concurrency assertions.
5. **Policy failure is not a ticket failure.** Mapping it to `TICKET_FAILED` or `INTERNAL_FAILURE` violates L54/L55/L384; the tests assert no event append in both fresh and replay cases.
6. **Runtime boundaries.** Static review cannot prove PostgreSQL lock/transaction timing, provider call counts, Redis TTL behavior, ACL catalogs or CI XML inventory; those remain implementation-gate obligations.
