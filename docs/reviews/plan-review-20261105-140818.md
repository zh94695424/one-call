The strongest probes that were tested and did not yield a material plan defect:

- **Ordering:** Replay-before-terminal/expiry/witness, changed-fingerprint-before-terminal, terminal `REVOKED` 410 before stale/expiry, and `EXPIRED`/elapsed `ACTIVE|LOCKED` 409 before witness are internally consistent with Control's required behavior and docs/14 §9.29 step 5. The stricter lock-then-`findTransition` order (needed because identity requires the locked grant UUID) preserves the frozen semantics and only strengthens ownership concealment; it does not change state, identity, or error outcomes.
- **NotUpdated path:** Under the held grant `FOR UPDATE` lock a zero-row conditional update is defensively unreachable, and the plan's one bounded reread plus stable 409/410 classification (never success/current state) is an acceptable conservative backstop matching the accepted foundation plan.
- **Facts and rollback:** Event append before the conditional update, followed by Outbox and audit, is safe because every failure throws and rolls back the event; the plan forbids catch-and-continue, second updates, and invented denial facts. Payload key sets, hashes, `occurredAt` placement, audit before/after shapes, and the double-prefixed Outbox dedupe literal all match the accepted full plan.
- **Redaction:** Raw key, reason, token, code, salt, hash, mobile HMAC, and object identity are excluded from access-event and Outbox payloads; the raw key exists only transiently for identity computation and in the request attribute; no raw key is logged or persisted. The access event stores only the digest/fingerprint; the audit stores the reason.
- **Transport precedence:** Authentication → revoke header validation → Content-Type → controller workspace/path/body matches the stated precedence; missing/duplicate/blank/overlong keys, invalid media, body, explicit nulls, unknown fields, and rejected routes map to the frozen 422/404/401/503 outcomes with no provider/DB effects.
- **Inventory feasibility:** 78/16 + 113/6 = 191 is arithmetically and structurally achievable by adding exactly one `@Test` to `CustomerShareCommandServiceTests` and five to `CustomerShareCommandsIT`; CI regexes accept plain `@Test void name()`, reject parameterized/conditional tests, compare source=CI=XML pairs, and POM already includes the IT. The plan names every dictionary/total/message to update.
- **Boundaries/overcoupling:** The slice adds nested command/result types, four repository operations, one service path, one controller handler, four web-file extensions, and in-place test expansions; it adds no new file, provider, datasource, export, module, migration, or public contract. The accepted full plan already froze these interfaces. No overengineering or goal drift was found.

1. **How should the exact-route web test configure the 200 proof?** §8.2 requires `exactGetAndPostRoutesPassHighestPriorityFilter` to prove an admitted revoke can reach 200 "where configured", while the existing `WebBeans` test context has no `customerShareCommandService` bean (so the same request yields the deliberately controlled 503). The existing fixture's create-503 assertion also constrains any global bean addition. The plan permits editing only `CustomerSharesWebTests.java`; an implementation agent must choose an isolated test context/bean setup without changing other assertions. This is a bounded test-fixture design question, not a behavioral contract gap. Owner: Backend/web implementation owner.
2. **Duplicate-header visibility under the container's `getHeaders` semantics.** The design intentionally preserves a legitimate single comma-containing value and rejects duplicate values only when the servlet surfaces them as more than one value. Tomcat's behavior is the production/test container; if a future front proxy combines duplicate header lines into one comma-joined value, duplicate detection would depend on that proxy. The frozen plan explicitly declines a comma-splitting policy, so this is an accepted boundary. Owner: web/gateway owner if deployment topology changes.
3. **`newExpiresAt` wording in docs/14 vs the accepted full plan.** Already adjudicated in Control as `deferred-with-owner` (design/docs owner); this work unit uses the accepted plan's always-present JSON-null member. No action in this slice.
