## 5. Open questions

1. **Controller registration annotations.** §5 pins the reader and configuration
   annotations but not the `@RestController`/`@Profile("web")`/`@ConditionalOnWebApplication`
   pattern for `OperationsCatalogProductReadController`. The shipped
   `OperationsIvrSessionReadController.java:23-31` is the obvious model. Owner:
   Backend/Operations IAM; destination: implementation gate. Low risk.
2. **Full V004 matrix vs the 410-tuple oracle.** The existing
   `EvidenceRoleIvrAssociationAclIT.currentOracle()` grantee filter (`ACL` at `:24-37`)
   does not include `catalog_order_role`; the 410-tuple oracle therefore cannot by itself
   prove the `catalog_order_role` matrix. `observesFrozenRoleMatrix` must query the actual
   V004 matrix (table SELECT/INSERT on seven tables, selected column UPDATE, four EXECUTE,
   schema USAGE plus cross-schema SELECT) directly, while the 410/7-9-11 oracles remain the
   no-new-delta baselines they actually cover. The plan's §5 wording is compatible with
   this, but the implementation report should show the direct matrix query. Owner:
   Database/Security + Backend; destination: implementation evidence. Low risk.
3. **Approved internal columns.** §3 names the DTO projections but not every internal key
   the reader needs (`catalog_version.product_id` for phase-two grouping/order,
   `catalog_benefit_line.catalog_version_id`, benefit `id`, and `product_family` for the
   product summary). These are implied by the frozen DTO/SQL design and should be pinned in
   `assertsApprovedProjection`/`rejectsUnapprovedTablesAndColumns`. Owner: Catalog-order
   owner + Backend; destination: §5 boundary-test implementation. Low risk.
4. **`rejectsMalformedFacts` reachable inconsistency.** V004's checks make most persisted
   inconsistencies unrepresentable; the reachable DB-legal/API-invalid fact is a non-CNY
   `currency` (plus timestamp precision/listener-injected failures). The IT method is
   satisfiable, but it may overlap `rejectsNonCnyCurrency`; the implementation should either
   use a distinct execute-listener failure path or record the intentional overlap. Owner:
   Backend/CI; destination: implementation evidence. Low risk.
