## Findings

### PA38-CODE-A-01 — Medium (non-blocking; test-evidence gap, not a production defect)

The Outbox tests do not assert the exact per-argument **payload values** required by §8.2/§9.3. `outboxArguments()` verifies the SQL literals `'OPERATIONS'`, `'CATALOG_VERSION'`, `NULL`, a 5-bind count, payload-hash self-consistency and a six-field payload (`OperationsCatalogVersionLifecycleIT.java:31-35`). `publicationOutboxArgumentsAreExact` checks only the first Outbox's dedupe/aggregate-id/event (`:34`), and the retirement branch only event order (`:35`). There is no assertion that the candidate/retirement payload's `catalogVersionId`, `productId`, `versionNo`, `saleStatus`, `publishedAt` and `snapshotSha256` equal the corresponding post-transition row, nor that both Outboxes carry the right dedupe/aggregate-id, nor that the ciphertext bind is the exact 7th argument. A semantically wrong payload that is internally self-hashed would pass these assertions. The production builder currently passes the correct status, preserved/decision timestamps and row IDs (`CatalogSaleLifecycleSemantics.java:24-26`; `JooqCatalogSaleLifecycleRepository.java:134-139,184-188`), so this is an acceptance-evidence weakness, not an observed wrong behavior. Recommendation: harden the identity tests with per-branch exact six-field payload assertions and both Outboxes' dedupe/aggregate-id/event/NULL position; this does not require a product-code change.

### PA38-CODE-A-02 — Low (test false-green)

`OperationsCatalogVersionConfigurationTests.defaultRuntimeHasNoWriteBeans` registers only `OperationsSubjectReadPersistenceConfiguration` with no `onecall.operations-subject-read.enabled` property (`:54-58`) and checks the two catalog beans are absent. It never registers/loads `CatalogSaleLifecycleConfiguration`, so it would still pass if that command configuration lost its `@Profile("persistence")`/`@ConditionalOnProperty` gating. The production annotations are correct (`CatalogSaleLifecycleConfiguration.java:12-16`), and runtime missing-provider is 503, but the named test does not prove the default-runtime property it claims. Recommendation: load the catalog configuration under missing profile/enablement and assert the command bean is absent.

### PA38-CODE-A-03 — Low (wire-format assertion is self-referential)

`successHasExactStateAndHeaders` compares the controller body to `mapper.valueToTree(expected)` using the **same** `JsonMapper` instance (`OperationsCatalogVersionWebTests.java:106-111`). It verifies the seven field names/values, status, headers and content length, but a change in the serialized `Instant` representation (e.g., a numeric epoch instead of the OpenAPI date-time string) would change both sides equally and still pass. The current Jackson-3 default is ISO-8601, and existing read DTOs use the same mapper, so no defect is observed; the test simply does not pin the wire format. Recommendation: assert the literal serialized `publishedAt` text or a canonical byte body for one success case.

### PA38-CODE-A-04 — Low (coverage gap in an existing subcase)

`adminPublishesWithoutPreviousActive` covers the zero-benefit publication and asserts the candidate `currentActiveVersionId` (`:18`), but its existing-benefit subcase (`:19`) asserts only content preservation/fact counts, not that the response returns the candidate ACTIVE ID, although §9.3 requires both subcases to do so. Recommendation: add the same candidate-ID assertion to the benefit subcase.

### PA38-CODE-A-05 — Low (test robustness / possible false-red)

The real 55P03 subcase holds the advisory lock and detects the waiting command by polling `pg_stat_activity` while `lock_timeout` is 250 ms (`OperationsCatalogVersionLifecycleIT.java:69-72`; limit at `Jooq…Repository.java:39`). On a slow host the wait can end before the observation, leaving `waiting == false` and failing the test even though the product behavior is correct. Recommendation: make the wait observable deterministically (latch/listener or an observed wait state before releasing), or use a test-scoped longer lock timeout; keep the product 250 ms limit unchanged.
