## 4. Material findings

### 1-Unfixed-[Low]-Docker raw-exit capture is unreachable under set -e, so the canonical preflight cannot record failing Client or Server exits

- **Location:** Plan section 11.0 (lines 592-619) and section 13; fix7 section 4.
- **Problem type:** Validation/evidence gap; false evidence risk.
- **Current writing:** The block uses `PA38_DOCKER_CLIENT="$(docker version --format "{{.Client.Version}}")"`, then `printf ... "$?"`, then the Server command, then `docker info`, under `set -euo pipefail`.
- **Counterexample:** On the recorded host the daemon is unreachable and the Client command exits 1. The assignment status is 1, so Bash exits immediately; the `printf` and the Server and `docker info` checks never run. The block produces no separate raw exit for the failing command and no server-specific observation. An agent that records `29.1.3` from the client banner can then mislabel it as server evidence.
- **Why problematic:** RR6-02 requires the Client version, the Server version and each raw exit to be recorded separately. The only executable preflight cannot produce that evidence on the failure path, even though fix7 obtained it with separate commands.
- **Direct evidence:** Fix7 section 4 records Client exit 1, Server exit 1 and `docker info` exit 1 with `permission denied` at `/var/run/docker.sock`; the plan block lines 608-617 place `printf ... "$?"` after the assignments.
- **Impact:** Environment-stop evidence can be incomplete or misattributed; acceptance report may claim a client-only version as server proof. No false green is possible on the success path because the nonempty-Server and `docker info` exit checks are real.
- **Suggested fix and verification point:** Capture each command with `if output=$(...); then rc=0; else rc=$?; fi` while keeping `set -euo pipefail`, or make three separate diagnostic commands the authoritative preflight. Print `rc`, the full output, and the Client and Server lines distinctly; require nonempty Server and `docker info` exit 0. Verify on a daemon-reachable host and on the recorded denied host.
- **Fix risk:** Low.
- **Severity:** Low.
