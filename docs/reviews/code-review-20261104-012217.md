# Code Review — PA13 Sharing Role Least Privilege Re-Review 2 B

## Findings

- Verdict: `fail`. Two direct material findings remain after code-fix-2.

### F-01 — Stale sharing-role membership permits owner escalation

- Severity: High.
- V010 rejects incompatible memberships only when the command role is involved (`backend/src/main/resources/db/migration/V010__sharing_role_least_privilege.sql:29`, `:154`). It does not reject a state where `sharing_role` is already a member of another role.
- An administrator can seed `GRANT sharing_owner TO sharing_role` or `GRANT evidence_owner TO sharing_role` after V009. V010 then succeeds, and a legitimate `query_login -> sharing_role` membership gains an effective path to that owner role. This defeats the query-role least-privilege boundary even though the command-role path remains blocked.
- The rollback/replay tests exercise stale command-role membership and `BYPASSRLS`, but do not seed a stale `sharing_role -> owner` edge (`backend/src/test/java/com/onecall/archtests/container/SharingRoleLeastPrivilegeIT.java:185`).
- Required correction: V010 must deterministically fail for any direct or transitive membership where `sharing_role` is the member, in addition to all command-role paths. Add replay coverage that proves such a stale edge fails, leaves V010 absent, and restores the membership/attribute/catalog snapshot.

### F-02 — Sequence ACL reset and PUBLIC/grantor checks are incomplete

- Severity: Medium.
- The V010 reset query excludes `relkind = 'S'` (`backend/src/main/resources/db/migration/V010__sharing_role_least_privilege.sql:56`), so sequence ACLs are not reset with relations. The later PUBLIC checks also exclude sequences (`backend/src/main/resources/db/migration/V010__sharing_role_least_privilege.sql:168`).
- V010 checks only `sharing_role` and `sharing_command_role` sequence privileges (`backend/src/main/resources/db/migration/V010__sharing_role_least_privilege.sql:172`). It does not reject PUBLIC sequence grants or verify sequence grantor/grantability.
- No V001–V009 object is currently a sequence, so the emitted green tests can pass vacuously for this dimension. That does not satisfy the required complete reset/check scope for relations and sequences across all nine bounded schemas, nor protect a replay after future sequence provisioning.
- Required correction: include sequences in the bounded reset and postcondition scope, including role-effective denials, PUBLIC absence, owner grantors, and no grant options.
