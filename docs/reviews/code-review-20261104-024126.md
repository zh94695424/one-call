- **文件(行号)**: `docs/14-production-data-model-and-flyway-schema-spec.md:4037`；对照 `:2338`、`:2372`、`:3990` 和 `backend/src/main/resources/db/migration/V010__sharing_role_least_privilege.sql:98`、`:100`、`:101`、`:105`、`:107`。
- **输入场景**: 后续开发者需要判断当前 `sharing_role` 是否可以写 `sharing.share_admission` / `sharing.share_access_event`，或需要从 §10.21 推导查询角色与命令角色边界时。
- **实际分支**: §10.21 的说明只把其下方的矩阵表限定为 frozen V008/V009；`:4037` 是表外正文，没有历史限定，并以现在时无条件声明 `sharing_role` 在 admissions/access events 上拥有 `INSERT`。
- **预期行为**: 当前 post-V010 契约应是：`sharing_role` 对三张 sharing 表没有 table-level privilege，只拥有 13 列查询 `SELECT`；`sharing_command_role` 才拥有表的 `SELECT, INSERT` 和有限 grant `UPDATE`，且该角色未接线。
- **实际行为**: 文档仍在当前权限说明中断言查询角色拥有 admissions/access events 的 `INSERT`，与 V010、同文件新增的 V010 boundary 段落以及 §10.21 已限定的当前汇总文字相互矛盾。
