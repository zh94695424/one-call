## Residual Risk

- **Evidence not independently verified**: XML/CI/container/JAR claims rest on the S1 reports; source, CI script, POM includes, ACL literals, test counts (12/8/8/4 + 18/8) and frozen hashes are consistent with the plan, but green execution is unverified here.
- **Qualified DSL bean inversion / hidden coupling (accepted)**: `CustomerPersistenceConfiguration.customerBusinessNumberQueryService` resolves bean names `customerBusinessNumberReader`/`customerActivationStatusReader` owned by `subject_number`/`activation_consent`; renaming or removing those beans in their owner modules fails only at lazy runtime (endpoint 503), not at compile time. The plan records this as an accepted post-PA27 follow-up; same-connection/snapshot behavior is covered by the latch IT.
- **Tenant isolation is application-level, not RLS (accepted)**: `customer_iam_role` has column grants, not row-level security; a compromised LC login can read approved columns across rows. The plan explicitly excludes RLS redesign.
- **Cursor key is a mandatory external operational dependency (accepted)**: no production key is assigned; all replicas must share one key; replacement invalidates existing cursors with `CURSOR_INVALID`; distribution/rotation/custody remain Security/Operations work.
- **Snapshot semantics (accepted)**: single-request REPEATABLE READ only; no cross-page snapshot or linearizable revocation; a lifecycle change committed after snapshot creation applies on the next request.
- **Performance (accepted)**: `ORDER BY s.created_at DESC, b.id ASC` may sort large owned sets; existing owner indexes help the predicate but no EXPLAIN was measured and no index was added.
- **Observability**: sanitized failures carry only code/traceId; no failure-category logging exists, consistent with the existing customer boundary but limiting diagnosis.
- **Public `Scope` seam convention**: `Scope(accountId, organizationId)` does not itself forbid `organizationId=null` for an organization workspace (personal/org selection is inferred from null in `JooqCustomerBusinessNumberReader`); only `CustomerBusinessNumberQueryService.requireScope` enforces the invariant today. Any future caller of the public named interface must preserve it.
