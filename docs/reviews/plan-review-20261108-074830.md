## Findings

### RR2-01-未修复-高-V013 exact `pg_shdepend` predicate omits the schema-USAGE `pg_namespace` ACL dependency that V013's own required grant creates, so replay/precondition rejects the correct expected state

- **位置**: Plan line 58 ("Exact dependency predicate: `pg_shdepend` … permits `deptype='a'` only for `pg_class` dependencies on the four listed tables …"; "before grants, permit none"; "Reject … every unexpected ACL item"), read with line 35/38 (`GRANT USAGE ON SCHEMA evidence …` under `SET LOCAL ROLE evidence_owner`), matrix line 51 (Schema row: `USAGE` on `evidence` required), line 31 ("Permit only exact expected ACL state or no ACLs for replay"), and line 45. Fix source: `pa19a-sharing-evidence-media-read-acl-plan-fix-2.md` RR1-02 bullet ("only expected ACL dependencies for the four granted tables").
- **问题类型**: 状态机漏洞 / 契约缺失 / 不可直接实施（fix 自身引入的错误 exact predicate；与 V013 自己的 grants 矛盾）。
- **当前写法**: The exact dependency predicate permits `deptype='a'` **only** for `pg_class` dependencies on the four listed tables; everything else is "unexpected". The plan never permits any `pg_namespace` dependency row, although the same plan unconditionally grants schema `USAGE` and requires it in the matrix.
- **反例/失败场景**: On PostgreSQL 16.15, executing exactly the plan's grant set (one `GRANT USAGE ON SCHEMA evidence` + fifteen column `SELECT` grants as `evidence_owner`) produces **16** `pg_shdepend` rows for `evidence_media_reader_role` with `deptype='a'`: 15 rows with `classid='pg_class'` (one per granted column, `objsubid` = attnum) **and 1 row with `classid='pg_namespace'`** (the schema-USAGE dependency). A fresh role pre-grant has 0 rows (so "before grants, permit none" holds). Under the plan's literal permit clause, the `pg_namespace` row is not permitted → "reject … every unexpected ACL item" fires. Therefore: (a) the mandated double-execution replay on a fully migrated fixture fails at the first precondition check (role + exact grants already present → 16 rows → 1 rejected), so "both succeed, then `flyway.migrate()` executes zero migrations" is unreachable; (b) the postcondition after the grant transaction also fails; (c) an implementer who instead filters the query to `classid='pg_class'` silently ignores one of the sixteen expected rows, contradicting line 31 ("permit only exact expected ACL state") and the accepted requirement that the fix "allow only those expected ACL rows" (Control line 54), which by RR1-A's own evidence are all 16 ("1 `pg_namespace`, 15 `pg_class`"). The plan forbids resolving the conflict by invention (line 45 "Do not repair unexpected ACL state"; line 123 stop condition).
- **为什么有问题**: RR1-02's accepted fix obligation was to permit **all** `deptype='a'` rows created by the plan's own expected grants and reject only memberships/settings/ownership/non-ACL/unexpected grants. The corrected predicate is explicit but wrong: it counts only the four tables and forgets that a schema grant necessarily creates a `pg_namespace` ACL dependency. This is the same failure class RR1-02 was raised for (precondition defeats the role's own correct state), now baked into an "exact" predicate — deterministic, not ambiguous.
- **直接证据**:
  - Plan line 58 verbatim permit clause (pg_class-only); line 38 grants schema USAGE; matrix line 51 requires USAGE true; line 31 requires permitting the exact expected ACL state.
  - Empirical PG 16.15 (exact V013 grant set, grantor `evidence_owner`): `classid` breakdown `pg_class=15`, `pg_namespace=1`, all `deptype='a'`, grantee `pg_authid` row for the reader role; fresh pre-grant role rows = 0; `aclexplode` counts nspacl=1, relacl=0, attacl=15.
  - RR1 A artifact `plan-review-20261108-070404.md` F-2 evidence: "16 `pg_shdepend` rows with `deptype='a'` (1 `pg_namespace`, 15 `pg_class`)" and its prescribed fix "permit the plan's own `deptype='a'` ACL rows".
  - Control line 54: "The fix must allow only those expected ACL rows … the exact catalog predicate and replay assertion must be explicit."
  - Fix-2 artifact RR1-02 bullet itself scopes expectations to "the four granted tables" — confirming the omission, not a deliberate filter design.
- **影响**: Implementation agent following the plan exactly writes a V013 whose precondition/postcondition and mandated replay test fail on the correct state → V013 cannot apply or verify → plan is not code-generation-ready for the migration slice; RR1-02 closure is false; work returns to another fix/re-review cycle.
- **建议改法和验证点**: Amend the line-58 predicate so the permitted `pg_shdepend` set is exactly: (i) `deptype='a'`, `classid='pg_class'`, `objid` in the four listed tables, per-column expanded ACL item equals expected grantor (`evidence_owner`)/grantee (`evidence_media_reader_role`)/`SELECT` with `is_grantable=false`; **plus (ii) `deptype='a'`, `classid='pg_namespace'`, `objid` = schema `evidence`, ACL item equals expected grantor/grantee/`USAGE` with `is_grantable=false`**; zero rows before grants; reject every other row (`deptype<>'a'`, any other classid/objid, any unexpected ACL item), memberships (`pg_auth_members`), `pg_db_role_setting`, and unexpected `relacl`/`attacl`/`nspacl` items. Verification point: on a fully migrated fixture with V013 applied, `SELECT classid,deptype,count(*) … GROUP BY 1,2` for the reader role returns exactly `pg_class/a/15` + `pg_namespace/a/1`; the double-execution replay then succeeds and `flyway.migrate().migrationsExecuted == 0`; pre-grant role returns 0 rows.
- **修复风险（低）**: Low — bounded predicate-text edit in one paragraph; no grants, columns, query, allowlist, arithmetic, or goal change.
- **严重程度（高）**: High — deterministically defeats the plan's own mandated replay/precondition test on the correct state; same impact class as PR-01; blocks code-generation handoff of the V013 slice.
