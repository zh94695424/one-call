## 3. Findings

No Critical / High / Medium / Low material finding was established against the allowlisted candidate changes. Evidence by area:

### 3.1 Strict JSON bundle (`MediaPlaybackKeyBundleParser`)

- Byte bound `MAX_SOURCE_BYTES = 65_536`; UTF-8 REPORT decoder; BOM rejected; trailing tokens fail; nesting depth bound 8.
- Closed root `{schemaVersion, keys}` and entry `{kid, role, keyHex}`; unknown / missing / duplicate fields rejected (including unicode-escaped duplicate keys).
- `schemaVersion` must be integral `1`; exactly one `ACTIVE`; `VERIFY_ONLY` sorted by ASCII kid; duplicate kids rejected even when hex material differs or kid is unicode-equivalent (`K1` vs `K1`).
- `kid` regex `[A-Za-z0-9_-]{1,32}`; `keyHex` lowercase `[0-9a-f]{64}` → 32-byte material (no base64 / uppercase / `0x` / colon forms).
- Roles limited to `ACTIVE` / `VERIFY_ONLY`; `DISABLED` / `DESTROYED` / `EXPIRED` / deferred roles → `Result.Unavailable`.
- Parse failures (`CharacterCodingException | RuntimeException`) → `Unavailable`; successful results copy material and zero input buffers; `toString` / `@JsonValue` redacted.
- Tests: `MediaPlaybackKeyBundleParserTests` — **12** methods, matching plan/CI `pa22_additions`.

### 3.2 File adapter (`FileMediaPlaybackSigningKeyProvider`)

- Constructor rejects null / blank / non-absolute / non-normalized / NUL / URI paths; no fallback search locations.
- Per call: `readAttributes(..., NOFOLLOW_LINKS)` on root and path components; must be regular file; size in `1..65536`; channel open with READ + NOFOLLOW; before/after fileKey + mtime consistency; short-read and oversize → `Unavailable`.
- No cross-call cache: every `currentKeys()` rereads; removal / corruption immediately fail closed; snapshots are independent and immutable (`List.copyOf`, material clones).
- IO / permission / security failures → `Unavailable` without logging path, material, or exception messages.
- Tests: `FileMediaPlaybackSigningKeyProviderTests` — **10** methods; race/short-content covered via `mockStatic(Files.class)` attribute-swap; redaction canaries asserted against `CapturedOutput` + Jackson render.

### 3.3 Spring wiring (`MediaPlaybackKeySourceConfiguration` + authority)

- `@ConditionalOnProperty(... provider=file, matchIfMissing = false)` — file provider only when explicitly selected; missing path property → null path → provider `Unavailable` (Environment `RuntimeException` also mapped to null).
- `MediaPlaybackCredentialAuthority.snapshot()` uses `keys.stream().limit(2)` and rejects `size != 1` **before** any `currentKeys()` call (ambiguity-before-read).
- `issueOrReplay` / `verify` take a full snapshot **before** decoding or token parse (snapshot-before-token); missing anchor kid on replay → `Unavailable`; codec missing kid on verify → exception → `Invalid`.
- Fresh issuance selects **only** `Role.ACTIVE`; anchor replay uses recorded kid; recorded-key removal → `Unavailable` (never mints a replacement under a new kid).
- PA21 authority remains the sole issuer/verifier; no second registry introduced. Configuration tests assert zero/one/many cardinality and order-independent ambiguity.
- Tests: `MediaPlaybackConfigurationTests` — **13** total (**9** existing + **4** new: `fileSourceRequiresExplicitSelectionAndPath`, `fileSourceSharesOneAuthorityAcrossProfiles`, `fileSourceAndCustomProviderAreAmbiguousInEitherOrder`, `unsupportedSourceAndInvalidFileKeepUnavailable`).
