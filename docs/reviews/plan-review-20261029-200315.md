2. **The revised V004 sequence is lifecycle-executable.** Plan `§7.1` now requires target `004`, immediate invocation of a dedicated transactional helper, successful orphan-consent order insertion, whole-transaction rollback, explicit absence verification for the order and every probe parent, immutable evidence return, exactly-once static assignment, and fail-fast propagation before target `005`, target `006` and latest/V007 (`plan.md:440-450`). 3. **Transaction boundaries do not leave a committed orphan.** The helper is required to begin one transaction, create only method-local V004 parents, execute the valid order insert, roll back the whole transaction, and verify all generated IDs are absent before migration advances (`plan.md:445`). That prevents the staged proof from blocking V007's validating late FK. The plan expressly prohibits a committed orphan, disabled FK, second container or downgrade (`plan.md:455`).
4. **Evidence visibility and failure semantics are explicit.** The returned evidence value contains generated IDs plus `insertSucceeded` and `rollbackVerified`; setup assigns it once to a private static field and never mutates it. SQL, assertion and runtime failures must be rethrown, and setup may not catch-and-continue or migrate further without a successfully returned and assigned value (`plan.md:445-448`). The later test reads the captured value instead of rerunning the V004 insert (`plan.md:454-455`, `plan.md:470`).
