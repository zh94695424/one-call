## Findings

### 01-未修复-[高]-The admission implementation cannot read the exact capability-token UTF-8 bytes, and the only accessor is package-private in a non-allowlisted file

- **位置**: Plan §2.1 line 20 (hash the exact supplied UTF-8 bytes with the existing `Sha256Provider`); §4 line 95 and item 159 (fixed `admit(OpaqueCapabilityToken, ShareAdmissionRequest, Optional<TrustedShareAdmissionCaller>)`); item 13/allowlist items 5–20 (`DefaultShareAdmissionService` in `sharing/internal/admission`); plan line 165 (no existing public-GET implementation path is writable).
- **问题类型**: 不可直接实施 / 架构边界 / 契约缺失
- **当前写法**: The service receives `OpaqueCapabilityToken` and must hash its exact UTF-8 bytes to query `sharing.evidence_share_grant.capability_token_hash`. The type is `sharing.internal.publicquery.OpaqueCapabilityToken`; its only byte accessor is package-private `byte[] utf8()`; `toString()` is `[REDACTED]`. The new implementation package is the sibling `com.onecall.core.sharing.internal.admission`.
- **反例/失败场景**: Java package-private access is limited to the exact package. `DefaultShareAdmissionService`/`JooqShareAdmissionRepository` in `internal.admission` cannot call `token.utf8()`, and `PublicShareQueryService.digest(...)` is private (`PublicShareQueryService.java:202–204`). The controller is in `customer_iam.internal.web`, also outside `publicquery`, and cannot obtain the bytes either. The plan's allowlist contains no `backend/src/main/java/com/onecall/core/sharing/internal/publicquery/OpaqueCapabilityToken.java` entry, and line 165 forbids writing existing public-GET implementation paths. The implementation therefore cannot compile the required digest lookup without a forbidden edit or an unplanned reflection/accessor workaround.
- **为什么有问题**: The token digest is the sole lookup key for the endpoint (`capability_token_hash`); the plan freezes the service signature to accept `OpaqueCapabilityToken` and freezes the allowlist to exclude the token class. The architectural split moved the implementation one package away from the only byte accessor without providing a public sharing-owned digest seam.
- **直接证据**: `OpaqueCapabilityToken.java:5,17,20` (`public final class`, package-private `byte[] utf8()`, redacted `toString()`); `PublicShareQueryService.java:202–204` (private digest only); plan lines 20, 95, 159, 165; allowlist items 5–20 contain no `publicquery` change.
- **影响**: Implementation gate cannot compile/execute the core token-resolution path within its own allowlist; likely forbidden source edit, reflection hack, or mid-slice redesign; all `PublicShareAdmissionIT` token/digest methods are blocked.
- **建议改法和验证点**: Either (a) add the existing `publicquery/OpaqueCapabilityToken.java` to the allowlist with a minimal public exact-bytes accessor or a public digest seam (and update the 35-path count, RF-01/RF-02 file sets, and architecture assertions), or (b) change the fixed service/API contract to accept the validated raw token text or a new sharing-owned opaque token value whose exact bytes are available to the implementation, while preserving 1–512/no-NUL/UTF-8 validation and redaction. Verify the token digest equals the existing public-GET digest for the same token, no raw token/digest leaves the service, and `SharingQueryBoundaryTests`/`CustomerApiBoundaryTests` still pass.
- **修复风险（中）**: Touches a PA15 file or the public service signature; must preserve existing GET behavior and exact architecture imports.
- **严重程度（高）**: Deterministic compile/integration blocker under the closed allowlist.

### 02-未修复-[中]-The admission persistence configuration omits the SHA-256 provider bean it requires, and the only production bean is command-gated

- **位置**: Plan §2.1 line 20 (existing `Sha256Provider`); §4 line 105 (exact admission-config bean list); §3 line 70 (admission pool independent of creator-command pool).
- **问题类型**: 架构边界 / 不可直接实施 / 契约缺失
- **当前写法**: The admission config is gated by `@Profile("persistence")` plus `onecall.sharing-admission.datasource.enabled=true` and is listed with exactly `sharingAdmissionDataSource`, `sharingAdmissionTransactionManager`, `sharingAdmissionTransactionTemplate`, `sharingAdmissionDsl`, `shareAdmissionRepository`, `shareAdmissionService`, plus the five unavailable provider beans. No `Sha256Provider` bean is listed. The only production `sha256Provider` bean is in `SharingCommandPersistenceConfiguration`, whose class is gated by `onecall.sharing-command.enabled=true` (`SharingCommandPersistenceConfiguration.java:41–42,131–137`).
- **反例/失败场景**: With `onecall.sharing-admission.datasource.enabled=true` and `onecall.sharing-command.enabled` absent/false (the plan's "independent" and "absence of command/public-read fallback" framing), the admission service bean has no `Sha256Provider` to inject; context creation fails or the implementation must add an unlisted bean. If the agent instead relies on the command config, admission availability is silently coupled to command enablement, contradicting the independent-configuration claim.
- **为什么有问题**: The service needs SHA-256 for the token digest, admission key, and every deterministic event fingerprint. The plan's exact bean list and independence statement do not define where that implementation comes from.
- **直接证据**: Plan lines 20, 70, 105; `SharingCommandPersistenceConfiguration.java:41–42` (`@Profile("persistence")` + `@ConditionalOnProperty(prefix="onecall.sharing-command", name="enabled", havingValue="true")`) and `:131–137` (only `sha256Provider` bean); no `Sha256Provider` bean in `SharingPersistenceConfiguration.java` or `PublicSharePersistenceConfiguration.java`.
- **影响**: Admission-only persistence context startup failure or hidden command-config coupling; the `policyAndProviderAbsenceFailClosedWithoutWrites` "absence of command fallback" claim is not fully specified.
- **建议改法和验证点**: Define a conditional `Sha256Provider` bean in `ShareAdmissionPersistenceConfiguration` (allowlisted) using the same deterministic digest behavior, or explicitly require the command configuration and test that dependency. Add a context/wiring assertion for admission-enabled-without-command and for the provider seam.
- **修复风险（低）**: Config-only, allowlisted file.
- **严重程度（中）**: Deterministic production-wiring risk; may be masked if tests enable both configs.
