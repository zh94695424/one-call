#### F-S3-R1-02

| 字段 | 值 |

| **Verification** | 见下 |

**修复核验（direct evidence）**

1. **正向 PUT 要求**：`security/validate.mjs:2098-2099`：
   ```js
   const forbiddenOperation = request.method !== 'PUT'
     || ['READ', 'LIST', 'DELETE'].includes(request.operation);
   ```
   `undefined !== 'PUT'` 为真 → 缺省 method 一律进入 `:2100-2114` 的 `403 FORBIDDEN / WRITE_SCOPE_VIOLATION` 分支。
2. **门在 scope/expiry/size 之前**：method gate（`:2098-2115`）→ scope（`:2116-2124`）→ expiry（`:2125-2129`）→ oversize（`:2130-2134`）→ accept（`:2135-2147`）。缺省 method 在任何 scope/expiry/size 接受前被拒。
3. **显式 PUT 保留**：`use-put-within-scope`（method+operation 均 PUT）仍走 accept，返回 `acceptedUpload:true`、`acceptedOperations:['PUT']`、`deniedOperations:['READ','LIST','DELETE']`。
4. **既有 codes/audit/副作用保持**：拒绝路径仍返回 `SECURITY_UPLOAD_CREDENTIAL_DENIED` security/audit event、`acceptedUpload:false`、`sideEffectsZero()`（经 `common` 展开）；`state.uploadDenied += 1` 与 `state.auditFactsAppended += 1` 与其它 deny 路径一致。READ/LIST/DELETE operation 检查保留为 defense-in-depth。
5. **fixture 抓住旧错误实现**：`sec-s3-01` 新步骤 `use-missing-method-denied`（`:112-135`）在 scope/expiry/size 全匹配时省略 `method` 与 `operation`，期望 `DENIED/403/FORBIDDEN/WRITE_SCOPE_VIOLATION`。旧实现会因缺省 method 兼容而 `UPLOAD_ACCEPTED` → fixture 失败。步骤插在 `use-put-within-scope` 之后，此时 `state.upload` 已存在，命中的是 method gate 而非 `NO_CREDENTIAL`。
6. **计数**：`uploadDenied` 由 5→6（assert `:306`）。推演：CV4 deny + missing-method + read + cross-object + expired + oversize = 6；`uploadIssued` 仍为 1。

**结论**：`F-S3-R1-02` **`已修复`**。缺省/非 PUT 在 scope 接受前被拒；显式 PUT 与既有拒绝码/审计/副作用保持；fixture 区分旧实现。
