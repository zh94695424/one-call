### 1-未修复-[低]-端口拒绝归类过宽：`execute` 将任意 `IllegalArgumentException` 一律映射为 503

- **入口/函数**: `DefaultOperationsOrderReadService.execute(Caller, LongFunction)` 异常分类链
- **文件(行号)**: `backend/src/main/java/com/onecall/core/operations_iam/internal/orderread/DefaultOperationsOrderReadService.java:145-156`
  （判定位于 `:152`，`throw new Failure(Code.SERVICE_UNAVAILABLE)` 位于 `:153`）
- **输入场景**: 今日仅 owner 端口按契约拒绝时可达（`JooqOperationsOrderReader.java:46`
  `"Invalid order query"`、`:62` `"Missing order identity"`、
  `JooqOperationsOrderIssuanceReader.java:32` `"Invalid order batch"`）。后续任何进入
  `list`/`detail` 调用链的代码或第三方库（jOOQ/Spring/Driver/JDK）抛出
  `IllegalArgumentException`（含 `NumberFormatException`、`PatternSyntaxException` 等子类），
  或在任意 `Failure` 之外把它作为 cause 包装抛出，都会走到同一分支。
- **实际分支**: 因果链上出现**任何** `IllegalArgumentException` 即
  `throw new Failure(Code.SERVICE_UNAVAILABLE)`，先于 `:155` 的已知 `Failure` 透传之后的
  `:156` `Code.INTERNAL` 兜底。该规则是全局的，而非 B F3 所要求的“端口拒绝”局部归类。
- **预期行为**: 只有 owner 端口对契约域的拒绝应映射为 503；请求路径上真正的程序缺陷应保持
  500 `INTERNAL`，以便与依赖不可用在运维信号上区分。既有同层实现
  `DefaultOperationsSubjectReadService.java:168-171` 只把
  `DataAccessException | org.springframework.dao.DataAccessException | TransactionException | BeansException`
  归为 unavailable，**不**把 `IllegalArgumentException` 归为 503。
- **实际行为**: 本 change 在 PA43 服务里新增了 sibling 不具备的 IAE→503 规则；异常对象本身被丢弃
  （`Failure` 以 `super("Operations read failed", null, false, false)` 构造，见
  `OperationsSubjectReadService.java:59-61`），既不记录也不保留 cause，503 对外不含真实原因。
- **直接证据**: `:152` 的 `|| cause instanceof IllegalArgumentException` 与 `:147` 的整链遍历
  （遍历对象是整个 `transaction.execute` 闭包，而不是端口调用）；对照
  `backend/src/main/java/com/onecall/core/operations_iam/internal/subjectread/DefaultOperationsSubjectReadService.java:168-171`；
  `grep -rn 'IllegalArgumentException' backend/src/main/java/com/onecall/core/operations_iam`
  显示除端口守卫外，PA43 自身的 IAE 源均已在局部被吞掉并显式归类
  （`OperationsOrderCursorCodec.java:35,49,88-89`、`OperationsOrderReadRequest.java:99`、
  `DefaultOperationsOrderReadService.java:172,200`），即该规则**当前**只为端口拒绝服务，
  其余命中面是不可达的未来/库内异常。
- **影响**: 不改变今日任何可观测行为（既有 422/400/401/403/409/500/503 期望全部由无 cause 的
  `Failure` 产生，`Failure` 为 `final` 且 cause 恒为 `null`，故 `:147-154` 的链遍历不可能命中
  已知 `Failure`，`:155` 优先透传仍成立）。风险是错误语义归属漂移：一个真实代码缺陷会呈现为
  “依赖不可用”这一可重试状态，掩盖 500 告警面，且无任何日志指向原因。
- **建议改法和验证点**: 把端口拒绝显式化为契约拥有的异常类型（例如
  `OperationsOrderReadPorts.InvalidQueryException extends IllegalArgumentException`，仍由 owner 端口抛出），
  `:152` 只判该类型；或把 IAE 判定收窄到 `orders`/`issuances` 端口调用处。验证点：在
  `OperationsOrderReadServiceTests` 增加一例——非端口代码抛
  `new IllegalStateException(new IllegalArgumentException())` 仍得 `Code.INTERNAL`；端口拒绝仍得
  `Code.SERVICE_UNAVAILABLE`。属 Controller 可 `deferred-with-owner` 的健壮性项
  （Owner: Backend/Test Maintenance），不阻塞本切片。
- **修复风险（低/中/高）**: 低——单个异常类型 + 一处判定，不触及产品数据路径。
- **严重程度（低/中/高/严重）**: 低
