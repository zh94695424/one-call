## Findings

### 1-未修复-中-Live B/C evidence has no defined evidence-credential/session lifetime versus the B retention and retirement horizon; the C "still-time-valid old K1" check is unexecutable or ambiguous as written

- **位置**: Plan §4 "Preconditions and evidence custody" items 4–5; §4 checkable table B and C rows; §4 "Fleet sequencing and mixed-version safety" steps 1–5; §11 future S1 report/evidence requirements.
- **问题类型**: 状态机漏洞 / 验收证据契约缺失（凭据有效性与退役 horizon 未闭合）.
- **当前写法**:
  - Precondition 5 requires Security/Sharing to provide "the approved maximum outstanding credential/session/replay horizon and Q22 skew/propagation basis"; Operations records "last possible K1 issuance."
  - Step 4 says "Keep B until the approved overlap/replay/expiry horizon and all owners' retirement preconditions are satisfied."
  - Step 5 then switches the cohort to C and says "Retest old K1 Invalid/replay Unavailable and fresh K2 success in protected, still-time-valid acceptance fixtures; never extend an expired real credential to obtain evidence."
  - The B row expects old K1 exact replay "despite clock advance"; the C row expects old K1 Invalid verification and Unavailable replay with an otherwise valid K2 bundle.
  - The plan also states the fixed 60-second fixture window is test data and not production TTL/Q22 approval; Q22 remains unselected.
- **反例/失败场景**:
  - The last K1 credential is issued while A is serving, before the quiesced A→B cutover. If the team follows step 4 and keeps B until the *maximum outstanding/expiry horizon* has elapsed, every A-issued K1 credential is already expired when C is checked.
  - At B, if the quiesced stop/restart/drain exceeds the remaining validity of the captured K1 credential, `MediaPlaybackCredentialAuthority.issueOrReplay` reaches `MediaPlaybackCredentialCodec.valid(claim, now)` (`MediaPlaybackCredentialAuthority.java:55`) and returns `Malformed`, and `verify` returns `Invalid` (`:68-70`), not the required exact replay/Verified result. The operator sees a failed B check that is actually an expiry, or a "pass" that did not prove VERIFY_ONLY overlap.
  - At C, old K1 replay is `Unavailable` because `snapshot.get(anchor.kid())` is null (`:46-47`) *before* any validity check; old K1 verify is `Invalid` for either an absent kid or an expired claim. The C verify result therefore does not by itself separate key retirement from expiry, and the B exact-replay result requires an unexpired credential. The table's requirement to prove the transition with "still-time-valid acceptance fixtures" cannot be met by a normal A-issued K1 credential after the step-4 horizon.
  - The plan does not define a synthetic, separately authorized long-lived evidence credential, a separate non-serving acceptance cohort, or a procedure to issue a fresh K1 credential after A is stopped. "Still-time-valid acceptance fixtures" is therefore either impossible with real A-issued material or requires an unstated synthetic-credential mechanism that conflicts with "never extend an expired real credential" and with the unselected Q22 upper bound.
- **为什么有问题**:
  - The confirmed C success condition is old K1 verification `Invalid`, old K1 replay `Unavailable` **and** fresh K2 success as a key-retirement result, not an expiry/state result. The plan's own evidence contract requires separating key retirement from expiry/state denial, but its B-retention rule and C check are not jointly satisfiable for a normal A-issued credential.
  - This is not a code defect: the deterministic tests prove the authority behavior with controlled clocks (`MediaPlaybackTencentKeySourceIntegrationTests.java:74-83` uses `NOW.plusSeconds(1)`; `:85-95` uses `NOW` for C). It is a runbook/evidence-contract defect in the only future deliverable.
- **直接证据**:
  - Plan lines 80–81 (preconditions 4–5), 90–93 (B/C rows), 101–102 (B retention and C evidence).
  - `MediaPlaybackCredentialAuthority.java:46-47` (unknown recorded kid → `Unavailable`), `:55` (invalid/expired claim → `Malformed` on replay), `:62-72` (verify → `Invalid` on decode/validity failure).
  - `MediaPlaybackTencentKeySourceIntegrationTests.java:40-41` (`EXPIRY = NOW.plusSeconds(60)`), `:74-83` (replay only one second later), `:85-95` (C with no clock advance).
  - Plan §4 item 4 itself says the 60-second window is "test data, not production TTL/skew/propagation approval."
- **影响**:
  - The S1 implementation agent would write a runbook whose central retirement-evidence step cannot be executed with a still-valid A-issued K1 credential, or would write a false-pass procedure using an expired credential. Operators could retire early (risking in-flight sessions) or misclassify expiry as key retirement.
  - Live C acceptance evidence cannot prove the confirmed success signal; the Controller/Security reviewer may reject S1 or require rework after the runbook is written.
- **建议改法和验证点**:
  1. Add an explicit evidence-credential/session design before the A phase: define a synthetic acceptance admission/session/grant and credential with a recorded validity `E` such that the A→B cutover, B checks, B retention, B→C cutover and C checks all occur before `E`; `E` must be within the approved Q22/policy maximum. If the approved maximum is shorter than the required sequence, either use a separate non-serving acceptance cohort for C checks or state that live C old-key evidence is unattainable and use the deterministic C oracle with explicit Security/Sharing approval.
  2. Record `issuedAt`, `notBefore`, `expiresAt` and the current time at each B/C check; require `now < expiresAt` (with approved skew) and classify any expired/malformed replay or expired verify as **INVALID EVIDENCE**, not pass/fail. The S1 evidence template must include these booleans/timestamps.
  3. If a synthetic long-lived credential is used, define who constructs/issues it, how the same K1 kid/material continuity is preserved, how it is protected/redacted, and why it does not violate the Q22 upper bound. Do not extend an expired real credential.
  4. Update the B/C rows, steps 4–5 and §11's required evidence fields; add a precondition that the approved horizon is either longer than the full evidence sequence or the live C row is marked NOT EXECUTED/external.
  - Validation: the S1 document review must show the B/C evidence template contains the validity check and the classification rule; the existing deterministic tests already prove exact replay at `NOW+1` and C `Invalid`/`Unavailable`/fresh K2.
- **修复风险（低/中/高）**: 中（runbook text and external-input definition; no Java/test/POM/CI change; may require Security/Sharing to approve a synthetic acceptance fixture or mark live C unattainable).
- **严重程度（低/中/高/严重）**: 中.
