## Residual Risk

- Evidence provenance: the green 78/113/191 unified run, exact source=CI=XML inventory, packaged-JAR smokes and 82-probe firewall are controller-reported. This review did not rerun Maven/Docker, so those runtime claims remain evidence to be spot-verified by the gate owner rather than independently reproduced here.
- Layering coupling: `JooqSharingCommandRepository.findTransition` calls the application-layer static serializer `DefaultCustomerShareCommandService.canonical` to verify the stored payload hash (`JooqSharingCommandRepository.java:211-214`). Correctness is preserved (single canonicalization source), but this is a persistence→commandservice reverse dependency; a future move/rename or canonicalization change requires coordinated edits, and the canonical contract has no neutral owner. A shared internal canonical-hash collaborator (requiring bounded plan correction) would remove the coupling.
- Header-combination boundary: the servlet contract returns one value for a single comma-containing header and separate values for repeated headers; an intermediary proxy that coalesces duplicate `Idempotency-Key` lines into one comma value could turn a would-be duplicate (422) into a single opaque key. The plan classifies this as a web/gateway owner residual, not a defect in this slice (`CustomerBoundaryFilter.java:65-66`).
- Concurrency evidence is bounded: the IT covers two connections with identical/distinct keys and personal/organization lock ranks, but does not exercise lock-wait timeout, deadlock detection, event unique-constraint `23505` injection, or multi-replica/partition behavior. The one-winner argument also relies on the configured READ COMMITTED + row lock (verified by the unchanged `SharingCommandPersistenceConfigurationTests`), not on an explicit isolation assertion in the revoke IT itself.
- Replay projection intentionally uses the current locked grant's metadata plus the first event's status/generations; it is safe because V009 makes REVOKED terminal and immutable fields are guarded, but there is no independent test of a hostile/non-service writer racing the replay read.
- Web precedence coverage: header-vs-body failures both surface as 422, so their relative ordering is proven mainly by filter/controller code order and provider-resolution counters rather than distinguishable responses; no side effect distinguishes them beyond the inspected order.
- Out-of-scope product guarantees remain unproven by design: revoke does not recall already-issued short-lived credentials or buffered media, and gateway rate limiting is not enforced here.
