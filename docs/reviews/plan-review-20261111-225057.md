Non-finding implementation notes (not blockers; do not treat as findings):

1. **V016 ACL literal width.** V015's `old_acls`/`final_acls` literals are six-element arrays `(grantee,kind,object,column,privilege,grantor)`; `is_grantable=false` is synthesized during `expected_resolved` construction (V015 `:1118–1124`, PA25 `:2663–2669`). Plan §5.2 describes a seven-field tuple including `is_grantable`. This is functionally compatible because resolution reads indexes 0–5 and appends `false`, but the implementation should follow the existing six-field literal/index semantics (or otherwise prove the extra element is uniformly ignored) so `old_acls @> item`, set-equality and grant loops remain correct.
2. **404 handler return shape.** The accepted transport lets a `Detail`-returning handler return null only after `CustomerProblemWriter.notFound` has written the response. The new web/IT tests (§7.1 test 10, §7.2 tests 6/11, §7.5 test 8) must prove the writer's 404 status/body on a real context and that a null transaction/service result is 500, never 404.
