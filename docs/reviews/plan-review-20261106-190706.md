## 7. Findings

### PA17-RR5-A-01-未修复-[中]-Same-key replay/reconstruction does not explicitly bind the authenticated caller to the `ADMISSION_GRANTED` witness recipient

- **位置**: Plan §2.2 L35 (member predicates), §2.3 L44/L46 (replay/final recheck), §2.4 L56 (same-key reconstruction), §4 L131 (`AdmissionWitness` nullable original recipient IDs), §5 L281 (member/replay acceptance map).
- **问题类型**: 安全/授权契约缺失; 状态机与重放语义.
- **当前写法**: The final order's step 5 is "organization/member/account/tenant predicates (`SHARE_WRONG_TENANT` for mismatch, otherwise fail-closed membership/auth)"; §2.3 says "non-lockingly collect current member/risk facts" and "recheck ... organization/member/account/tenant"; §2.4 says reconstruction "re-reads the PostgreSQL witness". The plan never states the reference identity for the member/account comparison on the replay/reconstruction path. It only names `recipientAccountId`/`recipientOrganizationId` as fields of the durable `ADMISSION_GRANTED` witness.
- **反例/失败场景**: An `ORGANIZATION_MEMBER` admission is committed for recipient account A in organization O. A different account B, currently an `ACTIVE` member of the same organization O, submits the same capability token with the same `admissionRequestId` (for example, a replayed request observed on a shared device, or a client that reuses its stable request ID). Step 5's tenant/account predicate can pass on B's current membership in O; step 6 then replays A's witness and reissues the ticket. No admission is counted, so B obtains a media credential without consuming an admission and without being the recorded recipient.
- **为什么有问题**: docs/14 §9.31 item 3 requires reconstruction to "require the authenticated account to equal the witness `recipientAccountId`, the current active membership pair to equal `recipientOrganizationId`/`recipientAccountId`, ... and the grant `owner_organization_id` to equal the witness organization"; docs/14 §9.0.2 item 2 says the service must "re-authenticate the recipient bound in the original `ADMISSION_GRANTED` witness". The plan claims to follow the frozen S3 ordering but does not freeze this comparison. The existing tests `wrongTenantAccountOrMembershipFailsClosed` and `lostResponseRetryReconstructsWithoutSecondAdmission` can pass while only checking a wrong tenant, not a different same-tenant account.
- **直接证据**: Plan L35, L44, L46, L56, L131, L281; docs/14 `docs/14-production-data-model-and-flyway-schema-spec.md` lines 3412 and 3424 (§9.31 item 3); V009 `share_access_event` / `ck_share_access_event_admission_facts`; live `PublicSharesController`/`CustomerRequestPrincipal` supply only the authenticated caller, not a request-supplied identity.
- **影响**: Implementation Agent may omit the witness-recipient equality check; a same-tenant member different from the original recipient can replay an admission and receive a ticket without recounting, bypassing the per-recipient witness and the admission limit; acceptance may still pass because the existing method names do not distinguish wrong-tenant from wrong-recipient.
- **建议改法和验证点**: Add one sentence to §2.2 step 5 and both §2.3 replay branches and §2.4 reconstruction: for `ORGANIZATION_MEMBER`, require the trusted authenticated account to equal the witness `recipientAccountId`, the current active membership pair to equal `(recipientOrganizationId, recipientAccountId)`, and the grant `owner_organization_id` to equal the witness organization; any mismatch is `SHARE_WRONG_TENANT` or the approved fail-closed membership refusal. Extend the existing `wrongTenantAccountOrMembershipFailsClosed` and `lostResponseRetryReconstructsWithoutSecondAdmission` methods with a different-same-tenant-account replay case; no new method.
- **修复风险（低/中/高）**: 低.
- **严重程度（低/中/高/严重）**: 中.

1. **Manifest recipe / provenance (Controller-owned).** The declared manifest `0555EE9C169185C73A06B3691B04B31EC136F1EA4BA7B74D7469147B3871C186` was not reproduced from the 1,429-file snapshot under the recorded sorted `lowercase-sha  path` recipe, or under common `path  hash`, tab, NUL, `./`-prefix, or JSON variants (the recorded `sha  path` recipe recomputed to `72ED324EC17A1E80D27D47593C182FEC53F8BC1136179F41301D434365041E44` over 176,629 bytes; the exact file count, byte total and zero-private-path state match). This is a provenance/bookkeeping question, not a plan-content defect. Tracking: Controller freeze record.
2. **`share_access_event.result` column.** The plan freezes event identities/payloads but does not freeze the required `result` column value for `VERIFICATION_FAILED`, `EXPIRED`, `TICKET_ISSUED` and `TICKET_FAILED`. V009 requires one of `SUCCESS`/`DENIED`/`FAILED`/`IGNORED`. The existing convention writes `SUCCESS` for `ADMISSION_GRANTED` and command transitions. Freeze the per-event result (or state it derives from the typed outcome) so implementation and tests cannot choose different valid values.
3. **`TICKET_WINDOW_EXPIRED` HTTP mapping.** Plan §2.4 L54 says any post-commit ticket failure returns 503 and L55 lists `TICKET_WINDOW_EXPIRED` as a `TICKET_FAILED` reason; docs/14 §9.31 item 1 says a zero/negative Redis TTL fails closed with the existing `SHARE_SESSION_EXPIRED`/policy outcome. Clarify whether a post-commit non-positive window is 410 `SHARE_SESSION_EXPIRED` or 503 `DEPENDENCY_UNAVAILABLE`/policy, and pin it in the existing methods.
4. **§3 "each generation" wording.** Plan §3 L105 says expiry sets "status/each generation/revision to the exact `OLD + 1` values", while §2.3 L46 says code generation is unchanged and the V012 UPDATE grant excludes `code_generation`. The sentence should say `revocation_generation` only, otherwise an implementation agent could attempt a code-generation update that the ACL and V009 guard reject.
5. **Fix-5 byte-identity claim.** Fix-6 §9 L358 asserts sections 3 and 7–8 are byte-identical to the 339-line fix-5 plan, but that intermediate plan is not present in this snapshot. The migration hashes and contract text are consistent; the byte-identity claim is not independently reproducible here.
6. **Absent-session `ORGANIZATION_MEMBER` code.** The filter permits absent bearer to reach the controller; the service is to fail closed. The plan does not explicitly freeze whether a missing session is 401 `UNAUTHENTICATED` or 403 `FORBIDDEN`/membership refusal. The 18-code table defines code→status, not this scenario→code mapping.
7. **Test-double location.** The 37-path allowlist contains no separate test-double file, while §6 L299 requires deterministic policy/media/Redis adapters. State explicitly that those adapters are nested in the allowlisted 12/24 test classes (or name an allowlisted existing helper) so the implementation does not require an unlisted path.
