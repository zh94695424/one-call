### F-01 — Medium — 越权拒绝断言是空洞 oracle（`customerRoleCanReadOnlyApprovedColumns`）

- 位置 `backend/src/test/java/com/onecall/archtests/container/CustomerOrderReadPrivilegesIT.java:158`、`:159`、`:160`。

- 产品安全性已独立确认（不构成漏洞）：按官方文档 GRANT/“Granting Privileges”“Object Ownership”节，非属主只能转授其**以 WITH GRANT OPTION 持有**的权限，否则仅产生 WARNING 且不记录权限（no-op）；`customer_iam_role` 的 17 项授权均由属主授予且不带 grant option，V020 本身还显式拒绝任何 grant-option 状态（`backend/src/main/resources/db/migration/V020__customer_order_read_privileges.sql:2124`）。因此不存在提权路径，问题纯粹是该测试**没有证明它声称证明的东西**。
- 与已接受基线的差异：同类断言 `backend/src/test/java/com/onecall/archtests/container/CustomerCatalogOfferReadPrivilegesIT.java:391-393` 至少 `rollback(savepoint)` 并附带 `has_column_privilege('pa27_query', …) = f`；本轮新文件把它替换成“commit + 无效果断言”，方向上是退步。

### F-02 — Low — snapshot seam 的 catch-all 会把编码缺陷伪装成 404

- 位置 `backend/src/main/java/com/onecall/core/catalog_order/internal/customerorder/DefaultCustomerOrderSnapshotReader.java:19-21`：`catch (RuntimeException failure) { throw new InvalidSnapshotException(); }`。
- 影响：`storedSnapshot()`/`canonical()` 内任何非预期 `RuntimeException`（例如 `:186` 的 `ObjectNode` 强制转换、jOOQ/Jackson 内部错误）都会变成 `InvalidSnapshotException` → `CustomerOrderQueryService.java:96-100` 映射为 `Optional.empty()` → **404 NOT_FOUND**，而非 500 INTERNAL；缺陷被静默吞掉，排障时无日志/原因链保留（新异常不带 cause）。
