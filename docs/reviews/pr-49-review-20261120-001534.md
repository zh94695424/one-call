### Product behavior walked against the anchor's matrix

- **Routes and concealment.** The two POST templates are exactly `/api/v1/operations/catalog/versions/{versionId}/publications` and `.../offsales`; `OperationsBoundaryFilter` requires the exact method, `[^/;%]+` segment shape, and `contextPath + servletPath == requestURI` before authentication. Alternate methods, matrix/encoded separators, trailing/duplicate segments and context mismatches return sanitized `404 NOT_FOUND` before auth; the Customer filter's added early pass-through uses the same predicate and does not authenticate or wrap an admitted catalog request.
- **Precedence.** Order is: route admission → employee authentication (`401`/sanitized `503`) → one JSON `Content-Type` and acceptable `Accept` plus structural parse (`422`) → exactly-one command provider (`503`) → in-transaction authority (`ACTIVE + ADMIN` admits; `OPS`/`DISABLED` → `403`; missing/ambiguous/unavailable → `503`) → catalog state. The controller reads the body only after the caller check; the boundary filter never reads it. Tests `authenticationPrecedesStructuralParsing` and `structuralValidationPrecedesAuthorityWitness` pin the body-read counts and canaries.
- **Bounded body and strict parsing.** `readNBytes(8193)` with a hard `>8192 → 422`; malformed/overlong UTF-8 rejected with a reporting decoder; JSON mapper enables duplicate-field detection and trailing-token rejection; object shape is exact (`2` fields for publication, `1` for offsale); UUIDs must equal canonical lowercase `UUID.toString()`; revisions must be integral, `>=1`, and fit 31 bits. The binder suite covers unknown/duplicate/missing/trailing fields, quoted/fractional/exponent/overflow/zero/negative revisions and invalid UTF-8.
- **State matrix.** Publication P1–P8 and offsale O1–O6 map correctly onto `JooqCatalogSaleLifecycleRepository.transition`: target missing → `404`; malformed/duplicate/non-current ACTIVE → `503`; OFFSALE publish / DRAFT offsale → `409 CATALOG_PUBLICATION_CONFLICT`; expectation mismatch → `409 PUBLICATION_STALE_VIEW`; exact current-state replay → `200` with zero writes; real transitions update conditionally and require exactly one row. Pre-transition retries (old revision and/or old/null active witness) are stale, not replay; exact post-transition replays are zero-write.
- **Concurrency and recovery.** The product advisory lock serializes all lifecycle writes; retirement precedes activation so the immediate partial unique `uq_catalog_version_active` never sees two ACTIVE rows. Only SQLSTATE `23505`/`40001` trigger one fresh `REQUIRES_NEW`/`READ_COMMITTED` reread, which performs no authority call, advisory/write lock, mutation or fact append and returns `200` only for the exact current-state replay, otherwise `409 CATALOG_PUBLICATION_CONFLICT`. `55P02`/`55P03` map to `409`; `57014` and unclassified technical failures map to sanitized `503`. The PostgreSQL IT exercises one-winner races, an injected competing ACTIVE with real `23505`, injected `40001` recovery, real `55P03` lock timeout while an unrelated read on the same pool succeeds, and a real `57014` statement cancel with full rollback.
- **Audit/Outbox atomicity.** All lifecycle, audit and Outbox writes share the one transaction. A real publication appends exactly one candidate audit and one or two Outboxes (retirement offsale first, then publication); a real offsale appends one audit and one Outbox; replay/stale/conflict append none. Audit and Outbox dedupe keys, `ACTION_DERIVED`, decision-time timestamp, frozen snapshot fields and canonical payload SHA256 are bound exactly and independently asserted. Fault stages after the real audit/Outbox function calls roll back all lifecycle/fact rows.
- **Role and connection custody.** The transaction asserts `login == current_user`, writable autoCommit-off READ COMMITTED, the transaction-bound connection/PID/transaction id and local timeouts (2s/250ms/5s); it switches `login -> operations_iam_role -> catalog_order_role -> login`, restoring before commit and failing closed with `503` on any unproven restoration/cleanup. The shared guarded pool evicts a dirty connection; the IT proves restoration and eviction. `catalog_order_role` cannot read `employee_account`; only `operations_iam_role` reads the authority projection `id,status,role,revision`.
- **Freezes.** No migration, OpenAPI, ACL/role SQL, credential or pool fork is added. The only build/CI changes are the two POM Failsafe includes and the inventory-counter updates, both internally consistent with the 86/38 test additions.
