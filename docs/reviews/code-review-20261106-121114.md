## Findings

### 1-未修复-[中]-并发与双池隔离证据未实现 accepted plan 的两连接/PID witness

- **入口/函数**: `PublicSharesIT.publicReadIsPostgresEnforcedAndRestoresPoolRoleAndTransactionState`
- **文件(行号)**: `backend/src/test/java/com/onecall/archtests/container/PublicSharesFixture.java:154-157`; `backend/src/test/java/com/onecall/archtests/container/PublicSharesIT.java:274-289`
- **输入场景**: six concurrent public HTTP GETs submitted on a three-worker executor while the public pool maximum size is 1; then, after the public-only assertions, one explicit command create on the separate command pool.
- **实际分支**: every concurrent request queues for the single public connection (`pool.setMaximumPoolSize(1)`), so the test observes one serialized public PID stream; the command create observes a separate command stream, but a public connection and a command connection are never held simultaneously.
- **预期行为**: the accepted plan §9 requires the public test pool to be set to size 2 and a barrier across two held transactions to prove two **distinct** public backend PIDs, both with `current_user=session_user=sharing_public_read_role` and `transaction_read_only=on`, explicitly "rather than merely queueing six reads through size 1"; it also requires proof of "distinct simultaneously borrowed public/command PIDs" and unchanged command login/role restoration.
- **实际行为**: the suite proves serialized reuse on one public PID, unchanged 11-table snapshots, distinct Hikari bean instances, a nonempty positive command INSERT stream and an unchanged public observation stream, but it never proves two simultaneous public connections/PIDs nor simultaneous public+command borrows.
- **直接证据**: `PublicSharesFixture.java:155` sets `pool.setMaximumPoolSize(1)`; `PublicSharesIT.java:274-278` runs six futures on a three-thread pool; `PublicSharesIT.java:280-289` compares borrowed bean identity (`isNotSameAs`) and command observations but holds no second connection. Repository-wide search finds no `CyclicBarrier`/`CountDownLatch` or pool-size-2 public concurrency witness.
- **影响**: verification blind spot only (no production defect found). The production public pool uses Hikari's default multi-connection sizing, so concurrent multi-connection identity/transaction-state isolation is not exercised by executable evidence; a future connection-level identity or transaction-state leak could pass this 221-method suite. This is a conformance gap against binding plan §9 and a gap in the gate's claimed "concurrent reads" evidence.
- **建议改法和验证点**: inside the existing renamed method (no new JUnit method), temporarily set the public test pool to 2, hold two transactions concurrently behind a bounded barrier, assert two distinct `pg_backend_pid()` values with public current/session identity and READ ONLY=on, roll back/close in `finally` (with a timeout so CI cannot hang), and separately borrow one public and one command connection simultaneously and assert distinct PIDs/identities plus the command pool's post-transaction reset. Re-run the unchanged source=CI=XML inventory afterwards.
- **修复风险（低/中/高）**: 低 — test-fixture/method-body only, no production path; the main risk is a hanging barrier, mitigated with timeouts and unconditional `finally` rollback/close.
