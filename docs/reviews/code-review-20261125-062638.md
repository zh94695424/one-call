## Residual Risk

- **Canonicalization is dual-implemented**: the producer hashes `sha256(writeValueAsBytes(TreeMap))` (`CatalogDraftSemantics.java:135,169`) while the consumer verifies `sha(canonical(node))` built by string assembly (`CustomerOrderSemantics.java:104`). They agree by construction for the bounded snapshot grammar (both sort via `TreeMap`, both use Jackson string escaping, both emit plain digits and reject fractional nodes), and the IT seeds the digest through a *third* encoder (`CustomerOrdersFixture.java:250-258`), so no test crosses the two production encoders end-to-end. Any future divergence fails closed (500/422 with zero delta), never as a wrong 201; recommend the Q4/Q20 publisher add a cross-encoder IT.
- **Lost-201 exposure window** remains dependent on post-commit connection clean-assert/close behaviour in the guarded template; pinned by tests but inherently bounded by pool state — a commit-outcome ambiguity surfaces as 503, so client-visible success can be lost even though the order committed (retry returns the first immutable order).

- **Plan-owned `terms` bounds** (depth 8 / 256 nodes / 1024 code points / 8192 canonical bytes) reject legitimately approved larger terms with 422 zero-delta; a bound revision needs the documented Q4/Q20 route.
