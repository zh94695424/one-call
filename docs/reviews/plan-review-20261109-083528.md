### 2-未修复-中-authority bean 的条件装配与 `@ConditionalOnMissingBean` 胜出机制未钉死，字面实施会破坏 allowlist 外的上下文测试

## Open Questions

1. **重放元数据的传输通道**：prior `issuedAt`/`notBefore`/`kid` 如何从 access-event payload 到达 authority？plan §4 只说 "The authority receives the prior committed success metadata"，§6 又说 authority 只收 "immutable authorized fact bundle"（无 repository）。合理推断是扩展 allowlisted 的 `MediaAuthorizationCredentialRequest`（现无 prior-success 字段）并由 `DefaultShareMediaAuthorizationService` 注入读取，但 plan 未写明——实施者可能误加 repository 依赖或漏传字段。（owner: plan fix / PA21 实施 Agent）
2. **首发 `expiresAt` 的来源**：golden 显示 `expiresAt = issuedAt + 3600s`，但 plan 未规定 fresh issuance 的 expiry 取自 request 的 `credentialExpiresAt`/bound 还是 `now + durationSeconds`；二者在时钟推进时不同，影响 fingerprint 与重放一致性。（owner: plan fix）
3. **§6 与 §7 的依赖方向措辞**：§6 称 "playback consumes only `MediaCredentialVerifier`"，§7 却要求在 `MediaPlaybackConfiguration`（playback 包）声明 authority bean。实际禁词表不阻止该做法，但两节措辞不一致，实施时可能误以为不能在 playback 配置类引用 authority 类。（owner: 实施 Agent，按 §7+扫描事实执行）
4. **PA20 端到端证明的落点**：§8 把 "PA19/PA20-compatible end-to-end" 指定给 `PublicShareAdmissionIT`，§8 line 91 又要求 "PA20 full-object success"，但网关 HTTP 真源测试 `MediaGatewayTransportIT` 不在 allowlist。是接受 allowlisted IT 内的 window-兼容断言，还是需要扩 allowlist 走网关 IT？（owner: 门禁编排方 / plan fix）
5. **ci.yml 中 pa18/19/20 additions 分解字面量**（`baseline_totals == [112,178]` 及逐 work unit 字典）是否被 §10 "every CI class/method literal" 覆盖——字面读法是覆盖，但实施时须逐条枚举核对。（owner: PA21 实施 Agent）

## Final plan review conclusion

**fail**

理由（简洁）：三个 material finding——(1) **高**：固定 golden vector 的 purpose `DOWNLOAD` 不在 `Purpose {PLAYBACK, SEEK, RENEW}` 枚举中，与 plan 自身的 "invalid enum" 拒绝规则、PA19 类型化 purpose 校验及 allowlist（枚举文件不可改）三重冲突，按字面实施第一步即失败，fix artifact 声称的 "fixed golden-vector inputs" 不成立；(2) **中**：§7 只钉了 Spring 装配的目标状态、未钉条件装配与 `@ConditionalOnMissingBean` 胜出的机制，字面无条件 + 必填 key provider 的写法会破坏 allowlist 外的 `OneCallApplicationTests` 与既有 default-profile 断言，ordering 断言对两个用户 `@Configuration` 无依据——原始 finding 仅部分闭合；(3) **中**：§3/§8 仍声称 PA19 执行 "requested-window rule/validation"，与源码相反（full-window 仅存在于 PA20 `MediaGatewayFilter:78-81`），而 Control line 36 明确要求更正该措辞——accepted correction 未闭合。其余七项决策（重放设计前提、evidence 窗口/accessor、架构落点、构造点集合、CI/POM/XML 可行性、二进制逐字段契约除 purpose 外、legacy P2、allowlist 精确性/目标一致性）均核验通过。plan 在身份、算术与总体结构上自洽，但与枚举真源、Spring 上下文测试事实及 Control 裁决的交叉验证失败，按现状不能通过 re-review。
