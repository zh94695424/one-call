## Findings

### CR-006-未修复-[严重程度（中）]-EVIDENCE 与 ENTITLEMENT 的域级结果唯一性只在快照校验执行，重放仍接受重复结果身份

- **入口/函数**: `replayEvent` → `validEventRecord`; aggregate duplicate-result check in `validProcessedEvents` is bypassed on replay.
- **文件(行号)**: `shared/onecall-business.js:519`, `shared/onecall-business.js:522`, `shared/onecall-business.js:612`, `shared/onecall-business.js:618`, `shared/onecall-business.js:651`, `shared/onecall-business.js:681`.
- **输入场景**: 在合法状态中为某确认会话成功生成两个不同 evidence events，或为已到账订单的同一权益对象复制一个第二 ENTITLEMENT 事件记录，并让两条记录的结果都指向同一个 evidence/entitlement ID。调用方以任一原事件 ID 和匹配输入进行重放。
- **实际分支**: `validProcessedEvents` 为快照导入建立 `resultIdentities` 集合并拒绝域内相同创建结果身份。但 `replayEvent` 只对命中记录调用单条 `validEventRecord`，没有调用该域的 aggregate 检查。EVIDENCE 与 ENTITLEMENT 的结果对象没有持久保存创建 eventId，单条校验只用结果对象 ID 在当前集合中找到匹配对象，因此每一条重复声明都单独有效。
- **预期行为**: 导入与重放应共同遵守事件身份到创建结果对象的域内一一对应。格式正确但所属域已有其他事件声明相同 evidence 或 entitlement identity 的状态，重放应返回 `INVALID_TRANSITION`，不能因为只检查当前记录而成功；合法同键重放仍返回首次结果且不写状态。
- **实际行为**: 两组内存只读探针中，重复 evidence-result 和重复 entitlement-result 都得到 `snapshot=INVALID_TRANSITION, load=INVALID_TRANSITION`，但各自两个原始 event ID 的 replay 都返回 `DUPLICATE`；完整状态保持不变。系统不产生新的证据/权益，但成功回包掩盖了全域状态本身不符合共享唯一性契约的问题。
- **直接证据**: 519–525 行仅在 `validProcessedEvents` 聚合结果 ID 唯一性；618 行 replay 调用只接受单个 `validEventRecord` 后直接 duplicate；651–657 行验证 evidence 与当前会话/主体/grant 的兼容引用而不查看其它 EVIDENCE 事件；681–683 行验证 entitlement 与订单的兼容引用而不查看其它 ENTITLEMENT 事件。`docs/10-cross-channel-rules.md:43` 和 round-3 fix 的 `docs/gateflow/cross-channel-alignment-s1-fix.md:174` 都要求事件域内创建结果一对一、导入与重放共享校验；当前 aggregate helper 只在导入/快照路径调用。测试 18（`shared/qa/business.test.js:654` 起）覆盖重复订单及激活输入键，但未为 EVIDENCE/ENTITLEMENT 构造两个不同 event ID 指向同一对象并调用旧键重放。
- **影响**: 跨端本地快照在整体校验时正确拒绝，但直接调用公共业务转换仍可把一个格式有效、身份模糊的事件记录当作成功历史事实返回。消费该结果的 UI/适配器会得到一个成功的 `DUPLICATE`，而同一状态通过权威 `snapshot`/`loadReviewSnapshot` 又被认定无效；这使重放与快照 validator 对状态有效性的判断分叉。没有新的权益副作用或额度扣量在本反例中发生。
- **建议改法和验证点**: 让共享事件所有者为域内创建结果身份提供一个可由单记录重放查询的唯一解析规则，例如在 `validEventRecord` 的 EVIDENCE/ENTITLEMENT 分支确认当前 event key 是该结果 ID 的唯一 owner，而非仅检查对象存在；或在 replay 对该域执行同一 aggregate 结果身份校验。保持 PAYMENT 多事件例外、不同 eventId 对不同 evidence 的正常消费、同一权益多次新调用按既有 DUPLICATE 语义返回不新增记录，以及相同字符串跨域合法。增加每个重复结果的 `snapshot`/`loadReviewSnapshot` 原子拒绝与原键重放失败断言，并验证正常七域结果重放通过；避免引入 validator 互相调用的环依赖。
- **修复风险（低/中/高）**: 中；共享 helper 需按域区分结果身份唯一性，避免错误限制 PAYMENT 多事件或误将普通已处理调用当作创建结果事件。
- **严重程度（低/中/高/严重）**: 中。
