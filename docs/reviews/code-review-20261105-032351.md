## Open Questions

- Evidence projection recording join semantics: `JooqShareableEvidenceProjectionReader.java:26-29` left-joins `evidence.recording` on `media_object_id`, and V008 has no unique constraint on that column (`V008__evidence_media.sql:56-67`). If the Evidence owner permits multiple recording rows per media object, the join duplicates artifact projections and this reader fails closed with 503. Whether that schema state is legal is an Evidence-owner semantic, not settled by this slice.
- Recording lifecycle semantics: the projection exposes `recording.validated_duration` but not recording status/`validated_sha256`; whether an unvalidated/DECLARED recording may be shareable is likewise an Evidence-owner contract question (Control records it as deferred). This review does not treat it as a defect in slice 1.
