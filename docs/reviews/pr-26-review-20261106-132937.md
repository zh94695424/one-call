  reproduced because no generator/manifest file exists in the bundle (the 1,513-file count was reproduced). The
  `protected-hashes.sha256` raw values are EOL/worktree-sensitive: canonical-LF identities match the accepted
  plan, plan-fix, implementation report, code-review-fix-1 and V011, and the exact patch is byte-identical to
  `git diff base..head`, but several raw hashes cannot be reproduced from this CRLF checkout. Runtime evidence is
  a local synthetic PostgreSQL 16.15 Testcontainers bundle, not hosted CI, a deployed environment or production
  acceptance; this reviewer did not rerun Maven/Docker/PostgreSQL.
- **Deployment-owned PUBLIC TEMPORARY revoke**: `REVOKE TEMPORARY ON DATABASE ... FROM PUBLIC` is
  current-database/global; external temp-table consumers are not inventoried by this repository. Database/SRE
  owns assessment and escalation; incompatibility must not be waived or repaired by broadening the public role.
- **Deployment-owned authentication/ACL**: the role is created with no password; credential provisioning,
  pg_hba/TLS, rotation, cross-database ACL drift, role-name collision resolution and post-deploy ACL monitoring
  remain Database/Security/SRE responsibilities. The application fails closed if the dedicated credentials or
  reader/manager are absent.
- **Table-wide column access inherent to the accepted design**: a holder of the public role credential can read
  all rows of the five allowlisted tables (all share snapshots and `identity_at_capture`), not only one token;
  there is no row-level security, and PostgreSQL catalog/built-in visibility plus trusted-JVM/DBA powers are not
  sandboxed. This is the accepted column-ACL boundary, not a defect in this PR.
- **Capacity/abuse**: the dedicated Hikari pool uses default sizing; no production load, abuse, restore or
  penetration evidence is claimed. Backend/SRE owns capacity review.
- **Test-maintenance residuals**: explicit `pg_foreign_server.srvacl` and large-object ACL/ownership
  enumeration is not expanded (the Controller previously classified it as a deferred test-maintenance residual;
  V011's `pg_shdepend` incompatibility checks cover direct role grants, while PUBLIC foreign-server/large-object
  ACLs remain a deployment concern). PUBLIC default ACLs are not explicitly rejected by V011 (its postcondition
  covers role grantee/grantor default ACLs); this is a defense-in-depth note, not a current application privilege.
  The concurrency witness relies on Hikari thread affinity/soft eviction for same-PID reset and the six HTTP
  requests assert status, not byte-identical envelopes; both passed in the final clean/targeted runs but remain
  test-harness assumptions.
- **Maintainability coupling**: the evidence module's public adapter references a sharing-owned property prefix
  and transaction-manager bean name, and the fixed role name is duplicated across V011, the properties record and
  the service identity assertion. This is fail-closed and accepted by the plan; future renaming requires
  synchronized edits.
