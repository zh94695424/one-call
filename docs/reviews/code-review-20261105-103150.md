## Findings

### Accepted PR-review fix 1: closure verification (no new finding)

The original accepted medium defect was that `scopeDigest` and `content_sha256`
were computed over wrapper member names (`contentObject`, `verificationObject`,
`creationObject`) while frozen docs/14 §2.12 and the persisted V009 snapshot use
`content`, `verification`, `creation`. The corrected candidate closes this on
every named surface:

- Service (`DefaultCustomerShareCommandService.java:140-159`):
  `scope` is built from `content` + `verification` and hashed for `scopeDigest`;
  `snapshot` is built from `content` + `verification` + `creation` and hashed
  directly for `content_sha256`; `creationFingerprint` remains the digest of
  `creation` with only the fingerprint member absent (added afterwards).
  This matches `scopeDigest = H(JCS({content,verification}))`,
  `content_sha256 = H(JCS({content,verification,creation}))`, and the
  fingerprint exclusion rule.
- Unit oracle (`CustomerShareCommandServiceTests.java:121,129-134`): independently
  constructed canonical vectors now use `content`/`verification`/`creation` and
  assert both the persisted snapshot text and `contentSha256` against the complete
  persisted snapshot.
- Container read-back oracle (`CustomerShareCommandsIT.java:415-427`): reads the
  stored JSONB through an admin connection, asserts all three members are JSON
  objects, and recomputes `scopeDigest` from `{content,verification}` and
  `content_sha256` from `{content,verification,creation}`. This would have failed
  under the old wrapper-key implementation.
- Competing-grant helper (`CustomerShareCommandsIT.java:613-621`): builds the
  complete snapshot from the same three persisted members and hashes it.
- Plan (`pa14-sharing-command-service-foundation-plan.md:23,100,142`): the three
  formerly contradictory formula passages now state the single persisted-member
  contract and explicitly retain RFC 8785 (the added note at line 18).
- Repo-wide wrapper-literal search over `backend/`, `api/`, `shared/`, `security/`,
  `acceptance/`, `deployment/`, `.github/` returns no `contentObject` /
  `verificationObject` / `creationObject` occurrences. Residual mentions exist only
  in historical gateflow records (fix artifacts and an append-only Control entry),
  not in active source, tests, plan or contract.
