### 02-未修复-低-Request trusted-fact guard is bypassable by an inline open request body and by valid tuple arrays (`prefixItems`)

- **入口/函数**: `validateTrustedRequestFacts` (folded into `onecall/sensitive-fields`), `requestSchema`, `walkRequestSchema`, `deref` in `api/openapi/contract-rules.mjs`
- **文件(行号)**:
  - `api/openapi/contract-rules.mjs:639-646` (`requestSchema` accepts any schema, including an inline open object)
  - `api/openapi/contract-rules.mjs:728-746` (`walkRequestSchema` walks only `properties`, `items`, `allOf`, `anyOf`, `oneOf`; not `prefixItems`, not `additionalProperties`, and `$ref` sibling keywords are dropped by `deref`)
  - `api/openapi/contract-rules.mjs:140-155` (`deref` replaces the whole `$ref` node, discarding siblings)
  - `api/openapi/contract-rules.mjs:748-795` (the `additionalProperties: false` check iterates only `components.schemas`, not inline request bodies)
  - `api/openapi/contract-rules.mjs:801-819` (only declared property names are checked)
  - Contract intent: plan `docs/gateflow/a1-production-openapi-surfaces-spec-plan.md:337-339` (all request/response use component schemas; objects default `additionalProperties: false`) and the accepted request-body trust-boundary requirement.
- **输入场景**: (a) Replace C4's request body `$ref` with an inline `{type: object, additionalProperties: true, properties: {...}}`; (b) add a valid OpenAPI 3.1 tuple property using `prefixItems: [{type: object, properties: {amountCents: ...}}]`.
- **实际分支**: The walker visits only the declared properties. An inline open object declares no trusted fact, and `additionalProperties: true` is not inspected; tuple `prefixItems` is not visited. `redocly lint` exits 0 for both.
- **预期行为**: Request bodies should be closed component schemas and must not accept undeclared trusted facts. The accepted guard exists to reject account/owner/role/price/amount/payment/trial/entitlement facts anywhere in the request body.
- **实际行为**:
  - `/tmp/a1rr/p25_inline_open.yaml` (C4 request body replaced with an inline open object): `redocly lint` exit 0; a client could send `accountId` and no rule objects.
  - `/tmp/a1rr/p22_prefixitems.yaml` (valid tuple element containing `amountCents`): `redocly lint` exit 0.
  - `/tmp/a1rr/p6_ref_sibling.yaml` (`$ref` plus sibling `properties.accountId`): lint exit 0, but the referenced `ClaimRequest` is closed and the generated type drops the sibling, so this specific form does not currently accept the fact.
- **直接证据**: `walkRequestSchema` (lines 728-746) and `validateTrustedRequestFacts` (801-819) have no unknown-property or `prefixItems` handling; the `additionalProperties: false` check (748-762) is scoped to `components.schemas` only. The probe exits are recorded below.
- **影响**: Latent. A single future request-schema edit can accept arbitrary trusted facts while the full S1 check remains green. All current S1 request bodies are `$ref`s to closed component schemas and are clean.
- **建议改法和验证点**:
  - Require every request-body media schema to be a `$ref` to a component object with `additionalProperties: false`; extend the walker to `prefixItems`/`additionalProperties` schemas and reject `$ref` siblings, or explicitly forbid those constructs in request bodies.
  - Verify stock S1 still passes and add negative probes for the inline-open body, `prefixItems` and `$ref` sibling forms.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低
