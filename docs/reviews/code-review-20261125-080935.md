## Findings (Sorted By Severity)

Two new non-blocking **Low** findings; no Critical/High/Medium. Both are test-oracle strength issues, not
product defects, and neither reopens a previously accepted closure in a material way.

- `PA41-RR2-A-01` **Low / test-oracle non-vacuity (B-F01 residual).** `databaseInventory()` now issues 16
  count-bearing catalog snapshots (`CustomerOrdersFixture.java:257-276`), but its `inventory()` helper
  (`:252-256`) only asserts `isNotBlank()`. An empty result renders as `[0,[]]`, which is non-blank, and
  `noNewDatabaseObjectPrivilegeOrMigrationAppears` (`CustomerOrderRoleLeastPrivilegeIT.java:160-165`)
  only compares the before/after digest. Therefore a category query whose `WHERE`/join silently matches
  zero rows in **both** snapshots (e.g. a future schema-filter typo) would contribute a constant
  `[0,[]]` and pass unnoticed. Coverage of the omitted classes is real and the SQL executes on real
  PostgreSQL 16 (proved by the green target selector), so the current bytes are not defective; the gap
  is that non-vacuity is not self-asserted. Recommended (non-blocking): assert `count > 0` for the
  categories guaranteed populated by the 19 migrations (`schemas`, `relations`, `columns`, `indexes`,
  `constraints`, `routines`, `rls`, `roles`, `memberships`, `flyway`). Owner: Test/CI (PA41 test
  maintenance).
- `PA41-RR2-A-02` **Low / guard narrowing (B-F02 residual).** In
  `customerOrderAdapterHasNoSqlOrTransactionAuthority` the SQL/JDBC/transaction/`SET ROLE`/`RESET ROLE`
  token prohibition is applied via `assertAdapterHasNoAuthority(...)` only to
  `CustomerBoundaryFilter` (`CustomerOrderCreationBoundaryTests.java:36`) and
  `CustomerWebConfiguration` (`:37`). `CustomerProblemWriter` (`:38-45`) receives only exact
  foreign-reference equality and a static-sharing-import ban; it no longer receives the authority-token
  scan. The fix-1 report/dispatch explicitly said "the same SQL/JDBC/transaction authority prohibitions
  apply" to all three modified web files, so this reads as a narrowing of the authority scan for one
  file (not a blocking regression; the current `CustomerProblemWriter` bytes contain none of the
  forbidden tokens, so the omitted scan would pass today). Recommended (non-blocking): call
  `assertAdapterHasNoAuthority(MODIFIED_CUSTOMER_ADAPTER.get(1), expected)` (it already performs both the
  exact-reference check and the token scan) instead of the bespoke reference-only block. Owner: Test/CI
  (PA41 architecture-guard maintenance).
