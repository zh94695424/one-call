### P2-01-已修复-[高]-客服可在综合对账页执行幂等查询并关闭差异
- **入口/函数**: `pageReconciliation` 与 `reconcile-query` handler
- **文件(行号)**: `operations-prototype/onecall-operations-admin.html:735`、`:1031`
- **输入场景**: 客服角色因拥有 `service` 区域可进入 `/reconciliation`，点击“执行幂等查询”。
- **实际分支**: 页面无动作权限判断，handler 直接把全局差异状态写成 `RESOLVED` 并记录成功事件。
- **预期行为**: 客服可以查看工单上下文，但供应商/支付/存证对账命令只允许运营、对应领域人员或财务等有命令权限的角色。
- **实际行为**: route read 权限再次被当作写权限，客服可以关闭跨域差异。
- **直接证据**: `pageReconciliation` 无条件渲染按钮；handler 不调用 `canCommand`。
- **影响**: 错误 RBAC、差异被无权人员标记为解决。
- **建议改法和验证点**: 将 `reconcile-query` 纳入动作权限矩阵，渲染和 handler 双校验；QA 增加客服入口不可见和伪造 action 拒绝。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### P2-02-已修复-[中]-供应商升级工单始终记录为公证供应商
- **入口/函数**: `pageVendorDetail`、`vendor-escalate` handler
- **文件(行号)**: `operations-prototype/onecall-operations-admin.html:731`、`:1028`
- **输入场景**: 在运营商渠道 A 或 AI 服务 C 详情点击“创建升级工单”。
- **实际分支**: 按钮不携带当前供应商 ID；handler 把审计对象硬编码为 `VND-NOTARY-YZ`。
- **预期行为**: 工单和审计必须绑定当前详情对象。
- **实际行为**: 非公证供应商的升级事件被归到错误对象，无法追踪真实链路。
- **直接证据**: 页面 action 只有 `data-action`，handler 固定调用 `addEvent(...,'VND-NOTARY-YZ',...)`。
- **影响**: 工单对象错配、供应商升级和审计链错误。
- **建议改法和验证点**: 按钮携带 `data-object=id`；handler 从事件目标读取并验证 ID；QA 分别从运营商与 AI 详情发起并断言审计对象。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
