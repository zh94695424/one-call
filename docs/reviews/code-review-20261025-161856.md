#### F-S2-R1-01

| 字段 | 值 |
| --- | --- |
| **ID** | `F-S2-R1-01` |
| **最终状态** | **`已修复`** |
| **原严重度** | High（accepted review；controller 又发现一次 incomplete-fix edge 并驱动 correction 1） |
| **原缺陷** | recovery 新鲜性仅靠不等式，缺省/null/空 transport 被当作新鲜；identity guard 在任一侧缺省时被跳过；成功恢复不滚动 `previous*` 基线；首次 401/403 观测可省略 transport 并创建 null-baseline blocked entry |

**独立核验（最终树，逐条）：**

1. **本地谓词**（`security/validate.mjs:795-809`）：`isValidDomainIdentity` 要求非 null、非数组对象、至少一个 own value、每个 value 为非空 string（`{}`、`null`、`""`、含空字段、非对象均失败）；`isValidIvrTimestamp` 要求 `^[0-9]{1,12}$` 且长度 ≤64；`isValidIvrNonce` 要求 `[A-Za-z0-9_-]{1,128}`。无新增 Problem code：非法值复用 `403 FORBIDDEN / IDENTITY_MUTATION_FORBIDDEN` 与 `403 FORBIDDEN / STALE_TRANSPORT`。
2. **首次观测建项**（`1422-1449`）：`observedStatus` 为 401/403 时，必须先通过 identity 校验（`1407-1420`，失败在 `state.outbox.set` 之前返回）且携带完整合法 transport（`1424-1438`），否则返回 `403 STALE_TRANSPORT` 且**不**创建 entry。fixture 步骤 `initial-observation-transport-omitted-denied`（新 eventId `TEST_ONLY_OUTBOX_EVENT_ORPHAN`，无 transport）期望 `403 STALE_TRANSPORT` / `securityBlocked: false`；最终 assert 仍为 `outboxEntries=2`、`securityBlockedEntries=1`，即 durable no-orphan 证明。**无 orphan entry。**
3. **既有 entry 观测**（`1496-1547`）：`entry.securityBlocked = true` 在观测分支入口设置（fail-closed，符合契约「观测到 401/403 时保持 PENDING 并 security-blocked」）。supply 了 transport 时双方必须格式合法，否则 `STALE_TRANSPORT` 且 baseline 不前移（部分接受被拒绝：`transportSupplied` 为真但单字段非法即整体失败）；完全省略时仅当 entry 已持有完整合法 baseline（`1526-1537`），否则 fail-closed `STALE_TRANSPORT`。`reblock-403` 依赖 `recovery-403-accepted` 记录的 `0908/1700000600` baseline 通过省略路径，与 correction 报告一致。
4. **Recovery**（`1549-1580`）：仅在 `entry.securityBlocked` 且存在 recovery signal 时进入；signal 必须是既有四个值之一；`step.domainIdentity` 必须存在、合法且 `deepEqual` 等于存储 identity（`1554-1555`；`deepEqual` 经 `canonicalJson` 键排序比较，`422-437`）；transport 必须双方格式合法（omitted/null/empty/malformed 全部在 `1557-1558` 被拒）；`freshTransport` 不等式（`1560-1561`）在两侧均已验证为非空合法字符串后才生效；接受时 `securityBlocked=false` **且** `previousNonce`/`previousTimestamp` 前移至接受元组（`1565-1567`）。
5. **Reuse-after-accept 与 re-block**：fixture `recovery-403-accepted` 前移 baseline 至 `0908/1700000600`；`reblock-403` 重新 block 且不改动 baseline；`reused-accepted-transport-denied` 以同一元组 recovery → `STALE_TRANSPORT`。固定后，跨 block/recovery 周期复用被拒绝。
6. **Identity/payload 不可变、PENDING、零 A2、分支顺序**：`entry.eventId`/`payloadFingerprint`/`identity` 仅在建项时写入（`1440-1448`），此后无赋值；payload mutation、`mutateEventId`、全局 identity 不等检查（`1474-1483`）先于 policy attempts；hot retry/redial/re-resolve/reservation/settlement 保持原顺序与原 reason（`1484-1494`）；所有 outbox 返回携带 `identityChanges: 0`、`payloadChanges: 0`、`a2BusinessSideEffects: 0` 与 `sideEffectsZero()`；entry state 始终 `PENDING`。最终 assert 与 24 步轨迹（correction 报告 §5）逐步吻合。
7. **原五类 false-pass 与 correction edge 的 durable 覆盖**：`omitted/null/empty/malformed/partially-reused-transport-denied`、`omitted/empty/mismatched-recovery-identity-denied`、`reused-accepted-transport-denied`、`initial-observation-transport-omitted-denied` 均以期望 403 + 不变最终计数固化在 `sec-s2-09`；旧 evaluator（纯不等式 + falsy-guard 短路 + 无 baseline 前移 + 无首次观测 transport guard）在这些步骤上必然失败。

**结论**：初始观测、既有观测、恢复、缺省/null/空/畸形/部分复用 transport、缺省/空/不匹配 identity、accepted-recovery baseline 前移、re-block 与 reuse-after-accept 全部按契约强制；无 orphan；entry 保持 `PENDING`；identity/payload 不可变；零 A2 副作用；分支顺序保留。状态 **`已修复`**。

#### F-S2-R1-02

| 字段 | 值 |
| --- | --- |
| **ID** | `F-S2-R1-02` |
| **最终状态** | **`已修复`** |
| **原严重度** | Medium |
| **原缺陷** | `signatureMode: 'invalid'` 将末字符替换为 `A`，当合法签名已以 `A` 结尾时是恒等变换 |

**独立核验：**

1. `security/validate.mjs:1221-1224`：`replacement = validSignature.endsWith('A') ? 'B' : 'A'`；`headers['X-ONECALL-SIGNATURE'] = validSignature.slice(0, -1) + replacement`。对任意以 `A` 结尾的 `s`，`s.slice(0,-1) + 'B' !== s`；对任意不以 `A` 结尾的 `s`，`s.slice(0,-1) + 'A' !== s`。**恒不恒等（always non-identical）。**
2. 替换字符仍在 base64url 字母表内，故 `signatureFormatValid` 正则（`1236`）仍为真，评估继续走到 key 查找（`1265-1270`）与 `timingSafeEqualStrings`（`1275-1277`），稳定返回 `401 UNAUTHENTICATED / SIGNATURE_INVALID`。
3. `sec-s2-04` 步骤 `bad-signature` 使用 controller 证实的碰撞时间戳 `1700000019`（`receivedAt: 1700000019`，窗口 300 内）。Controller 证据：该材料派生签名 `v1.TEST_ONLY_K17_V1.qNGJzl7JjmI9YuVDdsDJ8Ta9xtK0EiFnNVdhY3seLKA`（末字符 `A`）；旧代码恒等变换 → `OK/200/ACCEPTED`、`passed=14 failed=1`；新代码改为 `…LKB`，fixture 期望 `DENIED/401/UNAUTHENTICATED/SIGNATURE_INVALID` + `signatureFormatValid: true`（fixture L71-84）。本会话 Node 权限门禁止实算 HMAC（见 §4），该派生签名与 401 落点采用 controller hash-bound 运行证据；构造逻辑本身由字符串代数独立证明恒不恒等且格式保持。
4. `sec-s2-04` 的 fixture ID、`slice`、`negative: true`、步数与其余步骤未变；S2-04 哈希与 fix-1 报告一致且 correction 未触碰。

**结论**：末字符 `A` 碰撞被确定性关闭；负例稳定到达 401 `SIGNATURE_INVALID`。状态 **`已修复`**。

### 新 finding

**未发现新的实质性问题。** 已按任务清单对抗性检查以下类别，均未构成新 material defect：

- **rejection 前状态变更**：`1497` 在观测分支内先置 `securityBlocked=true` 再做 identity/transport 检查——这是契约要求的 fail-closed block（观测本身即证据），且被拒绝路径显式返回 `securityBlocked: true` 与 alert 信号；非 orphan 路径在 `state.outbox.set` 之前失败，无 entry 状态污染。

- **baseline rollback（程序性）**：无路径将 `previous*` 重置为 null 或旧值；recovery 只前移；观测省略 transport 不改 baseline。观测 supply 新元组时覆盖 baseline 属「记录本次失败投递」的既定语义（见 Open Question 1）。
- **部分 transport 接受**：`transportSupplied` 为真即要求双方合法，单字段合法/缺失均 `STALE_TRANSPORT`。
- **非法 identity 接受**：`isValidDomainIdentity` + 建项时即校验 + 全局/观测/recovery 三处 `deepEqual` 交叉，空对象/空字段/不匹配/缺省全部拒绝。

## 2. Open Questions

1. **观测 supply 已用过元组时的 baseline 覆盖语义**：既有 entry 的 401/403 观测若 supply 一个曾经在更早 recovery 中接受过的元组，`1524-1525` 会将 baseline 覆盖为该元组，后续 recovery 仅需与其不等即可再次接受该元组。当前 fixture 不覆盖该序列（`reblock-403` 省略 transport）；该行为在语义上等价于「记录本次失败投递使用的元组」，与 docs/17 §14「生成新的 timestamp/nonce（相对上次投递）」一致，且不构成缺省值假通过。归类为非阻塞观察，不升级为 finding；若未来 runtime 集成要求「跨全历史不可复用」，应在 A2/IVR integration 层用 nonce store 全局去重覆盖（既有 `R-A3-NONCE-STORE` 残留已指向该方向）。
2. **本会话 Node/npm 权限门**：`node --check`、A1 `check:s3`、A2 stage-S3、S1/S2 两次运行与 focused mutation probes 均被 harness 拒绝（`This command requires approval`）。运行期证据完全采用 controller `A3 S2 correction 1 return and re-review entry` 在同一最终哈希树上的记录（见 §4），本评审不声称复跑。
3. **Controller S2 stdout 哈希 `5BA15F81…` 与原 S2 implementation 相同**：因 stdout 仅含计数器而步骤数不进入计数器，fixture 内容变化不改变该哈希；这不削弱 `passed=15 failed=0` 的有效性，仅说明 stdout 哈希对步骤级变更不敏感。
