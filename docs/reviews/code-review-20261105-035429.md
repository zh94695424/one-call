### A-01-未修复-中-Production command transaction manager does not enable rollback-on-commit-failure, and the only commit-failure IT uses a differently configured manager

- **入口/函数**: `SharingCommandPersistenceConfiguration.sharingCommandTransactionManager` / `DefaultCustomerShareCommandService.execute` / `CustomerShareCommandsIT.createAppendFailureRollsBackGrantAuditAndOutbox`.
- **文件(行号)**: `backend/src/main/java/com/onecall/core/sharing/internal/persistence/SharingCommandPersistenceConfiguration.java:53-65`; `backend/src/main/java/com/onecall/core/sharing/internal/commandservice/DefaultCustomerShareCommandService.java:74-77`; `backend/src/test/java/com/onecall/archtests/container/CustomerShareCommandsIT.java:411-421`.
- **输入场景**: The command transaction's `commit()` fails with a transaction-level exception while the physical transaction has not been server-side committed (for example a driver-level `doCommit` exception or a synthetic/wrapped manager failure).
- **实际分支**: Production constructs a vanilla `DataSourceTransactionManager` at line 55 without `setRollbackOnCommitFailure(true)` (Spring default false). On `doCommit` failure Spring does not call `doRollback`; it triggers `STATUS_UNKNOWN` and `doCleanupAfterCompletion`, which restores auto-commit. The only test that claims to prove commit rollback constructs a different manager at lines 412-418 and explicitly calls `setRollbackOnCommitFailure(true)` before invoking the service.
- **预期行为**: Plan transactions/ordering (plan lines 67 and 69) and the required success signal require any append or commit failure to roll back grant, Outbox, audit, state, generations and revision, yielding a sanitized `INTERNAL` and no durable facts.
- **实际行为**: The shipped manager does not enforce that rollback path; the test exercises a manager configuration that is not the shipped one, so commit-failure atomicity is unproven for production. On PostgreSQL, restoring auto-commit on a still-active connection can commit the pending transaction instead of rolling it back; if the server already aborted the transaction the outcome is benign, but the guarantee is configuration-dependent rather than enforced.
- **直接证据**: `SharingCommandPersistenceConfiguration.java:53-56` returns `new DataSourceTransactionManager(dataSource)` with no rollback-on-commit-failure setting; `CustomerShareCommandsIT.java:412-418` creates `new DataSourceTransactionManager(pool)` overriding `doCommit` to throw and sets `manager.setRollbackOnCommitFailure(true)`; `DefaultCustomerShareCommandService.java:74-77` maps the thrown commit exception to `INTERNAL`.
- **影响**: A commit failure could leave grant/Outbox/audit facts durable despite an `INTERNAL` response, violating atomicity and the one-time capability/code contract; a retry of the same creation identity would then replay metadata without the lost token/code. The test gap also hides regression of the plan-required rollback branch.
- **建议改法和验证点**: Set `manager.setRollbackOnCommitFailure(true)` on the production manager, and make the IT exercise the production manager/template (for example a DataSource wrapper that fails only at commit, or a subclass/spy of the actual configured manager that delegates rollback) while retaining `assertNoFacts()` and the sanitized `INTERNAL` assertion. Re-run the existing IT 8; no new test method is required.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### A-02-未修复-低-Equivalent-offset timestamp normalization and fingerprint equality are not tested end to end

- **入口/函数**: create web binding plus `DefaultCustomerShareCommandService.utc` / creation fingerprint.
- **文件(行号)**: `backend/src/test/java/com/onecall/archtests/sharing/CustomerShareCommandServiceTests.java:28-29,72-73`; `backend/src/test/java/com/onecall/archtests/CustomerSharesCommandWebTests.java:34-35,49-54,66,164`; `backend/src/main/java/com/onecall/core/sharing/internal/commandservice/DefaultCustomerShareCommandService.java:255-257`; accepted plan line 288.
- **输入场景**: The same creation identity sent once with `2026-11-05T10:00:00.123456Z` and once with the equivalent `2026-11-05T12:00:00.123456+02:00`.
- **实际分支**: The service unit test uses only a `Z` `EXPIRY` and tests `utc()` padding separately; the Web test parses the `+02:00` body to an `Instant` and asserts the command argument, but its success response comes from a mock `ShareState` with a hard-coded `Z` expiry. No test executes the service with two equivalent-offset inputs and compares identity, fingerprint, stored text or replay.
- **预期行为**: Plan line 288 requires equivalent offsets to produce identical canonical RFC 3339 UTC `Z` microsecond text and identical creation fingerprints, and therefore to replay rather than conflict.
- **实际行为**: The offset-normalization/fingerprint guarantee has no assertion on the real create path; the Web test's mocked state makes the response text assertion independent of the service canonicalization.
- **直接证据**: `CustomerShareCommandServiceTests.java:29` (`EXPIRY` is `Z` only), `:72-73` (only `utc()` formatting); `CustomerSharesCommandWebTests.java:35` (`+02:00` input), `:54` (mocked response assertion), `:66` (command `Instant` only), `:164` (mock state hard-codes the `Z` expiry); `DefaultCustomerShareCommandService.java:255-257` is the sole normalization helper.
- **影响**: A regression that retains the client offset, truncates fractional precision differently, or uses different text in the fingerprint would not be caught; equivalent clients could receive `SHARE_CREATION_CONFLICT` or `503` with a green suite.
- **建议改法和验证点**: Extend the existing `createBuildsDeterministicIdentityAndFingerprint` (no new method) to execute the same key with `Z` and an equivalent offset, asserting equal `shareId`, `creationFingerprint`, `scopeDigest`, stored `creation.expiresAt` text, typed `expires_at` Instant and replay; keep the existing Web assertion for parsing.

Design-owner confirmation is needed on whether docs/14's literal names must be reconciled or annotated; no current runtime consumer recomputes these digests outside the sharing service and its IT.
