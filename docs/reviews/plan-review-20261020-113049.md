## Findings

### PR-003-未修复-[中]-快照契约同时要求导入 IVR 会话又禁止加载 session
- **状态候选**: `accepted-candidate`
- **位置**: §3.2 business state、§7 `loadReviewSnapshot` paragraph (plan line 147)、S3 cross-surface sequence
- **问题类型**: 契约缺失 / 不可直接实施 / 架构边界歧义
- **当前写法**: §3.2 states that business state contains `sessions`; §7 requires imported confirmed sessions and evidence→session→subject validation, then ends with “It never loads employee/session/role, widget UI state or arbitrary code.”
- **反例/失败场景**: S3 exports an IVR trial recording to the miniapp. An implementation following the explicit “never loads … session” exclusion removes IVR sessions while retaining evidence, so it must either reject a valid handoff or admit evidence with missing session references. An implementation including sessions instead violates the literal exclusion. The newly strengthened PR-001 loader tests cannot satisfy both interpretations without the implementer making a fresh contract decision.
- **为什么有问题**: Excluding employee/login session state is correct, but `IVRSession` is a required business fact and must travel with evidence. The plan now makes session reference integrity a hard S1 completion condition, so the ambiguous exclusion sits on the implementation-critical path rather than being a harmless wording preference.
- **直接证据**: §3.2 line 55 includes `sessions`; line 64 defines IVRSession; §7 line 147 requires every imported confirmed session to resolve a subject and every evidence record to resolve an existing confirmed session, then excludes “employee/session/role”. S3 lines 188–192 depend on importing an IVR session and its evidence from admin to miniapp/Web.
- **影响**: Invalid snapshot adapter, valid handoff rejected, evidence reference validation weakened to bypass the contradiction, or rework during S1/S3 implementation.
- **建议改法和验证点**: Replace the exclusion with exact names: snapshot includes business `sessions` (IVRSession); it excludes employee records, employee login session/credential/role state and customer authentication/UI session state. Prefer listing the allowed top-level business fields once and referring to that list. State the expected round-trip test: a valid dynamic IVR session and evidence survive unchanged, while a payload carrying employee/login-role state is rejected or ignored according to one explicit policy without importing it.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
