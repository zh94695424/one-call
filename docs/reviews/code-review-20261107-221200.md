## Findings

### 1-未修复-低-valid provider expiry with sub-microsecond precision is rejected as 503 after the SUCCESS event is committed

- **入口/函数:** `DefaultShareMediaAuthorizationService.authorize` fresh-success path; provider-issued expiry → durable success payload/event → durable-expiry equality check.
- **文件(行号):** `backend/src/main/java/com/onecall/core/sharing/internal/admission/DefaultShareMediaAuthorizationService.java:84-96` (payload `credentialExpiresAt` at `:88`, success insert at `:91-92`, parse and mismatch check at `:94-96`), `:205-209` (`validCredential`), `:221` (`utc` formatter); provider result contract `backend/src/main/java/com/onecall/core/sharing/internal/admission/ShareMediaCredentialProvider.java:33-39`.
- **输入场景:** a plan-valid deterministic provider returns `MediaAuthorizationCredentialResult.Issued(credential, expiresAt)` where `expiresAt` is strictly after the decision time and at or before `credentialExpiresAtBound`, but carries sub-microsecond precision (any `Instant` with `nano % 1000 != 0`, e.g. deterministically `bound.minusNanos(1)` or a clock-derived expiry). The plan only constrains the expiry to be after the decision time and at or before the bound; it does not require microsecond alignment.
- **实际分支:** `validCredential` passes (`expiry.isAfter(now())` and `!expiry.isAfter(bound)`); the success payload is built with `"credentialExpiresAt", utc(issued.expiresAt())`; `utc` emits exactly zero or six fractional digits (`appendInstant(...)`, same as PA17), truncating sub-microsecond precision; `repository.insertAccessEvent` returns `INSERTED`; `durableExpiry` is parsed back from the truncated payload and is not equal to `issued.expiresAt()`; the condition `written.status() == INSERTED` is true, so the service throws `DEPENDENCY_UNAVAILABLE` (503) **after** the SUCCESS event has been committed.
- **预期行为:** a valid provider credential/expiry must be returned as 200; the durable success payload, the durable expiry, the response and any later replay must use one canonical expiry representation; a mismatch should only fail when the provider is genuinely inconsistent with the durable first success. Where canonical formatting is required, the provider expiry must be canonicalized before it is validated, compared, stored and returned.
- **实际行为:** first call returns 503 `DEPENDENCY_UNAVAILABLE` while a durable `PLAYBACK_AUTHORIZED`/`SEEK_AUTHORIZED`/`RENEWED` SUCCESS event already exists; an immediate retry (same request/purpose) finds the prior success, the provider deterministically replays, the insert is `REUSED_IDENTICAL`, the equality check is skipped for non-`INSERTED` and the caller receives 200 with the truncated durable expiry. The externally visible outcome therefore depends on whether this was the first or a repeated call.
- **直接证据:** `DefaultShareMediaAuthorizationService.java:88` canonicalizes the provider expiry into the payload; `:94-96` compares the parsed canonical value to the raw `issued.expiresAt()` only on `INSERTED`; `:205-209` accepts the raw sub-microsecond expiry; `utc()` at `:221` emits 0/6 digits; `ShareMediaCredentialProvider.java:35-37` exposes `Instant expiresAt` with no precision contract. All existing fixtures use bounds/`minusSeconds` values that are microsecond-aligned (PA18 service fixture provider `ShareAdmissionServiceTests.java:695` returns `expires.minusSeconds(180)`; IT provider returns `request.credentialExpiresAt()` at `PublicShareAdmissionIT.java:436`), so the path is not exercised.
- **影响:** bounded availability/consistency defect for a plan-valid provider output: a credential is issued and a success fact is durably claimed, but the first caller receives 503; retry-dependent behavior and a success event without a successful response. No credential/internal fact is leaked and no admission/count/session row changes. Production providers are currently unavailable/fail-closed, so this is latent until a provider returning sub-microsecond-precision expiries is integrated.
- **建议改法和验证点:** canonicalize the provider expiry once (e.g. a truncating helper matching `utc`) and use that canonical `Instant` for `validCredential`, the payload, the durable-expiry comparison and the returned `MediaAuthorization`; or compare `Instant.parse(utc(issued.expiresAt()))` on the INSERTED path and return the canonical value. Add a service test (and IT provider mode) using `bound.minusNanos(1)` / an expiry with 7–9 fractional digits and assert 200, a single SUCCESS event, canonical durable `credentialExpiresAt`, and replay equality. Keep the 17-path boundary.
- **修复风险（低）:** one canonicalization/comparison change in an existing allowed production file plus one existing test; no schema, OpenAPI, ACL or production-value change.
- **严重程度（低）:** low, non-blocking for this gate because the production provider is not configured and the path is fail-closed/recoverable; it should be fixed before a production provider is enabled.

Material/high/medium findings: **none**.
