## Findings

### A-01-未修复-中-grant-extension-is-wrongly-rejected-by-witness-grant-expiry-equality

- **位置**: §5 step 5 (plan line 179), and its test coverage in §7 `SharingPlaybackStateReaderTests` #3/#4 and `MediaPlaybackIT` #3 (plan lines 252-257, 275).
- **问题类型**: 状态机漏洞 / 与设计真源冲突 / 测试缺口.
- **当前写法**: "Require `admittedAt < sessionExpiresAt <= admissionExpiresAt <= witness.grantExpiresAt`, **witness grant expiry equal to current immutable grant expiry**, `claim.issuedAt >= admittedAt`, `claim.notBefore >= grant.validFrom`, and `claim.expiresAt <= min(current grant expiry, witness grant/admission/session expiries)`. Broken witness order/expiry consistency => Unavailable ..."
- **反例/失败场景**: An owner extends an `ACTIVE`, not-yet-expired grant after an admission (the documented `EXTEND` transition). The admission witness remains immutable with its original `grantExpiresAt`; the current grant `expires_at` is now larger. The plan's equality fails, so `SharingPlaybackStateReader` returns `Unavailable`/a denial and the still-valid admitted session cannot open playback even though `now` is before the frozen `sessionExpiresAt`, `admissionExpiresAt` and witness `grantExpiresAt`.
- **为什么有问题**: `expires_at` is **not** immutable. docs/14 §4.44 (line 2328) explicitly defines `EXTEND` as a conditional `expires_at` increase and states it "neither retroactively extends an admission recorded under the earlier expiry nor lengthens an existing admission/session"; docs/14 line 253 repeats that `admissionExpiresAt` is the grant `expires_at` frozen at admission and a later extension never lengthens the session. V009 lines 238-240 explicitly permit the increase for an `ACTIVE` grant and only reject it when non-ACTIVE/expired. PA18's own `DefaultShareMediaAuthorizationService.authoritative` validates witness bounds and uses `bound = min(witness.grantExpiresAt, witness.admissionExpiresAt, witness.sessionExpiresAt)` (line 198) and never requires `witness.grantExpiresAt == current grant.expiresAt`; the plan's equality is strictly stricter than PA18's already-shipped behavior, not a neutral fail-closed hardening. `PublicShareAdmissionIT.lostResponseRetryReconstructsWithoutSecondAdmission` (line 199) already performs exactly this extension and proves the original admission/session bounds are retained.
- **直接证据**:
  - Plan line 179: "witness grant expiry equal to current immutable grant expiry".
  - docs/14 line 2328 (`An extension is a conditional expires_at increase ...`) and line 253 (`admissionExpiresAt` frozen at admission; a later grant extension never lengthens an existing admission or session).
  - `backend/src/main/resources/db/migration/V009__sharing.sql` lines 238-240 (`NEW.expires_at > OLD.expires_at` allowed for ACTIVE/future grants).
  - `backend/src/test/java/com/onecall/archtests/container/PublicShareAdmissionIT.java` line 199 (`UPDATE sharing.evidence_share_grant SET expires_at=expires_at+interval '1 day' ...`).
  - `backend/src/main/java/com/onecall/core/sharing/internal/admission/DefaultShareMediaAuthorizationService.java` lines 136 and 198 (witness bounds only; no equality against current grant expiry).
  - Plan line 275 `witnessExpiryMembershipBindingAndRiskChangesFailClosedWithoutWrites` and `MediaPlaybackIT` #2/#3 do not exercise a post-admission extension; the plan's success signal ("valid verified claim reaches one controlled-read open") is therefore unproven for this documented state.
- **影响**: A valid admitted playback session is denied after a normal owner extension, a user-visible playback failure; the plan's deterministic acceptance evidence would not detect it; an implementer following the frozen plan would encode a predicate that disagrees with V009, docs/14 and PA18. It is fail-closed (no unauthorized read/data loss), so it is not a privilege escalation, but it is a material correctness/readiness defect.
- **建议改法和验证点**: Replace the equality with a monotonic check, e.g. `witness.grantExpiresAt <= grant.expiresAt` (the current grant may be extended, never shortened), keep `claim.expiresAt <= min(current grant expiry, witness.grantExpiresAt, witness.admissionExpiresAt, witness.sessionExpiresAt)`, and keep the frozen witness/session/admission bounds. Add: (a) a `SharingPlaybackStateReaderTests` case that admits, extends an ACTIVE grant with `revision + 1`, and proves the original witness/session still yields `Allowed` within its frozen bounds and a claim beyond the frozen bound is denied; (b) a `MediaPlaybackIT` case using the real repository/admin connection that extends the grant after the real admission and proves no new admission/event/count and the frozen session bound still governs; (c) explicitly state in §5 that extension never updates the witness or lengthens the session. If the intent is instead to invalidate extension-affected sessions, the plan must say so and reconcile docs/14/PA18; the current wording ("immutable") is factually wrong.
- **修复风险（低/中/高）**: 低-中. The predicate change is local; the integration fixture needs an owner-role `expires_at` update with a revision increment and a second attempt, using existing V009 semantics. No schema/ACL/API change.
- **严重程度（低/中/高/严重）**: 中.

### A-02-未修复-低-outcome-contract-says-no-IDs-but-the-required-handle-carries-them

- **位置**: §4 exception/redaction rules (plan line 159) conflicting with §3 (lines 116, 118) and §4 step 8 (line 139); test #15/#17 in §7.
- **问题类型**: 契约缺失 / 内部矛盾.
- **当前写法**: "No Throwable, SQL state/text, raw JSON, credentials, **IDs**, bucket/key/version, URL or provider message is stored in an outcome or thrown to a caller." At the same time the success path requires `ControlledReadHandle`/`ReadScope` to contain the exact `ResolvedMediaObject` with `mediaObjectId`, `sha256`, `sizeBytes`, `mimeType`, `durationSeconds`, and §4 step 8 requires the returned handle's complete scope to equal the requested scope "including object ID/hash/size/MIME/duration".
- **反例/失败场景**: An implementer taking the "no IDs stored in an outcome" sentence literally could strip `ResolvedMediaObject` from the success handle or replace it with an opaque token, breaking the required scope equality and the contracted provider input; alternatively, the redaction test could assert structural absence and fail a correct implementation.
- **为什么有问题**: The internal success handle must carry the exact bounded scope; the security requirement is that the value is not exposed through `toString`/Jackson/log/exception, not that the internal value is absent. The two sentences currently contradict.
- **直接证据**: Plan lines 116/118 (handle contains the exact read scope; immutable typed bounded handle), line 138 (compare object ID/duration; construct scope from Found metadata), line 139 (complete scope equality including IDs/hash/size/MIME/duration), line 159 ("No ... IDs ... stored in an outcome").
- **影响**: Implementation/test drift; the success proof may be weakened or the scope equality broken; no security escalation if the redaction is applied, but the contract is ambiguous.
- **建议改法和验证点**: Reword to "no sensitive identifier is exposed through outcome serialization, `toString`, logs or exceptions; the internal handle intentionally retains the exact verified scope, which includes the media object ID/hash/size/MIME/duration." Add a test that the handle's scope is exactly the requested scope while `toString`/root/nested Jackson output is a constant redacted label.

### A-03-未修复-低-inconsistent-Allowed-outcome-is-not-pinned

- **位置**: §4 step 6 (plan line 137), `MediaPlaybackServiceTests` #10 (line 236).
- **问题类型**: 验证优先级未收敛 / hidden design decision.
- **当前写法**: "Allowed requires a non-null checkedAt satisfying the same credential time interval (future/expiry mapped as above); inconsistent Allowed is Unavailable."
- **反例/失败场景**: A state reader returns `Allowed(checkedAt)` with `checkedAt < claim.notBefore` or `checkedAt >= claim.expiresAt`. The first clause says "future/expiry mapped as above" (i.e. `NOT_YET_VALID`/`EXPIRED`), the second says "inconsistent Allowed is Unavailable". Both are fail-closed, but they are different typed outcomes; `MediaPlaybackServiceTests` #10 says it tests "invalid Allowed" without pinning the exact expected result, and the CI source=CI=XML method is already fixed.
- **为什么有问题**: The plan claims an "ordered decision procedure; the first failure wins" and a typed result contract, but this branch has two readings. A future implementation could choose either and still claim plan compliance, producing inconsistent denial semantics and test expectations.
- **直接证据**: Plan line 137; plan line 236 (`stateDenialsUnavailableAndMalformedResultsPreventEvidenceLookup — every state Denied reason, missing/throwing/null/invalid Allowed`).
- **影响**: Minor contract/review ambiguity; both outcomes fail closed, so no unauthorized read.
- **建议改法和验证点**: Pin one rule explicitly: e.g. a non-null `checkedAt` outside the claim's time interval is `Unavailable` (inconsistent `Allowed`), while only a valid adapter `Denied` carries `NOT_YET_VALID`/`EXPIRED`; or emit the mapped typed denial consistently. Update test #10 to assert the exact result at `checkedAt < notBefore`, `checkedAt == expiresAt`, and null.
- **修复风险（低/中/高）**: 低.
- **严重程度（低/中/高/严重）**: 低.

## Open Questions

- **Q-01 `expectedPurpose` provenance and RENEW semantics.** `MediaPlaybackService.authorizeAndOpen(credential, expectedPurpose)` takes an intended purpose from its caller, while the plan forbids client object identifiers but does not state that `expectedPurpose` must be trusted internal transport intent, or whether a `RENEW` purpose should open a read at all rather than only verify/renew. The claim's purpose must match and all three purposes share the same bounds, so this is not an escalation; it should be stated or deferred explicitly.
- **Q-02 dual-clock/skew interaction.** The service uses an injected local `Clock` for claim time and the final fence, while `SharingPlaybackStateReader` uses `repository.now()` (`clock_timestamp()`) for current sharing time; `claim.issuedAt >= admittedAt` and `claim.notBefore >= grant.validFrom` compare provider-claim instants with database instants. The plan intentionally invents no skew/tolerance, but the residual table does not name clock skew or the local-vs-DB comparison as a Q22-owned risk.
- **Q-03 `@ConditionalOnMissingBean` ordering for explicit providers.** The plan requires explicit verifier/reader beans to replace the fail-closed defaults in `MediaPlaybackConfigurationTests` #3, but a regular scanned `@Configuration` with `@ConditionalOnMissingBean` can be processed before a later user configuration, leaving both beans and causing the `ObjectProvider.getIfAvailable` multiple-candidate failure. The plan should state the ordering mechanism (e.g. auto-configuration placement, `@Order`, or an explicit replacement contract), or the test should pin the intended behavior.
- **Q-04 test coverage of a post-admission grant extension.** This is the test side of A-01; until it is added, the plan's "all 320 existing methods unchanged / new methods" arithmetic is accurate but the extension lifecycle remains unproven.

## Final conclusion

**fail (bounded correctness finding; narrow fix, no structural rewrite).** The plan's architecture, one-slice scope, exact 21-path allowlist, source=CI=XML arithmetic (`128+34=162`, `192+6=198`, `320+34+6=360`, `321+40=361`), module/named-interface map, V001-V013 preservation, evidence-seam use, transaction ordering and test/command design are all evidence-consistent and ready. However, §5 itself mandates `witness.grantExpiresAt == current grant.expiresAt` and labels the grant expiry "immutable"; the schema (`V009` lines 238-240), docs/14 (lines 253 and 2328) and PA18's own `DefaultShareMediaAuthorizationService` (lines 136/198) explicitly support a later `expires_at` extension without invalidating or lengthening the existing admission/session, and `PublicShareAdmissionIT` line 199 already exercises it. As written, a valid admitted session would be denied after a normal extension, and the plan's tests do not cover it. Correct A-01 (replace the equality with a monotonic witness-vs-current bound and add the extension state-reader/IT case), pin A-03's `Allowed` outcome, and reword A-02's outcome/redaction sentence; then the retained internal goal has no other blocking question.
