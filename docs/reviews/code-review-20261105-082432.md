## Residual Risk

- Runtime evidence (reported 8 focused command IT / 185 combined tests on PostgreSQL 16.15, Java 21.0.13) was not independently executed because this review is read-only and forbidden from running Maven/Docker; the verdict is static review plus the supplied fix 3/4/5 artifacts. Any claim of green execution rests on those artifacts.
- `CustomerSharesController.createCustomerShare` reads the entire body with `request.getInputStream().readAllBytes()` without a cap (`CustomerSharesController.java:59`). Fix 4 records this as explicitly deferred-with-owner to gateway/security; until a cap exists, very large bodies are a memory/DoS surface. Not re-reported as a new defect because the deferral is accepted, but it remains a live risk.
- Risk/open-binding resolution is a non-locking re-read (`JooqSharingCommandRepository.java:107-143`). A risk-open committed after this read but before the grant commit can still allow one grant; the plan explicitly permits this no-foreign-row-lock window, and later OPEN risk governs subsequent access, so it is a bounded residual window rather than a spec violation.
- Risk SQL/decode failure is deliberately mapped to 403 `SHARE_RISK_BLOCKED` (`JooqSharingCommandRepository.java:142`; plan line 116/142), which hides an outage from clients/operators; the command package is also forbidden by the frozen scans from using `Logger`. Only the returned Problem `traceId` and success-path audit/Outbox provide observability for create. This is plan-mandated but operationally noteworthy.
- No end-to-end integration test creates via the command and then lists via `CustomerShareQueryService`; cross-slice visibility is proven statically (query scope at `JooqShareQueryRepository.java:56-59` matches persisted `created_by_account_id`/`owner_organization_id` and V010 grants), but a create→list regression test would strengthen evidence.
- Low-value test gaps (static behavior still covered by fingerprint): changed `evidenceId` or `verificationMode` under the same creation identity is not explicitly asserted (fingerprint includes both); `creationRequestId` exactly 128 code points is not accepted-boundary-tested; Outbox `codeGeneration` is only key-presence asserted, not value-asserted in `CustomerShareCommandsIT.java:193-203`; POST near-miss create paths (`/shares/`, encoded collection, `;v=1`, `/error`) rely on the shared exact-path filter logic exercised via GET/transition cases rather than dedicated create-POST assertions.
