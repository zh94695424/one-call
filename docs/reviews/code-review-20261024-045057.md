### 01-未修复-低-Request-schema closure misses schema-valued `additionalProperties` on untyped map nodes (pre-existing; outside the adjudicated R3-02 wording)

- **入口/函数**: `walkRequestSchema` in `api/openapi/contract-rules.mjs` (request trust-boundary walker, invoked by `validateTrustedRequestFacts` through `onecall/sensitive-fields`).
- **文件(行号)**:
  - `api/openapi/contract-rules.mjs:805-816` — the walker asserts "no open maps, no schema-valued additionalProperties" but only computes `objectAdmitting` from `node.properties`, `node.type === 'object'` or a `type` array containing `object` (`:809-811`).
  - `api/openapi/contract-rules.mjs:828-832` — `additionalProperties` is walked only when truthy, so `{}` or a typed schema is traversed without any closure failure.
  - `api/openapi/contract-rules.mjs:847` — the generic component rule has the same `type === 'object' && properties` assumption.
- **输入场景**: Add a property to the closed `ClaimRequest` component (`onecall-v1.openapi.yaml:1459-1478`), keeping the C4 media schema a pure `$ref` to that component:
  ```yaml
  probeBareMap:
    additionalProperties:
      type: string
  ```
  or `additionalProperties: {}`. Probe fixtures: `/tmp/a1-rereview3-probes/s1-bare-additionalProperties-empty-schema.yaml`, `s2-bare-additionalProperties-string.yaml`, `s4-items-bare-additionalProperties.yaml`.
- **实际分支**: For a node with `additionalProperties` but no `properties` and no `type: object`/object-containing `type` array, `objectAdmitting` is `false`, so the closure problem at `:812-815` is not emitted. The `additionalProperties` schema is then walked at `:830-831`; `{}` and `{type: string}` produce no problem. The trusted-fact visitor (`:929-941`) only enumerates declared `properties`, so arbitrary keys such as `accountId` are invisible.
- **预期行为**: Per the accepted R2-02 request-body contract and the fix-3 report's own stated invariant ("no open maps, no schema-valued additionalProperties"; `a1-production-openapi-surfaces-spec-s1-implementation.md:99-100`), every request schema that admits an object value must set `additionalProperties: false`, and trusted facts must not be accepted anywhere. A schema-valued `additionalProperties` is an open map even without a sibling `type: object`.
- **实际行为**: `npx redocly lint` exits 0 (valid) for the `s1`, `s2` and `s4` fixtures. A client can therefore send `{"probeBareMap":{"accountId":"..."}}` (or `{"accountId":"..."}` inside the array item) while lint, bundle and `check:s1` stay green. Controls prove the detection asymmetry: `s5` (`properties: {}`) and `s6` (`type: object` + `additionalProperties: {}`) correctly fail with `request object schema must set additionalProperties false`; `s3` (map schema that itself declares `accountId`) fails with `request must not accept trusted fact accountId`.
- **直接证据**: The object-admission predicate at `contract-rules.mjs:809-811` has no `additionalProperties` term; the only closure message is gated by that predicate (`:812-816`); `s1/s2/s4` exit 0 while `s5/s6` exit 1. The walker comment at `:805-806` and report line 100 claim the stronger invariant, so implementation and declared policy diverge for this form.
- **影响**: Latent trust-boundary/validator false negative. No current canonical drift: all 14 S1 operations use the pure closed `ClaimRequest`, `ActivationRequest` or `ActivationTransitionRequest` components, and every `additionalProperties` in the canonical file is `false` (verified at all 38 occurrences). A future coordinated schema edit can introduce an arbitrary-key map that carries server-derived facts while `npm run check:s1` remains green.
- **建议改法和验证点**: Treat `node.additionalProperties !== undefined && node.additionalProperties !== false` as object-admitting (or emit an explicit map-closure problem whenever a non-`false` `additionalProperties` is present) and keep walking the subschema. Add negative probes for `{additionalProperties: {}}`, `{additionalProperties: {type: string}}` and `items: {additionalProperties: {}}`; verify stock S1, the fix-1/fix-2/fix-3 suites and closed-map controls remain green.
