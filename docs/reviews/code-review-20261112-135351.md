# Code Review

## Findings

### LOW-1 — V017 accepts and silently repairs two ACL/history hybrid states, contrary to the stated exact-pre-state/exact-final-state contract

**Evidence**

- `backend/src/main/resources/db/migration/V017__customer_evidence_read_privileges.sql:1278-1295` permits `flyway_schema_history` cardinality `16` **or** `17` and validates only the shape of a row at `installed_rank = 17`.
- `…:1377-1384` chooses the expected ACL set solely from one discriminator: whether `customer_iam_role` currently has `SELECT` on `evidence.evidence_record.id`. When that grant is absent it expects the 50-tuple V016 ACL; when present it expects the 69-tuple V017 ACL. It never cross-checks that choice against whether a V017 history row exists.
- `…:1582-1594` then grants every `final_acls` tuple that is absent from `old_acls`.

**Triggering state and actual behavior**

1. ACL exactly at V016 (269 global; 50 target-pair tuples) **plus** a valid `installed_rank = 17`, version `017`, script `V017__customer_evidence_read_privileges.sql`, description `customer evidence read privileges`, type `SQL`, success `true` row: history passes (17 is allowed), the discriminator selects `old_acls`, the ACL comparison passes, and pass 1 re-grants all 19 V017 tuples. The migration exits successfully and leaves the complete V017 final ACL.
2. ACL exactly at V017 **plus** only 16 predecessor history rows: history passes (16 is allowed), the discriminator selects `final_acls`, the ACL comparison passes, and the migration exits successfully; Flyway then records row 17.

**Expected versus actual**

The sealed plan §7.2 and the synchronized current-boundary prose in `backend/README.md:17`, `docs/17-production-security-design-spec.md:17` and `docs/operations/pa25-production-database-identity-provisioning-runbook.md:17` state: “Replay accepts only exact V016 pre-state or complete V017 final state; partial/widened/wrong-grantor/grant-option/history drift rejects atomically.” These two hybrid states are neither exact pre-state nor complete final state, and V017 accepts them. The state-1 path actively repairs missing grants rather than rejecting.

**Impact**

Non-widening: the accepted states converge to the exact authorized 19-tuple/288-global V017 ACL, cannot add an unauthorized grant, and are unreachable from an ordinary clean Flyway upgrade. The defect is weakened tamper/inconsistency detection: a superuser-level operator who removes the 19 grants while leaving a V017 history row (or who forges a V017 row after manually applying the ACLs) receives a successful migration/repair instead of the documented atomic rejection. No customer API, tenant-isolation, read-path or production-acceptance impact was found.

**Fix direction**

After the ACL discriminator is evaluated, require history cardinality to agree with it: V016 (`old`) ACL state must have exactly 16 predecessor rows and no V017 row; V017 (`final`) ACL state must have the 17th row. Reject the two hybrids with `V017_HISTORY_REJECTED`/`V017_ACL_REJECTED` before any grant. Add the all-19-revoked-with-history-17 and final-ACL-with-history-16 cases to `v017RejectsPartialWidenedWrongGrantorAndGrantOptionStatesAtomically`. Because V017 is frozen input for PA25 and tests, a fix changes the V017 raw SHA256/Flyway checksum and requires re-sealing the PA25 history literal, the boundary/IT checksum literals and the report; that re-seal cost is why this is classified LOW rather than blocking this slice.
