### F-PA6-AGG-01 — Category-2 savepoint evidence never creates or asserts a trial row

- **Entry/function**: `assertV006CategoryTwoSavepointPreservesCommittedTrial` (helper invoked by `concurrentV006FirstTrialAndReservationIdentityHasOneWinner`)
- **File/line**: `backend/src/test/java/com/onecall/archtests/container/PostgresContainerIT.java:11664-11718` (fixture at 11676-11680; assertions at 11709-11718)
- **Triggering scenario**: A reviewer relies on the S2 acceptance claim that the category-2 savepoint preserves the accepted trial, grant and balance after a failed reservation/issuance insert.
- **Actual branch**: The fixture inserts a subject, one `entitlement_grant` and one `entitlement_balance`, commits them, then starts a new transaction, creates a savepoint, attempts an invalid `usage_reservation`, rolls back to the savepoint, and asserts that the grant and balance still exist and that no reservation remains. It never inserts or calls `issue_first_trial`/`trial_grant`, and never asserts a trial row survives.
- **Expected/actual behavior**: Expected evidence: a method-local trial (or a `GRANTED` call) exists before the savepoint and its trial/grant/balance all survive the failed reservation. Actual: only grant/balance are created; trial preservation is unproven. The S2 implementation artifact §3.4 and plan §6.3 item 4 claim trial/grant/balance preservation.
- **Direct evidence**: Lines 11676-11680 insert subject/grant/balance; lines 11709-11718 assert only `entitlement_grant`, `entitlement_balance` and zero reservations; there is no `trial_grant`/`issue_first_trial` reference in the method. `grep` confirms the method contains no trial fixture.
- **Impact**: The category-2 acceptance criterion is not supported by the current suite. A regression in savepoint behavior that discarded trial rows would remain green. This is test-evidence only; the V006 DDL/function rule itself is not shown incorrect.
- **Fix/validation**: Add a method-local `trial_grant` (or invoke `issue_first_trial` in the same transaction after the savepoint setup) and assert trial/grant/balance survival after `ROLLBACK TO SAVEPOINT`; keep the failed-reservation and zero-reservation assertions. Run the focused method and one final full container profile; expected 45/0/0/0 plus exact source/CI/XML set equality. No migration change.
- **Fix risk**: Low; test-only, method-local fixture/assertion.
- **Severity**: Low (test evidence).
