### B-01-未修复-[中]-文档“当前能力”反例未在 allowlist 责任中逐条点名

- **位置**: `backend/README.md:9`; `docs/operations/pa25-production-database-identity-provisioning-runbook.md:28`; `docs/14-production-data-model-and-flyway-schema-spec.md:329-333,626,664,700,2087,2225,2262,3538-3542,3564-3566,4037`（及同类 current-tense 句）；plan §7 paths 16/17/19；plan §2.3。
- **问题类型**: Documentation scope / residual-claim supersession (needs-evidence).
- **当前写法**: Allowlist 只写 “Current privileges / Current V014 runtime overlay / current inventory”；§2.3 要求 append overlay、preserve frozen model，但**未列出** V014 后必然为假的 current 句。
- **反例**:
  - README:9 仍称 “Customer/evidence roles retain existing write/routine capabilities”。
  - Runbook:28 仍称两角色 “have existing write/routine capabilities” 且 command 可 assume “broader approved capabilities”。
  - docs/14 多处将 `evidence_role has SELECT and INSERT only`、`customer_iam_role has column UPDATE only on …`、platform/audit USAGE+EXECUTE 写成当前模型，而非 V001–V013 历史。
- **为什么有问题**: 实现者若只改 inventory 数字与新增 overlay 段，读者仅看 README/runbook/docs/14 原文会得到与 PA26 相反的“当前权限”结论；这与 Goal 的 “replace broader frozen capabilities … minimum” 以及 success signal 的可执行边界不一致。
- **直接证据**: 上述行号原文（本轮 Read/Grep）；plan path 16/17/19 未引用这些句。
- **影响**: 文档同步不完整 → 后续运维/安全按旧能力面理解凭证；不阻断 SQL 正确性，但削弱 “executable least-privilege” 交付完整性。
- **建议改法**: 在 path 16/17/19 责任中显式要求：(1) README:9 与 runbook:28 的 write/routine 句必须改写为 V014 后状态（或明确标注 superseded-by-V014）；(2) docs/14 对 customer_iam_role/evidence_role 的 INSERT/UPDATE/EXECUTE/USAGE current 句必须由 overlay 显式 supersedes，而不是仅追加一段；(3) 其他角色的 “SELECT and INSERT only” 句保持不动（非目标）。
- **修复风险**: 低（纯文档）；过度改写历史模型会违反 plan “preserve frozen structural/business model”，故需按句点名而非全文重写。
- **严重程度**: 中（needs-evidence：S1 文档 diff 必须证明上述句已 supersede/改写）。
- **状态**: needs-evidence
