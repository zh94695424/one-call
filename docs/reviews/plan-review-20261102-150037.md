## 8. Attack-surface assessment

- **Goal-bound minimal design.** One behavioral slice for one endpoint. Every added production artifact is
  forced by the frozen contract: `SelectedCustomerWorkspace` (the goal's server-attested selection),
  `CustomerSharesController` (the goal's route), `CustomerSharePage` (OpenAPI's `SharePage` cannot be the domain
  `SharePage`, whose `nextCursor` is `Optional<ShareCursor>` and would leak the internal cursor record),
  `CustomerShareCursorCodec` (the frozen opaque `Cursor`), and one `package-info.java` (the seam). The plan
  explicitly refuses a fifteenth module, a copied query/projection, a generic cursor framework, a new persistence
  graph and any reflection/request-attribute authority.
- **Architecture boundaries.** Exactly one declared edge (`customer_iam → sharing::customer-query`), one
  annotation change (`customer_iam` `{}` → `{"sharing::customer-query"}`), all 14 rows of the plan's map match the
  real `package-info.java` declarations byte-for-byte in content, sharing stays web-free and customer-import-free,
  and the reverse/implicit dependency is avoided by using DB ACLs rather than Java edges. The exception is
  documented, adjudicated and routed to Architecture rather than silently absorbed into docs/12.
- **State/error sequencing.** The eight-step precedence is total, mutually exclusive and matches the existing
  code paths; buffering guarantees no partial body; `response.reset()` in the writer plus the
  `errorStatus == 0` guard in `CustomerBoundaryFilter.BufferedResponse.finish()` is what makes the serialization-fault
  500 clean, and the filter's outermost `HIGHEST_PRECEDENCE` position means a `ServletException` escaping
  `DispatcherServlet` is still converted to a closed Problem.
- **Concurrency/recovery.** Stateless codec, no key registry, no cursor store, one immutable caller per request,
  per-context session-map reset, explicit context/pool closure before replacement, bounded executor teardown in
  §8.1#8, and §8.2#5/#8 for pool separation, fault recovery and pool reuse. The plan requires 42501 probes to run in
  autocommit separately from the read-only probe so an aborted transaction cannot mask later ACL results — a real
  hazard correctly anticipated.
- **Overcoupling.** Sharing imports are confined to three new customer web files by an exact allowlist replacing
  the blanket ban; customer application/security/persistence keep zero sharing imports; diagnostics stay
  sharing-owned by assertion. The one deliberate coupling (transport composition) is named, bounded and owned.
- **Overengineering.** The 21-bit fixed-width scalar loop is the only non-obvious mechanism and T3/T4 show it is
  necessary: 128 arbitrary Unicode characters are legal in `share_id`, naive UTF-8 base64url would need 683
  characters against a frozen 512 bound, and the chosen encoding lands at 382 bytes / 510 characters. Alternatives
  (compression dependency, DB cursor state, truncation, lossy sort-key hashes, rejecting legal identifiers) are
  explicitly rejected. The cursor is honestly labelled a continuation fingerprint, not a credential.
- **Maintainability.** Two duplication costs are accepted knowingly: the literal web-mapper builder in two test
  files (cheaper than a fifth file or a cross-package public helper) and production assertions appearing in both
  `ModuleBoundaryTests` discovery methods. Both are bounded, both are inside the frozen method budget, and the
  socket-level exact-JSON assertion in §8.1#1 backstops mapper drift.
- **Adversarial test-gap review.** I looked for implementations that would pass the frozen inventory while
  violating the goal and found none unaddressed: client-supplied selectors (§8.1#3), request attributes and
  principal spoofing (§8.1#3), cross-account/workspace cursor reuse including a valid cursor with a reselected
  server workspace (§8.1#2/#4, §8.2#3), method/alias/trailing-slash/encoded-path/HEAD/`/error` bypass (§8.1#6),
  provider-resolution-before-validation (§8.1#4/#9), secret projection canaries across success and every failure
  status (§8.2#7), lifecycle commit between pages (§8.2#4), dual-pool cross-checkout and cross-`SET ROLE`
  (§8.2#5), and default non-web/database-free startup (§8.1#10). The two gaps I did find are B3-02 (profile
  conditions on the new controller) and the B3-04 documentation sites; neither permits a wrong runtime behavior
  to pass silently.
