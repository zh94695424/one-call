- **位置**: §9 "Expected modified production paths" 第 1 项；§9 `OperationsOrderReadBoundaryTests` 断言行；§10 "Customer regressions" 与 positive/negative bullets
- **问题类型**: 测试缺口 / 契约缺失

- **反例/失败场景**: 实施 Agent 为满足 §5.1 的 TRACE/405 探针而加宽 `read` 表达式（再放行一个非 GET method、写成 `path.startsWith("/api/v1/operations/orders")`、顺带放行别的 route family），或把 ERROR 分支改成通用处理。现存守卫全是 `contains`/`doesNotContain` 形式（`OperationsLifecycleBoundaryTests.java:53`、`OperationsCatalogVersionBoundaryTests.java:18`、`OperationsIvrSessionReadBoundaryTests.java:60`、`OperationsActivationReadBoundaryTests.java:104`），只能检测已有字面量被**删除**，无法检测**新增**放行项，因此这类加宽不会让任何现有断言变红。
- **为什么有问题**: 该文件是本次能力唯一的 admission 边界；binding check 3/4 要求 employee authentication 不变且 alias 仍被拒绝。plan 对风险较低的客户文件给了精确 delta 守卫，却对风险更高的 operations 文件只给散文约束，约束不对称，而 §5 step 1 又授权了一个探针驱动的可选二次修改。
