## Findings

### CR-01-未修复-高-歧义主叫可通过停用分支跨归属拒绝待拨任务
- **入口/函数**: `resolveIvrInbound`
- **文件(行号)**: `shared/onecall-business.js:855`
- **输入场景**: 一个仍通过 `validateCallTask` 的快照中，同一 `normalizedCaller` 存在两个活动绑定；该主叫已有一个归属于原账户的 `PENDING` 任务。IVR 请求携带可信主叫和 `callerState: SUSPENDED`。
- **实际分支**: 代码先进入 `SUSPENDED` 分支，按 `normalizedCaller` 遍历并把所有待拨任务改成 `REJECTED/SUSPENDED`；唯一绑定校验直到 `shared/onecall-business.js:872` 才执行，因此此分支完全绕过它。
- **预期行为**: 缺失或歧义的活动绑定必须 fail closed，返回拒绝且任务、呼叫和归属事实保持字节级不变。只有解析出唯一绑定后，才允许拒绝该绑定所拥有的待拨任务。
- **实际行为**: 返回 `ok: true / REJECT_SUSPENDED`，并把另一个归属下的待拨任务不可逆地改为 `REJECTED`。本轮用 `CB-PERSONAL-4471` 加第二个活动绑定复现，`uniqueCallerBinding` 返回 `null`，但 `CT-2001` 仍从 `PENDING` 变为 `REJECTED`。
- **直接证据**: `shared/onecall-business.js:855-865` 在 `shared/onecall-business.js:872-873` 之前写任务；`shared/qa/call-task.test.js:321-339` 只覆盖 ACTIVE 歧义绑定，没有覆盖 SUSPENDED 歧义绑定。控制文档 CF-07 已要求唯一绑定先于任何任务/无任务执行。
- **影响**: 账户/空间隔离和原子失败约束被破坏；异常或脏绑定状态可终止其他归属的有效待拨任务，且任务不能恢复为 `PENDING`。
- **建议改法和验证点**: 在任何会写任务的分支前解析唯一活动绑定；SUSPENDED 仅允许拒绝 `callerBindingId`、owner 和 workspace 均与该绑定一致的任务。补充 missing/ambiguous + SUSPENDED 的无变更测试，以及唯一绑定 + SUSPENDED 只拒绝本绑定任务的正向测试。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### CR-02-未修复-低-Web 截图等待未覆盖 Toast 淡出过渡
- **入口/函数**: Web QA 的任务诊断截图和跨端任务截图
- **文件(行号)**: `web-prototype/qa/qa.js:497`；`shared/qa/cross-channel.js:282`；对应样式 `web-prototype/evidence-hub.html:431`
- **输入场景**: 前序号码验证或授权操作触发 Toast；2.6 秒后应用移除 `visible` 类，QA 立即拍摄任务诊断页面。
- **实际分支**: 两个 QA 仅等待 `classList.contains('visible') === false`，但 Toast 的 `opacity` 和 `transform` 还有 0.2 秒 CSS transition。
- **预期行为**: 诊断截图应在 Toast 完全透明后拍摄，不包含与被审页面无关的覆盖层。
- **实际行为**: 全量 Web Runner 通过，但 `alignment-call-task-diagnostics-1440.png` 和跨端 `alignment-cross-call-task-1280.png` 仍可见灰色 Toast 残影并覆盖表格内容。
- **直接证据**: `.toast { transition: .2s; opacity: 0 }` 与 `.toast.visible { opacity: 1 }`；本轮原尺寸截图直接显示残影，证明类移除不是视觉稳定信号。
- **影响**: 自动化退出码为绿但视觉验收证据受污染，可能遮挡新诊断字段并掩盖布局问题。
- **建议改法和验证点**: 两处等待条件改为 Toast 不存在或 `getComputedStyle(toast).opacity === '0'`，保留无固定 sleep；重跑并原尺寸检查 Web 1440/1024/720 和跨端 1280 截图。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低
