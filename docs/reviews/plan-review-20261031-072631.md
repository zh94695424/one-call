## Material Findings

### F-PA9-PR-01-未修复-中-“All physical indexes”分表计数与 13 个索引总数矛盾

- **位置**: Plan §3 `Exact V009 DDL inventory` table, line 66; corroborated by §3.3 lines 180–182 and §7.3 line 348; S1 test responsibility at §7.1 line 313.
- **问题类型**: 不可直接实施 / 契约缺失 / 测试缺口（exact catalog inventory inconsistency）。
- **当前写法**: The inventory table says “All physical indexes, including PK/UNIQUE” = `5 | 3 | 3 | 13` for grant / admission / access event / total. The same plan’s §3.3 lists `pk_share_admission`, `uq_share_admission_key`, `uq_share_admission_no`, `ix_share_admission_grant_time` (four physical indexes) and `pk_share_access_event`, `uq_share_access_event_domain_id`, `ix_share_access_event_grant`, `ix_share_access_event_admission` (four physical indexes). §7.3 correctly says “all 13 indexes including five secondary definitions”.
- **反例/失败场景**: A code-generation agent that implements the S1 inventory assertion from the per-table row will assert admission=3 and event=3 physical indexes. After creating the named PK/UNIQUE/secondary objects in §3.3, the catalog has 4 and 4, so the assertion fails. Conversely, an agent that follows the total 13 and the explicit object list can produce a correct schema but the plan’s exact inventory table remains a false oracle. The row’s numbers sum to 11, not the stated total 13.
- **为什么有问题**: The work unit’s acceptance depends on exact catalog/test-oracle evidence, and the plan explicitly says to pin keys, indexes, names, key order and index/constraint relationships rather than counts alone. Contradictory per-table counts force the implementation agent to guess which of two plan statements is authoritative and can make an otherwise correct V009 migration fail the S1 test.
- **直接证据**: Plan line 66: `| All physical indexes, including PK/UNIQUE | 5 | 3 | 3 | 13 |`. Plan §3.3 lines 180–182 enumerate 5 grant, 4 admission and 4 access-event physical indexes. Plan §7.3 line 348 requires “all 13 indexes including five secondary definitions”. Doc-14 §4.45 lines 2354–2357 defines admission PK + two UNIQUE + one secondary index; §4.46 lines 2396–2399 defines event PK + one UNIQUE + two secondary indexes; §4.44 lines 2313–2317 defines grant PK + two UNIQUE + two secondary indexes. Current V008 test style uses exact per-table index inventories, not just totals.
- **影响**: Implementation can produce a wrong/missing index-count assertion, fail S1 acceptance on an otherwise correct migration, or weaken the oracle to a total-only check and thereby miss a per-table index omission/regression. The defect is bounded to the plan/test inventory, not the frozen DDL semantics.
- **建议改法和验证点**: Correct the row to `5 | 4 | 4 | 13`; keep the explicit named objects in §3.3 and the total-13 assertion in §7.3. Add a per-table index definition test that asserts all 13 indexes by name and key columns, including the five secondary index names and the `DESC` flag on `ix_share_access_event_grant`. Do not add or alter any migration object. Recheck that the S1 test responsibility says “all 13 indexes” and that the oracle is not derived from the actual migration.
- **修复风险（低/中/高）**: 低.
- **严重程度（低/中/高/严重）**: 中.
- **Status**: `accepted-candidate`.

No other material finding was established. The existing plan’s residual/caller-obligation items are classified below rather than duplicated as findings.
