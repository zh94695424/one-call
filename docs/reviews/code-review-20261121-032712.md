- Location: `backend/src/test/java/com/onecall/archtests/container/OperationsCatalogDraftFixture.java:75-80`;
  consumers `OperationsCatalogDraftLifecycleIT.java:17` and `:40`; DB side

  `audit.append_fact` inserts `p_trace_id` verbatim into `audit_fact.trace_id`. Therefore
  `a.trace_id = callerTrace()` is true by construction and cannot fail for any value the application sends.
  Mutation check: replacing `caller.traceId().toString()` in `appendAudit():218` with a constant or a fresh
  `UUID.randomUUID()` keeps every current test green. Under the previous fixture the same mutation failed,
  because the compared value came from the filter's per-request attribute.
- The surviving non-circular link is unit-level only:
  `CatalogDraftRepositoryTests.appendsExactlyOneActionDerivedAuditAndNoOutbox:89` asserts
  `audits.getLast().get(7)).isEqualTo(caller.traceId().toString())`, so repository→Caller is proven. What is no
  longer proven anywhere is that `Caller.traceId()` is the request trace the web layer hands to the client:
  `OperationsCatalogDraftController.java:52` uses `OperationsBoundaryFilter.trace(request)`, whose fallback at
  `OperationsBoundaryFilter.java:21` returns a **new random UUID** when the attribute is absent, and both the
  container fixture and `OperationsCatalogDraftWebTests.problem()` only ever check that a trace parses as a UUID.
- Impact: a regression in the controller/binder wiring would silently decouple durable audit rows from the
  `traceId` returned in problem envelopes — the operator/customer correlation path for this slice — and success
  bodies carry no trace field, so nothing would surface it. Audit-integrity evidence only; no data, authorisation
  or contract impact; production code as written is correct.
- Bounded fix (zero new identities, no private literal): inside the existing
  `OperationsCatalogDraftWebTests.unexpectedFailuresUseSanitizedInternalProblemWithoutInventedLimiter`, capture
  the argument with an `ArgumentCaptor` and assert the captured `caller().traceId()` equals the `traceId`
  field of the sanitized 500 envelope already parsed by `problem()`. Optionally add one cheap strengthening in
  the fixture helper — assert two successive requests produce two distinct `callerTrace()` values — which kills
  the constant-trace mutation without touching web internals.
