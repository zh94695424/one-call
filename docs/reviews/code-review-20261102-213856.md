### R1-[Low]-The `/me` no-sharing assertion in `CustomerSharesWebTests` is still vacuous and permissive

- **Entry/function**: `CustomerSharesWebTests.meRemainsCompatibleWithLegacyAndSelectedSessions`.
- **File (line)**: `backend/src/test/java/com/onecall/archtests/CustomerSharesWebTests.java:518-519`.
- **Trigger**: a future regression makes `/me` resolve the sharing provider or call `listCustomerShares`.
- **Actual branch**: the test asserts `mockingDetails(...).getInvocations().allSatisfy(invocation -> ... equals "listCustomerShares")`. `allSatisfy` is vacuously true for an empty list and also passes when the only invocations are `listCustomerShares`, and the test does not assert `SELECTION==0` after the `/me` requests.
- **Expected**: A F5 explicitly required replacing this with an explicit zero-invocation/no-provider-resolution assertion.
- **Actual**: The weak form remains.
- **Mitigation already present**: `onlyTwoExactGetPathsPassHighestPriorityFilter` asserts `SELECTION==0` after a prefixed `/pa12/.../me` (`:479`), and `CustomerMeWebTests` asserts the web context has no `CustomerShareQueryService` bean/`CustomerSharesController`. Runtime isolation is therefore evidenced elsewhere, but not by the method the accepted finding named.
- **Impact**: Low test-strength residue; a `/me` regression inside the main web context would not be caught by this method.
- **Fix direction**: replace `allSatisfy` with `assertThat(SELECTION).hasValue(0)` (or an explicit empty-invocation assertion) after the `/me` loop, keeping the ten methods.
- **Severity**: Low.
