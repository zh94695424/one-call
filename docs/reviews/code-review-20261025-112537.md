### Q5 — 两处 Web 等待是否等待计算不透明度 0、无固定 sleep、无应用行为改动，以及 CSS 生命周期边缘

- `web-prototype/qa/qa.js:498-501`：`waitForFunction(() => { const toast = document.getElementById('toast'); return !toast || getComputedStyle(toast).opacity === '0'; })`，紧邻首张任务诊断截图（`:502`）之前；该段无 `waitForTimeout` 或其他固定 sleep。
- `shared/qa/cross-channel.js:283`：对 Web `#toast` 使用相同计算不透明度条件，紧邻三端任务一致性截图（`:284`）之前；同样无固定 sleep。
- CSS 生命周期（`web-prototype/evidence-hub.html:431-432`）：`.toast { … opacity: 0; transition: .2s; … }` 与 `.toast.visible { opacity: 1; … }`；`showToast`（`:3497`）在 2600ms 后仅移除 `visible` 类。因此类移除后仍有 0.2s 不透明度过渡，计算 `opacity === '0'` 是类移除之后真正的视觉稳定信号；两处等待与该生命周期精确对应。
- 挂起边缘：等待上限约为剩余 Toast 时间（≤2.6s）加 0.2s 过渡；Playwright `waitForFunction` 默认超时 30s，且等待与截图之间（`web-prototype/qa/qa.js:495-504`、`shared/qa/cross-channel.js:280-284`）没有再触发 Toast 的操作，不会挂起。
- 假阴性（误放行）边缘：唯一理论窗口是新 Toast 从 0→1 过渡的 t=0 瞬间计算值恰为 `"0"`；该序列中等待前无新 Toast 触发，等待后立即截图，窗口不可达。`#toast` 元素静态存在，`!toast` 分支为防御性兜底。
- 应用行为：Toast 时长、CSS、`showToast` 计时器均未被本修复修改；Operations 侧的 `#toast-root .toast` 分离等待（修复 4 引入、CR-02 未要求改动）保持原样，分离态不存在残影问题。
