## 4. Open questions (non-blocking)

1. **K1 continuity preparation method.** Plan §4 step 2 requires independently confirming "K1 continuity" before B without emitting material, but does not name the method (e.g. out-of-band digest comparison by Security). Mitigation already exists: the B old-K1 verify/replay acceptance row fails observably if bytes diverge, so a bad bundle cannot pass acceptance. Suggested disposition: the S1 runbook should state which non-egressing method Security uses and fold it into CV-2 evidence.
2. **Quiesce-premise citation.** The §4 step 2 premise "A cannot verify fresh K2 credentials" is code-true and covered generically by absent-kid oracles (`disabledAbsentAndUnknownKeysFailClosed`), but no single test is named for the A-rejects-K2 direction. Suggested disposition: the S1 evidence section may cite the absent-kid oracle explicitly so the quiesce rationale is traceable to a named assertion.
3. **Section 9 helper fragility.** The three Python helpers extract CI run blocks by string-splitting `ci.yml`; a formatting change between plan acceptance and S1 execution would break them (loudly, via `check=True`). CI is frozen by this plan's no-CI-change rule, so the window is small. Suggested disposition: Backend QA treats helper failure as a runbook defect to report, not a reason to hand-edit commands silently.
