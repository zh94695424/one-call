### 01-未修复-低-Cursor codec attributes a server-side crypto outage to the caller on continuation reads, so one fault is 400 on page ≥2 and 503 on page 1
- **入口/函数**: `OperationsActivationCursorCodec.decode` / `.encode`, reached from `GET /api/v1/operations/activations?cursor=…` via `DefaultOperationsActivationReadService.read`.
- **文件(行号)**: `backend/src/main/java/com/onecall/core/operations_iam/internal/activationread/OperationsActivationCursorCodec.java:75`, `:48`, `:83`-`:91`; `backend/src/main/java/com/onecall/core/operations_iam/internal/web/OperationsProblemWriter.java:21`, `:23`.
- **输入场景**: a perfectly valid server-issued `cursor` on a second/third page request while the JCE stack cannot serve `Cipher.getInstance("AES/GCM/NoPadding")` or `MessageDigest.getInstance("SHA-256")` — hardened/FIPS provider swap, provider removal, or a `ProviderException` surfacing as `GeneralSecurityException`.
- **实际分支**: `decode`'s single `catch (GeneralSecurityException | RuntimeException invalid)` at `:75` converts the provider failure raised inside the shared `cipher()` helper (`:84`, `:89`) into `Failure(Code.CURSOR_INVALID)` → HTTP 400; the identical helper called from `encode` is caught by `catch (GeneralSecurityException unavailable)` at `:48` → `SERVICE_UNAVAILABLE` → HTTP 503.
- **预期行为**: caller-attributable failures (`IllegalArgumentException` frame/shape failures, `AEADBadTagException` tag mismatch) map to `CURSOR_INVALID`/400; algorithm-provider unavailability is a server condition and must map to `SERVICE_UNAVAILABLE`/503 on both directions, as `:48` already does.
- **实际行为**: one internal fault is externally classified by whether the client happened to hold a cursor. Page 1 (no cursor) fails 503 and is retryable; page ≥2 fails 400 "Invalid cursor", which correct HTTP clients treat as terminal and answer by discarding the cursor and restarting from page 1 — a wrong answer about who broke, plus a retry-semantics inversion and an unrecoverable-looking paging walk.
- **直接证据**: `:48` catches only `GeneralSecurityException`; `:75` catches `GeneralSecurityException | RuntimeException`; `cipher()` at `:84`/`:89` is the only JCE entry point and declares `throws GeneralSecurityException`, so its outage is inside `decode`'s try block (`:68`) and is swept into `CURSOR_INVALID` at `:75`; `OperationsProblemWriter.java:21` renders `CURSOR_INVALID` as 400 while `:23` renders `SERVICE_UNAVAILABLE` as 503. No test cell exercises a provider failure: `OperationsActivationCursorCodecTests.java:47`-`:58`, `:78`-`:90`, `:101`-`:106` cover only malformed frames, tampered tag, wrong/retired keys and malformed anchors.
- **影响**: wrong error class attributed to the caller, silently non-retryable continuation paging under a transient server fault, and externally inconsistent classification of one root cause inside one endpoint. No data, auth or contract-boundary breach; both codes are documented in `api/openapi/onecall-v1.openapi.yaml:1358`-`:1414`.
- **建议改法和验证点**: in `decode`, keep `IllegalArgumentException` and `javax.crypto.AEADBadTagException` → `CURSOR_INVALID`, map remaining `GeneralSecurityException` → `SERVICE_UNAVAILABLE` (parity with `:48`), and let non-security `RuntimeException` fall through to `DefaultOperationsActivationReadService.java:66` → `INTERNAL`. Verification points: `OperationsActivationCursorCodecTests.java:47`-`:58`, `:62`-`:75`, `:78`-`:90`, `:101`-`:106` must still expect `CURSOR_INVALID` (the tampered-tag cells are the guard against over-folding `AEADBadTagException`), `:93`-`:97` must still expect `SERVICE_UNAVAILABLE`, `OperationsActivationReadServiceTests.java:147` must still expect `CURSOR_INVALID`, and `OperationsActivationReadsIT.java:138`-`:145` must keep its 400 shape over real HTTP.
