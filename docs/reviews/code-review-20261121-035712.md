## 10. Ownership drift, over-coupling and maintainability risk

- **Ownership is clean.** The port interface and its `Caller`/`Commercial`/`Code` vocabulary live in
  `operations_iam::operationscommand`; the implementation, projection, SQL and recovery live in
  `catalog_order/internal/operationsdraft`; authority switching stays in `operations_iam`; the web layer owns
  grammar and the single problem envelope. `OperationsCatalogDraftBoundaryTests` and
  `OperationsCatalogDraftConfigurationTests` assert the direction of each edge (no `catalog_order` import in
  the controller, no Spring/jOOQ/SQL in the port, no `operations_iam.employee_account` read by the owner, one
  shared datasource/DSL/transaction template). The two fix rounds removed the only test-side reverse coupling
  (private web trace attribute) and added no new module edge.
- **Intra-package type coupling worth watching.** `CatalogDraftSemantics` imports
  `JooqCatalogDraftRepository.StoredDraft`, so the domain validator depends on the jOOQ adapter's row record
  while the adapter calls the validator. It is package-private and behaviourally harmless, but if a second
  persistence adapter ever appears, hoisting `StoredDraft` onto the `CatalogDraftRepository` interface is the
  one-line move. Not actionable now: the five-file production inventory is plan-pinned.
- **Deliberate duplication retained.** Transaction-witness mechanics mirror the adjacent PA38 adapter, and the
  binder and `CatalogDraftSemantics` each enumerate the enum vocabulary (grammar vs policy). Both are explicit
  plan §11 first-principles choices, and splitting them either now would be an unrelated security-sensitive
  refactor.
- **Guard arithmetic scales linearly.** The CI inventory now ORs 20 historical `paNN_names` sets into every
  per-unit baseline expression, and the frozen-pin guards keep parallel active and historical README rows. This
  is the established convention, correctly applied here (historical digests are preserved, not overwritten),
  but each future unit adds ~20 lines of combinatorial bookkeeping to the same script — a real maintenance
  cost that belongs to CI/evidence custody rather than to PA39.
- **Bind-position coupling in the live fixture.** `callerTrace()` asserts 8 binds, the request-id shape at
  index 6 and the trace at index 7, which ties container tests to `appendAudit`'s positional form. That is the
  intended replacement for the private-attribute coupling and is guarded by the unit-level bind assertion; it
  is a cost to know about, not to undo.
