## Open Questions

1. **`CatalogVersionDraft.versionToken` meaning.** `CatalogVersionDraft` declares an optional `readOnly` singular `versionToken` (`yaml:4439-4443`), but A0 defines `version_token` only per `catalog_order.catalog_offer` channel (`docs/14:374,1065,1073`), the plan's `CatalogVersionDraft` dictionary does not list it (`plan:476`), and O19/docs now say channel version tokens are non-public. With a multi-channel `channels[]` draft, one token has no defined channel association. Owner: A1 contract author/catalog-order; destination: remove the field or define a non-channel token with an explicit A0 owner before aggregate contract review. This is a residual, not an F-01..F-06 regression.
2. **Producer of `PURCHASE_CONSENT_DECLINED`.** C10 accepts `decision: ACCEPT` only, so no A1 operation can submit a PURCHASE `DECLINE`; the 409 code remains declared and documented but has no S1/S2 producer. A0 `append_purchase_consent` still names a declined typed denial (`docs/14:3965`). Owner: Product/activation-consent/catalog-order; destination: a separately approved consent/UI flow or later contract clarification. The controller accepted ACCEPT-only C10, so this is not counted as an F-01 failure.
3. **Scope-extension coverage boundary.** The unknown-scope rejection scans operation objects only; a root-level or component-level `x-onecall-*scope*` extension would not be rejected and is not covered by the current controller probes. No such extension exists in the canonical document. Owner: A1 validation; destination: aggregate review if the policy is intended to cover the whole document.
