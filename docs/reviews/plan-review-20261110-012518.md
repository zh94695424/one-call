## 4. Open questions

1. **Concrete Platform mount mechanism.** The plan rejects symlinks in the file and every path component (§4). Which deployment mechanism will provide a *direct regular file* (not a Kubernetes Secret `..data` symlink mount, Vault-agent symlink, or similar) at the configured absolute path, and where is that confirmed? Destination: Platform/deployment runbook; not a PA22 code change.
2. **Secret-to-bundle production procedure.** Who converts Tencent Secret Manager versions into the exact schema-v1 lowercase-hex bundle, removes DISABLED/DESTROYED versions, guarantees exactly one ACTIVE, and records the kid→version mapping? The plan defers this; confirm the handoff artifact/receipt owner. Destination: Platform/Security later work unit.
3. **Per-call read budget.** The adapter reads and parses on every `currentKeys()` call (§4). Is one bounded 65 KiB read/parse per credential operation acceptable for the target request rate and availability target, and what is the measurable budget? Destination: Platform/operations; the plan explicitly makes no SLO claim.
4. **Atomic replacement contract.** The plan requires operators to replace the whole file coherently and fails closed on an incomplete update (§4). Which deployment mechanism guarantees atomic whole-file replacement (e.g., rename/ConfigMap projection) and who owns that guarantee? Destination: deployment owner.
5. **Frozen-manifest verification.** The task supplied a 1,647-file manifest SHA-256 `6d3e2ddb…818ad`, but this review workspace contains no manifest list and no `.git`; I could not independently recompute it. Confirm Controller-owned manifest evidence. Destination: Controller.
