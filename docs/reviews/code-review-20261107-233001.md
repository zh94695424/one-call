This was investigated as a candidate production-enabling defect and **withdrawn**: `docs/14` §9.31.4 (`:3425`) and T-S3-26 (`:4763`) explicitly pin media playback/seek/renewal to "`OPEN` risk **or an absent/unresolvable** binding/risk projection denies ... with `SHARE_RISK_BLOCKED`, issues no media credential and appends no access event", while §9.31.3 (`:3424`) pins reconstruction/admission as "no `OPEN` risk" (absence allowed). ## Open Questions

1. **Production risk-row provisioning precondition (spec-owned, out-of-slice).** `docs/14` §9.31.4 requires a present binding/risk projection for media authorization (absent/unresolvable → 403 `SHARE_RISK_BLOCKED`, no credential, no access event), while PA17 admission reconstruction and customer share creation allow zero risk rows, and this snapshot contains no production writer for `subject_risk_state` (test INSERTs only). Confirm that production guarantees at least one risk row per shareable binding (or an equivalent unresolvable-projection policy) before media use is expected to succeed; otherwise default-no-risk-row subjects would be denied media despite successful admission/creation. Not adjudicable as an implementation defect against the frozen contract.
2. **Q22 production provider values** remain unavailable in this snapshot; the fail-closed `issueOrReplay` default and `MEDIA_CREDENTIAL_UNAVAILABLE`/`MALFORMED` redaction are the correct behavior until Platform/Security supplies production certification.

## Residual Risk

- **A R-A18-06 (deferred — Sharing backend/provider integration + Platform/Security):** concurrent cross-purpose provider I/O under partial outage can append both a SUCCESS and a FAILURE event for the same share; frozen identity derivation keeps each row internally consistent, but dual-purpose visibility remains. Known, classified, not re-opened.
- **B-R-03 (deferred — Sharing persistence + Platform database reliability):** if the database is down at failure-append time, a FAILURE row cannot be guaranteed; fail-closed 503 is returned but durable FAILURE evidence may be absent.
- **B LOW-1 (deferred — Sharing backend maintainability):** dual fingerprint/event derivation (outside vs inside `authoritative()`) is behaviorally equivalent today but is a drift hazard.
- **B LOW-2 (deferred — Sharing backend maintainability):** duplicate defensive `bound()` / `validateWitnessBounds` checks after the authoritative path; redundant but harmless.
- **A09 (recorded):** `SHARE_GENERATION_STALE` is overloaded for both stale generation and request-identity conflict (contract-forced 409 mapping); consumers cannot distinguish the two causes from the Problem code alone.
- **Denial observability:** media denials append no durable event (spec-pinned §9.31.4) and the media path bans logging (arch-test); denial attempts are therefore visible only at the HTTP/Problem layer — audit-visibility note for operators, not a slice defect.
- **Web test precision:** `PublicShareWebTests:505` uses `isIn(409, 503)` for three Problem codes; exact statuses are pinned elsewhere (service + IT). Minor precision gap, no false-pass path.
