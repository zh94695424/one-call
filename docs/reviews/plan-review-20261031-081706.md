## 4. Material findings

### 01-未修复-低-Non-terminal same-state generation-increase successes are not required witnesses

- **位置**: §4.1 generation paragraph; §7.4 lifecycle matrix / same-state terminal probes; §10 residual row for same-state generation inflation
- **问题类型**: 测试缺口 / 契约缺失
- **当前写法**: The plan states a general rule that same-state generation increases are not limited to named status edges, and requires structural-success witnesses only for same-state EXPIRED and REVOKED. §10 residual names only EXPIRED/REVOKED same-state inflation.
- **反例/失败场景**: An implementation oracle can accept generation increases on (a) named status-changing revoke/expiry edges, (b) code rotation, and (c) terminal same-state writes, while rejecting `LOCKED → LOCKED` or `ACTIVE → ACTIVE` generation increases with no code change. That oracle passes every required S2 success/negative named in §7.4 but still implements a restricted allow-list that contradicts the stated structural rule.
- **为什么有问题**: The plan’s prose is broader than its mandatory witness set. Prior RR-02 accepted the rule that same-state increases are structurally accepted; the required proofs cover only the terminal subset. An implementation agent that builds the oracle from the named witness list can ship a too-narrow classifier and still look compliant.
- **直接证据**: §4.1 “Same-state generation increases are not subject to an exclusive named-status-edge allow-list”; §7.4 “require the same-state terminal successes below”; fix-2 §4 required SQL only uses `:terminal_status = 'EXPIRED'` then `'REVOKED'`.
- **影响**: Test oracle under-specifies the structural contract; later service/replay work may treat non-terminal same-state generation inflation as structurally impossible when it is not; review cannot distinguish a correct guard from a terminal-only carve-out using the required probes alone.
- **建议改法和验证点**: Add one rollback-isolated same-state non-terminal generation-increase success witness (prefer `LOCKED → LOCKED`, optionally also `ACTIVE → ACTIVE` with no code change, `revision +1`, all other fields unchanged) beside the terminal pair. Assert structural success and service-forbidden classification. Keep decrease negatives unchanged. A blanket edge allow-list remains incorrect.
- **修复风险（低）**: 低 — one more bounded S2 probe in the already-planned method; no DDL/ACL/slice change.
- **严重程度（低/中/高/严重）**: 低

### 02-未修复-低-Non-lock mixed owner-action shapes remain prose-only

- **位置**: §4.1 mixed-action paragraph; §7.4 mixed-action probe; §10 residual mixed-action row
- **问题类型**: 测试缺口 / 残余风险分类
- **当前写法**: Exactly one mixed structural probe is mandatory: ACTIVE→LOCKED plus strict future expiry increase. The matrix is explicitly not an exhaustive SQL-shape classifier; services must issue one named action per conditional update.
- **反例/失败场景**: A guard or test helper that special-cases only “status change to LOCKED plus expiry increase” can still accept other mixed writes (for example ACTIVE→REVOKED plus expiry increase while `OLD.status` is ACTIVE) as if they were named actions.
- **为什么有问题**: The general service rule is broader than the one required probe. This is acceptable as residual service discipline, but it is the same class of under-proof that produced prior mixed-action confusion.
- **直接证据**: §4.1 “This matrix describes atomic owner actions, not every structurally possible mutable SQL statement shape”; §7.4 requires one exact mixed probe only.
- **影响**: Residual service/replay risk; not a persistence DDL blocker if the service contract is later enforced outside this migration.
- **建议改法和验证点**: Keep as residual. If a later slice hardens the oracle, add at most one additional mixed revoke+extension structural probe; do not add a mixed-action DDL ban.
- **修复风险（低/中/高）**: 低 if deferred; 中 if forced into this persistence slice.
- **严重程度（低/中/高/严重）**: 低
