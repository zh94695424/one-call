## Residual Risk

- 已接受容量上限（detail >100 bindings/claims → 503；`activationStatus` 过滤 >100 batch/10,100 候选且 tail 未证明 → 503，`DefaultOperationsSubjectReadService.java:115` 与 `:91`）。Owner/destination: Product/Backend/Database。**注意：该残余的前提“存在总请求 deadline”被 finding 1 推翻，需 Controller 重新裁决，不得按原样视为已闭合。**
- 缺 `(created_at, id)` 稳定排序索引、count 聚合扫描量（`V003:28-30` 无该索引）。Owner/destination: Database/Platform，需 synthetic `EXPLAIN (ANALYZE, BUFFERS)` + 部署 SLO 证据；新索引/迁移是停止条件。
- 可观测性：`DefaultOperationsSubjectReadService.java` 的 24 处 `require()` fail-closed 分支（另有 owner 适配器/`OperationsReadContext` 的 `unavailable()` 分支）与全部 SQL/privilege/timeout/config 故障统一塌陷为 sanitized 503，`Failure` 关闭 stacktrace/cause（`OperationsSubjectReadService.java:61`），jOOQ `withExecuteLogging(false)`，整条链无 logger、Hikari 无 leak detection → 运维只能用 traceId 关联到 PG 侧日志才能区分“缺 key/缺凭据”与“角色成员被撤”与“数据形状不符”。与既有仓库约定一致（254 个主源文件仅 1 处 Logger），故不作 finding。Owner/destination: Platform/Backend（建议：与隐私规则兼容的非 PII 分类计数器/结构化原因码）。
- 路由准入谓词在两个模块两处复制（`OperationsBoundaryFilter.java:30-33` 与 `CustomerBoundaryFilter.java:55-60` 使用相同的 `[^/;%]+` + `contextPath+path==requestURI` 判定），且计划 §（`pa33-...-plan.md:47,281`）明确要求保留这种“相同局部谓词”。漂移后果是 fail-closed（新 GET 变 404/504），不构成绕过：operations 过滤器 order `HIGHEST_PRECEDENCE` 早于 customer `+1`，且两者同受 `@Profile("web")`+servlet 条件约束（`OperationsWebConfiguration.java:23-25`、`CustomerWebConfiguration.java:51-53`）。Owner/destination: Backend/Web（未来若再加读路由，考虑共享谓词常量或按前缀注册过滤器）。
- 端到端可达性依赖尚不存在的生产件：仓内无任何 `implements EmployeeSessionVerifier`（被 `OperationsSubjectReadBoundaryTests` 显式钉住），故真实员工会话签发前该路由在部署中恒 401/503；cursor key ring 的生成/分发/轮换属 Security/Platform；六角色 login 供给属 Platform/Database。Owner/destination: Identity/Platform/Security（Q17/Q23、deployment readiness）。
