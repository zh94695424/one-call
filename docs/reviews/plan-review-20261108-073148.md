## New findings

### RR2-01-未修复-高-V013 “exact” `pg_shdepend` predicate rejects the schema-USAGE ACL dependency created by V013's own grant

- **位置**: Corrected plan §8 / “V013 exact privilege matrix and assertions” line 58 (`Exact dependency predicate: pg_shdepend … permits deptype='a' only for pg_class dependencies on the four listed tables … Expand relacl and attacl …`), the matrix “Role identity … Any role config, membership, ownership/dependency …” row, and the required V013 replay/postcondition proof.
- **问题类型**: 状态机漏洞 / 契约缺失 / 不可直接实施（计划内部自相矛盾，RR1-02 的残余）。
- **当前写法**: The plan permits `deptype='a'` rows only for `pg_class` dependencies on the four granted tables, expands only `relacl`/`attacl`, and says “Reject every other deptype … and every unexpected ACL item”, while V013 itself executes `GRANT USAGE ON SCHEMA evidence` under `evidence_owner`.
- **反例/失败场景**: On PostgreSQL 16.15, the exact planned role attributes and grant set produce `pg_shdepend` rows (`refclassid='pg_authid'`, `deptype='a'`) grouped as `pg_class: 15`, `pg_namespace: 1` (total 16; zero non-`a` rows). The single `pg_namespace` row is the expected `GRANT USAGE ON SCHEMA evidence` ACL (grantor `evidence_owner`, grantee `evidence_media_reader_role`, privilege `USAGE`, not grantable). A literal implementation of the stated predicate flags exactly 1 unexpected row: the postcondition after initial grants raises `P0001`, and the role-present replay precondition (exact expected ACLs) likewise fails before the compatibility branch. V013 can therefore never satisfy its own “exact state” check, and the required “two successful V013 SQL executions” role-IT cannot pass as written.
- **为什么有问题**: V013 necessarily creates both ACL dependency classes; the plan's own V011 precedent explicitly permits `pg_namespace` dependencies on `sharing`/`evidence` in addition to `pg_class` table dependencies. The correction addressed RR1-02 for the 15 column rows but omitted the 1 schema row and the `nspacl` expansion, leaving the same reported failure mode partially unfixed. Because the plan calls this the “Exact dependency predicate” and “pre/postconditions compare exact state, not samples”, an implementation agent cannot safely infer the missing carve-out.
- **直接证据**: Isolated PG16.15 probe (no workspace writes): `SELECT classid::regclass::text, count(*) … GROUP BY 1` → `pg_class|15`, `pg_namespace|1`; `SELECT count(*) … WHERE deptype <> 'a' OR NOT (classid='pg_class' AND objid IN (four tables))` → `1`. V011 precondition (lines 75–84) permits `pg_namespace` rows for `sharing`/`evidence` alongside `pg_class` rows; V011/V012 postconditions use `deptype <> 'a'`. Plan line 58 and matrix line 49.
- **影响**: A literal V013 implementation fails its postcondition on first application and/or its replay precondition; the required replay proof fails; the implementation agent must invent an unstated predicate; the plan is not code-generation-ready for the specific RR1-02 area under re-review.
- **建议改法和验证点**: Permit exactly the expected second dependency class: one `deptype='a'` row with `classid='pg_namespace'::regclass`, `objid='evidence'::regnamespace`, expected grantor (`evidence_owner`), grantee (`evidence_media_reader_role`), privilege `USAGE`, `is_grantable=false` (expand `nspacl` too), and reject every other `pg_namespace`/non-`a`/unexpected row. Add a role-IT assertion enumerating all 16 expected `pg_shdepend` rows (15 `pg_class` + 1 `pg_namespace`) both after initial apply and on replay; keep the “no ACLs” initial state assertion.
- **修复风险（低/中/高）**: 低（单条谓词/扩展补全，不改变 role、column、query、DTO、allowlist 或 CI 算术）。
- **严重程度（低/中/高/严重）**: 高。
