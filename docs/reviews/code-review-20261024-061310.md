Any object target — an empty `{}` schema, an arbitrary annotation-only object, or a non-schema OpenAPI component object such as a Response Object — is returned as `{ node }`.

  - `api/openapi/contract-rules.mjs:856-871` — the closure test only recognises `properties`, `type: object`, an object-containing `type` array, or the R4-01 `additionalProperties` form. A terminal `{}` (or an object whose only keys are annotations/unknown keywords) is not object-admitting, so no closure problem is emitted. The trusted-fact visitor at `:987-993` only enumerates declared `properties`, so an empty terminal hides every key.
  - `api/openapi/contract-rules.mjs:897-911` — the generic component closure rule only fires for `type === 'object' && properties`; it does not reject an empty component schema. `api/openapi/redocly.yaml:20` additionally disables `no-unused-components`.
  - `api/openapi/onecall-v1.openapi.yaml:321-326`, `:405-410`, `:777-782`, `:851-856` — the media-schema purity check is applied only to the immediate `$ref` string; the chain terminal is unrestricted.

An empty object is a valid Schema Object.
- **输入场景** (coordinated future edit; not present in the canonical contract): add `components.schemas.Empty: {}` and a closed `ClaimRequest` property `evil: {$ref: '#/components/schemas/Empty'}` (or make the chain terminal `#/components/responses/NotFound`). - **实际分支**: `resolveRequestSchemaRef` returns `Empty`/the Response Object; `walkRequestSchema` visits it, finds no `type`, `properties`, `additionalProperties` or banned boolean, and emits nothing. The property therefore admits arbitrary JSON, including `{"accountId":"...","role":"..."}`, while the operation still passes the closed request components and the `x-onecall-replay-order`/error checks.

### R4-02 — finite local `$ref` chains and fail-closed unresolved refs: 已修复

- `contract-rules.mjs:179-203` resolves any finite local `#/...` chain with a seen-set keyed by `$ref` string and no depth cutoff; external refs return a problem at `:184-186`, cycles at `:187-190`, missing/non-object/non-boolean targets at `:196-199`.
- `walkRequestSchema:828-846` consumes the resolver result, reports an explicit custom problem and stops the branch; an unresolved ref is never visited as a concrete schema.
- Legitimate closed recursive object schemas terminate through the resolved-node `seen` set (`:845-846`) while the resolver's pure-ref cycle detection does not reject object recursion. The entry-node `$ref` sibling check (`:829-832`) is preserved.
- The accepted 21-hop/50-hop trusted-fact manifestation is closed by construction: the chain reaches its terminal object and the trust/closure checks run on it. The generic `deref` remains unchanged for non-request-schema consumers, as disclosed in the fix artifact §7.
- This matches the controller wording (`project-execution-control.md:194`, `:205`). Finding 01 above is a different terminal-kind/permissiveness gap and does not reopen R4-02.
