## 3. Route, Canonical URI, Connector, Optional Auth, Problem

### 3.1 Route admission

- Exactly one `@GetMapping` on `PublicSharesController` for `GET /api/v1/public/shares/{capabilityToken}`. No POST/PUT/DELETE/HEAD/PATCH sibling; no alternate media type.
- `CustomerBoundaryFilter` public branch: `GET` + `servletPath.matches("/api/v1/public/shares/[^/;%]+")` — token segment forbids slash, semicolon and percent, so encoded/canonical-breaking presentations never enter token construction or DB work.
- Canonical gate remains `(contextPath + servletPath).equals(requestURI)`. Encoded slash is not authorized: it fails the matcher/canonical check first and is answered as closed `404 NOT_FOUND` Problem.

### 3.2 Tomcat encoded solidus

- `CustomerWebConfiguration.customerEncodedSolidusHandlingCustomizer` is the **sole** `WebServerFactoryCustomizer<TomcatServletWebServerFactory>` and sets only `EncodedSolidusHandling.PASS_THROUGH`. No second filter/valve, no `DECODE`, no system property, no ERROR-dispatch fallback.
- Purpose (implementation report): Tomcat 11.0.27 previously rejected encoded slash **before** the filter with HTML 400; PASS_THROUGH lets the request reach the existing canonical gate for a closed 404 Problem.
- Tests pin the behavior:
  - `PublicShareWebTests` rejects `a%2Fb`, `a%20b`, `//`, wrong case with `404 NOT_FOUND`.
  - `CustomerWebConfigurationTests` starts a real connector, asserts `passthrough`, then probes root-path encoded slash → `404`.
  - `PublicSharesIT` probes `a%2Fb`, `a%2fb`, `a%252Fb` (and hostile Accept/Authorization) → `404 NOT_FOUND` on both `/` and `/pa15` contexts (implementation report §connector tests; IT lines 51–53).
- `CustomerApiBoundaryTests` freezes single filter, `/*`, REQUEST-only, HIGHEST_PRECEDENCE, connector source shape, and bans competing filters/valves/decoding.

### 3.3 Optional customer authentication

- Public GET with **absent** `Authorization` → anonymous path; service proceeds; if mode requires `ORGANIZATION_MEMBER` (or membership does not match), response is metadata + `verificationChallenge.customerSessionRequired=true` and **`content` absent**.
- Public GET with **any supplied** `Authorization` → strict authenticator; **no anonymous downgrade**. Failure is a typed Problem, not a silent fallthrough to metadata-only success with a forged principal.
- `PublicSharesController.MemberAccess` is a single lazy closure: non-`CustomerRequestPrincipal` → `NONMATCH`; match only when workspace is ACTIVE `ORGANIZATION` and grant `organizationId` equals the selected customer. No second filter, no connector, no session cookie path on this route.
- `CustomerBoundaryFilter` null-guards `getRemoteUser()`; optional bearer construction only when `publicRead && no Authorization` (defensive; the controller still re-derives membership).

### 3.4 Problem contract

- Envelope stays closed five keys: `{type,title,status,code,traceId}` with `type:"about:blank"` and `application/problem+json`.
- `CustomerProblemWriter` additions: `SHARE_TOKEN_INVALID` → 404, `SHARE_EXPIRED` → 410; `SHARE_REVOKED` remains 410. Route rejection remains separate `404 NOT_FOUND`.
- `PublicShareQueryException` is stackless, code-only; frozen codes only. Unknown `RuntimeException` in the service outer catch maps to sanitized `SERVICE_UNAVAILABLE` (503) without leaking message/cause.
- Web tests assert the typed mapping set including 401/403/410/422/429/503/500 and both 404 codes.
