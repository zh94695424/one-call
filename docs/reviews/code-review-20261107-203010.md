### RH-01 — Low (test coverage): provider credential/expiry validation boundaries are only partially exercised

- **Entry/function:** `DefaultShareMediaAuthorizationService.authorize` provider-result branch and `validCredential`.
- **File(lines):** `backend/src/main/java/com/onecall/core/sharing/internal/admission/DefaultShareMediaAuthorizationService.java:77-83`, `:205-209`; test provider `backend/src/test/java/com/onecall/archtests/container/PublicShareAdmissionIT.java:419-425`, failure matrix `:919-925`.
- **Input scenario:** provider returns `Issued` whose credential contains a NUL, has more than 2048 code points, or is not UTF-8 encodable; or whose expiry is null, equal to the decision time, or at/below it.
- **Actual branch:** `validCredential` correctly rejects all of these (`:206-208`), but no test drives those branches. The IT provider modes cover only `UNAVAILABLE`, `THROWN`, `MALFORMED`, `BLANK` (a whitespace credential) and `BEYOND_BOUND`; a repository-wide test search finds no 2048/2049, NUL, surrogate, null-expiry or equal-window media-credential case.
- **Expected:** accepted plan §6.1/§7 require “all credential/expiry validation boundaries”.
- **Actual:** the length, NUL, encoding, null and equal-window expiry checks are implemented but unproven.
- **Direct evidence:** the enumerated modes at `PublicShareAdmissionIT.java:419-425`; `validCredential` at `:205-209`.
- **Impact:** a regression that drops the 2048/NUL/encoding/expiry guard would still return an invalid or out-of-bound credential with HTTP 200, and no test would fail.
- **Suggested fix / verification:** add IT provider modes (or service-level cases) for over-length, NUL, unpaired-surrogate and null/equal-time expiry, asserting 503 `DEPENDENCY_UNAVAILABLE`, exactly one `FAILURE`/`FAILED` event with `MEDIA_CREDENTIAL_MALFORMED`, and no success event.
- **Fix risk:** Low (test only).
- **Severity:** **Low**.
