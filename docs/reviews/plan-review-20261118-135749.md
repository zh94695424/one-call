### RR4-A-01-未修复-[低]-Operations-side catalog admission literal is not pinned while the Customer predicate is exact

- **位置**: cumulative plan §4.2 `OperationsBoundaryFilter` bullet (`:121`), §5.1 classifier (`:150-164`), and §9.3 concealment subcase (`:383`), contrasted with the exact §5.4 Customer literal (`:194-204`).
- **问题类型**: 契约缺失 / 测试缺口.
- **当前写法**: The Customer predicate is specified byte-for-byte, but the Operations admission is described only as "add exact catalog POST templates to the admission classifier" and "exactly the two PA38 POST templates". No Operations-side method/regex/context-path literal is written, although the two filters must agree and the Operations filter runs first.
- **反例/失败场景**: An implementer uses a broader Operations pattern (for example, omits `[^/;%]`, adds a `.*` suffix, or uses a regex that admits `/publications;x` or a percent-encoded suffix). Because admission is checked before authentication at `OperationsBoundaryFilter.java:46-49` versus `:50-51`, a malformed path with missing or invalid credentials then returns `401 UNAUTHENTICATED` instead of the specified sanitized `404 NOT_FOUND`. With valid credentials it would be 404'd later by the Customer filter, and §9.3's concealment subcase explicitly requires valid credentials (`:383`), so the precedence deviation escapes the planned assertions.
- **为什么有问题**: §5.1 promises that every non-allowlisted catalog mutation is concealed as the shipped sanitized NOT_FOUND (`:156-164`), and a code-generation-ready plan should make the two filters' route shapes identical. The Customer side alone is pinned; the first-line classifier remains an inference for the implementation agent.
- **直接证据**: Plan `:121`, `:150-164`, `:383`, `:194-204`; `OperationsBoundaryFilter.java:38-49` (admission precedes `authenticate`); `CustomerBoundaryFilter.java:48-68`.
- **影响**: Implementation divergence or rework; an unauthenticated path-shape oracle / 401-vs-404 precedence divergence that the planned positive-concealment test would not detect; review cannot treat the Operations-side literal as verified from the plan alone.
- **建议改法和验证点**: Add the exact Operations literal to §4.2/§5.1, identical to §5.4: `"POST".equals(request.getMethod()) && path != null && path.matches("/api/v1/operations/catalog/versions/[^/;%]+/(publications|offsales)")`; state that both predicates are the same template. Add one missing/invalid-credential concealment assertion for a malformed catalog alternate inside the existing `concealsOtherCatalogMethodsAndUris` identity; no new test identity or count change is needed.
- **修复风险（低/中/高）**: 低.
- **严重程度（低/中/高/严重）**: 低.
