## 4. Open questions

1. **Byte-exact comparison implementation detail (low).** §4.4 requires byte-for-byte comparison but does not name the SQL mechanism (`=`, `COLLATE "C"`, `convert_to(..., 'UTF8')`, `bytea`). All grammar operands are enforced ASCII, and deterministic collations (the default) equate text only when byte-equal, so a plain `=` is correct on typical targets; a nondeterministic ICU collation (external cluster input) could accept canonically equivalent but byte-different text. Confirm at implementation that comparison is explicitly byte-exact. Impact if omitted: at worst cosmetic marker variants pass; identity fields (decimal OIDs) cannot be collation-confused, so no adoption bypass was demonstrated.
2. **Pre-fix verbatim diff not recomputable from this snapshot (informational).** The frozen pre-fix plan (`23FEF94F…`) is not present in this snapshot; the fix artifact's verbatim-comparison claims for unchanged sections (§3, §§5.2–5.3, §7, fifteen test methods) were instead cross-checked by independently re-deriving every checkable invariant from primary sources (all passed, §2 items 8–10), plus structural line-shift consistency with initial review A's quoted pre-fix line numbers. Residual confidence is high but the byte-diff itself is author evidence.
