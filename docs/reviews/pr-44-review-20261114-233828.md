### 2-未修复-中-详情历史 101 上限只由 bindings 侧触发，claims 侧上限与 1 边界未被真实证明

- **文件(行号)**: `backend/src/test/java/com/onecall/archtests/container/OperationsSubjectReadsIT.java:234-248`; `backend/src/test/java/com/onecall/core/operations_iam/internal/subjectread/OperationsSubjectReadServiceTests.java:328-338`; `backend/src/main/java/com/onecall/core/operations_iam/internal/subjectread/DefaultOperationsSubjectReadService.java:128`; `backend/src/main/java/com/onecall/core/subject_number/internal/operationsread/JooqOperationsSubjectReader.java:80,86`

### 3-未修复-中-“任意 binding 存在 OPEN 风险”未被区分于“展示 binding 风险”
- **入口/函数**: `OperationsSubjectReadsIT.allBindingRiskStatesAndAbsentActivationHaveExactProjection`
- **文件(行号)**: `backend/src/test/java/com/onecall/archtests/container/OperationsSubjectReadsIT.java:106-114`; `backend/src/main/java/com/onecall/core/subject_number/internal/operationsread/JooqOperationsSubjectReader.java:31-33`; `backend/src/main/java/com/onecall/core/operations_iam/internal/subjectread/DefaultOperationsSubjectReadService.java:301`
- **输入场景**: The test inserts `RETIRED/CLEARED` (id 1) and `DISABLED/OPEN` (id 2). Ranking is ACTIVE=0, DISABLED=1, RETIRED=2, so the DISABLED row is also the display binding.
- **实际分支**: `risk_open` is computed by `EXISTS (... subject_risk_state r ... WHERE rb.subject_id = s.id AND r.state = 'OPEN')` over all bindings. In this data set the only OPEN row is on the display binding.
- **预期行为**: OPEN must be proven to come from any binding, including a non-display disabled/retired binding; an all-CLEARED/no-risk subject must be CLEARED; ACTIVE bindings must be covered.
- **实际行为**: An implementation that derived `riskState` from the display binding only would produce the asserted OPEN here; no ACTIVE binding, no OPEN on a non-display binding, and no binding-without-risk CLEARED case exists.
- **直接证据**: IT 108-109 (only RETIRED/CLEARED and DISABLED/OPEN); SQL 31-33 (existential over all bindings); service 301 (display rank). The test name says "all binding risk states" but only two of three lifecycles and one risk shape exist.
- **影响**: The core existential risk rule (masked Operations risk projection) can regress to a simpler display-only rule without any test failing; a subject with OPEN risk on a non-display binding could then be misclassified as CLEARED.
- **建议改法和验证点**: Within the same method, add an ACTIVE binding, move the OPEN risk onto a non-display binding, add a CLEARED subject with no risk rows, and assert list/detail `riskState` and the masked display field independently.
- **修复风险（低/中/高）**: 低.
- **严重程度（低/中/高/严重）**: 中（test false confidence on a security-adjacent projection rule).

### 4-未修复-中-“least privilege”证据弱于声明：owner 投影只做正例、ACL oracle 不含列权限/成员关系、边界测试不校验 owner SQL 的 schema 封闭

No active privilege escalation or current production defect was observed — the shipped five adapters do use their own schemas and the operations role test is a genuine 42501 proof.

- **修复风险（低/中/高）**: 低.
- **严重程度（低/中/高/严重）**: 中（test/claim overstatement over a security boundary; recommend `needs-more-evidence` or narrow the claim).
