## Assumptions tested

| 假设 / lens | 反例与判断 |
| --- | --- |
| Goal-bound minimal design | 旧工单/退款/发票直达 URL 可能仍可操作；计划明确移除可执行代码并检查旧路由；13 页单 slice 无中台扩展 |
| Architecture boundary | 机房位于运营商不意味着外部开通；本文把开通/资格/权益归后台，IVR 仅提供真实会话与确认，边界成立 |
| Identity / claim | 登录同手机号可能是号码回收；计划禁止无条件开放历史证据，保留冲突与线下处理，原型不播放原文 |
| State machine / best practice | 重呼、重复确认、跨端认领可能再次领试用；稳定业务主体+活动唯一键，不按账户/规则版本新发，试用不可覆盖 |
| Versioning / recovery | 发布套餐可能改旧订单；新版本和订单快照隔离，执行重验版本与页面，适合本地原型 |
| Optimal solution / overengineering | 可以仅隐藏旧菜单，但旧链接和授权还会保留错误模型；替换当前入口与动作比十角色打补丁更直接，保留 Git 历史即可追溯 |
| Overcoupling | 三端不需要同步重写；当前基线文档统一接口语义，只改后台，客户原型作为未更新边界明确列出 |
| Testing | 主叫缺失、拒绝、试用耗尽、冲突、旧版本、角色切换均有失败路径验收；不以页面存在代替真实状态断言 |

## Findings
