- **位置**: Plan §Exact application and persistence interfaces (evidence reader and create step 2) and §Datasources, transaction and bean lifecycle; docs/14 §2.12/§10.21; V010 evidence grants.
- **问题类型**: 架构边界 / 不可直接实施

- **为什么有问题**: The plan prohibits V001-V010 changes and adds no `SECURITY DEFINER` object. Java module ownership does not change the PostgreSQL effective role. ### 7-未修复-高-The 23505 replay strategy cannot run in the aborted transaction
- **位置**: Plan §repository SQLSTATE handling and create step 4 / concurrent-create test.
- **问题类型**: 并发恢复风险 / 状态机漏洞
- **当前写法**: The plan says recognized deterministic uniqueness is translated to a replay reread and prohibits implicit retries. It does not specify `ON CONFLICT`, a savepoint or a new transaction.
- **反例/失败场景**: A concurrent insert that loses the unique constraint raises PostgreSQL `23505`; PostgreSQL aborts the entire current transaction, so a subsequent select in that same transaction fails with `25P02` rather than returning the winner. The planned concurrent same-identity test cannot prove one grant and one replay with the stated behavior.
- **为什么有问题**: A caught Java SQL exception does not restore a PostgreSQL transaction. The plan simultaneously forbids implicit retry and gives no transaction-preserving conflict strategy.
- **直接证据**: `docs/gateflow/pa14-sharing-command-service-foundation-plan.md:94`, `:108-112`, `:151`; `docs/14-production-data-model-and-flyway-schema-spec.md:3403`; V009 unique `share_id` and token-hash constraints at `backend/src/main/resources/db/migration/V009__sharing.sql:33-34`.
- **影响**: Concurrent creation can return a sanitized 500 after a correct loser insert, or the implementation may add an unapproved retry.
- **建议改法和验证点**: Specify `INSERT ... ON CONFLICT (share_id) DO NOTHING` with same-statement/transaction-safe reselect, or establish a savepoint and roll back only to it. If the advisory locks make this path impossible, remove the 23505 replay claim and prove the lock serialization. Test the exact winner/loser SQLSTATE and replay result.
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高

## Final conclusion

**fail**

The plan is not code-generation-ready. The evidence projection cannot execute under the planned command role/ACL, the deterministic share/event identities are typed incorrectly, the transaction port omits required lock/risk/context operations, the new named interfaces are not representable under the current Modulith boundaries, an existing boundary test is omitted, and rotation/error/payload/concurrency contracts remain incomplete. These are structural blockers rather than residual implementation risks; revise and re-review before starting implementation.
