### F2-Low-RR5-01/RR5-03 preflight and projection are fused into one block, so an environment retry can silently rebind to a second projection

- Location: plan §11.0 setup block (`PA38_VALIDATION_ROOT="$(mktemp -d /tmp/pa38-lf-validation.XXXXXX)"` followed in the same block by the launcher/JDK/Docker preflight subshell), §11.0 "run this setup once per candidate ... in one Bash shell retained for all §11 commands", §11.3 "same bound projection", §13 Fix6 evidence paragraph requiring preflight "before source implementation and again in the final bound projection".
- Failure scenario: with `set -euo pipefail`, the current Docker denial aborts the fused block after the projection has already been created and normalized. The plan then requires re-running preflight once the host is resolved, but preflight has no standalone form, so re-running the block executes `mktemp -d` again and yields a second `/tmp/pa38-lf-validation.*` tree. Nothing in §11.0/§13 says whether the bound root is reused, retired or duplicated, so gates and XML custody can be spread over two projections while still being reported as "the bound projection", and the recorded `projection_backend=` value from the first run no longer matches the tree that produced the reports. The regeneration rule in §11.0 is keyed only to candidate-byte changes, which does not cover this environment-driven path — the exact situation fix6 is currently in.
- Consequence bound: `clean -Pcontainer-smoke verify` prevents stale-report false-green within any one reused tree, and the copied `backend/.gitignore` keeps `target/` out of `git status`, so this is a provenance/custody ambiguity, not a totals-integrity defect.
- Fix: require the report to name one recorded `PA38_VALIDATION_ROOT`, and state that after an environment stop the agent re-runs only the preflight subshell against that recorded root (its inventory assertions stay valid because generated `target/` is excluded), regenerating the projection only on candidate change and then re-running every §11.1-§11.3 gate from the single new root. Add one clause forbidding any relaxation of `set -euo pipefail` as a way to "record individual exits"; per-step exits are recorded by re-running each check separately after the fail-fast block, never by neutralizing it.
