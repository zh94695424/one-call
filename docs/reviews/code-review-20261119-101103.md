### PA38-RR-A-02 — Low (non-blocking; residual observer starvation)

- **Entry/function:** real 55P03 subcase of `concurrentPublishersYieldOneActiveWinner`.
- **Location:** `backend/src/test/java/com/onecall/archtests/container/OperationsCatalogVersionLifecycleIT.java:73-90`.
- **Expected:** deterministic observation of the real lock wait while the product `lock_timeout=250ms` (`JooqCatalogSaleLifecycleRepository.java:39`) stays unchanged.
- **Actual:** the fix pre-starts one persistent prepared observer and completes its first `pg_stat_activity` query before submitting the blocked command; the admin holds the advisory xact-lock for the whole command wait, so the wait window is the full 250 ms and the observer polls it. This removes the prior ordering race in practice.
- **Impact:** on an extremely scheduler-starved host the poll could in principle miss the ≤250 ms wait and yield a false-red. It cannot yield a false-green (a success requires a real observed wait); product behaviour is unaffected.
- **Fix direction:** only if it ever flakes, replace polling with a lock-wait event/latch; do not change the product timeout.
