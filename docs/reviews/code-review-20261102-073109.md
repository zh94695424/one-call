## Findings (ordered by severity)

### RR-1 — Low — Verifier acquisition/creation failure is classified as 500, not 503

**Location**

- `backend/src/main/java/com/onecall/core/customer_iam/internal/security/CustomerBearerAuthenticator.java:26-37`
- `backend/src/main/java/com/onecall/core/customer_iam/internal/web/CustomerBoundaryFilter.java:71-75`

**Evidence**

`authenticate()` performs `verifiers.stream().limit(2).toList()` at line 26 *outside* the verifier-invocation `try` block that begins at line 29. `ObjectProvider.stream()` is the acquisition point: it resolves/creates candidate verifier beans. If an existing verifier bean cannot be constructed, a `BeansException` (for example `BeanCreationException`) is thrown by `stream()` and escapes `authenticate()`. The boundary filter then catches it in its generic `catch (Exception failure)` branch and writes `INTERNAL` (HTTP 500). The accepted plan's failure contract maps an unavailable verifier and bean-initialization failures to `SERVICE_UNAVAILABLE` (503).

I reproduced the escape with a process-local probe: an `ObjectProvider` whose `stream()` throws a `BeansException` caused `CustomerBearerAuthenticator.authenticate(...)` to throw that `BeansException` uncaught (`ESCAPED ...BeansException`), rather than a `CustomerContextException(SERVICE_UNAVAILABLE)`.

**Impact**

This is fail-closed and does not leak the cause, secrets or a partial body. It is a client-visible status-classification gap (500 instead of 503) and is not covered by the current tests. It is **not reachable in the current zero-adapter product**: with no verifier bean the stream is empty, and zero/multiple candidates are already handled as 503. It becomes reachable when a future lazy verifier bean exists and its creation fails.

**Relationship to prior B2**

This does not reopen B2. The candidate-count check is correctly outside the invocation `try` (zero/multiple → 503), and invocation exceptions retain the specified 401/503 translation. RR-1 is the adjacent acquisition/creation path before the count check.

**Disposition**

Owner: Backend/Security, together with the future production verifier adapter. Preferred treatment: wrap provider enumeration/creation in the same `SERVICE_UNAVAILABLE` translation used for invocation, or catch `BeansException` around the stream. Not a blocker for the current no-adapter S1 slice; record it as a forward-looking contract gap.

No Critical, High or Medium findings were found.
