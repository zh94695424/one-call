## 3. Findings

### F-PA15-01 — P3 — The throwing `MemberAccess` callback branch is not actually exercised

- Location：`backend/src/test/java/com/onecall/archtests/sharing/PublicShareQueryServiceTests.java:170-180`; production branch `backend/src/main/java/com/onecall/core/sharing/internal/publicquery/PublicShareQueryService.java:67-69`.
- Evidence：The test stubs the callback to throw at line 173, but the next call at line 174 passes a **null** `MemberAccess`; `PublicShareQueryService` fails first at `require(grant.ownerOrganizationId().isPresent() && memberAccess != null)` (line 66) without invoking it. The following call at line 178 uses a grant with `Optional.empty()` owner organization and again fails before invocation. Therefore the `try { match = memberAccess.check(...) } catch (RuntimeException) { throw error(SERVICE_UNAVAILABLE); }` branch is never executed by the suite.
- Root cause：The test orders the throw stub after the null/no-tenant cases but never issues a request with a non-null throwing callback and a valid tenant.
- Trigger：A future regression in the inner callback catch (e.g. mapping to `INTERNAL` or allowing a customer type to escape) would not be caught. Today the outer `catch (RuntimeException)` in `getPublicShare` still maps such a failure to 503, so the current runtime behavior is fail-closed.
- Impact：Plan §9 `organizationContentRequiresCurrentMatchingMember` explicitly requires “null/throwing callback fails closed”; the throwing half is not proven. Test-only defect; low severity.
- Recommendation：Within the existing test method, call `fixture.service.getPublicShare(new OpaqueCapabilityToken("token"), fixture.member)` after the throw stub with a valid tenant-bearing grant and assert `SERVICE_UNAVAILABLE`.

### F-PA15-02 — P3 — Malformed capture-timestamp case is masked by the identity equality gate

- Location：`backend/src/test/java/com/onecall/archtests/sharing/PublicShareQueryServiceTests.java:114-118`; production `PublicShareQueryService.java:149-151`.
- Evidence：The fixture’s evidence projection identity is fixed at `{"capturedAt":"2026-11-05T23:58:20Z"}`. The malformed case replaces that string in the frozen snapshot with `2026-11-05T23:58:20` (no offset). `content()` first evaluates `identity.equals(content.path("identityAtCapture"))` and fails 503 for the **mismatch**; `timestamp(text(identity, "capturedAt"))` and its `OffsetDateTime.parse` rejection branch are never reached. The IT’s malformed snapshots (`{}`, `null`, `{`, `{"content":null}`) likewise fail before a timestamp parse.
- Root cause：Only the frozen snapshot is mutated; the evidence-side identity is not made to match the malformed value.
- Trigger：A corrupted grant whose frozen identity and live evidence identity both carry an offset-less/unsupported timestamp. The service currently returns 503, but no test pins that parser behavior.
- Impact：Plan §9 requires malformed capture/snapshot fail-closed in `immutableEvidenceProjectionIsOrderedAndFailClosed` and `publicProjectionAndDependencyFailuresFailClosedWithoutPartialContent`; the parser branch is unproven. Test-only defect; low severity.
- Recommendation：Use a reader seam whose `identityAtCapture` equals the frozen malformed identity, or mutate both sides consistently, so the failure is demonstrably from timestamp parsing.

### F-PA15-03 — P3 — Negative dependency/provider coverage is narrower than the plan claims

- Location：`backend/src/test/java/com/onecall/archtests/container/PublicSharesFixture.java:117-126`, `PublicSharesIT.java:152-193`, `PublicShareWebTests.java` (mock service), `PublicShareQueryServiceTests.java` (null SHA only).

The constructor/config architecture tests and current source make this unlikely, and the service’s outer catch would still yield a sanitized 503.
