### RR-001-未修复-[中]-S1 parent-delete probes target append-only parents and do not isolate the deferred parent direction; the trigger hides the FK error

- **位置**: `docs/gateflow/pa8-v008-evidence-foundation-plan.md:527` (S1 RESTRICT parent-delete list), `:361` (§4 order table), `:572-577` (§9 S2 classification), `:604-607`; `docs/14-production-data-model-and-flyway-schema-spec.md:4038` and `:4042`; plan §3.2/§3.6.
- **问题类型**: 测试缺口 / 不可直接实施 / 状态机与触发器交互.
- **当前写法**: S1 says "RESTRICT parent-delete probes (delete `business_subject`, `call_record`, `inbound_session`, `usage_reservation`, `media_object`, `evidence_record` with children present) for the 8 ordinary RESTRICT FKs" and "Parent deletes involving the deferred event FK use `expectCommitFailure`." §4's table similarly says parent delete with a RESTRICT child is immediate `23503` and parent delete involving the deferred event FK defers to COMMIT.
- **反例/失败场景**: `evidence.media_object` has `trg_media_object_immutable BEFORE UPDATE OR DELETE` and `evidence.evidence_event` has `trg_evidence_event_immutable BEFORE UPDATE OR DELETE` (doc-14 §10.22). Deleting `media_object` to probe `fk_recording_media_object` or `fk_evidence_artifact_media` raises `P0001` from `reject_row_mutation`, not `23503`; deleting an `evidence_event` parent to probe `fk_evidence_source_event` likewise raises `P0001`, not the commit-time deferred `23503`. Only `evidence_record` is a mutable head with a BEFORE UPDATE-only guard, so it can be the deferred parent for `fk_evidence_event_record`; but if the same record also has an artifact child, the ordinary `fk_evidence_artifact_evidence` RESTRICT action fires immediately at `DELETE`, so the deferred probe must use an event-only child.
- **为什么有问题**: The plan promises exact negative evidence for the frozen FK matrix. A literal implementation cannot observe the promised `23503` for the media/event parent directions; the immutability trigger hides the target, and an implementer may delete or weaken the assertion. The established V007 pattern deliberately selects a mutable parent with no delete trigger for RESTRICT probes (`PostgresContainerIT.java:8253-8277`).
- **直接证据**: Plan lines 527/361; doc-14 §10.22 lines 4038/4040/4042; plan §3.2/§3.6; existing V007 parent-delete proof at `PostgresContainerIT.java:8253-8277`.
- **影响**: S1 FK test is red or passes for the wrong reason; the "all 8 ordinary RESTRICT FKs" and deferred-parent evidence is not trustworthy; implementer may disable constraints/triggers in an unplanned way.
- **建议改法和验证点**: State the parent table and child fixture per FK. For trigger-protected parents, either (a) exclude them from the literal statement-time probe and prove the FK with a savepoint-scoped `ALTER TABLE ... DISABLE TRIGGER <named trigger>` plus catalog restoration (the V007/V006 cleanup pattern), or (b) expect the append-only `P0001` and document that the FK is not reached. For deferred `fk_evidence_event_record`, use an `evidence_record` parent with an event-only child and `expectCommitFailure(..., "23503", "fk_evidence_event_record")`; do not use `evidence_event` as the deleted parent. Assert the trigger state/catalog is restored.

### RR-002-未修复-[中]-`ck_evidence_source_ref` cannot produce a `23514` witness: the NOT NULL column raises `23502` before the CHECK

- **位置**: `docs/gateflow/pa8-v008-evidence-foundation-plan.md:634` (witness map), `:147`/`:165` (§3.4), `:609` (exact-name claim); `docs/14-production-data-model-and-flyway-schema-spec.md:2148` and `:2166`.
- **问题类型**: 测试缺口 / SQLSTATE isolation / 不可直接实施.
- **当前写法**: The 39-check map assigns `ck_evidence_source_ref` the negative witness "`source_ref_id` NULL" and says savepoint-isolated `23514` with exact constraint name unless noted. The column is `source_ref_id uuid NOT NULL`; the check text is `source_ref_id IS NOT NULL`.
- **反例/失败场景**: Inserting a NULL `source_ref_id` violates the column's NOT NULL constraint first (`23502`, `null value in column "source_ref_id" ...`); PostgreSQL does not evaluate the redundant table CHECK for that row. `expectSqlFailure(..., "23514", "ck_evidence_source_ref", ...)` therefore fails because the actual SQLSTATE is `23502`, not `23514`.
- **为什么有问题**: The plan's completion assertion is "all 39 named checks have a positive or negative witness". This check is logically implied by the NOT NULL column attribute and is unreachable as a failing constraint under the frozen schema. Claiming a `23514` witness is factually impossible unless the test temporarily drops the column NOT NULL attribute, which would no longer prove the production contract.
- **直接证据**: doc-14 line 2148 (`uuid | NO`) and line 2166 (`source_ref_id IS NOT NULL`); plan line 634; plan line 609 exact-name rule.
- **影响**: S2 cannot satisfy "39/39" as written; implementer may weaken the assertion, silently skip the check, or mutate the column attribute. The completion report would overclaim coverage.
- **建议改法和验证点**: Mark this check as redundant with the column NOT NULL attribute. Record the executable witness as a `23502` NOT NULL probe (and separately assert the check definition exists in the catalog), or explicitly document an isolated `ALTER COLUMN ... DROP NOT NULL` savepoint probe with catalog restoration if the team insists on a `23514` witness. Do not claim the CHECK is the enforcement that fires. If the redundancy is considered a frozen-design residual, record its owner (doc-14/design owner) and destination rather than inventing a schema change in PA8.
- **修复风险**: 低
- **严重程度**: 中
