### PA14-R2-B-01-未修复-中-策略ProviderResult.UNAVAILABLE被笼统映射为503，与冻结create契约的403 SHARE_ACCESS_POLICY_UNAVAILABLE直接矛盾
- **位置**: §Canonical command contract（`ProviderResult<T> ... Provider/configuration absence is explicit unavailable/fail-closed`）、§HTTP behavior 末段（"Missing command service/provider maps to controlled 503"）、§Configuration and lifecycle
- **问题类型**: 契约缺失 / 不可直接实施
- **当前写法**: 策略 provider 返回 `ProviderResult.UNAVAILABLE`（或 bean 配置缺失）时，plan 的笼统句把它与"缺 command service"一起映射为受控 503；403 仅授予 "declared policy/risk failures"（即 ALLOW/DENY 形状下的 `FORBIDDEN`/`SHARE_ACCESS_POLICY_UNAVAILABLE`）。
- **反例/失败场景**: 生产环境（本 work unit 明确不批准 production policy）里每个 create：策略输入 missing/unreadable → provider `UNAVAILABLE` → 按 plan 返回 503 `SERVICE_UNAVAILABLE`；而冻结 create 契约规定该条件必须是 403 `SHARE_ACCESS_POLICY_UNAVAILABLE`。实现与按 plan 编写的映射/测试会固化错误状态码，且因生产 provider 不接线，CI 全绿也无法暴露——错误只在生产首次出现。
- **为什么有问题**: 三个冻结真源一致：OpenAPI create description "Missing or unreadable approved sharing policy is `SHARE_ACCESS_POLICY_UNAVAILABLE`"（`api/openapi/onecall-v1.openapi.yaml:2806-2810`，403 响应描述同文 :2856 附近）；docs/15:215 将 `SHARE_ACCESS_POLICY_UNAVAILABLE` 定义为 403 "分享访问策略依赖不可用"；docs/14 §9.29.1（docs/14-production-data-model-and-flyway-schema-spec.md:3396）"absent, unapproved or ambiguous policy fails closed with `SHARE_ACCESS_POLICY_UNAVAILABLE`"。plan 自己的 create 域名码集也用它表达"策略不可用"。笼统 503 句直接覆盖并违反该语义；rotate 侧则相反——rotate 的 docs/15:249 精确域集只有 `{NOT_FOUND, SHARE_TRANSITION_CONFLICT}`，其 `rotationPolicy` UNAVAILABLE 只能合法走 503，plan 未作区分。
- **直接证据**: 上述 OpenAPI/docs/15/docs/14 行与 plan 文本 "Missing command service/provider maps to controlled 503"、"Provider/configuration absence is explicit unavailable/fail-closed"；V001 `ck_outbox_event_domain` 含 `SHARE_ACCESS` 与 V010:151,158 的 append 函数授权说明失败关闭路径必然走这些映射。
- **影响**: 生成错误代码 / 违反冻结错误码集合 / 生产首个策略缺失路径返回错误状态，客户端与网关按 503 重试而语义应为 403；review 不可验收。
- **建议改法和验证点**: 拆分笼统句为逐操作规则：(a) command service bean 整体缺失（disabled）→ 503 `SERVICE_UNAVAILABLE`（保持不变）；(b) create：`creationPolicy` 的 `ProviderResult.UNAVAILABLE` 与配置缺失 → 403 `SHARE_ACCESS_POLICY_UNAVAILABLE`；(c) rotate：`rotationPolicy` UNAVAILABLE → 503 `SERVICE_UNAVAILABLE`（因 rotate 未声明策略码）。在 `CustomerSharesCommandWebTests.invalidCommandAndMissingServiceMapToProblemResponses` 与新增断言中固化 (b)/(c)，并断言每个 mutation 的实际码集恰等于该操作 docs/15 精确集。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### PA14-R2-B-02-未修复-中-create/transition 的授权 fail-closed 路径未映射到已声明类型码，NOT_FOUND 在 create 上不可表达且风险读不可为空
- **位置**: §Identity/modules（"Empty means no readable qualifying projection and is handled fail-closed"）、§Create algorithm（"Validate evidence ownership/solidified state and risk"）、§Repository and transaction API（`readEvidenceAccessAndRisk` 返回非 Optional；token-hash 碰撞 "fail closed without disclosure"）、§Revoke/rotation algorithms（context 重读失败无码）
- **问题类型**: 契约缺失 / 不可直接实施
- **当前写法**: plan 反复声明 fail-closed，但只有 `FORBIDDEN`/`SHARE_RISK_BLOCKED`/`SHARE_ACCESS_POLICY_UNAVAILABLE`（策略/风险）与 `SHARE_TRANSITION_CONFLICT`（transition）被显式接线；对以下路径未指定发出哪个 `ShareCommandException.Code`：create 时投影 empty（evidence 缺失/非本人/非 SOLIDIFIED）、binding/risk 投影 absent/unresolvable、active account/org/membership 重读失败、跨账户 token-hash 碰撞。
- **反例/失败场景**: A 账户用 B 账户的 `evidenceId` 调 create：plan 流程走到 "Validate evidence ownership/solidified state" 失败，但 create 未声明 404（OpenAPI create 响应集为 201/200/401/403/409/422/429/503/default），`ShareCommandException.Code` 枚举又含 `NOT_FOUND` 且 plan 只说 "operation mapping below determines which are emitted" 而未排除 create 使用它。实现者必须在 403 `FORBIDDEN`、422 `VALIDATION_FAILED`、409 `SHARE_CREATION_CONFLICT` 中自行发明一个（docs/14:3396 只说 "fails closed with the existing typed error"——该 typed error 在本 foundation 里尚不存在）；不同 slice/不同 agent 会固化不同码，且 `invalidCommandAndMissingServiceMapToProblemResponses` 不会覆盖此路径。同样：`readEvidenceAccessAndRisk` 返回类型非 Optional，subject/binding 行缺失时 repository 契约无法表达，只能现造异常。
- **为什么有问题**: 这是用户可见的 wire 映射与持久面契约，plan 自称 code-generation-ready 且"one canonical contract"；留下多个合法但互斥的实现选择即违反其自身的精确性约束，也与 docs/15:249 的精确集校验存在踩空风险。
- **直接证据**: plan §Repository and transaction API 签名 `readEvidenceAccessAndRisk(...): EvidenceAccessRisk`（无 Optional/空态定义）；OpenAPI `api/openapi/onecall-v1.openapi.yaml:2848-2860` create 响应集无 404；docs/14 §9.29.1/§9.29.2（absent/unresolvable 与 non-active context 均只写 "fails closed"）；docs/15:249 create 精确域集。
- **影响**: 实施 Agent 跑偏 / 生成未声明 404 或漂移的 403/422/409 映射 / 测试固化错误语义 / 后续返工。
- **建议改法和验证点**: 在 plan 内固定逐条件映射，例如：projection empty 与 ownership/solidified 失败 → 403 `FORBIDDEN`（或明确选择 422，二选一写死）；binding/risk projection absent/unresolvable → 同一声明码；active-context 重读失败（create/revoke/rotate 共用）→ 403 `FORBIDDEN`；token-hash 跨账户碰撞 → `INTERNAL`/500 且零披露；并把 `readEvidenceAccessAndRisk` 改为返回 Optional 或定义空态记录语义。为每条映射补一条 web/服务层命名断言。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### PA14-R2-B-03-未修复-低-create 请求校验谓词未收敛到 V009 check 约束，可产生客户端可达的未声明 500
- **位置**: §Canonical command contract（Create 字段定义与 "Validate request"）、§Create algorithm、§Test inventory
- **问题类型**: 测试缺口 / 契约缺失
- **当前写法**: plan 固定了字段类型与长度（expiresAt required、maxAdmissions positive、designatedMobile 1–32 "required only when mode policy requires"），但没有把校验谓词写到 V009 冻结 CHECK 所需强度。

## Residual Risks（建议跟踪去向）

- 事务隔离级别未书写：create 的 ON CONFLICT reselect 与 transition 的 replay lookup 依赖默认 READ COMMITTED 语句级新快照；若实现顺手加 REPEATABLE READ，replay 路径会在并发下返回错误空态。建议 PA14 控制文档记入"命令事务保持 READ COMMITTED"。
- revoke 过期不持久化 EXPIRED：与 §7.4 "expiry persists when observed" 的 owner-expiry 路径分工不同，属边界裁剪；留给后续 admission/expiry work unit 时应在 Control 记录该分工，避免误读为遗漏。
- docs/14 的注册与 wiring 措辞修改发生在 implementation 阶段；其措辞若偏离 owner 确认（no table/column/migration/role/grant/secret），应由 CI/docs 校验兜底。
- 新 IT 依赖 per-class 容器隔离（与 SharingRoleLeastPrivilegeIT 同型）；若未来共享容器复用，probe 成员资格会落入 PostgresContainerIT 快照面。
