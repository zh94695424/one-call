## Findings

### P1-01-未修复-[高]-路由可读权限被错误复用为订单、分享和导出的写权限
- **入口/函数**: `pageOrderDetail`、`pageShares`、`pageExports` 及对应 click handlers
- **文件(行号)**: `operations-prototype/onecall-operations-admin.html:614`、`:651`、`:656`、`:867`、`:873`、`:876`
- **输入场景**: 客服角色拥有 `trade-read` 和 `service` 路由访问权，进入失败订单、有效分享或部分失败导出任务。
- **实际分支**: 页面无条件渲染“执行幂等补发”“撤销”“重新申请”按钮；handler 不检查动作权限，直接更新业务状态并追加成功事件。
- **预期行为**: 客服只读脱敏元数据；订单补发限运营/财务，分享和导出命令限运营/证据公证等有 `C` 权限的角色。路由可读不应隐式授予写能力。
- **实际行为**: 客服可执行跨域写命令，形成错误的权限提升契约。
- **直接证据**: `roleAllows` 只控制 route area；三个 handler 均未调用动作权限判断。
- **影响**: 评审批准错误的 RBAC，生产实现可能把路由读取权限当作受控命令权限。
- **建议改法和验证点**: 建立 `canCommand(command)` 动作权限真源；按钮渲染与 handler 双重校验；QA 增加客服对三个动作的入口不可见和伪造事件拒绝。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### P1-02-未修复-[高]-列表第二条记录会打开第一条记录的业务事实
- **入口/函数**: P1 各列表与动态详情 renderer
- **文件(行号)**: `operations-prototype/onecall-operations-admin.html:516`、`:537`、`:551`、`:565`、`:580`、`:612`、`:632`
- **输入场景**: 点击 `AIJ-67022`、`NPS-44011`、`NRT-55184`、`ONA-60992`、`PRD-ENT-2026-R3`、`ORD-20261018-114` 或 `INV-261018-021`。
- **实际分支**: 动态路由只把 `id` 用于标题或完全忽略，正文仍硬编码第一条记录的证据、状态、商品、订单或发票事实。
- **预期行为**: 点击列表记录后，详情对象标识、状态和字段必须来自同一 fixture；未实现的详情不应提供可点击链接。
- **实际行为**: 页面显示互相矛盾的对象事实，可能对错误记录执行按钮。
- **直接证据**: 所列详情函数正文硬编码首条 fixture，而列表为第二条生成真实 `data-route`。
- **影响**: 对象身份错配、评审无法验证详情契约，动作可能看似作用于错误业务对象。
- **建议改法和验证点**: 为每个可点击 fixture 建立按 ID 选择的详情数据和只读/可操作状态；QA 遍历第二条链接并断言标题、对象和状态一致。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高

### P1-03-未修复-[中]-重试后时间线遗漏紧邻历史版本和尝试
- **入口/函数**: `pageAIJobDetail`、`pagePreservationDetail`、`ai-retry`、`preservation-retry`
- **文件(行号)**: `operations-prototype/onecall-operations-admin.html:522`、`:542`、`:843`、`:846`
- **输入场景**: AI v3 失败后重试生成 v4；存证尝试 #2 为 `0015` 后重试生成 #3。
- **实际分支**: handler 只增加数字计数器；AI 时间线固定渲染“当前版本、v2、v1”，遗漏 v3；存证时间线固定渲染“当前尝试、#1”，遗漏 #2。
- **预期行为**: 追加新版本/尝试后，所有历史记录仍可见且顺序稳定。
- **实际行为**: UI 声称历史不可覆盖，但最关键的直接前序记录从详情中消失。
- **直接证据**: 状态仅保存 `aiVersion` 和 `preservationAttempts` 计数，时间线由固定字符串重建，不保存追加历史集合。
- **影响**: 不可变历史契约无法验证，失败原因和重试依据丢失。
- **建议改法和验证点**: 将 AI 版本和存证尝试建模为追加数组，页面从数组渲染；QA 断言重试后新旧版本/尝试同时存在。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 中
