The fix artifact’s line “Added the bounded aggregate-fix amendment to §5.1/§5.2/§6.3” (`aggregate-fix-1.md:24`) overstates §5.2, which shows no corresponding hunk. Recommendation: sync §10.16/§5.2 (or explicitly label them as subsets). Owner: docs/plan maintainer; destination: same-wave doc errata or the controller.
2. **Plan §8 vs the fix authorization.** Plan §8 still says “Do not modify `docs/12` or `docs/14`: they are frozen design sources” (`plan:490`) while the newly added §6.3 “Allowed files” authorizes the docs/14 errata (`plan:376`) and the fix edited docs/14 (§4.27 errata, `docs/14:1534`). The prior S1 fix-1 had explicit user authorization; the aggregate-fix authorization provenance is in the controller/task record, not in the control document. Recommendation: record the aggregate-fix docs/14 authorization and reconcile plan §8. Owner: controller.
3. **Extra-member redacted-payload probe absent.** The check rejects extra top-level/source/receipt members via strip-to-empty (`V005:297-299`), and the whole predicate is catalog-verified by `pg_get_constraintdef` equality; but no executable negative probe inserts an *extra* member (the six new probes cover missing members and bad fingerprints only, `PostgresContainerIT:13905-13914`). Plan §6.3 item 3 says the check “rejects missing/extra members.” This is a test-evidence completeness item, not an observed SQL defect. Owner: database test maintainer.

This is the pre-existing accepted service-owned boundary, not introduced by the fix. Owner: IVR service wave.
