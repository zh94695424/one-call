## Open Questions

- `pg_default_acl` empty-ACL corner: the default-ACL predicate is `pg_default_acl CROSS JOIN LATERAL aclexplode(defaclacl)`; a row with an empty ACL (for example a function default ACL produced only by revoking PUBLIC EXECUTE) yields zero lateral rows, so the `defaclrole = ANY(managed_oids)` arm never evaluates for that row. A runtime-owned empty default ACL may still be rejected by the `pg_shdepend` ownership arm (classid `pg_default_acl`, deptype `o`), but this was not provable without a live catalog, and the new test covers only non-empty default ACLs. Impact is expected to be non-widening (empty defaults are restrictive), but the plan's literal "reject any row owned/granted by a runtime node" wording is not demonstrably satisfied for that corner.
- Plan-versus-evidence environment keys: accepted plan §3 still states dash-removed canonical keys (`ONECALL_SHARINGPUBLICREAD_DATASOURCE_URL`, `ONECALL_SHARINGCOMMAND_ENABLED`, ...), while the implementation, IT, README, runbook, implementation checkpoint and Control all use the evidenced underscore keys (`ONECALL_SHARING_PUBLIC_READ_DATASOURCE_*`, `ONECALL_SHARING_COMMAND_ENABLED`, ...). The correction is recorded truthfully rather than silently written back into the frozen plan; the Controller should retain it as an implementation-evidence correction and must not use the plan wording as production configuration guidance.
- Environment-binding proof is a synthetic `SystemEnvironmentPropertySource` added through an application initializer, not a real process-environment launch. This is the same property-source type and binder path as the OS environment, and the tested keys are the evidenced ones, but an actual process-environment run was not exercised.
- `\o /dev/null` is POSIX-specific output suppression. Under a native Windows `psql` the redirection can fail non-fatally, potentially adding nonsecret output and breaking the "success is exactly the fixed marker" claim. The runbook is shell/POSIX-oriented but does not state that requirement explicitly.
- Pre-existing A2/A5 contract failures remain present in the product tree; the task classifies them as baseline, and the base reproduction is identical, so they are not attributed to PA25.
