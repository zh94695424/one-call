The file is not in the 44-path allowlist. Both files are mandatory to make the post-S1 tree green, but neither is authorized or enumerated. An implementation agent following the plan literally cannot complete S1 without either stopping for a Controller amendment or violating the "additional path returns to Controller" rule.

## 4. Open questions

1. **PA25 relocation in PA26 tail methods**: The updated PA25 expects 15 history rows and rejects a V014-only database. The existing `psql("apply"); psql("check")` calls inside `v014UpgradesFrozenPrefixAndMatchesIndependentAclOracle` (`DatabaseRuntimeAclRbacHardeningIT.java:127`) and `v014ReplaysWithoutChangingAclsMembershipsOrBusinessObjects` (`:323`) run at V014 state. The plan says "finish the V014 assertions/replay first, then ... apply V015 and run the updated current PA25 apply/check", which implies those calls must be relocated after the V015 upgrade. Make that explicit, including whether the two PA25 runs in the replay method stay paired after V015.
2. **CI `pa27_additions` split**: The plan says to add `pa27_additions` with six classes and union it before `source_classes` equality, but does not state that four classes go to `unit_expected` and two to `container_expected`. The §9 table makes the split inferable, but stating it avoids a Surefire/Failsafe `exact_inventory` misplacement.
3. **V014 hash semantics**: `DatabaseRuntimeAclRbacHardeningIT.assertFrozen` normalizes CRLF to LF for V001-V013; the plan's V014 raw hash `bc9f9240...` is the CRLF raw hash. Clarify whether the required V014 check uses the LF-normalized logical hash in the existing `FROZEN` policy or a separate raw-bytes comparison (the plan's §10.1 says both policies must be retained).
4. **Mandatory cursor key availability**: The endpoint returns 503 whenever the HMAC key is absent/malformed, including a first/empty page. The plan routes key distribution/rotation to Security/Operations and says no live secret is assigned in S1. Confirm that this mandatory deployment precondition is accepted for endpoint availability and does not weaken the Control success signal in environments where the key is not provisioned.
5. **Cross-module DSL bean inversion**: The subject-number/activation-consent reader configurations inject the `customerQueryDsl` bean owned by `customer_iam`, avoiding a Java import but creating a runtime dependency invisible to Modulith. The new IT exercises the real wiring, but confirm this inversion is acceptable versus passing a transaction-bound query handle through a non-public adapter.
6. **Four-role fixture capacity**: The confirmed matrix requires all four ACTIVE organization roles. Because `uq_membership_live` allows one non-revoked membership per account/organization, exercising all four roles for the same reader account needs four organizations (or four accounts). The plan's "at least two accounts, two organizations" is a minimum; the exact fixture shape should be stated so the role loop is possible.
