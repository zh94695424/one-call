## 6. Open questions

If a future fix round is opened, naming that reuse explicitly would remove implementer choice. Does not block.
2. **Persisted-`EXPIRED` + nonpositive-window precedence (low).** §9A L379 contains both "terminal `REVOKED`/`EXPIRED` … no `TICKET_FAILED`" and "if `ticketExpiresAt - clock_timestamp()` is zero or negative, append `TICKET_FAILED` … 410". The §2.2 order (terminal state before time/expiry) and the explicit terminal sentence resolve this for implementation: a persisted terminal status wins and appends no `TICKET_FAILED`; the window rule applies absent a terminal status. Both outcomes are 410 and neither recounts. Literal adjacency could be clarified in a later bounded precision pass; not material.
3. **Post-commit "all other current predicates" scope (low).** §9A L379 says other current predicates still apply in exact §2.2 order. docs/14 §9.31 step 5 says revoke/rotation/expiry invalidates subsequent ticket issuance, so a concurrent generation change before the first ticket should deny without a `TICKET_FAILED`; the plan does not spell out that one race in the named test map. The outcome is fail-closed and preserves the admission; the existing race method (`admissionRaceWithRevokeOrRotateObserversCommittedWinner`) covers the winner semantics. Non-blocking.
4. **Manifest provenance (Controller-owned).** My own deterministic manifest is recorded in §1 and verified before/after this artifact; the Controller's historical canonical manifest recipe was not independently reproduced in this shell. File count, byte total, zero private-path state, target identity, fix-9 identity and all key content hashes match. Same provenance residual as prior rounds; not a plan-content defect.
