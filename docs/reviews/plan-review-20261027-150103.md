### F-PA2-PR-01-未修复-低-check 谓词清单未强制精确谓词文本

- **位置**: plan §1.3 success signal “every named check”; §8.2 Checks row (“Exact 4/7/7/4/4/8 named checks; no extra check”); §8.3 / §7.2 `mutableHeadsEnforceLifecycleRevisionAndNamedChecks` (“every named check has a violating row probe asserting `23514` and the exact constraint name”); contrast with §8.2 Partial unique/index row (“exact `indexdef` for both partial indexes”) and §10 R-12.
- **问题类型**: 测试缺口 / validation silent-miss
- **当前写法**: Inventory asserts check *names* and absence of the R-01 alias. S2 asserts one violating row probe per named check with SQLSTATE `23514` and the constraint name. Partial indexes require exact `indexdef`. FK catalog requires exact `confupdtype`/`confdeltype`/`confmatchtype`/deferrability. Check *predicates* (`conbin` / `pg_get_constraintdef`) are not named as an exact inventory field. R-12 states deparse forms can vary and says to assert “exact names/attributes and partial `indexdef`”, never weaken semantics.
- **反例/失败场景**: Implementation writes a check with the correct name but a looser or tighter predicate than `docs/14` (for example HMAC format regex, status enum membership, or `verified_at` ordering). Name inventory passes. A single violating probe still raises `23514` with the right name. Subtle near-miss values that the frozen predicate must reject are accepted (or valid future states are rejected) and still produce green S1/S2 evidence. Later waves that treat these parents as frozen trust a predicate that was never proven.
- **为什么有问题**: The work unit’s success signal is “exact named check” against `docs/14`. Exactness for partial indexes and FK flags is explicit; exactness for check predicates is implied by “exact” but not operationalized in §8.2/§8.3. That asymmetry is exactly the validation silent-miss the review lenses require the plan to close before implementation.
- **直接证据**: plan §8.2 Checks vs Partial unique/index wording; §8.3 single-name `23514` probes; §10 R-12; `docs/14` 4.6–4.11 named-check predicates as frozen text; success signal citing `pg_constraint` catalog assertions.
- **影响**: False-correct inventory evidence; wrong frozen parent predicates can ship and require a later `ALTER CONSTRAINT` correction; review cannot accept “exact catalog” on names alone; risk moved into later waves that depend on these parents.
- **建议改法和验证点**: Pick one explicit rule and put it in §8.2/§8.3: (a) inventory also asserts normalized `pg_get_constraintdef`/`conbin` equality for all 34 named checks against the `docs/14` predicates (allowing only container-evidenced deparse normalization), **or** (b) declare behavioral probes as the predicate authority and require at least one positive valid shape and one violating shape per distinct predicate class (enum, revision, time order, HMAC/text format), with the probe shapes listed. Validation point: S1 inventory or S2 `mutableHeadsEnforceLifecycleRevisionAndNamedChecks` fails if a same-named check’s predicate accepts a frozen-reject shape or rejects a frozen-accept shape. Do not drop the existing name/`23514` assertions.
