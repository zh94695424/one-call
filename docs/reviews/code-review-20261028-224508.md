- **入口/函数**: `ivr.guard_outbound_call_task()`、`ivr.guard_call_record_parties()` 以及 `ivr_role` 的 `UPDATE` 列权限；入口是 `ivr_role` 对 `ivr.outbound_call_task` / `ivr.call_record` 的 UPDATE。
- **文件(行号)**: `backend/src/main/resources/db/migration/V005__ivr_task_session_call.sql:407-409`（task guard 只拒绝 `OLD terminal → NEW PENDING/CLAIMED`）、`:446-477`（call guard 只检查 identity/parties/task_id，没有 status/terminal 规则）、`:531-545`（runtime 对 `status`、`reason_code`、`terminal_at`、`ended_at`、`authoritative_seconds` 等有 UPDATE 列权限）；binding prose：`docs/14:1268`（outbound task `terminal rows are immutable`）、`docs/14:1393`（call `terminal states are immutable`）、`docs/14:2788`（`every terminal state is immutable`）、`docs/14:2792`、`docs/14:2800`；plan claim：`docs/gateflow/pa5-v005-ivr-task-session-call-foundation-plan.md:286`。
- **输入场景**: 在独立 disposable PostgreSQL 16.15 容器应用 V001-V005 后，以 `ivr_role` 执行：
  - 将已 `COMPLETED` 的 task 更新为 `FAILED`（同时改 `reason_code`、`terminal_at`、`revision`）；
  - 将已 `ENDED` 的 call 更新回 `ACTIVE`（清空 `ended_at`、`authoritative_seconds`）。
- **实际分支**: `guard_outbound_call_task` 的条件只覆盖 `OLD.status NOT IN ('PENDING','CLAIMED') AND NEW.status IN ('PENDING','CLAIMED')`；`COMPLETED → FAILED` 不满足该条件，guard 放行。`guard_call_record_parties` 完全没有 status/terminal 判断，`ENDED → ACTIVE` 放行。`ck_outbound_task_terminal_shape` 对两个 terminal status 都要求 `terminal_at IS NOT NULL`，未禁止 terminal→terminal；`ck_call_record_terminal_shape` 对 `ACTIVE` 要求 `ended_at IS NULL`，清空 `ended_at` 后重新满足。
- **预期行为**: `docs/14:1268/1393/2788/2792/2800` 明确 terminal rows/states immutable；plan §5.1 声称 Terminal task rows 由 identity 列、terminal→non-terminal rejection 和 terminal check 保证。数据库 backstop 应拒绝 terminal task 的状态/原因/terminal 时间改写，以及 terminal call 的 status/ended_at 改写（至少 `ENDED/FAILED/REJECTED` absorbing；`UNKNOWN` 仅允许进入 `ENDED/FAILED`）。
- **实际行为**: 独立 probe 两条 UPDATE 均返回 `UPDATE 1`；task 最终为 `FAILED`、call 最终为 `ACTIVE`。terminal 事实可被 runtime 角色覆盖，ended call 可重新占用 canonical-caller active slot。
- **直接证据**: V005 `:407-409` 的单一 terminal→live 条件；`:446-477` 无 status 检查；`:531-545` 的 UPDATE grant；probe 输出：`UPDATE 1`（COMPLETED→FAILED）、`UPDATE 1`（ENDED→ACTIVE），最终 `task|FAILED|...`、`call|ACTIVE|no_end=t`。plan §5.1 的 “Terminal task rows are immutable by identity columns, rejection of terminal→non-terminal transitions, and ck_outbound_task_terminal_shape” 并不能覆盖 terminal→terminal；docs 的 immutable 语义未被数据库实现。
- **影响**: 历史 task/call 终态可被可信 runtime role 或其 bug 改写；terminal task 的 reason/terminal 时间、call 的结束时间和 authoritative seconds 可被覆盖；`ENDED → ACTIVE` 可重新进入 canonical-caller active/UNKNOWN guard，影响后续 resolve/direct authorization/reservation/settlement/evidence 对 call 终态的信任。当前 PA5 没有 application service，因此是数据库 backstop 缺口而非已上线可利用路径，但属于 architecture-sensitive 的 state-machine 契约。
- **建议改法和验证点**: 二选一并由 controller/user/schema authority 裁决：
  1. 增加 guard：task 在 `OLD.status NOT IN ('PENDING','CLAIMED')` 时拒绝 status/reason_code/terminal_at/claimed_call_id/claimed_at/updated_at/revision 变更（或至少拒绝任何 terminal row 实质变更）；call 在 `OLD.status IN ('ENDED','FAILED','REJECTED')` 时拒绝 status/ended_at/authoritative_seconds/end_reason 变更，`UNKNOWN` 仅允许 `UNKNOWN→ENDED/FAILED`；增加 terminal→terminal、ENDED→ACTIVE、UNKNOWN→REJECTED 的隔离 `P0001` probe，并保留 `UNKNOWN→ENDED` 合法路径。
  2. 若 §10.16 的 guard 列表被视为冻结且 terminal 状态属 service-owned，则修正 plan §5.1 和 README/evidence boundary，明确 terminal absorption 不是数据库保证，并把该风险交给 IVR service wave；不得继续声称数据库已保证 terminal rows immutable。
  验证点：上述 terminal 改写必须失败，`UNKNOWN→ENDED/FAILED` 与现有 category-2/3、claim/replay 测试仍绿；V005 inventory 计数不变（guard 函数/触发器仍为五个）。
- **修复风险（低/中/高）**: 中（涉及 frozen guard 语义、reconciliation 的 UNKNOWN 收敛、测试 fixture；若选方案 2 仅为证据/文档修正）。
