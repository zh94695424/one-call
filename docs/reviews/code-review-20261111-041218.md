- **V014’s preflight is deliberately stricter than the product contract.** A production database with any database-wide `pg_db_role_setting`, any extension/helper object with PUBLIC routine privileges in a non-system schema, any extra ACL touching a target role, or any unexpected routine in a managed schema will be rejected before mutation. That is fail-closed and consistent with the accepted “reject, do not repair” policy, but Platform/Database/Security must confirm that the real cluster has none of these before rollout; the runbook only describes them generically.
- **Cluster-global role comments couple databases.** The PA25-v1 marker scan is cluster-wide, so any other database in the same PostgreSQL cluster with its own PA25 identities would change `marked_count` and reject V014/PA25 for the current database. This matches the runbook’s exclusive-cluster-administration assumption but is not restated as a V014-specific precondition; Platform/Database should confirm one provisioned database per cluster (or per administration boundary).
