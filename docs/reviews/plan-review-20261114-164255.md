- AES-GCM cursor (plan §4) is stronger than the existing customer HMAC cursor; justified by Control “no plaintext timestamps” rather than unrequested design ambition.
- **Result:** no goal drift / scope creep finding.

### B. Route admission and filter lockstep

- `OperationsBoundaryFilter` registers at `Ordered.HIGHEST_PRECEDENCE` on `/api/v1/operations/*` (`OperationsWebConfiguration`); `CustomerBoundaryFilter` at `HIGHEST_PRECEDENCE + 1` on `/*` with an early Operations POST pass-through **before** `UUID traceId = ...` (line 55). - Precedence in plan §3.2 (hidden routes → bearer → single service bean → tx/authority → noncursor validation → Accept → cursor → providers → reads; detail NOT_FOUND only after authority+validation; empty list 200) matches filter/controller architecture and OpenAPI error sets (CURSOR_INVALID/CURSOR_FILTER_MISMATCH 400, VALIDATION_FAILED 422, NOT_FOUND on detail only).

### C. Auth / authority / employee failure modes

### 1-未修复-低-§7.2 两处 schema USAGE 行号引用与迁移真源不符

- **位置**: plan §7.2 “Existing capability proof and hard stop” rows `activation_consent_role` and `entitlement_metering_role` (plan lines 202–203).
- **问题类型**: 契约缺失 / 其它（evidence citation accuracy against frozen migrations）
- **当前写法**: “activation_consent_role | V007 lines 204–212 schema USAGE and SELECT”; “entitlement_metering_role | V006 lines 638–646 schema USAGE and SELECT”.
- **反例/失败场景**: Implementation agent or Controller spot-checks the cited lines to re-prove the hard stop. V007:204–212 is `REVOKE ALL ON FUNCTION…` plus table/function grants to `activation_consent_role` — no `GRANT USAGE ON SCHEMA`. V006:639 is `GRANT USAGE ON SCHEMA entitlement_metering TO catalog_order_role`, not `entitlement_metering_role`. The agent concludes the matrix is wrong and either stops unnecessarily or “fixes” grants (forbidden).
- **为什么有问题**: §7.2 is the frozen no-new-grant proof; wrong line pointers undermine the very evidence the hard stop depends on, even though the underlying capability is real.
- **直接证据**:
  - `V004__catalog_order_and_payment.sql:485–486` — `GRANT USAGE ON SCHEMA activation_consent TO activation_consent_owner, activation_consent_role, ivr_role, catalog_order_role`.
  - `V004__catalog_order_and_payment.sql:492–493` — `GRANT USAGE ON SCHEMA entitlement_metering TO entitlement_metering_owner, entitlement_metering_role, activation_consent_role, ivr_role`.
  - `V007__activation_and_consent.sql:204–212` — REVOKE FUNCTION / GRANT SELECT,INSERT on consent_record, service_activation, service_activation_transition to `activation_consent_role` (no schema USAGE).
  - `V006__trial_entitlement_issuance_reservation_usage.sql:639` — USAGE TO `catalog_order_role` only; `641–646` table grants to `entitlement_metering_role`.
- **影响**: Review friction / incorrect hard-stop verification / risk that an implementer adds a redundant or wrong grant under stress. Does not change the six-role sufficiency conclusion.
- **建议改法和验证点**: Correct the two citations to V004:485–486 and V004:492–493 for schema USAGE (optionally keep the nearby SELECT lines as separate pointers). Re-verify every §7.2 row against migration text before implementation intake. No migration edit.

### 2-未修复-低-GET Accept 失败路径的 filter 分支改法未显式化

Failure is caught late (test red) but the plan does not say where the check moves (GET branch must skip/relocate; POST keeps current behavior).
- **为什么有问题**: Precedence is a frozen acceptance criterion; the filter is allowlisted but the required control-flow split is not spelled out, forcing the implementer to re-derive it.
- **直接证据**:
  - `OperationsBoundaryFilter.java:47–55` — Accept parse + `if (!accepted.isEmpty() && (compatible.isEmpty() || … getQualityValue() == 0)) throw new Failure(Code.INTERNAL);`

- **影响**: Wrong first implementation, red retained/new tests, possible incorrect error code (500 vs 422) if tests are weakened instead of the filter split.
- **建议改法和验证点**: In the plan’s filter edit description, state explicitly: for admitted GET routes, incompatible/malformed Accept must not throw pre-authority INTERNAL; evaluate Accept after authority and map to VALIDATION_FAILED/422 via the read path; POST command Accept behavior unchanged. Verify with the two named tests plus retained `OperationsLifecycleBoundaryTests` source assertions.
- **修复风险（低）**: Clarifying existing §3.2 intent; no design change.
