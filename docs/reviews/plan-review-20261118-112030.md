1. **O-1 — Repository-test ownership wording.** Plan §9.3 assigns `CatalogSaleLifecycleRepositoryTests.readsAuthorityWithoutLocking`/`entersExactOperationsIamRole` and `acquiresProductLockBeforeDecisionTime` assertions about authority delegation and the three SET LOCAL statements, while §3/§6.1 assign the authority read to `DefaultEmployeeAuthorityReadPort` and the role/SET LOCAL orchestration to the command. 2. **O-2 — Command configuration condition.** `OperationsCatalogVersionConfigurationTests.defaultRuntimeHasNoWriteBeans` requires no write beans when the profile/property is disabled, but §4.1 file 10 (`CatalogSaleLifecycleConfiguration`) does not explicitly state the `@Profile`/`@ConditionalOnProperty` condition. 3. **O-3 — `55P02` semantics.** PostgreSQL 16 names `55P02` `cant_change_runtime_param`, not lock unavailability; the plan maps it to 409 per the Controller-accepted RR2-04 wording while setup installation failure is 503. If a non-setup `55P02` is possible, the Controller’s intended public outcome should be recorded explicitly. 4. **O-4 — Idle timeout runtime depth.** The plan installs and asserts `idle_in_transaction_session_timeout='5000ms'`, and the IT triggers real `55P03` and `57014`; no subcase forces the 5-second idle timeout. Is the effective-value assertion sufficient, or should an idle-timeout subcase (no new test identity) be added to prove the failure/eviction/503 path?
