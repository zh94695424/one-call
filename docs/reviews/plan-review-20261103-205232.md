## Material findings

### F-A-01 — Exhaustive README delta still omits two direct V010 contradictions

- Severity: blocking plan completeness defect.
- Evidence: `backend/README.md:308` still says “No sharing service function, V010 object, policy value or production integration is introduced.” `backend/README.md:326` still says “No service/API/worker/Redis/COS/KMS, production policy or V010 is added.”
- Contradiction: plan line 132 presents the README site list as exhaustive and line 92 says documentation edits are governed exhaustively by that list. The list includes lines 304/305/306 and 321/322 but not 308 or 326. Fix-3 line 18/31 therefore overstates that the complete accepted union is present.
- Impact: a literal implementation can leave current-state documentation asserting that V010 does not exist even while the same documentation states the post-V010 inventory.
- Required correction: add README lines 308 and 326 to the binding union and update or explicitly mark those statements historical. If section-level historical marking is intended instead, the plan must name the section/heading edits and remove the “those named sites only” conflict.

### F-A-02 — A third pre-V009 role-absence fence remains unmodified

- Severity: blocking closure defect for the stated fence requirement.
- Evidence: `PostgresContainerIT.assertNoV008PlusObjects` at `backend/src/test/java/com/onecall/archtests/container/PostgresContainerIT.java:10572` executes before V009 and queries only `sharing_owner` and `sharing_role` at lines 10602-10605. It is called at line 1103 alongside `assertNoV009PlusObjects`.
- Contradiction: plan lines 73 and 121 and fix-3 line 15 name only `assertNoV009PlusObjects` and `stagedV007SharingRolesAbsent` as the pre-V009 absence fences requiring `sharing_command_role`.
- Impact: the adjacent `assertNoV009PlusObjects` would still catch a stale command role in the current call sequence, but the named “every pre-V009 fence” contract is not implemented literally and fix-3’s closure statement is incomplete.
- Required correction: add `assertNoV008PlusObjects` to the binding source-site list and require its role count query to include `sharing_command_role`, while preserving the expected zero count and all 64 method names.

### F-A-03 — Standalone-IT bootstrap grantor identity is not pinned

- Severity: material implementation-time choice; resolve before acceptance.
- Evidence: plan lines 58 and 126 allow retained V001-V009 bootstrap grantors only as `onecall` or `fixture_admin`. Plan line 131 says the new standalone IT owns “per-run admin credentials” but does not pin the admin username. Retained grants in that standalone container will be attributed to that admin.
- Impact: exact grantor/grantee comparisons can be written only after choosing whether the new IT admin is named `fixture_admin` or a new identity; a new identity is outside the current allowed set.
- Required correction: pin the standalone IT admin username to `fixture_admin` (with a per-run password), or extend the deterministic retained-grantor rule to name the new IT admin exactly.
