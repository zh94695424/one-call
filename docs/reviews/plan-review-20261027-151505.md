### 6.3 Self-agreement challenge

**Decision: adequate at plan-contract level; residual authoring risk remains and is tracked, not an open finding.**

What is still true mechanically:

- Each expected definition is obtained from a real `postgres:16` container after V002 applies and then frozen as a test literal. A wrong migration can therefore produce a self-agreeing literal if the implementer freezes the wrong deparse and nobody checks semantics against `docs/14`.

Why the revised plan is still code-generation-ready and does not *authorize* a wrong migration to define its expected result:

- `docs/14` 4.6–4.11 remains the authoritative predicate source; the plan forbids hand-authoring an “equivalent” SQL predicate and forbids changing any source predicate.
- §8.2.1 explicitly states that capturing a deparse from a migration whose predicate disagrees with `docs/14` is not valid evidence.
- §8.2.1 and §12 item 5 require per-entry `docs/14` section/subsection plus raw captured deparse so S1 review can confirm derivation from the frozen predicates rather than from the implementation’s own DDL.
- Capture-then-freeze is the only practical way to obtain PostgreSQL 16 canonical deparse *format*; the same pattern already exists for V001 exact `indexdef`. Independence comes from freezing the literal and from the S1 review obligation, not from recomputing deparse from prose without a container.
- Once frozen, later migration drift fails closed against the literal.

Residual (not a new finding): if S1 review only checks “deparse equals frozen map” and does not re-read `docs/14` semantics per entry, a wrong initial capture could ship. That is RF-01 / RSK residual, owner Backend/QA, destination S1 implementation and S1 review. A tighter evidence format (docs/14 predicate expression beside each deparse, not only a section pointer) would reduce this residual but is not required to close F-PA2-PR-01.
