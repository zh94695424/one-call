## 1. 验收方法

验收分为六层：

1. **需求验收**：业务规则、页面状态和文案与批准版本一致。
2. **契约验收**：客户端、服务端和供应商对状态、回调、幂等和错误语义理解一致。
3. **功能验收**：正常、失败、超时、重试、撤销和只读路径可执行。
4. **证据完整性验收**：原始对象、哈希、时间证明、版本和访问日志可校验。
5. **安全合规验收**：敏感信息、授权、最小权限、供应商共享和数据生命周期已批准。
6. **生产验收**：监控、告警、对账、备份、灾备、客服和供应商联络机制就绪。

任何场景只通过界面演示、但没有服务端状态或审计证据时，不算通过。

## 5. 内部实施阶段

### Phase 0：决策和供应商可行性

交付：产品规格批准稿、原始设计源、供应商能力矩阵、法务问题清单、成本模型和技术验证报告。

退出条件：运营商开通接口能够同步返回可验证的成功/失败业务结果，并能够提供可匹配的通话/录音回执；实名、时间、AI、公证处存证、线下公证和支付均有可验证候选方案；上线阻断项有负责人。

### Phase 1：平台基础与首次开通

交付：账户、隐私指引、二要素实名、微信/短信手机号验证、独立固话主叫验证、个人三主叫号码管理、授权汇总确认、运营商同步开通结果、审计框架和后台异常列表。

退出条件：`ACC-T*`、`PHN-T*`、相关 `SEC-T*` 全部通过，运营商沙箱同步成功、失败、技术异常和幂等重试可重复验证。

### Phase 2：证据接入与取证电话

交付：手机号小程序拨号与强一致校验、固话声讯短号接入与唯一主叫解析、运营商录音接收、统一上传、相册、现场拍摄、微信文件、聊天截图、对象隔离、哈希、可信时间、证据箱基础、公证处自动存证和存证验证报告。

退出条件：`CALL-T*`、`FILE-T*`、`EVI-T*`、`NPS-T*` 通过；原始证据可独立校验；公证处异常不会错误显示成功。

### Phase 3：AI 与事情管理

交付：转写、说话人、时间定位、结构化摘要、引用校验、版本、用户注释、事情组织和受控分享。

退出条件：`AI-T*`、`BOX-T*` 通过；质量样本和降级规则获得产品、法务和供应商确认。

### Phase 4：套餐、支付、出证和运营闭环

交付：个人与企业商品版本、组织/成员/坐席、独立固话名额、共享权益账本、微信支付/合同报价、全主叫用量明细、分类公证资格、线下公证工单/材料/受理/交付、时间戳证书、证据包、退款和运营后台。

退出条件：`SUB-T*`、`ENT-T*`、`CRT-T*`、`OPS-T*` 通过；支付/合同、权益、全部实际主叫、存证平台和线下公证工单对账无未解释差异。

### Phase 5：生产硬化与上线

交付：性能容量、监控告警、备份恢复、灾备演练、安全测试、隐私评估、操作手册、客服脚本、小程序审核材料和灰度方案。

退出条件：所有门禁通过，阻断问题为零，残余风险有负责人、截止日期和书面接受记录。

## 8. 开工和完成定义

### Definition of Ready

一个工作单元进入实现前必须具备：批准的需求编号、页面/状态、接口契约、数据分类、供应商假设、验收场景、依赖和回滚策略。涉及敏感信息、录音、支付或公证的功能必须有法务/安全评审结论。

### Definition of Done

一个工作单元完成必须满足：代码和配置评审通过；单元、集成、契约、端到端和异常测试通过；指标、日志、告警和审计就绪；文档和 Runbook 更新；不存在未记录的数据迁移或人工数据库修改；对应追踪矩阵状态已更新。

### 首发完成

仅当 Phase 0 至 Phase 5 全部退出、所有 `BLK-*` 已关闭、G1 至 G6 有书面证据且严重缺陷为零时，版本才能标记为完整首发。任何未完成能力必须明确标为灰度/受限，不得用静态页面模拟生产能力。
