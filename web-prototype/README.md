# 一通话 · 证枢能力中枢 Web 原型

本目录是终端客户 Web 原型的唯一维护入口，覆盖个人用户工作台和企业用户工作台。

## 文件

- `evidence-hub.html`：原型源文件，所有页面与交互均在此维护。
- `preview.html`：运行 QA 后从源文件生成的浏览副本，不直接编辑。
- `qa/qa.js`：Playwright 交互、内容和响应式检查。
- `qa/run.ps1`：生成浏览副本并运行 QA。
- `qa/screenshots/`：各关键页面的评审截图。

## 运行

在 `D:\codex-call` 下执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\web-prototype\qa\run.ps1
```

运行成功后直接打开 `D:\codex-call\web-prototype\preview.html`。

## 当前范围

原型包含完整登录与身份承接、个人与企业两种工作空间和多类详情/向导页。S3 新增 `ivr-return`、`subject-claim`、`support`：同号验证后安全认领原 IVR 主体，实名独立完成，保留原试用与录音元数据；冲突/号码回收风险不开放历史。登录部分覆盖微信扫码、手机号验证码、首次隐私确认、企业邀请、多工作空间选择、会话过期恢复和账号/成员/坐席异常。企业空间保留企业管理员、普通成员、证据管理员和审计员四种评审视角；证据、分享、导出、事情、AI、出证及成员回归仍保留。

个人用户和企业管理员在左侧导航及顶部操作区均有套餐入口。个人用户进入共享目录和购买流程；企业管理员查看 ENTERPRISE + QUOTE 咨询比较，无在线合同/权益生效流程。企业普通成员、证据管理员和审计员不显示该入口。

证据箱统一管理通话录音、照片、视频、现场录音、文件和聊天截图；通话录音另有专门列表，展示主叫、被叫、接入方式、呼叫结果、录音时长、AI 和存证处理状态。

录音分享采用受控播放授权：外部默认使用短期链接与独立提取码，也可选择“免验证 · 链接直听”或指定手机号验证；企业内部可按成员授权。免验证链接打开后直接进入播放器，由接收方点击播放，无需登录、验证码或提取码；任何持有链接的人均可收听，因此创建页会明确提示转发风险。有效期、成功访问次数、撤销、分享内容和下载权限仍按单条分享记录执行。管理页覆盖有效、过期、次数耗尽、撤销、延期和提取码换码，接收方页面覆盖提取码错误锁定与各类阻断状态，不暴露原始存储地址。以上均为静态原型，不代表生产媒体流鉴权或持久化已经实现。

事情档案已覆盖列表检索、两步新建、按权限选择已有证据、创建结果、证据增删关联、负责人调整、归档二次确认和只读状态；关联关系不会改变原始证据。AI 结果支持提交带原文位置的纠错建议、重新处理生成新版本、历史版本切换和版本对比，旧结果不可覆盖。出证申请支持补件选材、材料快照核对、提交、审核状态和进度记录。消息中心支持角色隔离、全部/未读/待处理筛选、单条与批量已读及业务跳转。

自动化 QA 已通过登录/会话、六类证据、号码生命周期、授权、下载导出、分享、AI、事情、出证、消息、成员、企业角色、共享购买与线下客服回归，以及 1440/1280/1024/720px 无 document overflow。`invoice-apply` 旧路由仅显示线下指南，无在线开票提交或成功回执。新截图均为 `alignment-*`，历史截图保留。套餐全部标记 DEMO_NOT_APPROVED。

共享生成段由 `node shared/build-prototypes.js` 维护，runner 生成 preview 后执行 QA；禁止手改生成段。`window.__onecallWeb` 提供 `businessSnapshot()`、`loadReviewSnapshot(data)`、`setReviewScenario(name)`、`navigate(route)`、`currentRoute()`，仅用于经校验的本地 fixture 交接，不含员工、凭据、登录或 UI 状态。不是实时同步或生产 API；上线构建须关闭 hooks。三端验收运行 `node shared/qa/cross-channel.js`，执行证据和目视截图清单见 `docs/gateflow/cross-channel-alignment-s3-implementation.md`。

角色由当前自然人账户的有效成员关系派生，界面只读；已移除任意角色切换。空间下拉框只展示该账户可进入的个人及企业空间。会话过期重新登录会重建账户与成员权限，不继承前一人的管理员角色。云拓与未配置个人样例的账户显示明确空态，不显示华启或李晓的业务记录。

“设置”分开展示自然人账户、登录身份、当前成员角色和业务号码；绑定、开通和 IVR 认领均不会自动把业务号码变成登录身份。`accountContext()`、`expireSession(route)` 是新增本地评审 hooks，业务快照导入不会替换账号目录或会话。账号表职责与生产边界见 `docs/11-account-identity-and-workspaces.md`；前端角色 / 样例过滤不代替生产服务端鉴权。

S3-01/02/03 修复和新增回归证据见 `docs/gateflow/cross-channel-alignment-s3-fix.md`，不替代后续复审或验收。混合账户 fixture 由共享开通、订单、支付和权益 helper 生成；发放周期覆盖季付、年付及非默认间隔，并验证调整当前目录后历史快照仍保持原值。

认领在读取重放记录或处理同账户重复请求前检查 `CONFLICT / RECYCLED` 风险；原请求号和新请求号都保持阻断、隐藏历史且不改变快照。开通状态迁移的重复事件返回首次结果，复用事件号但改变目标状态会原子拒绝；导入缺失或畸形的迁移事件同样拒绝。

## 明确排除

- 平台运营台是独立产品面，不属于本原型。
- 企业总机、PBX、分机归属、统一外呼号拆分和坐席 PIN 不属于本期。
- 原型中的业务数据用于评审，不代表生产环境真实数据或已确认报价。
