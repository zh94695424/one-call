# 一通话平台运营后台原型

当前为跨端同步 S3：独立员工账号、六个主入口及完整套餐草稿/版本管理保持 S2 基线；IVR 展示分支与小程序/Web 本地快照交接已实现并验证。这里不宣称真实系统已经联调。

在仓库根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\operations-prototype\qa\run.ps1
```

成功后打开 D:\codex-call\operations-prototype\preview.html。源文件为 onecall-operations-admin.html；预览只由 runner 生成。共享规则来自 shared/onecall-business.js，runner 会先生成受控内联段。页面完全本地运行，刷新恢复样例，没有真实鉴权、支付、短信、线路或持久化。

## 员工与入口

登录使用员工登录名和六位 DEMO 码，权限从员工记录读取；不能选择角色。

| 登录名 | 初始 DEMO 码 | 角色 / 状态 |
| --- | --- | --- |
| admin.lin | 482916 | 管理员 / 启用 |
| admin.chen | 593027 | 管理员 / 启用 |
| ops.zhou | 604138 | 运营 / 启用 |
| ops.wu | 715249 | 运营 / 启用 |
| disabled.li | 826350 | 运营 / 停用，不能登录 |

六个主导航为概览、用户、套餐、订单、员工、操作记录。业务开通和 IVR 呼入归用户子导航；试用设置归套餐子导航。/roadmap 保留为线下客服说明地址，不是主导航。未知对象 ID 不回退到其他对象。

管理员可新增员工、编辑姓名和角色、停启用、重置 DEMO 码。新码只在操作结果中展示一次；审计不含码。最后一个启用管理员不能停用或降级。当前员工被停用、重置或改变角色时，本地会话失效，取消待执行操作并回到登录。运营不能查看员工管理或写套餐/试用，但可查询业务与暂停/恢复用户。

用户暂停/恢复只调用共享 `setActivationStatus`，迁移来源明确记录为 `OPERATIONS`；后台不直接改写主体开通状态或修订号。规范迁移同时保存前后状态、`fromRevision` / `toRevision`、时间和幂等事件，能在已有 Web 迁移历史后继续推进；重复键返回首次结果，冲突键或损坏账本原子拒绝，后台操作审计与规范迁移一并保留。

## 套餐与业务状态

套餐按产品族分组，支持状态、渠道、范围筛选及排序。完整配置包括编码/SKU、名称说明、类型/范围、价格、有效期、固定周期/期数/发放间隔、六类权益、附加权益、渠道与展示顺序。新建先存草稿；同一草稿编辑保留 ID、增加修订；已发布内容只能复制到下一版本。发布退市同 SKU 旧在售版本；上下架只影响新下单。所有商业参数均为 DEMO、待确认；企业方案仅咨询。

旧 PKG-PER/PLUS/TEAM 作为只读历史版本保存；ORD-601—604、历史试用、IVR 同意和由 `HISTORY-EVIDENCE-IVR-8001` 一致事件生成的历史证据，其原金额/额度/采集事实保留。目录换版及试用规则更新不改写历史订单、权益、已发试用或证据。试用仍以主体 + FIRST-TRIAL 永久一次，只在新主体首次领取时采用当前规则。

IVR 抽屉覆盖新手机、独立固话、重复主叫、超时、错误按键、无可信主叫、停用、关闭新试用、过期、剩余 20 秒、冲突和号码回收风险十二种场景。版本化录音告知后按 1 明确同意；同号复用主体和一次性试用。额度耗尽场景只在首次打开时从历史 `280/300` 通过共享 `consumeTrial` 消费到 `300/300`，关闭再打开仍保持耗尽，不回拨用量，也不重复新增证据或事件。固定取证事件重放不重复扣量或新增证据；请求 60 秒最多使用剩余 20 秒。购买引导只记录 GUIDED，不生成订单/支付；固话提示微信搜索，不宣称短信成功。不提供原始录音播放、下载或真实支付。

工单、退款、发票仅为共享配置中的线下客服指引；真实联系方式尚未配置，无虚构电话/邮箱、在线提交、回执或 SLA。

qa/screenshots/alignment-*.png 为本轮 S2/S3 截图，包含登录、员工、套餐表单/历史、用户试用、IVR 额度耗尽与跨端支付/客服。lean-* 和更早截图保留历史，不覆盖。目视清单和执行证据见 `docs/gateflow/cross-channel-alignment-s3-implementation.md`。

## 只读任务 / IVR 诊断

`/ivr-sessions` 在既有会话列表下方增加 `#call-diagnostics` 只读面板：任务表展示任务 ID、脱敏主叫、归属/空间、状态、冻结 30 秒、到期、领取 `callId` 与小程序拨号盘事实；呼叫表展示任务/无任务、决策/匹配、进度、录音秒数、录音上传、证据处理与结束原因。面板同时给出任务自动外呼（`DIAL_TASK_CALLEE`，无需确认被叫）与无任务 DTMF（`ENTER_CALLEE`）示例、三端所有权文案、无任务未注册/未实名可按 1 开通领取一次试用且不创建登录/实名身份的说明，以及“购买引导只记录 GUIDED、不创建订单/支付”的说明。

面板内没有 `data-action`、按钮、输入或编辑/重试/改派控件；伪造 `edit-task` / `retry-upload` / `mark-evidence` 不改变任何事实。评审抽屉新增“任务自动外呼诊断”和“无任务 DTMF 诊断”两个只读选择器，只设置高亮场景并导航到既有 `/ivr-sessions`，不创建 IVR 会话、不修改任务/呼叫事实。既有十二种 IVR 流程演示、六个主入口、15 个业务路由（6 主 + 9 次）和只读通话事实保持不变；不新增路由。

`callTaskSnapshot()` / `loadCallTaskSnapshot(data)` 与业务快照 hooks 分离，导入仍要求当前启用管理员和正常数据状态，且不改变业务事实；`setReviewCallScenario('task'|'no-task')` 只切换高亮。呼叫级证据状态只是诊断投影，权威证据列表仍是业务 `evidence`；所有数据为本地 fixture，不代表生产并发、线路、上传或持久化。

只编辑源 HTML 的应用区，禁止手改共享生成段或 preview。变更导航和权限时同步 QA；写操作必须同时验证允许与拒绝路径。生产身份服务、后端权限、凭据投递、不可变审计、并发扣量、支付和持久化仍由对应生产服务工作单元承担。
